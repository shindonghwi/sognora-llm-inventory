장르/단위: 크리에이티브 툴(디자인·웹 빌더 + AI 에이전트) / 랜딩 · 분석일 2026-08-15 · 상태: **완전**

## 실측 토큰

### 스프링 커브 — 사이트 전체가 커브 하나다

`linear()` 문자열을 전부 파싱해 형태를 복원했다.

```
duration 300ms → 30 stop   |  600ms → 60 stop
duration 400ms → 40 stop   | 1000ms → 100 stop
```

**샘플 해상도가 정확히 duration ÷ 10ms.** 스프링을 10ms 간격으로 구워 `linear()`로 굳힌 것이고, 이게 CSS에 cubic-bezier가 한 개도 없는 이유다.

복원한 곡선은 duration이 달라도 **정규화하면 같은 하나**다.

| 지표 | 300ms | 400ms | 600ms | 1000ms |
|---|---|---|---|---|
| 최댓값 | 1.0000 | 1.0000 | 1.0000 | 1.0000 |
| **오버슈트** | **없음** | **없음** | **없음** | **없음** |
| t@50% | 0.21 | 0.21 | 0.19 | 0.18 |
| t@90% | 0.45 | 0.44 | 0.42 | 0.42 |
| t@99% | 0.72 | 0.74 | 0.73 | 0.73 |

400ms 커브 실측 진행률:

```
 40ms → 24.5%      160ms → 89.2%      280ms → 99.0%
 80ms → 56.5%      200ms → 95.0%      320ms → 99.6%
120ms → 77.6%      240ms → 97.7%      390ms → 100%
```

두 가지가 결정적이다.

1. **오버슈트 0.** 스프링을 쓰면서 튕기지 않는다. `linear()` 최댓값이 네 duration 전부 정확히 1.0000이다. "스프링 = 통통 튐"을 이 사이트가 반증한다.
2. **명목 400ms인데 체감은 200ms.** 절반을 80ms에, 95%를 200ms에 끝내고 나머지 200ms는 꼬리로 흘린다. 꼬리가 공짜인 대신 베지어 특유의 "딱 멈추는" 순간이 사라진다.

## 자산 운용

**히어로는 비디오다.** 1200×673 표시 / 소스 2320×1300(2배) / 21.03초 루프 / `autoplay muted loop playsInline` + **poster 있음**. 내용은 Framer CMS 화면에 AI 생성 인물 그리드가 채워지는 실제 제품 화면이고, 우측 패널에 **제품 자신의 파란 선택 테두리(`#0099FF`)** 가 살아 있다. 목업을 새로 그린 게 아니라 캔버스를 그대로 녹화했다는 신호다.

**나머지 비디오 8개는 전부 525×150 마퀴 타일**이고 `autoplay: false`로 두고 뷰포트 진입 시 재생한다. 첫 화면 비디오만 자동재생, 아래는 지연 — 그래서 3.7MB 비디오가 FCP 148ms를 안 망친다.

**프레이밍 규칙 — 마스크로 녹인다.** `mask-image` 그라데이션 **26곳**이 이 페이지의 서명이다.

```
linear-gradient(rgb(0,0,0) 65.8052%, rgba(0,0,0,0) 100%)      세로 페이드
linear-gradient(270deg, rgba(0,0,0,0) 25.4748%, rgb(0,0,0) 62.4865%)  가로 페이드
radial-gradient(105px 125.58px at 193.974px 0.5px, …)          부분 마스크
```

정지점이 65.8052%·56.7113%·44.2383%처럼 **전부 비반올림**이다. 공유 토큰이 아니라 자산마다 눈으로 맞춘 값이라는 뜻이다. 효과는 명확하다 — 제품 스크린샷이 잘리는 게 아니라 **검정 배경으로 용해된다.** Linear가 그레인 오버레이로 푸는 "PNG가 떠 보이는" 문제를 Framer는 마스크로 푼다. 같은 문제, 다른 답.

**유일한 CSS 애니메이션이 그레인이다.** `betterGrainWebpFramesV22` · 0.75s · **steps(12)** · infinite — 12프레임 스프라이트를 똑딱 넘기는 필름 그레인. 정지 그레인이 아니라 **움직이는 그레인**이고, 페이지에서 CSS가 담당하는 모션은 이것 하나뿐이다.

**포화색은 남의 것에만 쓴다.** 페이지 크롬은 검정·흰색·회색이고, 채도가 폭발하는 구간은 `Shipped with Framer`의 고객 사이트 썸네일(오렌지 하늘, 초록 잔디, 잡지 화보)뿐이다. Framer 자신의 액센트 `#0099FF`는 캔버스 선택 테두리와 링크에만 나온다. Linear가 후기 카드에서 쓰는 전략과 동일한 결론에 다른 경로로 도착했다.

**목업에 창틀을 씌우는 경우와 안 씌우는 경우가 갈린다.** 제품 캔버스(Agents·벤토)는 창틀 없이 평면으로 놓고 마스크로 녹이지만, 커뮤니티 섹션과 터미널 데모는 **macOS 신호등 3점**을 붙인다. 기준은 "우리 제품 화면인가(창틀 없음) / 남의 앱처럼 보여야 하나(창틀 있음)"로 읽힌다.

## 인터랙션

### 호버 — 어휘가 값 하나다

40개 표본을 실제 마우스로 호버해 self + 자식 6개까지 비교했다. 반응 15 / 무반응 25.

| 요소 | rest → hover | 방식 |
|---|---|---|
| 내비 `Solutions`·`Resources`·`Enterprise`·`Pricing` | opacity **0.6 → 1** | 자식 |
| `Log in` | color·borderColor `rgba(255,255,255,.6)` → `rgb(255,255,255)` | self |
| `Sign up`(프라이머리) | opacity **1 → 0.6** | 자식 |
| `Get started for free` | opacity **1 → 0.6** | self |
| `Download app` | opacity **1 → 0.6** | 자식 |
| 로고월 항목 | 변화 없음 | — |

**호버 언어 전체가 `opacity 0.6 ↔ 1` 하나다.** 방향만 뒤집는다 — 쉬고 있을 때 어두운 것(내비)은 밝히고, 쉬고 있을 때 밝은 것(버튼)은 **어둡게 만든다.** 프라이머리 버튼을 호버해서 흐려지는 사이트는 드문데, 값이 하나라서 일관돼 보인다.

**40표본 전체에서 `transform` 변화 0, `box-shadow` 변화 0.** lift·scale·그림자 확장이 한 곳도 없다. Linear와 정확히 같은 결론이고, 수단만 `brightness()` 대신 `opacity`다.

호버 duration은 **400ms**(대부분)와 **300ms**(헤더 Sign up) 두 값. Linear의 0.1/0.16s보다 3~4배 길지만, 앞서 본 스프링 때문에 95%가 200ms에 끝나 체감은 비슷하다.

**인터럽트가 살아 있다.** 호버를 빠르게 뺐다 넣으면 keyframe 시작값이 정수가 아니다.

```
{"opacity":[0.9865112786164365, 0.6]}   ← 1이 아니라 진행 중이던 값
{"opacity":[0.997588441686482, 0.6]}
{"opacity":[1.0060658427605509, 0.6]}   ← 1을 살짝 넘긴 지점에서 이어받음
```

리셋 후 재생이 아니라 **현재 값에서 이어받는다.** CSS transition으로는 공짜로 얻는 동작인데, JS로 갈아엎고도 이걸 유지한 게 175건 전부 WAAPI인 이유다.

무반응 25개는 대부분 실제 타겟의 래퍼(자식이 반응)이고, 순수 무반응은 로고월 항목·본문 텍스트·`#7 on OpenRouter` 스탯이다. 전부 링크가 아닌 요소라 정상이다.

### 스크롤 리빌 — 트리거가 아니라 **스크롤 연동**

이 사이트에서 가장 중요한 발견이다. 리빌 대상을 뷰포트 하단에 60px만 걸치게 스크롤한 뒤 **2.2초간 스크롤을 멈추고** 값을 추적했다.

```
rest             opacity 0.200   translateX(-20px)
60px 진입 직후    opacity 0.275   translateX(-18.125px)
+0.5초 (홀드)     opacity 0.275   translateX(-18.125px)
+1.0초 (홀드)     opacity 0.275   translateX(-18.125px)
+2.2초 (홀드)     opacity 0.275   translateX(-18.125px)   ← 끝까지 안 간다
다시 y=0으로      opacity 0.200   translateX(-20px)       ← 정확히 원상복귀
```

**스크롤을 멈추면 애니메이션도 멈추고, 되돌리면 되감긴다.** IntersectionObserver 원샷 트리거가 아니라 스크롤 위치가 곧 애니메이션 진행률이다. 업계 표준인 "한 번 발화하면 끝"과 반대다.

세 가지가 따라온다.

- **되돌아가도 콘텐츠가 사라지지 않는다.** 위로 스크롤할 때 요소가 다시 흐려지지만, 그건 버그가 아니라 같은 규칙의 대칭이다.
- **rest opacity가 0이 아니라 0.2다.** 리빌 전에도 콘텐츠는 20% 보인다. 빠르게 스크롤해도 빈 화면을 통과하지 않는다.
- **축이 X다.** `translateX(-20px)` — 세로 20px 밀어올리는 그 관용구를 안 쓴다. 이 요소가 가로로 늘어선 아트보드 행이라서 이동 방향이 콘텐츠 배열 방향과 일치한다.

정지 상태 opacity 분포: **0.00 ×41 · 0.60 ×5 · 0.20 ×5 · 0.98 ×4 · 0.05 ×1.** 0.60 5개는 내비 항목(rest 상태), 0.20 5개가 리빌 대상이다. **0.00이 41개**인 건 문제로 볼 지점이다 — 그중 `Meet our customers`처럼 실제 텍스트를 가진 요소가 섞여 있다.

### 블러 — 초점 장치를 두 곳에서 재활용한다

`filter` 애니메이션 57건의 정체다.

**(1) 글자 단위 blur-in — 그런데 마케팅 카피가 아니다**

```
{"filter": ["blur(10px)", "blur(0px)"]}   ×25   400ms
{"opacity": [0.001, 1]}                   ×25   400ms
delay 0·50·100·…·1200ms  (50ms 등차 25단)
```

`span` 25개를 delay 순으로 정렬해 텍스트를 복원했더니 이렇게 나온다.

```
T·h·e·a·r·t·o·f·c·r·e·a·t·i·v·e·d·i·r·e·c·t·i·o·n
→ "The art of creative direction"
```

**글자 하나당 span 하나**, 공백 제외 25자, 총 1,600ms(1,200 stagger + 400 duration). 그런데 이 문장은 **히어로 헤드라인이 아니다.** 히어로 h1은 단일 요소이고 애니메이션이 걸려 있지 않다. 이 문장은 **제품 목업 안 CMS 행 제목**, 즉 에이전트가 방금 써낸 것처럼 보여야 하는 텍스트다.

페이지에서 유일한 글자 단위 타이핑/blur 연출이 **자기 카피가 아니라 시뮬레이션된 제품 출력에 걸려 있다.** 헤드라인을 한 글자씩 등장시키는 그 흔한 연출을 이 사이트는 한 번도 자기 문장에 쓰지 않는다. Linear가 유일한 엔트런스를 제품 목업 내부에만 둔 것과 같은 판단이다 — **연출은 제품이 일하는 모습에만 쓰고, 자기 주장에는 안 쓴다.**

`translateY`도 없다. 위에서 떨어지는 대신 **초점이 맞는다.**

**(2) 메가메뉴 — 페이지 전체를 뒤로 민다**

메뉴를 열면 DOM에 요소가 딱 하나 생긴다.

```
framer-6c3glj · 1440×900 · top 47 · z-index 1
backdrop-filter: blur(5px)
background: rgba(0,0,0,0.6)
```

**단일 스크림이다.** 히어로 h1을 체인 끝까지 따라가며 확인했더니 메뉴가 열려도 `filter: none / opacity: 1` — **콘텐츠는 손대지 않는다.** top이 47px이라 내비 행은 스크림 위에 남아 선명하고, 그 아래 전부가 흐려지며 60% 어두워진다. 메뉴를 닫으면 요소가 통째로 사라진다.

그래서 메뉴에 패널이 필요 없다. 배경을 뒤로 밀어버리면 맨 텍스트도 충분히 읽힌다.

**(3) 캐러셀 초점 — blur + dim 동시**

```
{"filter": ["blur(0px)", "blur(3px)"]}  +  {"opacity": [1, 0.4]}      600ms
{"filter": ["blur(2.97501px)", "blur(0px)"]} + {"opacity": [0.404998, 1]}  ← 인터럽트
```

비활성 항목을 `blur(3px) + opacity 0.4`로 밀고 활성 항목만 선명하게 둔다. 여기서도 시작값이 `blur(2.97501px)`처럼 진행 중 값이다.

**blur 값이 3px과 5px 두 개뿐이다.** 콘텐츠끼리의 초점 이동은 3px, 레이어를 통째로 밀 때는 5px. 텍스트 진입만 10px에서 시작한다.

### 마퀴 — CSS도 WAAPI도 아니다

`Shipped with Framer`의 고객 사이트 행을 1.2초 간격으로 두 번 측정했다.

| 트랙 | t=0 | t=1.2s | 속도 |
|---|---|---|---|
| 상단 1200×450 (자식 6) | `translateX(-68.289px)` | `translateX(-104.892px)` | **-30.5px/s** |
| 하단 1200×450 (자식 6) | `translateX(-2751.71px)` | `translateX(-2715.11px)` | **+30.5px/s** |

`animationName: none`, `getAnimations()` 빈 배열 → **rAF로 매 프레임 인라인 transform을 쓴다.** 두 트랙이 **정확히 같은 속도로 역방향**이고, 30.5px/s는 대단히 느리다(1200px 한 바퀴에 약 39초). 스크롤을 멈춰도 계속 움직이므로 시간 기반이지 스크롤 연동이 아니다.

### 헤더 — 아무것도 안 한다

`position: fixed` / 64px / z-index 10 / `background: rgba(0,0,0,0)`. y=0부터 8000까지 여섯 지점에서 **배경·블러·보더·높이·transform·opacity 전부 무변화**. 스크롤하면 제품 UI가 내비 글자 바로 밑을 그대로 통과한다(벤토 구간에서 `99.99% uptime`이 헤더 선에 잘리는 게 눈으로 보인다). 스크림도 페이드도 없다.

성립하는 이유는 배경이 순수 `#000`이고 페이지 서피스가 전부 `#111~#242424` 사이라 흰 글자 대비가 어디서든 유지되기 때문이다. **밝은 자산이 상단을 지나가는 순간 깨지는 구조**이고, 실제로 `uptime` 글자가 헤더에 걸리는 건 결함에 가깝다.

### 접근성 · reduced-motion

- 포커스 링 **`outline: rgb(0,95,204) auto 1px`** — **브라우저 기본값 그대로다.** 커스텀 포커스 스타일이 없다. 검정 배경 위 기본 파랑 링이라 눈에는 띄지만 디자인 시스템의 일부가 아니다
- CSS에 `prefers-reduced-motion` **@media 블록 0개**. 처리를 JS가 한다 — `reducedMotion: reduce` 컨텍스트에서 `Element.animate()` 호출이 **175 → 24로 줄고**, 남은 것도 `duration: 0.001`로 붕괴한다. 결과는 옳지만 **JS가 죽으면 모션 정책도 같이 죽는다**
- 다만 reduce 컨텍스트에서도 전 페이지 스크롤 후 **43개 요소가 opacity < 0.5로 남는다**. 모션은 껐는데 리빌 종료 상태가 적용되지 않은 것 — Linear와 같은 종류의 미완성이다
- 무라벨 아이콘 41개(IC3) · width/height 미지정 이미지 8개(QF6, CLS 위험)
- **JS를 끄면**: 텍스트 6,856자와 h1이 정상 출력된다(SSR 완비, 크롤러·AI 크롤러에 안전). 그러나 **71개 요소가 숨은 채 고정**된다. 콘텐츠는 있고 화면에 안 보이는 상태다

## 배울 것

1. **스프링을 쓰되 튕기지 마라.** 175건 전부 `linear()`이고 최댓값이 예외 없이 정확히 1.0000이다. 오버슈트 0. "스프링을 넣었다 = 통통 튄다"가 아니라, 감쇠를 임계까지 올리면 **베지어의 딱 끊기는 끝맛만 사라지고 장난스러움은 안 붙는다.**
2. **명목 duration과 체감 duration을 분리해서 설계하라.** 400ms인데 80ms에 절반, 200ms에 95%가 끝난다. 뒤쪽 200ms는 눈에 안 보이는 정착 구간이다. 짧게 느껴지길 원한다고 duration을 줄이는 대신 **앞을 무겁게 하고 꼬리를 길게 두면** 빠르면서 부드러워진다.
3. **호버 어휘를 값 하나로 줄여라.** 전 페이지가 `opacity 0.6 ↔ 1`이다. 쉴 때 어두운 건 밝히고, 쉴 때 밝은 건 어둡게 — 방향만 뒤집는다. 40표본 transform 0 · box-shadow 0. 색·그림자·크기를 각각 정의하기 시작하면 그 순간 시스템이 아니라 목록이 된다.
4. **호버 애니메이션은 진행 중 값에서 이어받아야 한다.** `[0.9865…, 0.6]` 같은 비정수 시작값이 그 증거다. JS로 모션을 짜면 가장 먼저 잃는 게 인터럽트인데, 이걸 잃으면 빠르게 움직이는 마우스 아래에서 UI가 덜컥거린다.
5. **리빌은 트리거가 아니라 스크롤 연동으로.** 멈추면 멈추고 되돌리면 되감긴다. 원샷 트리거는 "스크롤을 끝까지 해야 콘텐츠를 준다"는 계약인데, 연동은 그 계약을 안 만든다. 게다가 **rest opacity를 0이 아니라 0.2로 두면** 빨리 스크롤하는 사람이 빈 화면을 통과하지 않는다.
6. **리빌 축을 콘텐츠 배열 방향에 맞춰라.** 가로로 늘어선 행이면 `translateX(-20px)`다. 무엇이든 세로 20px 밀어올리는 관용구가 클리셰가 된 건 방향에 이유가 없어서다.
7. **초점은 블러로 옮기고, 값은 두 개만 쓴다.** 콘텐츠 간 초점 이동 `blur(3px)`, 레이어를 통째로 미는 스크림 `blur(5px)`. 텍스트 진입만 10px에서 시작. Linear가 명도로 하는 일을 Framer는 블러로 하는데, **둘 다 "움직이지 않고 시선을 옮긴다"** 는 같은 원칙이다.
8. **드롭다운에 패널을 안 그려도 된다.** 메가메뉴 컨테이너가 `background: transparent · border 0 · radius 0 · shadow none`이다. 대신 **`backdrop-filter: blur(5px)` + `rgba(0,0,0,.6)` 스크림 한 장**으로 페이지 전체를 뒤로 민다. 서피스를 그리는 대신 배경을 없애는 쪽이 요소도 적고 인상도 조용하다.
9. **스크림은 콘텐츠가 아니라 자기 자신에 걸어라.** 메뉴가 열려도 h1은 `filter: none / opacity: 1`이다. 콘텐츠 트리에 필터를 걸면 레이어가 통째로 재합성되고 텍스트 렌더링이 바뀐다. **요소 하나 추가/제거**로 끝내면 되돌리기도 공짜다.
10. **스크린샷을 자르지 말고 녹여라.** `mask-image` 그라데이션 26곳. 정지점이 65.8052%처럼 자산마다 다른 건 눈으로 맞췄다는 뜻이다. 다크 배경에서 UI 스크린샷이 뜨는 문제를 프레임·그림자 없이 해결한다.
11. **비디오는 첫 화면 하나만 자동재생.** 히어로 1개만 `autoplay` + poster, 나머지 8개는 `autoplay: false`로 두고 진입 시 재생. 비디오 3.7MB를 싣고도 FCP가 148ms다.
12. **버튼을 다섯 개 값으로 끝내라.** 높이 34 / radius 8 / padding 10·14 / 라벨 14px 400 / fill 2종(흰색, 흰색 10%). 보더 0, 그림자 0, 웨이트 500 이상 0. 너비만 내용을 따라간다.
13. **섹션 헤더를 행 하나로 통일하고 우측을 비워두라.** 좌측 44px 2줄 + 우측 끝 세컨더리 알약. 네 섹션이 같은 행을 쓰는데, 히어로만 알약 자리에 **라이브 스탯**(`#7 on OpenRouter: 787.1B tokens this week`)을 넣어 같은 자리에서 다른 말을 한다.
14. **디스플레이를 2단으로 고정하라.** 54px와 44px, 둘 다 weight 500 · letter-spacing -0.04em. 히어로와 최종 CTA만 54px이고 중간 섹션은 전부 44px이라, 크기 자체가 "시작과 끝" 표시로 쓰인다.
15. **마지막 CTA를 버튼이 아니라 제품으로.** 페이지 끝이 `Your next idea starts here` + **실제 동작하는 프롬프트 입력창**(모델 선택기 `GPT 5.6 Terra`, 제안 칩 4개, `Start without AI →`)이다. 유일한 중앙 정렬이기도 하다. 가입 버튼 대신 도구를 쥐여주고 끝낸다.
16. **포화색은 고객 작업물에만.** 페이지 크롬은 검정·흰색·회색이고 색이 터지는 유일한 구간이 `Shipped with Framer` 마퀴다. 디자인 툴이 "우리 색"을 안 쓰면 화면의 색이 전부 사용자 것으로 읽힌다.
17. **글자 단위 연출은 자기 카피가 아니라 제품 출력에만.** 페이지의 유일한 글자별 blur-in이 `"The art of creative direction"` — 목업 안에서 에이전트가 써낸 CMS 제목이다. 헤드라인을 한 글자씩 등장시키면 카피가 스스로를 광고하지만, 같은 연출을 제품 출력에 걸면 **기능이 작동하는 증거**가 된다. 연출의 값이 아니라 붙일 자리가 차이를 만든다.
18. **마퀴는 30px/s.** 두 트랙 역방향, 1200px 한 바퀴에 39초. 로고 마퀴가 싸구려로 보이는 건 존재해서가 아니라 빨라서다.

## 버릴 것

**이 사이트의 구현을 복제하려 하지 마라 — 손으로 쓴 코드가 아니다.**

```
CSS 변수            1개  (--one-if-corner-shape-supported)
inline style 속성  2,411개 / 전체 노드 3,240개 = 74%
@font-face         391건 · 40여 패밀리 (실사용 9)
script             1.14MB / 112 요청
```

Framer로 만든 Framer 사이트라 산출물이 컴파일러 결과다. **토큰 레이어가 아예 없고**, 마스크 정지점이 65.8052%처럼 비반올림인 것도 캔버스에서 눈으로 끌었기 때문이다. 여기서 가져올 수 있는 건 코드가 아니라 **결정값**(스프링 형태, duration 4단, blur 2값, opacity 0.6, 버튼 5값)이고, 그건 손으로 쓴 CSS에 다시 옮겨 담아야 한다. 391개 @font-face를 흉내 내면 그건 배운 게 아니라 베낀 것이다.

**나머지:**

- **투명 헤더는 배경이 순수 검정일 때만 성립한다.** 실측 `rgba(0,0,0,0)` + backdrop-filter 없음. 밝은 자산이 상단을 지나가면 즉시 깨지고, 실제로 벤토 구간에서 `99.99% uptime` 글자가 헤더 선에 어색하게 잘린다. 배경이 흰색이거나 이미지가 큰 사이트가 이걸 따라 하면 첫 스크롤에서 무너진다.
- **커스텀 포커스 링이 없다.** `rgb(0,95,204) auto 1px` = 브라우저 기본값. 모션에 이만큼 투자한 사이트가 키보드 사용자에게는 아무 디자인도 안 줬다. 따라 할 부분이 아니라 메울 부분이다.
- **`prefers-reduced-motion` CSS 블록 0개.** 정책이 전부 JS에 있다. 실제로 잘 동작하지만(175→24 호출, duration 0.001), **JS 실패 = 모션 정책 실패**다. 게다가 reduce 상태에서도 43개 요소가 opacity<0.5로 남고, JS를 끄면 71개 요소가 숨은 채 고정된다. 리빌을 쓸 거면 **"모션 없음"이 곧 "최종 상태"** 가 되게 만들어야 한다.
- **스크롤 연동 리빌은 되돌아갈 때 다시 흐려진다.** 규칙의 대칭이지만, 사용자가 위로 스크롤해 방금 읽은 문단을 다시 보려 할 때 흐려지는 건 실제 불편이다. Framer는 rest 0.2로 완화했을 뿐 없애지 않았다. 텍스트가 많은 페이지에서는 그대로 쓰면 안 된다.
- **호버로 프라이머리 버튼을 흐리게 만드는 건 값이 하나일 때만 성립한다.** `opacity 1 → 0.6`은 단독으로 보면 "비활성화됐나?" 로 읽힐 수 있다. 페이지 전체가 같은 값을 쓰기 때문에 문법으로 읽히는 것이지, 이 처리만 떼어 오면 그냥 이상한 버튼이 된다.
- **GT Walsheim은 유료 라이선스**(Grilli Type). 디스플레이 전용으로만 쓰이는데, 이 둥근 기하학 산세리프가 검정 배경에서 만드는 친근함이 페이지 인상의 절반이다. Inter로 대체하면 남는 건 그냥 또 하나의 다크 개발자 툴 랜딩이다. 폰트를 못 맞출 거면 **디스플레이를 다른 방향으로 다시 잡는 편이 낫다.**
- **`Input Mono`가 .ttf로 서빙된다**(woff2 아님). 실측에서 확인된 순수한 낭비고, 따라 할 이유가 없다.
- **전송 7.1MB / 198 요청.** FCP 148ms는 SSR과 지연 재생 덕이지 가벼워서가 아니다. networkidle까지 9.2초다. 이 자산량은 "제품 화면을 다 보여준다"는 선택의 비용이고, 보여줄 화면이 없으면 지불할 이유도 없다.
