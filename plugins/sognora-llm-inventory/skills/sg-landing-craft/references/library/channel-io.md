# channel.io 분석

장르/단위: 한국 B2B SaaS(고객 상담·AI 에이전트) / 랜딩 · 분석일 2026-08-15 · 상태: **완전**

측정 조건: 1440×900 · light · ko-KR · detect.mjs + probe.mjs + capture.mjs + fetch-assets.mjs + 스크롤 스윕 캡처 12컷(3000px 4조각 판독) + 별도 프로브 4회(헤더 거동·애니메이션·대비·벤토 기하).
전체 높이 **10,398px**(11.6뷰포트) · 섹션 14개 · DOM 요소 1,007개 · 텍스트 노드 230개.

한국어 B2B 랜딩의 표본으로서 가치는 **길이**에 있다. 같은 라이브러리의 toss.im이 20,149px인데 채널톡은 그 절반이다. 기능 수는 더 많은데 페이지는 더 짧다. 아래 구조·자산·카피 전부가 그 압축에서 나온다.

## 수치

### 타이포 — 14단인데 실제로 굴리는 건 4단

폰트 사이즈 고유값 14개: `12 13 14 15 15.5 16 18 19 22 25 35 44 54 65`.
그런데 230개 텍스트 노드의 분포는 이렇다.

| 층 | 사이즈 | 노드 수 | 정체 |
|---|---|---|---|
| 본문 | **16px** | 107 (47%) | 카드 본문 + 내비 + 푸터 |
| 리드·이미지 | **18px** | 35 (15%) | 섹션 리드문 · 아이브로 · 버튼 라벨 · 인용문 |
| 카드 표제 | **25px** | 13 | 3열 카드 제목 · 벤토 카드 제목 |
| 섹션 표제 | **44px** | 13 | 섹션 헤드라인 9개(44/62) + 벤토 통계 숫자 3개(44/44) |
| 나머지 10단 | 12·13·14·15·15.5·19·22·35·54·65 | 합계 62 | 칩·법인정보·성과 숫자·히어로 1회 |

**섹션 헤드라인 9개가 전부 단 하나의 사이즈(44px/62px/600)다.** 히어로만 54px, 그 위 단계는 없다. 54 → 44는 겨우 1.23배 차이다. toss가 80·66·60·50·40px 다섯 단으로 챕터를 구분한 것과 정반대 선택이다. 채널톡은 **크기로 위계를 만들지 않고, 배경 밴드와 여백으로 챕터를 끊는다**(→ 구조 참조).

65px은 고객사례 카드의 해결률 숫자 6개에만 쓰이고, 35px은 그 옆의 `%` 6개에만 쓰인다. 페이지에서 가장 큰 글자가 헤드라인이 아니라 **고객사 성과 숫자**다.

### 한글 타이포 실측값 (전부 1440 기준)

| 역할 | size / line-height | weight | letter-spacing | color |
|---|---|---|---|---|

| 성과 숫자(케이스) | 65px / normal | **500** | -3.25px (**-0.05em**) | `#FFFFFF` |
| 단위 `%` | 35px / normal | 500 | -1.4px (-0.04em) | `#FFFFFF` |
| 카드 표제 | 25px / **32px** (1.28) | 600 | -0.5px (-0.02em) | `#000000` |

| 리드문 | 18px / **28px** (1.56) | 400 | -0.18px (**-0.01em**) | `#000000` |
| 카드 본문 | 16px / **25px** (1.56) | 400 | -0.16px (**-0.01em**) | `#393A3D` |
| 푸터 링크 | 16px / **22px** (1.38) | 400 | -0.4px (**-0.025em**) | `rgba(0,0,0,.6)` |
| 법인 정보 | 15px / 22px | 400 | **normal** | `#A7A7AA` |

핵심 3가지:

1. **`word-break: keep-all`이 230개 중 224개(97%).** 예외 6개는 URL 계열의 `break-all` 4개와 `normal` 2개. toss와 동일한 결론이고, 한글 랜딩의 공통 상수로 봐도 된다.

2. **자간은 전부 음수다. toss와 정확히 반대다.** 230개 중 `normal`은 13개(대부분 법인정보·팝오버 잔가지)뿐이고 나머지는 전부 마이너스 트래킹. 게다가 **크기에 비례해 조인다**:

   | 사이즈대 | letter-spacing | em 환산 |
   |---|---|---|
   | 12·14px | -0.096 / -0.112px | **-0.008em** |
   | 16·18px (본문) | -0.16 / -0.18px | **-0.010em** |
   | 25·44·54px | -0.5 / -0.88 / -1.08px | **-0.020em** |
   | 35px | -1.4px | -0.040em |
   | 65px | -3.25px | **-0.050em** |

   Pretendard는 라틴 메트릭 기반 한글 서체라 기본 자간이 헐겁다. 채널톡은 그걸 **크기가 커질수록 더 조여서** 잡는다. toss는 자체 서체(Toss Product Sans)라 그럴 필요가 없었다. **"한글에 자간을 주지 마라"는 서체 종속 규칙이지 보편 규칙이 아니다** — 결론은 "Pretendard를 쓰면 -0.01em(본문)/-0.02em(표제)에서 시작하라"다.

3. **행간은 두 값뿐이다: 본문 1.56, 표제 1.20~1.41.** 18/28과 16/25가 소수점 둘째 자리까지 같은 1.56이다(28÷18=1.556, 25÷16=1.5625). 사이즈가 커질수록 배율이 내려가는 정석(54px→1.30, 44px→1.41은 예외)이고, 통계 숫자만 1.00으로 완전히 붙인다.

### 웨이트 · 색

- 웨이트 5종이 잡히지만 실질 3종: **400(113) / 600(75) / 500(39)**. 700은 웨비나 배너 2회, 550은 1회. 가변 폰트를 쓰면서도 본문 400·표제 600 딱 두 개로 굴린다.
- **그레이 사다리가 hex가 아니라 검정 알파다.** 디자인 토큰 실측: `--color-text-neutral: #000000d9`(85%) / `-light: #00000099`(60%) / `-lighter: #00000066`(40%) / `-heaviest: #000000ff`. 배경 위에 얹히는 톤이 자동으로 맞으므로 다크 반전 시 토큰 한 벌만 갈아끼우면 된다(`--inverted-*` 접두 토큰 세트가 실제로 존재).
- 실제로 화면에 찍힌 텍스트 색 상위 4개: `#000000`(83) / `rgba(0,0,0,.6)`(46) / `#FFFFFF`(39) / `#6E6E6E`(14). **본문이 순검정이다.** toss는 순검정을 히어로 H1 하나에만 썼는데, 채널톡은 헤드라인·본문·카드 제목이 전부 `#000`이다.
- 액션 컬러가 **없다.** 버튼도 `#242428`(거의 검정), 활성 탭도 `#242428`. 파랑/보라는 데모 입력창 테두리 그라디언트(`#4B72FF→#E098FF`)와 히어로 이미지 배경에만 있고, **텍스트나 버튼에는 단 한 번도 브랜드 컬러를 쓰지 않는다.**

### 배경 · 그리드

- **배경값이 2개다: 흰색 캔버스 + `#F7F6F3` 패널(20회).** 섹션 배경은 전부 `transparent`다 — toss처럼 섹션을 통째로 회색으로 깔지 않고, **라운드 35px 패널을 흰 바탕에 얹는다.** 따뜻한 오프화이트(`#F7F6F3`)를 골랐다는 게 포인트로, 제품 디자인 토큰의 중성 회색(`--bg-grey-lighter: #F7F7F8`)과 다르다. 마케팅 페이지만 종이 톤으로 따로 튜닝했다.
- 다크는 `#242428` 8회(버튼·활성 탭)와 케이스 카드 스크림뿐. **순검정 섹션 없음.**
- 콘텐츠 폭 **1320px**(38회) / 좌우 여백 **60px**. 리드문은 **540px**로 고정(3회 전부 동일), 카드 본문 392px 또는 650px.
- 섹션 상하 패딩: 주요 섹션 `80px 60px`, 챕터 밴드 `60px 28px`. **toss·해외 표본의 120~160px 대비 절반.** 페이지가 짧은 첫 번째 이유.

### 밀도 · 티 프로필

- 섹션 밀도가 **양극화**돼 있다. 챕터 밴드 3개와 최종 CTA는 **8.3% / 11.4% / 8.8% / 8.3%**, 제품 섹션은 **58~73%**(히어로 71.1 · AI빌더 66.5 · 근거 58.5 · CoS 73.1), 보조 섹션(로고월·후기·신뢰)은 34~42%. 중앙값 41.5%.
  고객사례(313%)와 채널웍스(151%)의 100% 초과는 캐러셀 슬라이드 6장과 자동 전환 카드가 같은 박스에 겹쳐 있어 중복 집계된 것이다 — 밀도 지표로 쓰면 안 된다.
- 티: 🔴11 🟡13 — 개별 검증 결과 **대부분 오탐**이고, 남는 실제 결함은 헤딩 시맨틱·이미지 치수 누락·행폭 2곳뿐이다(→ 버릴 것).
- 접근성은 스캐너 경고와 달리 양호하다. 라벨 없는 인터랙티브 요소는 **1개**(로고 링크)뿐이고, 캐러셀 화살표는 `이전 슬라이드`/`다음 슬라이드`, 데모 제출은 `데모 시작` aria-label을 갖고 있다. 이미지 84개 중 37개가 `alt=""`로 장식 선언돼 있다.

### 리듬 요약

`히어로 → 로고월 → ⟨점선⟩ → 밴드① → 제품A → 근거 → 고객사례 → ⟨점선⟩ → 밴드② → 제품B → ⟨점선⟩ → 밴드③ → 제품C → 후기 → 신뢰 → CTA`

**"거의 빈 챕터 밴드(밀도 8~11%, 높이 303~388px)"를 세 번 똑같이 반복해서 3개 제품 라인(채널톡 / 채널웍스 / AI CoS)을 나눈다.** 밴드는 언제나 `18px 아이브로 → 44px 표제 → 검정 알약 CTA` 세 줄뿐이고 배경도 흰색이다. 배경색을 바꾸지도, 폰트 사이즈를 키우지도 않고, **오직 "여기서부터 다른 제품"이라는 여백만으로** 챕터를 끊는다. 점선 구분선은 그 밴드 앞에만 3번 나온다.

제품 3개를 한 페이지에 넣으면서 10,398px에 끝낸 건 이 반복 구조 덕분이다.

## 자산 운용

이미지 86개 — **webp 42 / svg 43(인라인 40) / png 1 / jpeg 0.**

- **사진과 스크린샷이 전부 WebP다.** Next.js `/_next/image` 최적화 경유. 제품 스크린샷 1920×756·1920×940, 고객 사진 1300×854·1200×675, 로고 256×77. 원본 포맷이 페이지에 남아 있지 않다.
- **아이콘은 100% SVG, 그중 40개가 인라인.** 파일로 저장된 SVG는 소셜 3개뿐. 상담 채널 아이콘, 셰브런, 연동 다이어그램의 곡선 커넥터가 전부 인라인 SVG다.
- **제품 스크린샷을 목업 프레임에 끼우지 않는다.** 히어로는 1318×644 그라디언트 카드 위에 데스크톱 앱 화면을 **크롬 없이 그대로** 얹는다. 실제 한글 UI(팀챗, 사용자 이름, 타임스탬프, `₩3,400`, `#수동처리완료` 태그)가 읽히는 해상도로 보여준다. 폰 목업은 AI 채팅 데모에만 쓴다.
- **근거 카드 3개는 어드민 UI를 "잘라낸" 조각이다.** 토글 행 목록, 지식 문서 적중률 표(85%/82%/76%…), 워크플로우 노드 그래프 — 전체 화면이 아니라 그 주장을 증명하는 부분만 크롭했다.
- **고객사 사진은 스튜디오가 아니라 현장이다.** 브랜든 담당자는 매장 진열대 앞, 배경에 실제 가방 재고가 보인다. 인물이 카메라를 안 보고 말하는 중이다.
- **로고는 CSS 필터로 흑백 처리하지 않는다.** `filter: none`, `opacity: 1`. 이미 단색으로 정리된 파일을 받아서 쓴다. 15개 로고의 시각 무게가 균일한 건 자산 단계에서 맞춘 결과다.
- 그림자는 **6종 9개**뿐. 가장 무거운 것도 `0 4px 16px rgba(0,0,0,.15)` + `0 0 2px 1px rgba(0,0,0,.05)`(내비 팝오버). 카드에는 그림자가 없고 `#F7F6F3` 면색으로만 구분한다.
- 라디우스 3종: **패널 35px**(20회) / **알약 999px·9999px**(선언값 실측) / **소형 8px**(17회, 푸터 칩·팝오버 항목). 데모 입력창만 50px.

폰트: **Pretendard Variable 단일 woff2 하나로 페이지 전체.** 같은 CSS에 Inter(7 서브셋×2웨이트)·NotoSansKR·NotoSansJP·Poppins가 선언돼 있지만 이 페이지에서 로드되는 건 Pretendard뿐이다(나머지는 다국어 라우트용). 폴백은 `local("Arial")` 메트릭 오버라이드.

## 인터랙션

### 헤더 — 배경 없이 사라졌다 돌아온다

`position: sticky`, 높이 **135px**(배너 60 + 헤더 75), z-index 100, `transition: top 0.3s`.

| 스크롤 | `top` |
|---|---|
| 0 | 0 |
| 200 → 2000 (내림) | **-135** (배너까지 통째로 사라짐) |
| 1600 → 800 (올림) | **0** (배너까지 통째로 복귀) |

**배경색 `rgba(0,0,0,0)`, `backdrop-filter: none`, box-shadow 없음, 하단 보더 없음 — 전 구간 완전 투명.** 스크롤 다운에서 아예 치워버리기 때문에 가독성 처리 자체가 필요 없다. toss는 하드스톱 그라디언트로, 대부분의 사이트는 `backdrop-filter`로 푸는 문제를 **"안 보이게 한다"로 우회**했다. 형광 라임 배너까지 같이 사라지는 게 핵심으로, 배너만 남기고 헤더를 숨기는 흔한 절충을 하지 않았다.

### 모션 어휘 (전수)

duration 4개: `0.15s`×27 / `0.35s`×21 / `0.3s`×9 / `0.2s`×7. easing은 `ease`×63이 사실상 전부. property는 `color`(22) / `background`(20) / `background-color`(11) / `opacity`(10) / `border-color`(1) / `box-shadow`(1). **`transition: all`을 duration과 함께 쓴 곳 0건.**

키프레임은 6종이고 전부 목적이 분명하다.

| 키프레임 | 내용 | 쓰이는 곳 |
|---|---|---|
| `translateX(0 → -33.3333%)` | 24s linear infinite, 트랙 2153px | 챕터 밴드의 상담 채널 아이콘 마퀴(콘텐츠 3배 복제) |
| `scaleX(0 → 1)` | **5s linear**, origin 0 | 채널웍스 3열 카드 위 진행 바 |
| `opacity 0 + translateX(16px) → 0` | 0.45s ease | 진행 바가 넘어갈 때 스크린샷 교체 |
| `opacity 0 + translateY(12px) → 0` | 0.4s ease-out | 폰 목업 채팅 말풍선이 한 줄씩 |
| `translateY(±110%)` 진입/이탈 | — | 배너 카운트다운 숫자 롤링 |
| `scale(0.96 → 1)` / `scale(0.85 → 1)` | — | 섹션·요소 진입 |

### 스크롤 리빌이 없다

정지 상태에서 `opacity < 1`인 요소는 **내비 팝오버 4개와 로고월 호버 CTA 1개뿐**이다. 섹션 콘텐츠 중 사전 은닉된 것은 0건. detect의 QF2(비가시 텍스트 10건)는 캐러셀의 화면 밖 슬라이드와 순차 등장 대기 중인 채팅 말풍선을 잡은 오탐이다.

**즉 이 페이지에는 "스크롤하면 페이드인" 연출이 없다.** 모션은 전부 컴포넌트 내부(마퀴·진행 바·채팅 시연)에서만 돈다. 그 결과 fullPage 스크린샷이 정상 동작하고, JS 실패 시에도 백지가 되지 않으며, 리빌로 인한 CLS가 없다.

## 배울 것

### 한글 B2B 카피 문법

1. **챕터 헤드라인을 "제품명, 한 줄 정의" 동격 구문으로 통일하라.**
   `채널톡, 고객 상담에 최적화된 AI 솔루션` / `채널웍스, 흩어진 업무가 한 눈에 보이는 곳` / `AI CoS, 채널웍스의 AI 브레인`
   서술어 없이 쉼표로 잇는 명사구다. 세 챕터가 같은 틀을 쓰니 독자가 "아, 새 제품이 시작됐다"를 문장 구조만으로 안다. 아이브로도 짝을 맞춘다: `상담 혁신은 채널톡` / `업무 혁신은 채널웍스` / `분석부터 실행까지, CoS` — **셋 다 제품명으로 끝난다.**

2. **아이브로에 반론을 선점시키고, 헤드라인에 답을 놓아라.**
   `복잡하지 않습니다` → `상담 80%를 해결하는 AI가 가능한 이유`
   `써보는게 가장 빠릅니다` → `고객 상담의 80% 해결하는 채널톡 AI를 직접 사용해보세요`
   아이브로를 카테고리 라벨("FEATURES", "솔루션")로 낭비하지 않는다. 독자가 헤드라인을 읽기 직전에 품을 의심을 먼저 꺼내 놓는다.

3. **부정으로 선을 긋고 긍정으로 받아라 — AI 카피 피로에 대한 방어.**
   `그럴듯한 데모나 가능성에 대한 이야기가 아닙니다. 현장에서 이미 검증된 진짜 AI 사례가 있습니다.`
   `데이터를 단순 축적하는 것이 아니라, 구조화된 지식 체계(RAG)를 구축하여…`
   `앵무새 답변이 아니라 직접 실행까지`
   2026년 한국 B2B에서 "AI"는 이미 값이 떨어진 단어다. 채널톡은 **경쟁사가 아니라 "AI 마케팅 자체"를 부정 대상으로 세운다.** 자기가 속한 카테고리의 과장을 먼저 인정하는 화법이라 방어적으로 읽히지 않는다.

4. **진입 장벽을 "-없어도/몰라도 됩니다"로 지워라.**
   `데이터 팀이 없어도, SQL이나 Python을 몰라도 됩니다.`
   `강력한 연동, 쓰시는 플랫폼 계속 쓰셔도 됩니다`
   한국 B2B 구매자의 실제 저항은 "좋은데 우리는 못 쓴다"(인력·기존 스택)다. 기능을 자랑하는 대신 **자격 요건을 하나씩 취소하는 문장**을 쓴다. `-셔도 됩니다`의 허락형 존대는 영어 카피에 대응물이 없는 한국어 고유 자산이다.

5. **CTA를 명령이 아니라 "소요 시간 + 결과 상태"로 써라.**
   `3분이면, AI 상담원이 첫 인사를 합니다`
   최종 CTA 헤드라인이 "지금 시작하세요"가 아니다. 3분이라는 비용과 그 후의 상태를 제시하고, 실제 버튼 자리에는 **입력창**을 놓는다. `무료로 시작하기`는 페이지 전체에서 **딱 2번**(내비·히어로) 나오고 그 뒤로 한 번도 반복되지 않는다.

6. **수치는 반올림하지 말고, 불리한 숫자도 그대로 노출하라.**
   `245,019`(→ 15분 뒤 `245,021`) · `1,286,781+` · `98%`
   해결률 6개: `80.2 / 81.4 / 80.8 / 80.2 / 94.2 / **79.9**`
   **80% 주장을 반복하는 페이지에 79.9%를 그대로 실었다.** "약 25만" "80% 이상"으로 뭉갰다면 전부 마케팅 문구로 읽혔을 것이다. 소수점 첫째 자리와 살아 움직이는 일의 자리가 "이건 우리 DB에서 나온 값"이라는 신호다. 같은 숫자를 두 곳에 배치하되 반드시 일치시켜라.

7. **고객은 회사명·실명·직책까지 쓰고, 그 회사가 쓰는 경쟁 플랫폼도 지우지 마라.**
   `유치호, 브랜든 SCM 본부장` / `김송이, 콜로소 CS 파트장` / `윤수진, 아임웹 Customer Division 리더` / `김동명, 불스원 D2C팀 팀장`
   인용문 안에 `카페24에서 조회하고`가 그대로 남아 있고, 신뢰 벤토는 카페24·아임웹·식스샵·고도몰·샵바이·셀메이트를 **로고까지 실어서** 보여준다. 고객의 실제 스택을 세탁하지 않는 것이 한국 커머스 B2B에서 가장 강한 신뢰 신호다. 로고월 15개도 전부 실명 브랜드(LG전자·오뚜기·이랜드이츠·농심몰·에어프레미아·이스타항공·SPAO·토스비즈니스·대웅제약·롯데월드·메가박스…)다.

8. **제품 개념어는 홑따옴표로 못 박아라.**
   `‘규칙’` `‘지식’` `‘팀챗’` `‘노트북’` `‘CoS’` `'전략'`
   신조어를 볼드·컬러·대문자로 강조하지 않고 홑따옴표만 쓴다. 한글에서 볼드 강조는 어두워지기만 하고 위계가 안 생기는데, 홑따옴표는 "이건 우리가 정의한 말"이라는 신호를 정확히 준다.

9. **문체를 세 겹으로 고정하라: 본문 합니다체, CTA -세요, 인용문만 해요체.**
   실측 종결어미: `합니다`(10) `습니다`(7) `됩니다`(4) `입니다`(3) — 본문은 예외 없이 -습니다체. `보세요`(3) `하세요`(2)는 전부 CTA. `해요`·`아요`는 **고객 인용문 안에서만** 나온다(`두렵지 않아요` `찾아오실 거예요`). 화자가 바뀌면 문체도 바뀌는 게 눈에 보이므로 인용문이 진짜처럼 읽힌다.

10. **모든 줄바꿈을 손으로 넣어라.**
    `<br>` 강제 개행 16곳, `white-space: pre-line` 0곳. 헤드라인뿐 아니라 18px 리드문·16px 카드 본문까지 전부 수동이다.
    `이미 AI로 상담을 줄인 <br> 기업들의 진짜 결과가 있습니다`
    `업무 환경의 중심에 <br> 고객을 두는 채널웍스`
    폭이 아니라 **의미 단위**에서 끊는다. `keep-all`이 어절 중간 절단을 막아 주지만, 어디서 끊을지까지 정해 주지는 않는다. 한글 헤드라인은 자동 줄바꿈에 맡기는 순간 호흡이 무너진다.

### 구조·시각

11. **크기 대신 "거의 빈 밴드"로 챕터를 끊어라.**
    섹션 헤드라인 9개가 전부 44px 하나다. 대신 밀도 8~11%짜리 303~388px 밴드(아이브로 → 표제 → 알약 CTA, 딱 3줄)를 세 번 똑같이 반복해 제품 라인을 나눈다. 배경색도 안 바꾼다. **폰트 스케일을 늘리지 않고 챕터를 만드는 방법**이고, 제품 3개짜리 페이지를 11.6뷰포트에 끝낸 직접적 원인이다.

12. **섹션 배경을 칠하지 말고 라운드 패널을 얹어라.**
    배경값 2개(흰색 + `#F7F6F3`), 섹션 배경은 전부 투명, 패널 반경 35px. toss식 흰-회 교대 밴딩과 다른 해법으로, 컨테이너 폭(1320px)이 항상 보이므로 좌우 60px 여백이 페이지 전체를 관통하는 세로선 역할을 한다. 벤토(429×3 → 429+875 → 1320, gap 16px)도 같은 언어다.

13. **비대칭 2열 헤더를 페이지 문법으로 삼아라.**
    히어로가 1320을 **780/540**으로 쪼개 좌측에 54px 헤드라인, 우측에 18px 설명 + CTA를 같은 상단 기준선에 놓는다. 이 780/540 분할이 채널웍스·AI CoS 섹션 헤더에서 그대로 반복된다. 헤드라인 아래 설명을 세로로 쌓는 흔한 배치보다 세로 공간을 크게 아끼고, 리드문 폭이 540px로 자동 고정돼 행폭 문제도 같이 해결된다.

14. **버튼 위계를 2종·교대로 굴려라.**
    `무료로 시작하기` 2회(내비 127×43 16px/600, 히어로 156×48 18px/400, 둘 다 `#242428` 알약)와 `자세히 보기` 6회가 전부다. 자세히 보기는 **챕터 밴드에서는 검정 채움(125×48), 기능 섹션 헤더에서는 1px 아웃라인(127×50)** — 밴드/섹션이 번갈아 나오므로 버튼도 채움-아웃라인-채움-아웃라인으로 정확히 교대한다. 브랜드 컬러 버튼은 0개.

15. **전환 지점에 버튼 대신 제품을 놓아라.**
    페이지 중반(섹션 3)과 최종 CTA(섹션 12)에 **같은 데모 입력창 컴포넌트**를 놓는다. `기업 이름이나 브랜드 이름을 입력해보세요` + 예시 칩 `베리시`·`이스타항공`·`콜로소`. 회원가입 폼이 아니라 제품의 첫 입력이고, 페이지에서 유일하게 컬러(그라디언트 테두리)를 쓰는 UI라 시선이 자동으로 간다.

16. **탭을 탭처럼 만들지 말고 5px 진행 바로 만들어라.**
    392×5px 트랙 위를 `scaleX(0→1)` 5초에 채우고 다음 열로 넘어간다. 활성 열만 검정, 나머지는 회색. 클릭 유도 없이 "지금 이걸 보고 있고 곧 다음이 온다"만 알려 주는 최소 장치다.

17. **Pretendard를 쓰면 자간을 음수로 시작하라.**
    본문 -0.01em, 표제 -0.02em, 초대형 -0.05em. `letter-spacing: normal`은 230개 중 13개뿐. 한글 자간 무보정 원칙은 자체 서체를 가진 곳(toss)의 규칙이고, Pretendard처럼 라틴 메트릭 기반 서체에서는 큰 글자가 헐거워 보인다. **크기가 커질수록 더 조인다**는 방향만 지키면 된다.

18. **스크롤 페이드인 없이도 페이지는 살아 있을 수 있다.**
    사전 은닉 요소 0건. 대신 마퀴(24s)·진행 바(5s)·채팅 순차 등장(0.4s)·카운트다운·실시간 숫자가 **콘텐츠 안에서** 움직인다. 결과적으로 JS 실패에 강하고, CLS가 없고, fullPage 스크린샷이 정상 동작한다. "스크롤 리빌 = 잘 만든 사이트"는 근거 없는 관습이다.

19. **로고 정규화는 CSS가 아니라 자산 단계에서 하라.**
    로고 15개 전부 `filter: none` / `opacity: 1`. `filter: grayscale()`은 원본 명도차를 그대로 남겨서 어떤 로고는 진하고 어떤 로고는 흐려진다. 채널톡은 단색으로 정리된 파일을 받아 쓴다.

20. **B2B에서 스크린샷은 크롬 없이, 읽히는 해상도로 넣어라.**
    목업 프레임 없이 1318×644 그라디언트 카드 위에 앱 화면을 그대로 얹고, 사용자 이름·타임스탬프·`₩3,400`·`#수동처리완료` 태그가 읽히게 둔다. 근거 카드 3개는 전체 화면 대신 **주장을 증명하는 부분만 크롭**했다(적중률 표, 워크플로우 노드 그래프). 소비자 앱은 폰 목업이 필요하지만, B2B 어드민은 프레임이 오히려 정보를 가린다.

## 버릴 것

- **헤딩 태그를 안 쓰는 것.** 44px 섹션 헤드라인 9개 중 `<h2>`는 **2개**(고객사례·최종 CTA)뿐이고 나머지 7개는 `<p>`다. 세 챕터 밴드의 제품 정의 문장(`채널톡, …` `채널웍스, …` `AI CoS, …`)이 전부 `<p>`인 게 특히 아깝다. 페이지 전체 `h1`×1, `h2`×2, `h3`×7. 시각 위계는 완벽한데 문서 구조가 없다 — 스크린리더 목차와 검색엔진 양쪽에서 손해다. 44px을 `<h2>`로 바꾸는 데 드는 비용은 0이다.
- **완전 투명 sticky 헤더.** 스크롤 다운에서 사라지기 때문에 성립하는 설계다. 헤더를 상시 노출하는 페이지가 배경·블러·보더를 전부 빼면 텍스트 위에 텍스트가 겹친다. 배울 것은 "투명하게 하라"가 아니라 **"헤더 가독성 문제는 숨겨서 없앨 수도 있다"**다.
- **형광 라임(`#F4FF71`) 배너를 그대로 가져오는 것.** 순검정 본문 + 무채색 팔레트라는 극단적 절제 위에서만 성립한다. 컬러가 이미 여러 개인 페이지에 얹으면 그냥 하나 더 늘어난다.
- **본문을 순검정(`#000000`)으로 두는 것.** 83개 노드가 순검정이다. Pretendard의 낮은 획 대비 + `#F7F6F3` 오프화이트 조합에서는 버티지만, 순백 배경에 다른 서체를 쓰면 눈이 아프다. 안전한 기본값은 이들의 디자인 토큰이 실제로 정의한 `rgba(0,0,0,.85)`다.
- **`width`/`height` 미지정 이미지 32개**(전체 84개 중, 실측). 1920×940짜리를 속성 없이 던진다. 리빌이 없어서 CLS가 없다고 했는데, 이미지 쪽에는 남아 있다.
- **행폭 과대 2곳.** 리드문을 540px로 고정해 놓고 고객사례 섹션 설명문은 1440px 폭에 풀어 놨다.
- **1x 로고.** 256×77 파일을 238×72에 표시한다(1.07배). 로고월은 고해상도 화면에서 뭉갠 티가 가장 잘 나는 자리다.
- **라벨 없는 로고 링크 1개.** 헤더 로고(167×43)가 SVG 워드마크만 담고 있고 `aria-label`도 대체 텍스트도 없다. 스크린리더에서 홈 링크가 무명으로 읽힌다. 나머지 접근성은 깔끔한데 이 하나가 남았다.

### 스캐너 오탐 (기록용)

- **QF2**(정지 상태 비가시 텍스트 10건): 리빌 미발화가 아니라 캐러셀 화면 밖 슬라이드 + 순차 등장 대기 중인 채팅 말풍선. 실제 사전 은닉 요소는 내비 팝오버 4개와 로고월 호버 CTA 1개뿐이다.

- **LA1**(섹션 11 동일 카드 3개 나열): 신뢰 벤토 1행의 통계 타일 3개다. 2·3행이 429+875, 1320으로 폭이 다르므로 균일 그리드가 아니다.

- **IC3**(텍스트·aria 없는 아이콘 48개): 장식용 인라인 SVG를 센 것이다. 실제 인터랙티브 요소 중 라벨이 없는 건 로고 링크 1개뿐이고, 캐러셀 화살표·데모 제출 버튼은 전부 `aria-label`을 갖고 있다.

### 측정 방법 메모

- **스티칭 산출물의 마지막 조각을 그대로 믿지 마라.** 뷰포트 900px×12컷 = 10,800px인데 실제 페이지는 10,398px이라, 마지막 프레임이 최대 스크롤에서 클램프되며 푸터 402px이 중복 합성됐다. 판독 시 푸터가 두 번 나온 것은 페이지 구조가 아니라 캡처 아티팩트다.
- **detect가 보고한 `pageHeight`(capture.mjs 12,635px)와 스윕 실측(10,398px)이 다르다.** 지연 로딩 이미지가 자리를 잡기 전 값이다. 섹션 좌표는 스윕 실측 기준으로 써야 한다.
- **실시간 값이 있는 페이지는 측정 시각을 기록하라.** 누적 채널 수가 15분 사이 245,019 → 245,021로, 배너 카운트다운이 `16시 12분` → `16시 4분`으로 움직였다.
