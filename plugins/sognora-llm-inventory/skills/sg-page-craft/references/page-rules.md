# sg-page-craft — 페이지 유형별 규칙 (SSOT)

> 원칙: **근거 있는 것만 규칙으로 박는다.** 관행은 관행이라고 쓰고, 근거 없는 통설은 §9에 격리해 두어 다시 기어들어오지 못하게 한다.

## 0. 모든 하위 페이지의 공통 계약

1. **토큰 상속 — 두 종류를 구분한다.** 상속은 "같은 제품으로 보이게" 하는 장치이지 "같은 화면을 찍어내는" 장치가 아니다.

   | | 무엇 | 규칙 | 판정 |
   |---|---|---|---|
   | **정체성 토큰** | 팔레트·타입 스케일·radius 사다리·모션 duration | **그대로 상속. 페이지가 새로 만들면 위반** | `conform.mjs`(실제 관할: 색·font-size·radius·duration) |
   | 〃 (기계 미관할) | **폰트 패밀리·easing** | 같은 의무이나 **conform이 렌더에서 수집하지 않는다** — AD 검수 항목 | 사람 |
   | **밀도 토큰** | 섹션 패딩·블록 간격·행 높이·컨트롤 크기·그리드 갭 | **페이지 유형이 결정한다. 랜딩 값 상속 금지** | `alive.mjs` `PURPOSE-BELOW-FOLD`·`PURPOSE-LOW` + §0c(간격 기준표는 사람 판정) |

   실전 사고: 랜딩과 요금제가 다른 계열을 썼고, 수렴한 뒤에도 본문 뉴트럴이 웜 그레이 vs 쿨 슬레이트로 갈려 있었다(정체성 토큰 실패 — 실측으로만 잡힌다). **반대 방향 사고도 같은 무게다** — 도구 화면이 랜딩의 96~120px 섹션 패딩을 그대로 물려받으면 "일하는 화면"이 아니라 늘어진 소개 페이지가 되고, 그 여백은 `detect.mjs`의 `DE4`에도 걸린다.

   **왜 이렇게 나누나**: `conform.mjs`가 관할하는 `tokens.json`에는 **애초에 spacing 항목이 없다**(colors·type·radius·motion뿐). 즉 "간격까지 상속"은 기계가 강제한 적도 없는데 문서가 시켜온 것이었고, 그 결과가 "어느 페이지나 같은 형태"다.
2. **살아 있는가** — `alive.mjs`: 런타임 에러·콘솔 에러·빈 화면·**CSS 모듈 클래스 불일치**·컨테이너 좌단 밀착. 실전 사고 두 건(요금제 페이지가 `plan.highlights` undefined로 죽음 / CSS는 `.planLedger`인데 컴포넌트는 `.planGrid`라 레이아웃 전멸)이 이 검사 하나로 잡힌다.
3. **카피 길이·어휘** — `copylint.mjs`: 문장 25단어·문단 5문장·제목 65자·금칙어. 근거는 GOV.UK 콘텐츠 가이드(OGL v3.0)와 NN/G 열람 실측.
4. **AI 티** — `detect.mjs`(sg-landing-forge) 재사용. 단 **단일 패턴으로 실패시키지 않는다**(Design Slop Cop 1,590개 코퍼스에서 46%가 패턴 0~1개 — 단일 히트는 정상 작업에서도 흔하다). 배점은 상태 커버리지와 구조에 둔다.
   - **예외 — `DE4`(여백 지배)는 단독으로 실패다.** 다른 티 패턴과 달리 DE4는 취향이 아니라 계측이다: 아이템 박스의 상하 공백 합이 안쪽 콘텐츠보다 크다는 뜻이고, 화면에서 "덜 만든 페이지"로 읽힌다(사용자 지시로 무관용). 처방은 forge-rules §2d — 실체 투입 → 한 줄 압축 → 밴드 삭제 순이고, **패딩만 줄여 통과시키는 것은 금지**(콘텐츠 예산 위반이 남는다). 제품 화면의 정상적인 조밀함은 DE4를 건드리지 않는다(분모가 섹션이 아니라 아이템 박스라서).

## 0b. 유형을 먼저 정한다 — **동사로 정한다** (가장 흔한 사고)

실전 사고: `/product`를 만들라 했더니 **또 설득형 랜딩**이 나왔다(히어로 + CTA + 후기). 원인은 단순하다 — **유형 목록에 그 페이지가 없으면 에이전트는 가장 익숙한 형태(랜딩)로 회귀한다.** 스펙의 침묵을 사전분포가 채우는 그 패턴이다.

그래서 P0에서 **"이 페이지에서 사용자가 하는 동사"**를 먼저 정하고, 동사가 유형을 결정한다:

| 사용자가 하는 것 | 유형 | 필수 구조 | 랜딩 구조 허용? |
|---|---|---|---|
| **읽는다**(설득당한다) | 랜딩 | 히어로·증거·CTA | ✅ (여기만) |
| **고른다** | **카탈로그** | 반복 항목 그리드 + 항목마다 진입 액션 | ❌ |
| **쓴다**(직접 해본다) | **도구 화면** | 입력(업로드·텍스트·캔버스) + 실행 버튼 | ❌ |
| **정한다**(비교 후 결제) | 요금제 | 열=플랜·행=속성 비교 | ❌ |
| **적는다** | 폼 | 필드 3~5개 | ❌ |
| **본다·관리한다** | 대시보드·목록 | 반복 데이터 + 상태 화면 | ❌ |

**판정: `alive.mjs --url <URL> --type <유형> [--viewports 1440x900,390x844] [--expect-status 404]`**

- **알 수 없는 유형은 exit 2**다. 예전엔 `pricing`에 분기가 아예 없어 **오타(`catlog`)까지 "✅ 통과"** 도장을 찍었다 — 검사 부재보다 나쁘다. P3를 성실히 따를수록 "기계가 봤다"는 거짓 확신이 쌓인다.
- 유형별 🔴: 카탈로그 항목 4개 미만·진입 액션 부족·**`HOLLOW-CARDS`(반복 항목 과반의 잉크 0 — 이름도 설명도 없는 빈 상자)** / 도구 입력 0(**보이는 텍스트 입력·file·canvas만 센다** — hidden csrf로 통과하던 구멍 폐쇄) / 폼 필드 2개 미만 / **`NOT-A-PRICING`(가격·문의 마커 전무 — pricing의 유일한 🔴)**.
- **`PURPOSE-BELOW-FOLD`·`PURPOSE-LOW`**: fixed/sticky 요소는 세지 않는다(고정 챗위젯 textarea를 "입력"으로 오인하던 구멍). 뷰포트마다 판정.
- **`LANDING-DRIFT`는 단어가 아니라 섹션 실체로 판정**한다 — 인용 블록 2개+ / testimonial 클래스 블록(h≥120) / 가격+주기 패턴(`월 N원` 어순 포함). 내비의 "요금제" 링크 3개로 발동하던 오탐 해소.
- **`HOLLOW-CARDS`의 잉크 판정은 `sg-landing-forge/scripts/rules-lib.mjs`의 `inkBox` 단일 소스**를 주입해 쓴다(detect와 공유). 가상 요소·배경이미지 전용 카드는 잉크 0으로 잡히므로 문구에 사람 확인 안내가 붙는다.

**요금제의 법 관련 검사는 전부 🟡이고, 문구에 "존재만 확인 — 적법성 판정이 아니다"가 붙는다.** 기계는 존재·개수만 본다. 세금 포함 여부의 사실 판정, DMCCA "동등한 시각 비중", §17602 "동의 지점 곁"의 거리 판정, 로케일 자동 판별, 플랜 수 적정성은 **기계 금지**다 — 초록 도장의 의미 범위를 도장 자체에 새겨야 한다.

> **관할 경계**: 요금제의 결제 진입 CTA 버튼과 그 곁의 고지 문구까지가 이 스킬이고, **CTA 클릭 이후 첫 화면(결제 수단·청구 정보)부터 비대상**이다. 근거: 이 계기는 정적 렌더만 보므로 결제 폼의 본질인 거래 상태(카드 검증 실패·3DS 리다이렉트·PG iframe)를 관측할 수 없다. **관측 불가 영역에 도장을 찍지 않는다.**

## 0c. 밀도는 유형이 정한다 — 랜딩 여백을 물려받지 않는다

"같은 제품으로 보이는 것"은 색·글꼴이 하고, "이 페이지가 무엇을 하는 곳인지"는 **밀도**가 말한다. 같은 팔레트라도 랜딩은 넓게 숨 쉬고 도구 화면은 조밀해야 한다 — 밀도까지 상속하면 모든 페이지가 랜딩처럼 보이고, 그게 "어느 서비스나 똑같아 보이는" 원인이다.

| 유형 | 블록 간 세로 간격(중앙값) | 근거·비고 |
|---|---|---|
| 랜딩 | 96~120px | 리듬이 상품이다. 스크롤이 서사 |
| 카탈로그 | 32~64px | 그룹 소제목 사이만 넓게, 카드 갭은 좁게(실측: imgeditor 카탈로그 스크롤이 같은 사이트 랜딩의 1/3) |
| 요금제 | 32~64px | 비교표는 눈이 가로로 움직인다 — 세로로 벌리면 비교가 깨진다 |
| 폼 | 16~32px | 필드 간격은 §1 인용 토큰(Spectrum 내부 여백 8/9/12/15/18) |
| **도구 화면·대시보드** | **16~32px** | 입력→실행→결과가 **한 화면**에 들어와야 한다(§8). Carbon 행 높이 xs 24 / sm 32 / md 40 기준 |

**위 표는 사람이 판정한다(AD 검수 항목).** 블록 간격 중앙값을 자동으로 재는 방법은 시도했다가 버렸다 — DOM 중첩 깊이에 따라 같은 페이지에서 0px와 120px가 다 나와서, 그대로 두면 근거 없는 🔴을 뿌린다. **불안정한 게이트는 없느니만 못하다.**

대신 **결과를 잰다**: 랜딩 밀도를 물려받으면 소개문과 여백이 위를 차지하고 **정작 할 일이 첫 화면 밖으로 밀린다.** 그게 "어느 페이지나 같아 보이는" 증상의 관측 가능한 형태다.

- **판정: `alive.mjs`의 `PURPOSE-BELOW-FOLD`(🔴) / `PURPOSE-LOW`(🟡)** — 유형별 "일"(도구=입력, 카탈로그=고를 항목, 대시보드=데이터 블록, 폼=필드)의 첫 등장 y좌표를 잰다. 첫 화면(뷰포트 높이) 밖이면 🔴, 하단 1/3에 걸치면 🟡. 헤더·내비·푸터 안의 요소는 세지 않는다.
- 실측 사다리(1440×900 · 카탈로그 재현): 히어로 패딩 180/160 → 항목 y=603 **통과** · 300/260 → y=783 **🟡** · 420/360 → y=1003 **🔴**.
- **처방은 패딩만 줄이는 게 아니다** — 간격을 좁혀 생긴 자리에 그 페이지의 일(항목·데이터·컨트롤)을 채운다. 좁히기만 하면 §DE4의 반대편, 즉 빈약한 화면이 된다.
- 컨트롤·행 높이는 지어내지 말고 §1의 인용 소스(Spectrum·Carbon·Primer)에서 가져온다.

## 7. 카탈로그 페이지 (고르는 화면)

실측 레퍼런스: [imgeditor.co/tools](https://imgeditor.co/tools) — 스크롤 2,232px(같은 사이트 랜딩 6,607px의 **1/3**).

- **헤더는 짧게** — 라벨 + 제목 + 한 줄 설명. 설득 섹션(후기·가격·CTA 밴드) 없음
- **그룹 소제목으로 분류**("Editing Tools" + 한 줄 설명), 그 아래 카드 그리드
- **카드 = 아이콘 + 이름 + 상태 배지 + 한 줄 설명 + 진입 액션**("Use Now →"). **설명만 있고 들어갈 데가 없으면 카탈로그가 아니다**
- **상태 배지로 가용성 표시** — New / Pro / Coming Soon. 준비 안 된 것도 숨기지 않되 **비활성 처리**(회색 + 클릭 불가)
- 항목 순서는 중요도순, 알파벳순 금지

## 8. 도구 화면 (직접 써보는 화면)

카탈로그에서 항목을 고르면 도착하는 곳. **여기서 실제로 결과가 나와야 한다.**

- **입력이 화면 상단에** — 파일 업로드·텍스트 프롬프트·캔버스 중 하나가 첫 화면에 있어야 한다. 설명이 입력보다 위에 오면 안 된다
- **실행 → 결과 → 다음 행동**이 한 화면에서 끝난다(결과 보려고 스크롤·페이지 이동 금지)
- **비로그인 체험 경계를 명시** — 어디까지 무료로 되는지, 언제 로그인·결제가 필요한지를 실행 전에 알린다(요금제 §2의 자동갱신 고지와 같은 원칙)
- 상태 커버리지(§5)가 여기서 가장 중요하다 — 처리 중·실패·용량 초과·지원하지 않는 형식
- **설득 금지** — 후기·가격표·기능 자랑은 랜딩과 요금제의 일이다

## 2. 요금제 페이지

**플랜 개수** — 실측 근거: CAiSE'25 논문(arXiv:2503.21444, CC-BY, 세비야대) Table 1, 실제 SaaS 30곳의 2024년 요금제 코딩. **4플랜 53%(최빈)·3플랜 30%·5플랜 10%·6플랜 7%, 평균 3.93, 3 미만도 6 초과도 없음.** 흔히 말하는 "3개가 정석"은 데이터와 다르다. 3~5개 사이에서 정하되 개수 자체를 규칙으로 강제하지 않는다(N=30, 무작위 표본 아님).

**비교 구조** — NN/G 비교표 가이드(2024-02):
- 정적 나란히 비교 **최대 5개**, 인터랙티브 3~4개, **모바일은 한 번에 2개**
- **열 = 플랜, 행 = 속성.** 행 레이블 왼쪽·열 헤더 위, 한 화면 넘어가면 헤더 고정
- 셀에 완결 문장 금지, 열별 정렬 일관
- "차이점만 보기" 또는 전 플랜 동일 행 접기 제공
- **카드에 노출할 차별 속성은 2~3개**(영국 CMA 증거검토 ¶6.84: 사람은 한 번에 2~3개 초과 속성을 비교하기 어렵다)

> 실전 사고: 세 카드의 체크 항목이 서로 다른 것들이라(사용자 1명 / 팀 공유 크레딧 / 브랜드 설정) 행 축이 성립하지 않아 비교가 불가능했다. **플랜마다 다른 항목을 나열하는 것은 비교표가 아니다.**

**가격 표기 — 법적 요건(취향 아님)**
- EU 소비자권리지침 Art. 6(1)(e): 구독은 **청구 주기당 총액**, 정액 연간 플랜은 **월 환산액 병기**(B2C)
- EU 불공정상관행지침 Art. 7(4)(c): 플랜·가격·CTA가 있는 페이지는 "구매 유인" → **세금 포함가와 불가피 비용 전부**가 필수 정보
- 영국 DMCCA 2024 s.230(2025-04-06 시행): 총액 표시, 사전 계산 불가 시 **산정 방식 설명이 표시가와 동등한 시각 비중**
- 캘리포니아 B&P §17602(2025-07-01~): 자동갱신 조건을 **동의 지점 바로 옆에** — 카드에 CTA가 있으면 갱신 조건도 카드 안에. **체험 종료 후 가격 명시**
- 숨은 비용 실증: OFT 2010(UCL 수행) — 비용을 **2클릭 뒤로 숨기면** 구매 오류 14% 증가

**기능 매트릭스**(Baymard 공개분): 기능을 라벨 붙인 소제목으로 그룹화하고 중요도 순 배치, **플랜명과 기능 그룹 소제목을 2단으로 동시 고정**. 실측 평균 기능 40개.

## 3. 기능 소개 페이지 — 디자인 규범이 존재하지 않는다

조사 결론: 디자인 시스템·정부 패턴집·학술 어디에도 규범이 없다(에이전시 블로그의 "개인화 CTA가 202% 우수" 류는 원출처 없음 → 인코딩 불가). 대신 **측정된 열람 행동**만 근거로 쓴다(전부 NN/G):

- 첫 화면 위 체류 **57%**, 첫 2스크린 누적 **74%**, 3스크린 81% → **중요한 것을 2스크린 안에**
- **79%가 스캔, 16%만 정독** · 실제 읽는 텍스트 ~20~28% · **111단어 이하일 때만 절반이 읽는다**
- 간결화 +58% / 스캔 가능 레이아웃 +47% / 객관적 문체 +27% / **셋 다 +124%**
- 헤딩 스캔의 인지 범위는 **첫 11자(≈2단어)** → 헤딩 앞머리에 핵심어
- 목표는 F자 패턴이 아니라 **레이어 케이크 패턴**(헤딩·소제목이 층을 이루는 형태)

## 4. 문의·신청 폼

GOV.UK(govuk-frontend, MIT / 문서 OGL v3.0)가 유일한 개방 규범 소스:
- 라벨은 입력창 **위**, 힌트는 라벨 아래·입력창 위, 오류는 힌트 다음·입력창 앞
- **포커스가 떠날 때 검증하지 말 것**(제출 시점까지 대기), 오류 시 **입력값 초기화 절대 금지**, HTML5 기본 검증 끄기(`novalidate`)
- 이메일 254자 수용·최소 30자 표시, 전화번호는 **단일 필드**
- 오류 문구 금칙: forbidden, illegal, sorry, please, valid/invalid, oops, "An error occurred"
- 문의 폼은 **3~5개 필드**(NN/G), 선택 필드는 1~2개까지

## 5. 제품 화면(대시보드·목록·상세·설정)

치수는 §1에서 인용한다. 이 스킬이 새로 재는 것은 **상태 커버리지**뿐이다:

- **빈 상태** — 목록·표를 그리는 곳마다 0건 화면이 있는가, 그리고 그 화면에 **다음 행동**이 있는가("No data found"만 있으면 미달)
- **로딩** — 스피너 하나로 때우지 않았는가(구역별 스켈레톤), **실은 로딩인데 빈 상태를 먼저 보여주지 않는가**(NN/G가 "특히 해롭다"고 명시)
- **오류·권한 없음** — 존재하는가, 원시 에러 메시지를 노출하지 않는가
- **상호작용 상태** — hover·active·focus가 실제로 다른가
- **실데이터 내성** — 긴 이름·대문자 약어·0건·1건·많은 건수에서 레이아웃이 버티는가

`alive.mjs`가 목록 렌더에 빈 상태 분기가 없으면 경고한다. 나머지는 사람이 화면을 열어 확인한다.

## 6. AI 티 — 제품 화면에서 살아남는 증상

근거: Design Slop Cop(1,590개 사이트·수동 라벨 165개·임계값 공개), impeccable.style/slop(패턴 64개), CHI EA 2026(모바일 UI 138화면 — 오류 예방·복구·도움말 지원율이 낮고 "시각적 사용성과 기능적 사용성의 격차"가 유의미).

- **상태 부재**(위 §5) — 가장 가치 높은 신호
- **균질성** — 간격이 한 값으로 통일, 카드 높이·라운드·패딩 전면 동일, 타입 계층 평탄(비율 1.25 미만), **모든 액션이 같은 시각 무게**, 한 앱 안에서 화면마다 다른 라운드·폰트
- **표면 처리** — 모든 것이 카드·카드 속 카드, 장식용 좌측 액센트 스트라이프, 헤어라인 보더+넓은 그림자 동시 사용, 작은 카드에 radius 24px+, 채도 있는 컬러 글로우, 손 안 댄 `rounded-2xl shadow-lg p-6`
- **아이콘·카피** — 내비게이션 이모지(링크 3개 이상 중 40% 초과 — 단일 지표로 가장 강함), Lucide 5종(Sparkles·Zap·Shield·Check·BarChart3)+모든 CTA에 ArrowRight, **✦ 반짝이**(NN/G 실험 n=107에서 "AI"로 읽은 사람 **0명**), 라벨·서브라벨·헬퍼가 같은 말인 동어반복, 전면 Title Case
- **가짜 데이터** — "10K+ users"·"99.9% uptime"이 정적 마크업으로, `Acme Corp`·`John Doe`·`Item 1/2/3` 잔존, **하드코딩 위의 맥동하는 상태 점**, 모든 지표 카드에 같은 초록 상승 화살표
- **모션**(Emil Kowalski) — `transition: all`, 진입에 `ease-in`, `scale(0)` 진입, 300ms 초과(150~250ms 적정), 진입·퇴장 속도 동일(퇴장이 더 빨라야), `(hover: hover)` 가드 없는 hover 애니메이션

## 9. 규칙으로 박으면 안 되는 것 (근거 없음 — 격리 보관)

여기 있는 것들을 규칙·주장으로 쓰지 마라. 관행으로 채택하는 건 자유지만 **효과를 주장하면 거짓이 된다.**

- **"Most Popular" 배지의 전환 효과** — 실제 A/B는 GoodUI #517(n=127,712) 하나뿐이고 **효과 크기가 유료 차단**. 공개된 수치가 존재하지 않는다
- **연간 토글 기본값** — 어느 쪽이 낫다는 증거 없음
- **FAQ 배치** — 연구 전무, 순수 관행
- **"선택지가 많으면 마비된다"로 플랜 수 제한** — Scheibehenne 외 2010 JCR 메타분석(실험 50건, N=5,036) **효과크기 D=0.02, 신뢰구간 0 포함 = 사실상 0**
- **디코이 효과** — 실재하나 약함(Yang & Lynn 2014: 73개 선택집합 중 신뢰할 만한 효과 11건)
- **날조 출처 주의** — 티어 분포를 공개한다는 saasresearchlab.com은 **도메인 생성일이 발표 그 달**(2026-03), 저자·데이터셋 없음. ProfitWell/Price Intelligently 출처의 2025~2026 벤치마크("3플랜이 31% 더 전환", "연간 기본값이 ARR 15~20% 증가")는 원문 소멸로 **전부 허구**. "NN/G 연구: AI 대시보드 92%에 빈 상태 없음"도 NN/G에 그런 연구 없음
- **색·폰트 블록리스트** — 반감기가 짧다(보라 그라데이션은 이미 은퇴한 신호). 배점은 상태 커버리지·구조에 두어라
