# sg-page-craft — CHANGELOG

## 1.6.3 — 2026-08-19 (DE4 무관용 + 상속 범위 분리 — "어느 페이지나 같은 형태" 대응)

- forge의 신규 룰 `DE4`(아이템 박스의 상하 공백 > 안쪽 콘텐츠)를 심으로 그대로 상속받는다. **§0-4의 "단일 패턴으로 실패시키지 않는다"에 예외 1건 신설** — DE4는 취향 패턴이 아니라 계측이므로 단독 위반도 실패다(사용자 지시로 무관용).
- 처방 고정: 실체 투입 → 한 줄 압축 → 밴드 삭제. **패딩만 줄여 통과 금지.**
- 제품 화면의 정상적 조밀함은 영향 없음 — DE4의 분모가 섹션이 아니라 아이템 박스다.

**토큰 상속 범위 분리** — 사용자 지적: "토큰 상속하면 결국 같은 형태만 나오고 페이지 목적을 잃는 것 아닌가."

- 확인 결과 **문서와 기계가 어긋나 있었다**: §0-1은 "색·타이포·**간격**·radius·모션을 상속"이라 시켰는데, `conform.mjs`가 관할하는 `tokens.json`에는 **spacing 항목 자체가 없다**(colors·type·radius·motion뿐). 기계가 강제한 적 없는 상속을 문서가 시켜왔고, 그 결과가 "모든 페이지가 랜딩처럼"이다.
- **정체성 토큰(팔레트·폰트·타입 스케일·radius·모션 어휘) = 상속 의무** / **밀도 토큰(섹션 패딩·블록 간격·행 높이·컨트롤 크기) = 페이지 유형이 결정, 랜딩 값 상속 금지**로 §0-1을 둘로 쪼갬.
- **§0c 신설** — 유형별 블록 간격 기준표(랜딩 96~120 / 카탈로그·요금제 32~64 / 폼·도구·대시보드 16~32, Spectrum·Carbon 인용). 이 표는 **사람(AD)이 판정**한다.
- **`alive.mjs`에 `PURPOSE-BELOW-FOLD`(🔴)·`PURPOSE-LOW`(🟡) 신설** — 유형별 "일"(도구=입력, 카탈로그=항목, 대시보드=데이터, 폼=필드)의 첫 등장 y를 재서 첫 화면 밖이면 실패. 헤더·내비·푸터는 제외.
- **버린 접근 1건(기록)**: 블록 간격 중앙값 자동 측정을 먼저 만들었다가 폐기했다 — DOM 중첩에 따라 같은 페이지에서 0px와 120px가 다 나와 불안정했다. 근거 없는 🔴을 뿌리느니 사람 판정으로 두고, 대신 **관측 가능한 결과**(할 일이 폴드 밖으로 밀림)를 잰다.
- 검증: 실제 앱 4페이지(랜딩·카탈로그·요금제·문의) 오검 0건.
  > **정정(같은 날 감사에서 드러남)**: 이 "오검 0건"은 **우연한 통과 위의 검증**이었다. 당시 카탈로그 판정이 20px 버킷 휴리스틱으로 크롬 요소 노이즈를 카드로 세어 통과시키고 있었고, `/ko/product`에는 실제로 **상품 카드가 1개**뿐이다(DOM 실측 `a.productCard` ×1). 계기를 형제 시그니처로 바꾸자 🔴가 떴는데 그게 진탐이다. **게이트가 통과시켰다는 것이 대상이 옳다는 뜻이 아니다.** 재현 사다리 — 히어로 패딩 180/160 → 통과, 300/260 → 🟡(y=783), 420/360 → 🔴(y=1003).

### 계기 재작성 (같은 버전, 감사 반영)

- **유형 화이트리스트 + exit 2** — `pricing` 분기 부재로 **오타 유형까지 "✅ 통과"**를 찍던 것이 이 스킬 최대 결함이었다.
- **그룹화 교체**: 20px 크기 버킷 → **형제 시그니처**(태그+1뎁스 골격, 단일 래퍼 1겹 벗김, `display:contents` 투과, 페이지 전체 합산). 높이 분산·행 레이아웃 카탈로그를 🔴로 잡던 거짓 양성 2종 해소.
- **`HOLLOW-CARDS`** — 빈 상자 카탈로그가 만점 통과하던 구멍. `inkBox` 단일 소스 공유(빈 상자 ink=0 / 실카드 65~107).
- **pricing 검사 6종**(🔴 1 + 🟡 5) + **기계 금지 목록**을 코드 주석과 문서 양쪽에.
- **`LANDING-DRIFT` 격상**(단어 → 섹션 실체) · **`PURPOSE-*`에서 fixed/sticky 제외** · **`THIN-DASHBOARD`가 빈 상태+행동 존재 시 침묵** · `--viewports` · `--expect-status`.
- 회귀 15케이스 실측, 신설 룰 오탐 0.

## 0.2.1 — 2026-08-19 (적대적 시험으로 폼 판정 구멍 발견·수정)

유형 판정을 실제 페이지로 교차 시험(요금제를 카탈로그/도구라 우기기, 랜딩을 폼이라 우기기)했더니 **랜딩이 '폼'으로 통과**했다. 원인: 입력 요소를 canvas·hidden까지 세어 랜딩의 비가시 요소 3개가 필드로 잡혔다.

- 폼 판정을 **라벨 붙은 보이는 입력 필드**만 세도록 분리(도구 화면은 캔버스·업로드 포함 그대로)
- `<form>` 요소 부재 경고, 필드 5개 초과 시 경고(page-rules §4의 3~5개 권장)
- 검증: 랜딩→폼 우기기 🔴 차단 / 실제 사전신청 폼 통과 / 요금제·랜딩 회귀 없음

## 0.2.0 — 2026-08-19 (유형 판정 — "또 랜딩으로 만든다" 사고 대응)

실전 사고: `/product`를 만들라 했더니 설득형 랜딩이 나왔다(히어로+CTA+후기). 원인은 **유형 목록에 카탈로그·도구 화면이 없었던 것** — 유형이 규칙에 없으면 에이전트는 가장 익숙한 형태로 회귀한다.

- **§0b 동사로 유형을 정한다**: 읽는다(랜딩) / 고른다(카탈로그) / 쓴다(도구) / 정한다(요금제) / 적는다(폼) / 본다(대시보드). **랜딩 구조는 '읽는다'에서만 허용**
- **§7 카탈로그**: 실측 레퍼런스(imgeditor.co/tools — 랜딩의 1/3 분량) 기준. 카드 = 아이콘+이름+상태 배지+한 줄+**진입 액션**, 설명만 있고 들어갈 데가 없으면 카탈로그가 아니다. Coming Soon은 비활성 표시
- **§8 도구 화면**: 입력이 화면 상단, 실행→결과→다음 행동이 한 화면, 비로그인 체험 경계 명시, **설득 금지**
- **`alive.mjs --type`**: 유형별 필수 구조 기계 검사 + **LANDING-DRIFT**(후기·가격 섹션 혼입) 검출. 검증 — 레퍼런스 카탈로그는 통과, 랜딩을 카탈로그/도구로 우기면 정확히 실패
- `networkidle` 실패 시 `domcontentloaded` 재시도(실사이트에서 영원히 대기하던 문제)
