# 방향 카탈로그 — 스킨 목록이 아니라 조합 축

> **이 파일의 예시를 그대로 복사하면 위반이다.** 방향은 프로젝트 입력에서 유도(derivation)한다 —
> 입력이 다르면 산출이 달라야 정상이고, 같은 프로젝트를 재실행하면 같은 방향이 나와야 정상이다(입력 기반 = 재현 가능).
> 이 스킬이 "또 하나의 고정 스킨"을 찍어내는 순간 존재 이유가 사라진다.

## 유도 절차 (`_design/direction.md`에 근거와 함께 기록)

0. **히스토리 로드 (하드 제약)**: `_design/history.json`의 모든 이전 실행을 읽는다. 이번 추첨은 **① 베이스 팔레트 계열이 마지막 실행과 달라야 하고**(게이트 5가 결정적으로 검사 — 크림을 썼으면 크림·베이지·웜오프화이트 전 계열 배제) **② 7축 중 3축 이상이 마지막 실행과 달라야** 한다. 이 제약이 "매번 같은 형태"를 막는 본체다 — 모델의 취향은 방치하면 항상 같은 "안전한" 조합(크림+괘선+좌측 에디토리얼)으로 수렴한다.
1. **입력 수집**: ① 콘텐츠 도메인(무슨 서비스인가 — 페이지 텍스트에서) ② 기존 브랜드 자산(로고 색, 이미 쓰는 폰트, 기존 일러스트 톤 — 있으면 방향의 씨앗, 교체 대상 아님) ③ 격식도(B2B 공구·의료 = 높음, 커뮤니티·라이프스타일 = 낮음) ④ 사용자 명시 취향(있으면 최우선)
2. **반프로필 확정**: 배제 목록 = 원본 슬롭이 쓴 계열(파스텔+카드였으면 그 조합 배제) + AI 공식(보라-남보라 그라데이션, 유리morphism, Inter 단독) + **AI 수렴 룩 세대들**(2026 현재: 크림 배경+고대비 세리프+테라코타 / near-black+애시드 그린·버밀리언 단일 액센트 / 브로드시트 헤어라인·radius 0 — 이 목록은 유통기한이 있으니 벤치마크 실측에서 "요즘 AI가 다 이렇게 뽑는 룩"을 감지하면 갱신) + **직전 실행 산출물과 같은 조합**. 단 이 목록은 **금지가 아니다** — 브리프가 명시 요구하면 쓴다. 죄는 빈 축을 이 기본값으로 채우는 것이다.
3. **축별 선택**: 아래 7축에서 입력에 근거해 하나씩 고른다. 근거 없는 축이 있으면 도메인 관례에서 유도하고 "관례 유도"로 표기. 확정 직전 **재생성 자기검증**(rules.md — "비슷한 브리프에 또 나올 조합이면 기본값이다")을 거친다.
4. **구체화**: 축 조합을 실제 토큰(폰트 이름, hex 팔레트, 스케일 비율, radius 위계)으로 내린다. **팔레트와 타입 페어링은 반드시 ①②의 입력값에서 계산** — 예시 hex를 옮겨 적지 않는다.

## 7축 (조합 공간 — 축당 예시는 방향 감각용이지 선택지 전부가 아니다)

### 1. 타이포 보이스
- 그로테스크 단정(정보 밀도 높은 도구) · 세리프 에디토리얼(신뢰·읽을거리) · 라운드 산세리프(친근·생활) · 좁은 폭 디스플레이(임팩트 헤드라인) · 모노 포인트(기술 정체성)
- **극단을 써라**: 무게 대비는 400 vs 600이 아니라 100–200 vs 800–900, 사이즈 점프는 1.5배가 아니라 3배 이상. 중간지대가 밋밋함의 근원이다. 타입 트리트먼트 자체가 기억점이어야지 콘텐츠의 중립적 배달 수단이면 실패.
- **한글 제약(항상 적용)**: 이탤릭 금지(자형 없음), 본문 행간 1.6~1.8, 자간 0~미세 음수, 헤드라인·본문 모두 한글 대응 폰트 명시. 라틴 폰트는 한글 폰트와 x-height가 맞는 것으로 페어링.
- 무게 대비를 크기 대비보다 먼저 검토(한글은 무게 표현이 풍부하다). 폰트 선택은 코딩 전에 선언한다.

### 2. 컬러 전략
- 단색 지배 + 예리한 강조 1색 · 어스톤 · 고대비 흑백 + 유채 1점 · 저채도 2색 조화 · 딥톤 배경 + 밝은 전경
- 강조색은 브랜드 색이 있으면 그 hue에서 유도(보색·인접색), 없으면 도메인에서(외벽 도장 서비스면 실제 도료 색 계열 등).
- 그라데이션은 방향이 명시적으로 채택할 때만, 페이지 1곳.

### 3. 레이아웃 문법
- 비대칭 2단(본문 우세) · 에디토리얼 세로 흐름(섹션 경계를 여백 아닌 타이포로) · 신문형 밀집 그리드 · 풀블리드 미디어 교차 · 좌측 정렬 통일(중앙 정렬 전면 금지형)
- 카드 3장 한 줄·중앙 히어로는 반프로필 기본 배제 — 채택하려면 근거 필수.

### 4. 밀도 자세
- 밀집(정보 도구·목록 중심) · 중립 · 성긴 여백(단 콘텐츠가 실제로 받쳐줄 때만 — 여백은 콘텐츠 부족의 변명이 될 수 없다, rules.md §6)

### 5. 장식 언어
- 무장식(타이포·색이 전부) · 기하 도형 1종만 · 실사진 · 손그림/일러스트 · 괘선(rule line) 중심
- 어느 것이든 **한 언어로 통일**. 아이콘 세트도 이 언어를 따르는 1세트만.

### 6. 모션 자세
- 정적(모션 0) · 진입 1회(스크롤 인 1패턴만) · 포인트 모션(핵심 인터랙션 1~2곳)
- infinite 루프 장식은 어느 자세에서도 금지(rules.md MO1). 잘 오케스트레이션된 한 순간이 흩뿌린 효과들보다 세다.

### 7. 시그니처 (필수 — 방향의 마침표)
- **이 화면이 기억될 단 하나의 요소**를 이름 붙여 선언한다: 타입 트리트먼트, 히어로의 인터랙티브 모먼트, 독특한 자산 언어, 색의 한 방 — 무엇이든 하나.
- 대담함은 여기에만 쓴다. 나머지는 조용하고 규율 있게 시그니처를 받친다. 시그니처가 없는 방향은 미완성이다 — "리스크를 안 지는 것 자체가 리스크다".

## 기록 양식 (`_design/direction.md`)

```
방향: <7축 선택 요약 이름 — 직접 명명>
입력: 도메인=… / 브랜드 자산=… / 격식=… / 사용자 취향=… / 벤치마크 갭=<벌어진 축 순위>
반프로필: <배제한 계열과 이유>
축: 타이포=…(근거) / 컬러=…(근거) / 레이아웃=…(근거) / 밀도=…(근거) / 장식=…(근거) / 모션=…(근거) / 시그니처=…(단 하나, 근거)
토큰: 폰트=<한글 폰트+페어링> / 팔레트=<유도된 hex 5±2> / 스케일=<기준px·비율·단수> / radius=<위계> / 간격=<기준 단위>
자기검증: <재생성 검증에서 바꾼 것과 이유>
```

후속 명령 "방향 바꿔: X"는 이 파일의 반프로필에 현재 방향을 추가하고 재유도한다 — 재롤이 기계적으로 다른 결과를 내게 하는 장치다.
