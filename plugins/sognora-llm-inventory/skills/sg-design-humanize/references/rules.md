# sg-design-humanize — 룰북 (SSOT)

> Claude Code·Codex 양쪽이 공유하는 본체. 내용 수정은 이 파일에서만 한다.
> 룰 ID는 `scripts/rules-lib.mjs`와 1:1 대응 — 한쪽만 고치면 게이트가 어긋난다.

표기 —
- 심각도: 🔴 **즉시 수술**(하나만 있어도 AI 티) / 🟡 **반복·결합 시 수술** / ⚪ **개편 모드에서만**
- 층위: **[구조성]** 레이아웃 스켈레톤을 갈아야 사라짐 / **[표면성]** 토큰(폰트·색·radius) 교체로 사라짐
- 판정: **[결정적]** 스크립트 판정이 최종 / **[혐의]** 스크립트는 후보만 올리고, 승격/기각은 LLM이 감사 로그에 사유와 함께 확정

## 건드리지 않는 것 (Do-NOT)

본문 텍스트·링크(앵커텍스트+href)·정보성 이미지·폼 동작·라우팅·a11y 속성. 기존 브랜드 자산(로고·브랜드 폰트·브랜드 컬러)은 교체 대상이 아니라 방향 유도의 **입력**이다. surgical 모드에서는 프로젝트 디자인 시스템의 토큰 이름 체계도 보존한다(값 조정은 가능).

## 과잉 수술 가드

- **무티 섹션 면책**: 티 0인 섹션은 기본 모드에서 불가침. 개편 모드에서도 토큰(타입 스케일·팔레트·간격)만 새 방향으로 통일하고 구조는 보존 — 보고서에 "구조 보존: N개 섹션(사유: 티 없음)"으로 선언한다.
- **조기 종료**: before 스캔에서 확정 티 0이면 "이미 좋은 디자인입니다"로 종료한다.
- **콘텐츠 부족은 디자인으로 못 감춘다**: 밀도 처방(§6)이 전부 불가하면 장식으로 채우지 말고 "콘텐츠 부족" 섹션으로 보고한다.

## 5. 장식·아이콘 (불만 ①: 의미 없는 아이콘)

**생존 조건: 장식은 텍스트에 없는 정보를 담아야 한다.** 못 담으면 삭제가 처방이다 — 다른 장식으로 교체가 아니다.

- 🔴 `IC1` [혐의] 동일 글리프/SVG(path 해시 동일)가 그리드에 3회 이상 반복 — 스크린샷 2의 체크 그리드. 정보량 0이면 삭제
- 🔴 `IC2` [결정적][표면성] 이모지가 아이콘 노릇(nav·목록 머리·카드 아이콘) — 삭제 또는 정보성 표기로
- 🟡 `IC3` [혐의] 텍스트 형제도 aria-label도 없는 아이콘 — 정보 없으면 삭제
- 🟡 `IC4` [혐의] absolute + 원형(radius 50%+) + 텍스트 없음 + 80px 이상 = 장식 블롭 — 스크린샷 4 우하단. 방향이 명시적으로 채택한 장식 언어가 아니면 삭제

## 6. 밀도·자산 (불만 ②: 여백만 많고 콘텐츠는 적음)

- 🔴 `DE1` [결정적][구조성] 섹션 콘텐츠 면적비 < 페이지 중앙값 0.5× **∧** 섹션 높이 > 60vh **∧** 미디어 없음 — 절대치가 아니라 페이지 상대 + 결합 룰(좋은 에디토리얼 여백을 오판하지 않기 위해)
- 🟡 `DE2` [결정적][구조성] 카드 내부 콘텐츠 면적비 < 25%인 카드가 형제의 과반 — 스크린샷 1
- 🟡 `AS1` [결정적][표면성] 동일 이미지 3회 이상 재사용 — "채울 자산이 없었다"는 신호이자 반복이 티를 되살리는 주범. 처방: 섹션별 실자산 마련(실제 제품 화면 캡처 > 생성 > 타이포 중심 구조로 전환)
- **처방 3로 (순서대로 시도)**: ① 밀도 상향(레이아웃 압축, 폭·패딩 재배분) ② **섹션 병합**(얇은 카드 3장 → 콤팩트한 한 줄/목록 구성 — 콘텐츠 추가 없이 정보 구조만 바꾸는 합법 수술) ③ 둘 다 불가면 "콘텐츠 부족" 보고

## 개편 모드 퀄리티 바 (탈바꿈의 완료 조건 — 티 0은 필요조건일 뿐)

실측 교훈: 고퀄 레퍼런스도 티는 있다(omneky: 티 21건인데 실자산 밀도로 프리미엄 / plai: 폰트 8단·디스플레이 115px·전 섹션 실스크린샷). **퀄리티는 티 부재가 아니라 아트 디렉션에서 나온다.** 티만 빼고 자산 없는 골격을 남기면 "깨끗하지만 허접한" 결과가 재생산된다. 개편 모드는 아래 5항을 채워야 완료다(보고서에 항별 근거 명시).

1. **디스플레이 모먼트** — 히어로 헤드라인은 본문 기준 4배 이상(방향이 저강도 타이포를 명시 선택한 경우만 예외). 3배대 중간지대가 밋밋함의 주범이다
2. **타입 스케일 6±1단** — 실측 16단은 위계 없음과 같다. 모든 사이즈를 스케일 토큰으로
3. **자산 플랜** — 재설계 착수 전에 섹션별 시각 자산 목록을 확정한다. 우선순위: 실제 제품 화면 캡처(실행 중인 서비스가 있으면 브라우저로 직접 찍는다) > 실사진 > 생성 이미지 > 자산이 안 되면 타이포 중심 구조를 선택. 같은 자산 돌려쓰기는 AS1
4. **색 커밋** — 지배색 1 + 강조 1이 전 섹션을 관통한다. 섹션마다 다른 언어(크림 에디토리얼 + 네이비 글래스 + 옐로 배너 혼재)는 실패
5. **빈 공간은 의도일 때만** — 콘텐츠 없이 남는 영역은 실증(로고·수치·후기·스크린샷)으로 채우거나 섹션을 접는다. "정돈됨"과 "완성됨"을 혼동하지 않는다

## 게이트 기준 (scripts가 집행 — 자가 추정으로 덮지 않는다)

### 섹션 분할 (결정적 캐스케이드)

1. **시맨틱 우선**: `section·header·footer·main` 직계와 role/aria-label 보유 요소가 콘텐츠 높이 70% 이상을 덮으면 채택
2. **래퍼 체인 붕괴**: body부터 "자식 하나가 부모 면적 95% 이상"인 체인을 내려가 콘텐츠 루트를 찾고, 그 직계 자식이 섹션 후보
3. **병합**: 높이 < 뷰포트 15% 후보는 아래 이웃에 병합(마지막은 위로)

### before/after 섹션 매핑

정규화 텍스트 블록 집합의 **자카드 유사도 그리디 매칭**(동률은 문서 순서). n:1(병합) 허용, 매핑은 게이트 산출물에 기록. 각 before-티의 사후조건은 매핑된 after-섹션에서 평가한다.

### 게이트 1 — 티 사후조건

before의 확정 🔴 티와 같은 룰 ID가 매핑된 after-섹션에서 재탐지되면 실패. 목표: 🔴 잔존 0.

### 게이트 2 — 시그니처 린트 ("조정만 했음" 차단, 불만 ③)

적용 범위: **재설계가 요구된 섹션만**(기본 모드 = 구조성 🔴 / 개편 모드 = 구조성 🔴+🟡). **데스크톱 뷰포트에서만** 평가(모바일은 반응형 스택으로 원래 구조가 변함).

섹션 정규화(자식 박스를 섹션 기준 상대 좌표로) 후 **이산 시그니처 4성분**:
1. **행·열 구성**: 자식 박스 y-겹침 행 클러스터링 → 행별 열 수 시퀀스 (카드 3장 한 줄=`[3]`, 목록=`[1,1,1]`)
2. **형제 균일성**: 형제 크기 ε(4px) 동일 여부
3. **정렬 클래스**: 텍스트 블록 중심의 섹션 대비 위치 (centered/left/right)
4. **미디어-텍스트 관계**: 미디어가 텍스트의 above/side/background/none

**4성분 전부 불변 = "조정만 했음" 실패.** 연속 임계치 없음 — ε는 측정 오차 흡수용. 패딩 인플레이션·렌더 무변화 DOM 셔플은 어느 성분도 못 바꾼다.

### 게이트 3 — 텍스트·링크·이미지 불변 (하드)

- **정규화**: 이모지·픽토그램 제거, 공백 접기, NFC. 정규화 후 빈 블록은 자동 통과
- **연접 커버**: after-블록이 before-블록 1개 이상의 연접(순서 보존)과 정확히 일치하면 통과(병합), 역방향 동일(분할). 커버 안 되는 잔여 = 위반
- **삭제 허용 목록**: 순수 서수 블록(`^\d{1,2}$`, `^step ?\d+$` 류)이 CP2 티로 걸린 요소 내부면 삭제 허용 — 보고서 "삭제된 장식 텍스트"에 기재. 그 외 소실은 실패
- **순서 변화**: 통과시키되 경고로 보고
- **링크**: (정규화 앵커텍스트, 해석된 href) 멀티셋 불변 — 삭제는 무조건 위반
- **이미지**: 정보성만 불변 — alt 있는 img, 면적 > 뷰포트 5% 플로우 이미지, 대형(>30vh) 요소의 background-image. 장식(alt=""·aria-hidden·텍스트 없는 인라인 SVG·소형 블롭)은 삭제 가능하되 제거 목록으로 보고

### 측정 조건

- 뷰포트 3종 `1440x900, 768x1024, 390x844` — 분할·시그니처·밀도(DE1·DE2)는 데스크톱 기준(모바일은 반응형 스택·세로 확장으로 오판 원천), 사후조건·텍스트는 뷰포트별
- 테마 토글·`prefers-color-scheme` 감지 시 양 테마 스캔
- ε 상수: 크기 동일 4px / 래퍼 면적 95% / 소형 섹션 15vh / 자카드 동률 tie-break 문서 순서
- **정적 저하 모드**(렌더 불가): 소스 스캔으로 표면성 티 서브셋만 탐지, 게이트 2·밀도·캡처 생략 — 보고서에 "게이트 약함" 명시 (exit와 별개 필드)
