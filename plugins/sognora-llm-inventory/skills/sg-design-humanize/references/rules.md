## 건드리지 않는 것 (Do-NOT)

본문 텍스트·링크(앵커텍스트+href)·정보성 이미지·폼 동작·라우팅·a11y 속성. 기존 브랜드 자산(로고·브랜드 폰트·브랜드 컬러)은 교체 대상이 아니라 방향 유도의 **입력**이다. surgical 모드에서는 프로젝트 디자인 시스템의 토큰 이름 체계도 보존한다(값 조정은 가능).

**슬롭이 아닌 것 — 오탐 억제.** 다음은 티로 취급하지 않는다: ① 의도가 분명하고 방향과 정합하는 대담한 선택 ② 주석·`direction.md`·프로젝트 디자인 시스템 문서에 근거가 기록된 의도적 이탈 ③ (티 제거 모드에서) 이번 작업 범위 밖의 기존 코드 ④ 린터·포매터 소관 ⑤ **의도적 예시** — `examples/`·`fixtures/`·`__mocks__/`·`stories/` 경로이거나 slop-example 류 명시 표식이 있는 코드. 면제는 이 열거 신호가 있을 때만. **확신이 안 서면 결함이 아니라 결정으로 취급한다.** 클리셰 룩도 금지가 아니다 — 브리프가 명시 요구하면 쓴다. 죄는 "선택"이 아니라 "기본값으로 소비하는 것"이다. 그리고 **깨끗한 감사도 유효한 결과다** — 이미 의도적인 UI에는 그렇게 말하고 멈춘다.

## 과잉 수술 가드

- **무티 섹션 면책**: 티 0인 섹션은 티 제거 모드에서 불가침. 개편 모드에서도 토큰만 새 방향으로 통일하고 구조는 보존 — 보고서에 "구조 보존: N개 섹션(사유)"로 선언.
- **조기 종료 (티 제거 모드 전용)**: 확정 티 0이면 퀄리티 바 약식 평가 후 종료 — 미달 항목이 있으면 "개편 모드 권장"을 반드시 고지한다. **개편 모드는 티 0이어도 종료하지 않는다** — 완료 조건이 퀄리티 바이기 때문.
- **콘텐츠 부족은 디자인으로 못 감춘다**: 밀도 처방(§6)이 전부 불가하면 장식으로 채우지 말고 "콘텐츠 부족"으로 보고한다.

# LLM 판정 층 (스크립트가 못 보는 것)

## Squint 패스 — 구성 슬롭 (before 스캔 직후 + **after 게이트 통과 직후, 두 번**)

슬롭은 구성적이다 — CSS를 한 줄씩 읽어서는 못 잡는다. 섹션 크롭(detect의 crops/)을 **실제로 보고** 5축을 audit.md에 기록한다. 걸린 섹션은 재설계 대상에 추가(개편 모드). after에서 생략하면 게이트 통과본에 레터박스·폰트 폴백 같은 눈에만 보이는 결함이 살아남는다.

1. **초점 부재** — 모든 요소가 동등 경쟁. 처방: 주 목표 하나를 크기·무게·대비·고립로 지배
2. **평평한 위계** — 읽지 않으면 주/부/메타 구분 불가. 처방: 무게 + 명도 사다리(크기만으로 만들지 않는다)
3. **단조 레이아웃** — 카드 크기·간격·밀도가 처음부터 끝까지 동일. 처방: 구역별 밀도 차등
4. **소심한 색** — 저채도 틴트 균등 분산 또는 액센트 남용. 처방: 액센트 1색 ~10%, 나머지는 구조적 중립
5. **보더로 만든 구조** — 선 대신 간격·서피스 단차로

## 재생성 자기검증 (방향 확정 직전)

**"비슷한 브리프를 다시 받아도 이 조합이 또 나오겠는가?"** — 그렇다면 선택이 아니라 기본값이다. 반프로필에 추가하고 재유도, 바꾼 것과 이유를 direction.md에.

## 성공 판정 3테스트 (게이트 통과 후 — 게이트는 나쁜 변경을 막고, 이건 좋은 변경인지 판정)

토큰 스왑만으로도 🔴는 전부 지워지지만 잊히는 템플릿은 그대로다. 셋 다 판정해 보고서에:

1. **Justified** — 모든 변경이 커밋한 방향에 복무하는가
2. **Coherent** — 타입·팔레트·레이아웃·시그니처가 서로를 강화하는가("하나의 커밋된 아이디어")
3. **Not a re-run** — 직전 실행들과 같은 "안전한" 조합이 아닌가(history·반프로필이 근거)

## 개편 모드 퀄리티 바 (완료 조건이자 작업 동력 — 티 0은 필요조건일 뿐)

실측 교훈: 고퀄 레퍼런스도 티는 있다(library/ 참조 — omneky 티 28건인데 자산 밀도로 프리미엄). **퀄리티는 티 부재가 아니라 아트 디렉션에서 나온다.** 재설계 대상 = 구조성 티 섹션 ∪ 아래 미달 섹션. 티 0이어도 이 기준으로 진행한다.

1. **디스플레이 모먼트** — 히어로 헤드라인 ≥ 본문 4배(라이브러리 실측 4.1~7.2×. 방향이 저강도를 명시 선택한 경우만 예외)
2. **타입 스케일 6±1단** — 정확히는 "한 화면 동시 위계 ≤6단"
3. **자산 플랜** — 착수 전 섹션별 시각 자산 목록 확정. 실캡처 > 실사진 > 생성 > 타이포 중심 구조
4. **색 커밋** — 지배색 1 + 강조 1이 전 섹션 관통. 섹션마다 다른 언어 혼재는 실패
5. **빈 공간은 의도일 때만** — 실증(로고·수치·후기·스크린샷)으로 채우거나 섹션을 접는다

**마감 체크리스트 (재설계 섹션마다 — 마지막 5%가 사람 티를 만든다)**
- 인터랙션 상태 4종(hover/focus/active/disabled) 전부 정의, `transition: all` 금지, active 미세 프레스 피드백
- 정렬된 숫자엔 tabular numerals, 대형 라틴 헤드라인만 자간 미세 음수(한글은 0)
- 중첩 radius 동심(안쪽 = 바깥 − 패딩), reduced-motion 존중
- 대담함은 시그니처 한 곳에만 — 마지막에 "액세서리 하나를 뺀다"
- probe.mjs로 자기 검수: 무반응 호버 0 목표(로고는 예외 관례), duration 수렴 확인

## 병행 탐지기 (선택)

소스가 있으면 `npx impeccable detect --json <src>`(Apache-2.0, Node 22.18+)를 보조 신호로. 좌표계가 달라(file:line vs 섹션) 병합하지 않는다 — impeccable = 파일 수정 지점, 본 스킬 = 섹션 재설계·게이트. 훅 미설치(`--no-hooks`). 없으면 조용히 생략 — 본 스킬 게이트가 SSOT.

# 게이트 기준 (scripts가 집행 — 자가 추정으로 덮지 않는다)

### 섹션 분할 (결정적 캐스케이드)

1. **시맨틱 우선**: `section·header·footer·main` 직계와 role/aria-label 보유 요소가 콘텐츠 높이 70% 이상을 덮으면 채택
2. **래퍼 체인 붕괴**: body부터 "자식 하나가 부모 면적 95% 이상"인 체인을 내려가 콘텐츠 루트의 직계 자식을 후보로
3. **병합**: 높이 < 뷰포트 15% 후보는 아래 이웃에 병합(마지막은 위로)

### before/after 섹션 매핑

정규화 텍스트 블록 집합의 자카드 유사도 그리디 매칭(동률은 문서 순서). n:1 허용, 매핑은 산출물에 기록.

### 게이트 1 — 티 사후조건

before의 확정 🔴 티와 같은 룰 ID가 매핑된 after-섹션에서 재탐지되면 실패. 목표: 🔴 잔존 0.

### 게이트 2 — 시그니처 린트 ("조정만 했음" 차단)

적용 범위: 재설계 요구 섹션(티 제거 모드 = 구조성 🔴 / 개편 모드 = plan.redesign 전체). **데스크톱에서만** 평가(모바일은 반응형 스택으로 원래 변함). 섹션 정규화 후 **이산 4성분** — ① 행·열 구성(y-겹침 클러스터 → 행별 열 수) ② 형제 균일성(ε 4px) ③ 정렬(centered/left/right) ④ 미디어-텍스트 관계(above/side/background/none). **4성분 전부 불변 = 실패.** 연속 임계치 없음 — 패딩 인플레이션·렌더 무변화 DOM 셔플로는 못 속인다.

### 게이트 3 — 텍스트·링크·이미지 불변 (하드)

- 정규화: 이모지·픽토그램 제거, 공백 접기, NFC. 정규화 후 빈 블록은 자동 통과
- **연접 커버**: after-블록이 before-블록들의 연접(순서 보존)과 정확 일치하면 병합으로 인정, 역방향(분할)도 동일. 커버 안 되는 잔여 = 위반
- **삭제 허용 목록**: 순수 서수 블록(`^\d{1,2}$` 류)이 CP2 티 요소 내부일 때만 — "삭제된 장식 텍스트"로 보고. 그 외 소실·추가 전부 실패
- 순서 변화는 통과 + 경고. 링크는 (앵커텍스트, href) 멀티셋 불변 — 삭제 무조건 위반. 이미지는 정보성 고유 세트 불변(중복 배치 축소는 허용 — AS1의 처방이므로), 장식은 삭제 가능하되 제거 목록 보고

### 게이트 4 — 개편 커버리지 (--overhaul 전용)

- `_design/plan.json` **필수** — 없으면 즉시 실패(계획 없는 개편은 조정으로 퇴행)
- 구조성 티·DE1 섹션 ⊆ redesign(누락 = 실패), preserve 사유 필수, redesign∪preserve가 전 섹션 커버(미포함 = 경고)
- **커버리지 하한**: 콘텐츠 섹션(헤더·푸터·nav 제외) 시그니처 변화율 ≥ 60% — 미달 = "개편이 아니라 조정" 실패
- 고유 정보성 자산 ≥ `minUniqueAssets`(이미지 프록시 URL은 원본 파라미터로 해석)

### 게이트 5 — 탈바꿈 검사 (--overhaul 전용, "매번 같은 형태" 차단)

- `_design/history.json` = `{"runs":[{date, direction, axes(7축), baseHex, assetLanguage}]}`. 계약 단계에서 없으면 현재 화면을 0번째 실행으로 기록
- after의 페이지 필드 색(body 또는 화면 60%+를 덮는 main의 배경)이 **마지막 실행 baseHex와 같은 팔레트 계열이면 실패**(`samePaletteFamily` — 무채색권은 명도대, 유채색은 hue±30·명도·채도)
- 완료 시 이번 실행을 runs에 append — 다음 실행이 같은 옷을 못 입게 하는 유일한 기억 장치. **기록 후 재검증은 `--history-exclude-last`**(자기 자신과 비교하는 오탐 방지)
