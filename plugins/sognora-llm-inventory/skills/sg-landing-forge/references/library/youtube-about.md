## 자산 운용

**이미지가 전 페이지 4개다.** 헤더 로고 SVG · 히어로 webp · 푸터 흑백 로고 SVG · (모바일 드로어가 헤더 로고 재사용).

**아이콘 16개 전부 인라인 SVG 스프라이트.** `<use xlink:href="#menu">` 방식, 스프라이트 1장 45KB. 크기는 클래스로만 제어(`glue-icon--24px` / `--18px`). 소셜만 브랜드 색 클래스(`glue-icon--color-x` / `--color-instagram` / `--color-facebook`).
**심볼 재사용**: 푸터 아코디언의 `+`와 `×`가 같은 `#close` 심볼이다. 회전만 다르다.

**히어로 한 장으로 375~1920 전부 커버.** 원본 3000×1373, aspect 2.185가 모든 폭에서 그대로. 1440×2dpr = 2880 < 3000이라 2x 화면까지 원본 한 장으로 성립한다.

**로고를 두 벌 만든다.** 헤더 `youtube-logo.svg`(141×32, 레드 배지 포함) / 푸터 `youtube-dark-logo.svg`(108×24, **레드 제거된 완전 흑백**). 같은 로고를 재사용하지 않고, 푸터에서는 색을 뺀 판을 별도로 쓴다.

**폰트 2벌만 로드.** YouTube Display 39KB + Roboto 37.5KB = 76.7KB. YouTube Sans도 `<link>`로 선언돼 있지만 실제 다운로드는 2벌.

## 인터랙션

**모션 언어가 하나다.**

```
지속시간  0.2s ×86 (지배) — 0.3s ×4 · 0.35s ×3
이징     ease ×86 · cubic-bezier(0.4, 0, 0.2, 1) ×3
속성     background-color 41 · color 41 · box-shadow 4
`transition: all` 선언 0건
```

**스크롤 리빌 0건.** `main` 안에서 opacity·transform·animation이 기본값 아닌 요소가 **0개**. 페이드인도 슬라이드업도 패럴랙스도 없다. 히어로가 정지 이미지라 영상 자동재생도 없다(video/canvas/iframe 전부 0).

**헤더는 항상 고정이 아니다 — 올라올 때만 도킹한다.**

```
정지(scrollY 0)   position: static, top -64px, 그림자 없음 → 문서 흐름에 그냥 놓임
아래로 스크롤      static 유지 → 페이지와 함께 사라짐. 단 그림자만 미리 켜둠
위로 스크롤        position: fixed, top 0, z-index 820 + Material elevation 그림자로 도킹
                 (0 1px 2px rgba(60,64,67,.3), 0 1px 3px 1px rgba(60,64,67,.15))
전이              0.3s ×3속성
```

내려갈 땐 비켜서 히어로 659px를 온전히 보여주고, 올라올 때만 내비를 돌려준다. 반투명·blur 없이 불투명 흰 바.

**호버 — 요소마다 딱 한 속성만 바꾼다**

```
내비 링크    배경 투명 → #eaeaea        (색·밑줄 불변)      0.2s ease
푸터 링크    색 #5f6368 → #202124       (배경·밑줄 없음)    0.2s ease
소셜 원형    배경 #f8f9fa → #e8eaed     (transition 0s, 즉시)
로고        무반응 (hoverDead)
```

**포커스** — `outline: 1px solid #212121` + `box-shadow: 0 0 0 1px #212121`을 겹쳐 2px 링 효과. 푸터 링크·소셜에 적용.
스킵 링크("Jump to Content")가 첫 Tab에 160×48로 나타난다 — 흰 배경, 2px 링, z 840.

**툴팁이 접근명을 겸한다.** 소셜 `<a>`는 aria-label도 텍스트도 없지만 `aria-labelledby`가 `<span role="tooltip">Follow us on X</span>`를 가리킨다. 시각 툴팁 하나가 접근명까지 담당.

**모바일 (375)**

- 햄버거 48×48 @x12(radius 4) + 로고가 우측으로 밀림. `aria-label="Open the navigation drawer"` · `aria-controls` · `aria-haspopup`
- 드로어: 흰 패널 **319/375 폭** + 스크림, 상단에 풀컬러 로고 + 닫기 ×, 링크 4개 세로 스택. **transition 0s — 슬라이드 없이 즉시 등장**
- 푸터 5열 → 아코디언 5개. `<div role="button" tabindex="0" aria-expanded aria-controls title="Press to expand">`, 흰 카드 radius **24px** · padding 16 · h58 · 피치 70
- `data-footerlinks-is-animated="false"` — 펼침에 애니메이션 없음
- 펼치면 흰 카드가 늘어나고 링크 피치 63px로 벌어짐

**계측이 전면에 박혀 있다.** 링크마다 `data-tracking` JSON(`{"event":"click_to_follow","eventParams":{...}}`)이 붙는다. 푸터 아코디언에도 `footer_column_select`.

## 배울 것

1. **브랜드 컬러를 페이지의 0.165%만 쓴다.** 레드는 141×32 로고 안 재생 배지 하나. 헤드라인·미션 구간과 푸터 구간의 레드는 **0.000%**. 세계에서 가장 유명한 빨강을 가진 회사가 자기 소개 페이지에서 빨강을 거의 안 쓴다
2. **색을 뺀 자리를 서체가 채운다.** h1이 워드마크와 같은 YouTube Display 800. 브랜드 인식이 색이 아니라 **글자 골격**에서 온다. 컬러 없이도 첫눈에 YouTube다
3. **토큰에 있다고 다 쓰지 않는다.** 레드 5단 + 시그니처 그래디언트가 정의돼 있는데 페이지 사용 0개. 시스템의 크기와 페이지의 절제는 별개다
4. **푸터 워드마크는 레드를 뺀 별도 파일을 만든다.** 같은 SVG를 재사용하고 CSS로 죽이는 게 아니라 `youtube-dark-logo.svg`를 따로 둔다. 로고가 두 번 소리 내지 않는다
5. **영상 플랫폼이 자기 소개에 영상을 안 쓴다.** 히어로는 정지 모자이크 한 장. 대신 9칸에 사진5/일러스트3/패턴1을 섞고 인물의 인종·연령·지역을 매 칸 바꿔 "everyone"을 **형태로** 증명한다. 미션 문장이 하는 말을 이미지가 먼저 한다
6. **콜라주 칸 폭을 일부러 안 맞춘다.** 351/212/478/120/279 — 특히 120px 흑백 패턴 조각이 컬러 흐름을 끊는 구두점이다. 균일 그리드였으면 스톡 카탈로그가 된다
7. **거터(64)가 컬럼(49.33)보다 넓다.** 그리고 화면이 커질수록 콘텐츠 점유를 10/12 → **8/12로 줄인다**. 넓어질수록 행폭을 좁혀 가독을 지키는 역방향 설계
8. **h1→본문 간격 80px을 전 브레이크포인트 고정.** 글자는 80→140으로 1.75배 커지는데 그 사이 간격은 안 변한다. 간격을 같이 키우면 헤드라인이 떠버린다
9. **타이포 3단(140/40/16)으로 페이지 전체.** 중간 단계를 안 만든다. 위계가 3개면 3개만 있으면 된다
10. **푸터 위계를 색 하나로만 만든다.** 제목·링크·라벨이 전부 Roboto 16/24 500 동일. 가르는 건 #202124 대 #5f6368뿐. 크기·무게를 안 건드린다
11. **스크롤 리빌 0건 + 0.2s ease 단일.** 등장 애니메이션 없이도 브랜드 페이지가 성립한다. 움직임이 없으니 이미지가 다 말한다
12. **헤더를 항상 고정하지 않는다.** 내려갈 땐 비켜서 히어로 659px를 온전히 내주고, 올라올 때만 fixed로 도킹. "상시 sticky"의 기본값을 의심한 결과
13. **호버에서 속성 하나만 바꾼다.** 내비는 배경만, 푸터 링크는 색만, 소셜은 원형 배경만. 겹쳐 쓰지 않으니 각각이 또렷하다
14. **자사 색은 아끼면서 타사 색은 지킨다.** 소셜 아이콘만 X 검정 · IG #DF465F · FB #1877F2 원색 유지. 여기서 통일하면 아이콘 인식이 죽는다
15. **툴팁 span 하나가 시각 툴팁 + 접근명(aria-labelledby) 겸용.** 숨김 텍스트를 따로 안 만든다
16. **스프라이트 심볼 하나를 회전으로 재사용.** 아코디언 `+`와 `×`가 같은 `#close`
17. **저대비를 의도적으로 쓴다.** 소셜 원형 배경은 푸터 대비 1.06:1로 형태가 거의 안 보인다. 아이콘 색이 일하고 원은 히트영역만 잡는다

## 버릴 것

- **`<picture>` media 3단(≥1024 / ≥600 / ≤599)이 전부 같은 파일을 가리킨다.** 아트디렉션을 선언만 하고 안 한다. 그 결과 375에서 콜라주가 **172px**로 눌려 9칸 내용이 안 읽힌다 — 히어로가 하는 유일한 일이 모바일에서 사라진다
- **히어로 461KB webp에 width/height 미지정**(QF6). 페이지 최대 자산에 치수가 없어 CLS가 열려 있다
- **alt 품질**: 히어로 `alt="about hero"`는 CMS 파일명 유출이다. 로고도 헤더 `"youtube logo"` / 푸터 `"youtube-logo"`로 표기가 갈린다
- **모바일 로고 링크에 `title="Google"`.** Glue 템플릿 잔재가 YouTube 페이지에 그대로 남았다 (데스크톱은 `"YouTube about"`)
- **GA + GTM 289KB가 자사 JS 20.6KB의 14배.** 페이지 무게의 1/3이 계측이다. 디자인 예산은 극도로 아끼고 트래킹은 안 아꼈다
- **내비 링크에 포커스 링이 없다.** 호버 배경(#eaeaea)을 그대로 재사용해서 키보드 사용자는 호버와 포커스를 구분할 수 없다. 푸터 링크에는 2px 링이 있는데 헤더에는 없는 불일치
- **아코디언이 `<div role="button" tabindex="0">`.** ARIA는 다 붙였지만 네이티브 `<button>`이 아니다
- **og:image 치수 선언이 틀렸다.** `og:image:width=1440 height=700`인데 실제 파일은 3000×1373
- **CTA가 0개다.** 미션 문장 뒤에 다음 행동이 없다. 헤더에도 `--no-cta`. 브랜드 선언에서 끝나고 아무 데로도 안 넘긴다 — 초대형 플랫폼이라 성립하는 사치지, 유입이 필요한 서비스가 따라 할 문법이 아니다
- **저작권 표기(©)가 없다**
- **배율만 흉내 내는 것**: 140px는 659px 풀블리드 이미지 + 80px 여백 + 워드마크와 같은 서체가 같이 와야 성립한다. 브랜드 전용 디스플레이 폰트가 없는 상태에서 크기만 140으로 올리면 그냥 큰 글씨다

- 미사용 Glue 위젯(캐러셀·마퀴·티커) 전부

### 판정

**리드 자격 있음** — 단, 용도를 좁혀서. 이 페이지는 **"섹션이 세 개뿐인 브랜드 선언 골격"**의 완성형 표본이다(수리본 기준 3개 = 풀블리드 이미지 / 1296 카피 / 푸터. 아래 "계기 수리 후 재실행" 참조): 컨테이너 1296 고정, 배경 전환 1회, 타입 3단(140/40/16), 자산 3개, 스크롤 리빌 0, CTA 0. IR이 섹션·컨테이너·bgSequence·타입 스케일·duration을 전부 물었고 2일 전 수동 계측과 픽셀 단위로 일치하므로 **골격 입력으로 바로 쓸 수 있다.**

경고 둘: ① **전환이 목적인 랜딩의 리드로는 부적합하다** — CTA가 0개고 다음 행동이 없다(위 "버릴 것" 참조). ② keyframes 14개 중 대부분이 미사용 시스템 코드라, 모션 어휘를 여기서 베끼면 이 페이지에 없는 동작을 들여오게 된다. 실제 모션 예산은 **200ms 전환 하나**다.

### 계기 수리 후 재실행 (2026-08-17, 수리본 `record.mjs` + `ir.mjs`)

수리 내용: `ir.mjs` 섹션 문턱 `0.85 → 0.8`·`depth 9 → 10`, 오버레이 제외, 래퍼 분할 규칙, `layers` 필드 신설. `record.mjs` 셀렉터에서 header/nav/banner/cookie/consent/curtain 제외 + y축 분산 표집.

**ir 재증류 — 개선됨. 섹션 2개 → 3개.** 히어로 콜라주와 미션 카피를 분리해 잡는다:

| # | y / h | tag | 컨테이너 | 열 | bg | headline |
|---|---|---|---|---|---|---|
| 1 | 64 / **659** | `img` | 없음(풀블리드) | 1 | `#FFFFFF` | — (assetSlot 1) |
| 2 | 783 / **618** | `div` | **1296** | 3 | `#FFFFFF` | **140px "About YouTube"** |
| 3 | 1541 / **697** | `footer` | **1296** | 5 | `rgb(242,242,242)` | 18px `Footer links` |

`bgSequence`가 `#FFFFFF → #FFFFFF → rgb(242,242,242)` 3단으로, 높이 리듬이 **659 → 618 → 697**로 세분된다. **이쪽이 재현 입력으로 더 정확하다** — 풀블리드 이미지(컨테이너 없음)와 1296 컨테이너 카피는 실제로 다른 골격이고, 구 증류본은 둘을 `main` 하나(h=1417)로 뭉갰다. 모바일은 **2개**(`y=64 h=642` 콜라주 / `y=754 h=868` 카피+푸터 합본) — 390에서는 카피와 푸터가 한 블록으로 뭉친다.

**세 섹션이 페이지 전체를 정확히 덮는다**: 64(헤더) + 659 + 618 + 697 = **2238** = `scrollHeight`. 잔여 0px. 위 본문의 "헤더 64 + main 1417 + 푸터 697"과도 푸터 값이 정확히 맞는다.

> 이전 계기(2026-08-17 02:18판)에서는 푸터를 `footer.glue-footer` 전체가 아니라 그 안의 `nav`(h=481)만 잡아 216px을 잃었다. **12:05판에서 수정됐고, 최종 계기(문턱 0.75 / 깊이 14)에서도 위 표 그대로 유지된다** — 이 사이트는 섹션이 3개로 안정됐다.

`layers` 신설 필드는 **빈 배열** — 전면 앰비언트 레이어 없음.

**record 재실행 — 수리 효과가 가장 뚜렷한 사이트.** hover 5건 → **3건**으로 줄었는데, **사라진 2건이 정확히 쿠키바였다**(`glue-cookie-notification-bar__more`, `__accept`). 남은 3건은 전부 페이지 콘텐츠이고 그중 2건이 실궤적이다:

```
a.glue-social__link   배경 rgb(248,249,250) → rgb(232,234,237)    3프레임
a (푸터 링크)          배경 rgba(0,0,0,0) → rgba(26,115,232,0.04)  13프레임 / 1400ms
```

`rgba(26,115,232,0.04)`은 Google 파랑(`#1A73E8`)을 4% 알파로 깐 값이다 — 위 "버릴 것"의 "내비 링크 호버 배경 `#eaeaea`"와는 다른 계열이고, **푸터 링크는 파랑 틴트, 헤더 링크는 회색**으로 갈린다는 뜻이다. 구 record가 쿠키바에 갇혀 못 보던 사실이다. reveal 0건은 유지(scroll 리스너 1개짜리 페이지).

**갱신 후 ② 판정:** 통과 유지, 근거는 더 정확해졌다 — IR 3개 = 눈으로 센 구조 블록 3개(내비는 64px 문턱 미달). **리드 자격 있음 판정 유지.**
