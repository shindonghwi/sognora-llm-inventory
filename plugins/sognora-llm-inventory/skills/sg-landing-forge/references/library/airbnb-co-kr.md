3. **텍스트 색이 4개뿐이다.** `#222222`(본문·제목) / `#6C6C6C`(보조) / `#C1C1C1`(구분자) / `#FFFFFF`(사진 위). 위계를 사이즈로도 색으로도 거의 안 만든다 — 만들 게 없기 때문이다.

`letter-spacing`은 570개 중 **569개가 `normal`**(예외 1건 0.2px). weight는 가변폰트인데도 400·500·600·700 4단만 쓴다.

## 자산 운용 — 사진 문법

### 비율은 하나다: `aspect-ratio: 20 / 19`

**페이지 전체에서 사진 컨테이너 77개가 전부 20/19(=1.0526)를 쓴다.** 정사각(1/1)은 아이콘 14장 몫이고 카드에는 한 장도 안 쓴다.

정사각을 살짝 비껴간 이유는 실측으로 답이 나온다: 20/19는 가로가 5.3% 길다. 카드 7장을 1329px에 넣으면 폭 179.56이 강제되는데, 여기에 정사각을 물리면 사진 높이도 179.56이 되어 카드가 240px을 넘는다. 20/19를 쓰면 170.6으로 **9px이 줄고**, 7장 × 8행이면 한 화면에 행 하나가 더 들어온다. 비율은 미감이 아니라 행 밀도에서 역산된 값이다.

### 라운드와 비율을 다른 요소가 진다

```
div   radius 20px · overflow: clip · background #DDDDDD   ← 마스크 + 로딩 플레이스홀더
 └ div
    └ div   aspect-ratio: 20 / 19                          ← 모양
       └ div
          └ div   position: relative                        ← 오버레이 앵커
             └ picture
                └ img   object-fit: cover                   ← 채우기
```

- **`img` 71장 전부 `border-radius: 0`이고, 직계 부모(`picture`)도 radius 0 / overflow visible.** 둥근 모서리는 4단계 위 조상이 진다.
- `overflow: hidden`이 아니라 **`clip`** — 스크롤 컨테이너를 만들지 않는 최신 값.
- 클리핑 div의 `background: #DDDDDD`가 곧 **로딩 플레이스홀더**다. 페이지의 `#DDDDDD` 배경 56~65회(로드된 사진 수와 일치)가 전부 이것. 스켈레톤 컴포넌트가 따로 없다.

### 서버는 자르지 않는다

`<picture>`는 **`srcset`/`sizes`를 안 쓰고 미디어 쿼리 `<source>` 2개만** 쓴다.

```
(max-width: 743px)   → …jpeg?im_w=320   1x, 2x
(min-width: 743.1px) → …jpeg?im_w=240   1x, 2x
```

**모바일이 데스크톱보다 큰 파일을 받는다.** 카드가 화면을 더 넓게 쓰니까 당연한데, `sizes` 기반으로 짜면 잘 안 나오는 결과다.

`im_w`는 **폭만** 지정한다. 그래서 내려오는 원본 비율이 제각각이다 — 240×216, 240×320(세로), 320×213, 240×228, 240×240, 480×270… **20/19 크롭은 전부 클라이언트에서 `object-fit: cover`가 한다.** 호스트가 올린 사진의 종횡비를 서버에서 통일하지 않고, 배송은 폭만 맞추고 모양은 CSS가 잡는다.

### 사진 위에 얹는 것 — 용도마다 다른 기법 3개

**1. 하트 (칩 없음)**
32×32 버튼, `border-radius: 50%`, **배경 투명**. 안의 SVG가 `fill: rgba(0,0,0,0.5)` + `stroke: #FFFFFF` + `stroke-width: 2`, 24px.
반투명 검정 몸통에 흰 외곽선 2px — **밝은 사진에서도 어두운 사진에서도 읽힌다.** 배경 칩도 스크림도 필요 없다.

**2. 배지 "게스트 선호" (유리 칩)**
```
높이 26px · radius 14px · padding 5.5px 9.5px
background: rgba(255,255,255,0.8)
backdrop-filter: blur(32px)
border: 1px solid rgba(255,255,255,0.5)
box-shadow: elevation2
텍스트 11px/13px w600 #222222
```
페이지에서 `backdrop-filter`를 쓰는 요소는 **배지가 전부다.** 전수 조사 결과 30개 전부 `blur(32px)`이고 내역은 "게스트 선호" 28 + "인기" 2(행 지연 로딩 수에 따라 총수는 변동). sticky 헤더에도, 카드에도, 검색 바에도 블러는 없다.

**3. 그 외에는 아무것도 없다.** 그라디언트 스크림 0건, 어둡게 까는 오버레이 0건, 사진 위 캡션 0건.

**여백은 박스가 아니라 시각 모서리에 맞춘다.** 배지는 사진 모서리에서 12px, 하트는 8px. 그런데 하트는 32px 박스 안의 24px 글리프라 실제 그림 가장자리는 8+4=**12px**. 숫자를 다르게 써서 보이는 자리를 같게 만든다.

### 아이콘

- 내비 탭 아이콘은 SVG가 아니라 **72×72 박스에 `object-fit: contain`으로 담은 240×216 PNG**(3D 렌더 일러스트, `im_w=240`). **탭 4개에 `<img>`가 8장** — 같은 좌표에 쉬는 상태/활성 상태를 겹쳐 두고 교차 페이드한다.
- 나머지 아이콘은 인라인 SVG 130~150개(셰브런·별·하트·지구본·햄버거). 로드된 행 수에 비례.

### 접근성 처리 — 사진에 대체텍스트가 하나도 없다

**71장 중 설명 있는 alt는 0장**(속성 자체가 없는 게 22장, `alt=""`가 49장). 대신 카드를 감싸는 링크가 `aria-label="위시리스트에 추가: 수영구의 집"` 같은 완성 문장과 위 표의 SR 전용 문자열을 들고 있다. 사진은 장식으로 선언하고 접근 가능한 이름은 링크가 진다 — 이중 낭독을 피하는 의도된 설계지, 빠뜨린 게 아니다.

폰트: **Airbnb Cereal VF**(자체 가변폰트) 단독. `@font-face` 9건.

## 인터랙션

### 모션 어휘가 이징 하나로 통일돼 있다

transition 선언 14종 중 **13종이 `cubic-bezier(0.2, 0, 0, 1)`**(= `--motion-standard-curve`).

| 개수 | transition | 대상 |
|---|---|---|
| **165** | `transform 0.25s` | 모든 아이콘 버튼·하트·화살표 |
| 37 | `text-decoration-thickness 0.3s, box-shadow 0.3s, background-color 0.3s` | 링크(밑줄이 **두꺼워진다**) |
| 35 | `box-shadow 0.2s, transform 0.1s` | 카드 — **리프트가 그림자보다 2배 빠르다** |
| 16 | `clip-path 0.449123s linear(0, 0.2548, 0.6434, …)` | 스프링 토큰의 실물 |
| 3 | `transform 0.3s, height 0.3s` | 탭 밑줄 |
| 6 | `opacity 0.001s` | 사실상 즉시 — 속성만 남긴 자리 |

### 숙소 카드는 호버에 반응하지 않는다

카드 서브트리 **48개 노드를 전수 diff한 결과 변화 0건.** transform·box-shadow·opacity·background·filter 전부 불변. 사진을 확대하지도, 카드를 띄우지도, 어둡게 덮지도 않는다.

카드에서 유일하게 반응하는 건 **하트의 `scale(1.08)`**(32 → 34.6px, `transform 0.25s`). 사진이 상품인 페이지에서 사진을 건드리는 호버는 상품을 가린다는 판단이다. 위 표의 `box-shadow 0.2s, transform 0.1s` 35건은 체험 카테고리 타일(123.9px) 쪽이다.

### 실측 상태표

| 대상 | rest → hover |
|---|---|
| 숙소 카드(서브트리 48노드) | **무반응** |
| 위시리스트 하트 | `transform: none` → `scale(1.08)` |
| 검색 세그먼트 | 투명 → `#EBEBEB` |
| **검색 제출 버튼** | **플랫 `#DA1249` → `linear-gradient(to right, #E61E4D 0%, #E31C5F 50%, #D70466 100%)`** |
| 호스팅 하기 | 투명 → `#F7F7F7` |
| 캐러셀 화살표 | transform이 identity로 바뀔 뿐 시각 변화 없음 |
| 키보드 포커스 | `box-shadow: #222222 0 0 0 2px` (outline 미사용) |

검색 버튼이 **쉴 때 플랫이고 호버에서 그라디언트**인 건 흔한 방향의 반대다. 그라디언트를 상시 켜두면 페이지에서 제일 시끄러운 물체가 되므로, 평소엔 단색 `#DA1249`(= `rausch700`)로 눌러두고 손이 왔을 때만 브랜드 그라디언트를 켠다.

포커스 링을 `outline`이 아니라 `box-shadow`로 그리므로 **32px 라운드를 그대로 따라간다.** 색은 파랑이 아니라 본문색 `#222222`.

### 헤더 — 접히는 게 아니라 다른 컴포넌트로 교대한다

sticky 래퍼: `position: sticky; top: 0; z-index: 100; height: 96px;` **배경 투명 · 보더 없음 · 그림자 없음 · `backdrop-filter` 없음.**

| | 펼침 (scrollY 0) | 접힘 (scrollY ≳ 80) |
|---|---|---|
| 검색 바 | 850 × 66 @ y=102 | **337 × 46 @ y=25** |
| radius | 100px | 40px |
| 그림자 | elevation3 `0 8px 24px rgba(0,0,0,.10)` + 1px 링 | `0 1px 2px rgba(0,0,0,0.08)` … |
| 세그먼트 | 3개(278 / 283 / 278), 라벨 + 값 2줄 | 값만 1줄 |
| 내비 탭 | 4개 표시 | 사라짐 |

**두 바가 동시에 DOM에 존재한다**(`cwxaa06` 850×66과 `l1qdq8x2` 337×46이 같은 y=25에 공존). 하나를 리사이즈하는 게 아니라 별개 컴포넌트를 교차시킨다. 접힘에서 줄어드는 66→46px은 정확히 **라벨 줄 하나를 버린 값**이다.

펼침 상태 검색 바는 **같은 850×66 자리에 시트 4장을 겹쳐 쌓는다**: ① 흰 바닥 `#FFFFFF` ② 회색 `#EBEBEB` + 1px `#DDDDDD` ③ 그림자 전용(배경 투명, elevation3) ④ 콘텐츠(radius 32px). 배경·보더·그림자를 한 요소에 몰지 않고 층으로 분리해, 상태가 바뀔 때 해당 층만 건드린다. 세그먼트 호버를 실측하면 **시트 3장은 전부 불변이고 호버된 세그먼트의 배경만 투명 → `#EBEBEB`로 바뀐다** — 접힘/펼침 같은 큰 전환에서만 시트가 동원된다는 뜻.

- 세그먼트 구분자: 1px `#DDDDDD`, 높이 32px, 바(66px) 안에서 위아래 17px씩 들여 배치
- 제출 버튼 48px 원이 바 오른쪽 안쪽 9~10px에 앉고, 세 번째 세그먼트가 `padding-right: 96.968px`으로 자리를 비워준다
- 시트는 radius **100px**(과라운드=완전 필), 콘텐츠 레이어는 radius **32px**(토큰값). 66px 높이에서 완전 필은 33px인데 토큰이 32px이라 1px 모자란다 — 그래서 보이는 곡률은 시트가 진다

**탭 밑줄은 공유 막대 1개다.** 헤더 안에서 3px 이하 다크 막대를 전수 검색한 결과 **딱 하나** — 67.2 × **3px** `#222222`, `transition: transform 0.3s, height 0.3s`. 탭마다 border-bottom을 켜고 끄는 구조라면 4개가 잡혀야 한다. 막대 하나가 `transform`으로 이동하고, 애니메이션 속성에 `width`가 아니라 **`height`가 들어 있다**(전환 중간 프레임은 미포착 — 선언만 확인).

**스크림이 미리 깔려 있다.** `position: fixed`, 전체 뷰포트, `rgba(0,0,0,0.25)`, **`z-index: -2`**, `opacity: 0`, `transition: opacity 0.15s cubic-bezier(0,0,1,1)`. 검색 펼침 패널을 열어 확인하는 데는 실패했으므로 전개 후 레이아웃은 미측정이지만, **스크림이 상시 마운트 상태로 뒤에 대기한다**는 사실은 확정. 열 때 DOM에 삽입하는 방식이 아니다.

## 한글 로케일 — 같은 코드베이스, 두 페이지

airbnb.co.kr(ko-KR)과 airbnb.com(en-US)을 같은 조건으로 나란히 계측했다.

| | airbnb.co.kr | airbnb.com |
|---|---|---|
| `body`의 `word-break` | **`keep-all`** | `normal` |
| keep-all 적용 노드 | **533 / 560** | **0 / 653** |
| `html`의 `word-break` | `normal` | `normal` |
| 폰트 스택 | Cereal VF … | 동일 |
| `aspect-ratio: 20/19` | 77 | 86 |
| 타입 스케일 | 12/16, 14/18, 13/16, 11/13, 20/24 | 동일 |
| 가격 표기 | `총액 ₩476,693` | `₩423,000 total` |

**차이가 딱 한 줄이다.** 컴포넌트도 토큰도 폰트도 비율도 전부 같고, `<body>`의 `word-break` 하나가 로케일로 갈린다. 한글 조판을 전역 상수로 박지도, 컴포넌트마다 흩뿌리지도 않고, **로케일 스위치 한 지점**에 둔다.

값 위치도 정확하다: `html`이 아니라 `body`. `html`에 걸면 `<html>`을 만지는 서드파티 스크립트와 부딪히고, 컴포넌트마다 걸면 새 컴포넌트가 매번 빠뜨린다.

### `1인당`에 U+2060을 박아 넣는다

불가시 문자를 전수 조사했더니 **WORD JOINER(U+2060) 24개**가 나왔고, **전부 `1인당` 안에** 있었다.

```
⁠1⁠인⁠당⁠   =  WJ + "1" + WJ + "인" + WJ + "당" + WJ    (6개 노드 × 4개 = 24)
```

`keep-all`은 한글 어절은 지켜주지만 **숫자와 한글이 붙은 자리(`1`+`인당`)는 브라우저가 줄바꿈 기회로 본다.** 그래서 그 경계에만 WORD JOINER를 심는다. 순한글인 `그룹당`에는 안 들어간다 — `keep-all`이 이미 처리하니까. 필요한 곳에만 정확히 들어갔다.

### 한글 웹폰트는 없다 (실측)

Cereal VF의 `@font-face` 9건이 커버하는 스크립트: 라틴 · 아랍 · 키릴 · 히브리 · 데바나가리 · 태국 · 그리스. **CJK는 없다.**

100px에서 문자열 폭을 재서 확인:

| 문자열 | `"Airbnb Cereal VF"` | `sans-serif` | `monospace` | `serif` |
|---|---|---|---|---|
| `숙소체험서비스` | **605.5** | **605.5** | **605.5** | 699.33 |
| `Airbnb` | **314.31** | 280.41 | — | — |

한글은 Cereal을 지정하든 `monospace`를 지정하든 폭이 같다 = **Cereal이 한글 글리프를 하나도 안 낸다.** 라틴은 폭이 다르다 = Cereal이 실제로 쓰인다. 결론: **라틴은 자체 폰트, 한글은 OS 기본 폰트.** 7개 스크립트용 전용 폰트를 굽고도 한국어 사용자에게는 시스템 폰트를 준다.

`fontFamily` 집계상 한글 노드 390개가 전부 "Airbnb Cereal VF"로 보이지만 이건 **선언값일 뿐 렌더링 폰트가 아니다.** `unicodeRange`가 `U+780-FAFF`로 한글 영역(U+AC00–D7AF)을 포함하고 있어 스캐너는 폰트가 잡힌 걸로 읽는다. 계산 스타일만 보면 못 잡는 함정.

### 행간은 한글이라고 풀어주지 않는다

`12/16 = 1.333`, `13/16 = 1.231`, `11/13 = 1.182`. 영문 페이지와 **완전히 동일**하다. `detect.mjs`의 KO1(한글 본문 행간 1.29 < 1.5)이 걸리지만, 이건 한국 로케일의 결함이 아니라 카드 시스템 전체의 값이다.

변론: 텍스트 노드 570개 중 **225개(39%)가 `white-space: nowrap`**이고 101개가 `text-overflow: ellipsis`다. 한 줄로 끝나는 라벨에 1.5 행간은 카드 높이만 늘린다. 다만 제목(13/16, `line-clamp: 3`)은 실제로 2~3줄로 감기며, 그 자리에서 1.23은 한글에 빡빡하다. **행간을 역할로 나눠 쓸 수 있는데 안 나눈 것**이 정확한 진단이다 — 토큰에는 `text_14_20`, `text_16_24` 같은 문단용 계열이 이미 있다.

## 배울 것

1. **사진 카드의 비율은 미감이 아니라 행 밀도에서 역산해라.** airbnb는 `20 / 19` 하나를 77곳에 쓴다. 정사각이 아니라 20/19인 이유는 폭 179.56이 그리드에서 강제될 때 높이가 170.6으로 떨어져 카드가 230px 안에 들어오기 때문이다. "정사각이 예뻐서"가 아니라 "한 화면에 행이 하나 더 들어와서"다. 카드 비율을 정할 때 먼저 계산할 것은 컬럼 폭과 목표 행 수다.

2. **비율·마스크·채우기를 각각 다른 요소에 맡겨라.** `aspect-ratio: 20/19`는 모양만 잡는 div가, `border-radius: 20px + overflow: clip + background: #DDDDDD`는 마스크 div가, `object-fit: cover`는 `img`가 진다. `img` 71장 전부 `border-radius: 0`이다. 한 요소에 몰면 반응형에서 비율이 흔들릴 때 라운드도 같이 깨진다.

3. **클리핑 컨테이너 배경색이 곧 스켈레톤이다.** 마스크 div에 `background: #DDDDDD`를 깔면 로딩 중엔 회색 사각형, 로딩 후엔 사진이다. 스켈레톤 컴포넌트도, shimmer 애니메이션도 필요 없다. 페이지의 `#DDDDDD` 배경(56~65회, 로드된 사진 수와 일치)이 전부 이것.

4. **`overflow: hidden` 대신 `clip`을 써라.** 실측 분포가 `clip` 224 / `hidden` 156으로 `clip`이 더 많고, 그중 **48개가 `clip` + `radius: 20px` 조합 = 사진 마스크**다. `clip`은 스크롤 컨테이너를 만들지 않아서 안쪽 요소가 실수로 스크롤 가능해지는 사고가 없고 합성 비용도 낮다.

5. **서버는 폭만 맞추고 모양은 CSS가 잡아라.** `im_w=240`은 폭만 지정하고, 내려오는 원본 비율은 240×216·240×320·320×213로 제각각이다. 20/19 크롭은 전부 `object-fit: cover`가 한다. 호스트 업로드 종횡비를 서버에서 통일하려 들면 파생본 매트릭스가 폭×비율로 곱해진다.

6. **반응형 이미지는 `sizes` 계산 대신 미디어 쿼리 `<source>` 2개로 끝내라.** `(max-width: 743px) → im_w=320` / `(min-width: 743.1px) → im_w=240`, 각 1x·2x. **모바일이 더 큰 파일을 받는다** — 카드가 화면을 넓게 쓰니 맞는 답인데, `sizes` 수식으로는 잘 안 나오는 결과다. 브레이크포인트가 2개뿐이면 이 방식이 더 정확하고 더 읽힌다.

7. **사진 위 아이콘은 칩 없이 "반투명 채움 + 흰 외곽선"으로 해결하라.** 하트는 배경이 투명한 32px 버튼이고, 안의 SVG가 `fill: rgba(0,0,0,0.5)` + `stroke: #FFFFFF` + `stroke-width: 2`다. 밝은 사진에서도 어두운 사진에서도 읽힌다. 아이콘마다 흰 원 칩을 깔면 사진을 그만큼 가린다.

8. **`backdrop-filter`는 아껴서 한 컴포넌트에만 써라.** 페이지에서 블러를 쓰는 요소는 배지 30개가 전부이고 값도 `blur(32px)` 하나다. 레시피: `height 26px / radius 14px / padding 5.5px 9.5px / rgba(255,255,255,0.8) / blur(32px) / border 1px rgba(255,255,255,0.5) / elevation2 / 11px·13px·600`. 카드 전체나 헤더에 블러를 걸면 스크롤이 무너진다 — 실제로 sticky 헤더에는 `backdrop-filter`가 없다.

9. **여백은 박스가 아니라 시각 모서리에 맞춰라.** 배지 인셋 12px, 하트 인셋 8px. 하트는 32px 박스 안 24px 글리프라 그림 가장자리가 8+4=12px에 온다. 숫자를 다르게 써서 보이는 자리를 같게 만든다. 두 값을 같게 두면 오히려 어긋나 보인다.

10. **사진 카드는 호버에서 움직이지 마라.** 카드 서브트리 48노드 전수 diff에서 변화 0건. 확대도 리프트도 스크림도 없다. 반응하는 건 하트의 `scale(1.08)` 하나뿐. 사진이 상품인 화면에서 카드를 띄우는 순간 그림자가 옆 사진을 덮고, 확대하는 순간 크롭이 바뀐다. "카드가 들리는 효과"는 상품이 사진이 아닐 때 쓰는 것이다.

11. **텍스트를 라운드 사진 폭 안으로 4px 들여써라.** 사진 x=48, 텍스트 x=52. 20px 라운드는 위아래 모서리를 안으로 말기 때문에, 텍스트를 사진의 직선 변에 정렬하면 왼쪽으로 튀어나와 보인다. 라운드가 클수록 이 보정이 필요하다.

12. **줄 박스와 줄 간격을 분리해라.** 카드 텍스트는 `line-height: 16px`인데 줄 사이 step은 18px이다. 행간을 키워 간격을 만들면 각 줄의 클릭 영역과 클램프 계산이 같이 커진다. 박스는 조이고 간격은 margin으로 벌리는 편이 카드에서 다루기 쉽다.

13. **타이포 토큰 이름에 행간을 넣어라.** `text_14_18`, `text_16_24`, `display_72_74`. 그리고 **같은 사이즈에 한 줄용과 문단용을 따로 파라** — 14/18 대 14/20, 16/20 대 16/22 대 16/24, 18/24 대 18/28. "14px 본문"이라는 토큰은 한 줄 라벨과 세 줄 문단에 같은 값을 강요한다.

14. **그림자에 자기 보더를 태워라.** elevation 1~5가 전부 `0 0 0 1px rgba(0,0,0,0.02)`로 시작하고, `elevation0`은 아예 `0 0 0 1px #DDDDDD inset` — 보더를 그림자로만 그린다. 레이아웃을 밀지 않는 테두리를 얻고, "그림자와 보더 색이 따로 노는" 부패가 원천 차단된다.

15. **모션은 이징 하나로 끝내고 duration으로만 갈라라.** transition 선언 14종 중 13종이 `cubic-bezier(0.2, 0, 0, 1)`이다. `transform 0.25s` 하나가 165곳. 카드에서는 `box-shadow 0.2s, transform 0.1s`로 **리프트를 그림자보다 2배 빠르게** 둔다 — 물체가 먼저 뜨고 그림자가 따라붙어야 무게가 생긴다.

16. **스프링을 `linear()`로 구울 때 원본 물리값도 토큰으로 같이 남겨라.** `--motion-springs-fast-easing`(샘플 곡선) 옆에 `-source-damping: 35` `-source-mass: 1` `-source-stiffness: 300`이 있다. 곡선만 남기면 나중에 duration을 바꿀 때 다시 계산할 근거가 사라진다.

17. **탭 밑줄은 공유 막대 하나를 `transform`으로 옮겨라.** 67.2×3px `#222222` 한 장이 `transform 0.3s, height 0.3s`로 미끄러진다. 탭마다 `border-bottom`을 켜고 끄면 이동이 아니라 점멸이 된다.

18. **포커스 링은 `outline` 대신 `box-shadow`로 그려라.** `box-shadow: #222222 0 0 0 2px`가 32px 라운드를 그대로 따라간다. 색은 시스템 파랑이 아니라 본문색을 쓴다.

19. **스크롤 컨테이너 안쪽에 4px 여유를 남겨라.** 바깥 래퍼 `padding: 0 44px` + 안쪽 그리드 `padding: 4px 4px 8px` = 실효 여백 48px. 이 4px이 없으면 포커스 링과 리프트가 클리핑 경계에서 잘린다.

20. **비활성 컨트롤은 숨기지 말고 죽여서 보여라.** 캐러셀의 "이전" 버튼은 시작 상태에서 `disabled` + `opacity: 0.5`로 남는다. 사라졌다 나타나면 그 순간 옆 버튼 위치가 밀린다.

21. **눈에는 조각을, 낭독에는 완성 문장을 줘라.** 가격 줄은 보이는 `총액` + `₩476,693` + `·` + `5.0` 옆에 1×1px로 `총액 ₩476,693`, `,`, `평점 5.0점(5점 만점)`을 병렬로 심는다. 사진 71장의 `alt`를 전부 비우고 링크의 `aria-label`이 이름을 지는 것도 같은 원리 — 이중 낭독 회피.

22. **한글 조판 스위치는 `<body>` 한 곳에 두고 로케일로 켜라.** ko는 `body { word-break: keep-all }`(533/560 노드), en은 `normal`(0/653). `html`에 걸면 서드파티와 부딪히고, 컴포넌트마다 걸면 새 컴포넌트가 빠뜨린다.

23. **`keep-all`이 못 지키는 자리에 U+2060을 박아라.** 숫자+한글 경계(`1`+`인당`)는 `keep-all`로 안 막힌다. `⁠1⁠인⁠당⁠`처럼 WORD JOINER를 심는다. 순한글인 `그룹당`에는 안 넣는다 — 필요한 곳만.

24. **법정 고지는 지우지 말고 조용히 시켜라.** 한국 전자상거래법 고지를 10px/12px `#6C6C6C`, 2줄, 푸터 최하단에 둔다. 페이지에서 10px을 쓰는 유일한 자리다.

## 버릴 것

- **히어로 없는 구조를 그대로 가져오는 것.** 화면 최대 글자가 20px인 홈은 사진 71장과 "무엇을 파는지 이미 아는 사용자"가 있을 때만 성립한다. 설명이 필요한 제품이 이걸 흉내내면 그냥 아무 말도 안 하는 페이지가 된다. 배울 것은 "히어로를 없애라"가 아니라 **"사진이 카피보다 강할 때는 카피를 줄여라"**다.

- **한글 본문 행간 1.23~1.33을 표준으로 삼는 것.** 39%가 `nowrap` 한 줄 라벨이라 성립하는 값이다. 실제로 2~3줄로 감기는 카드 제목(13/16)에서는 빡빡하다. airbnb 자신의 토큰에도 `text_14_20`, `text_16_24` 같은 문단용 계열이 있다 — 감기는 텍스트에는 그쪽을 써야 한다. 이 페이지는 그걸 안 쓴 쪽이다.

- **한글 웹폰트를 안 싣는 선택.** 라틴은 Cereal, 한글은 OS 기본으로 갈린다. 실측으로 확인했다. 전 세계 로케일 수십 개를 굴리는 회사의 트레이드오프지 품질 판단이 아니다. 한국 사용자만 보는 서비스가 이걸 따라 하면 맥·윈도우에서 글자 모양이 갈라지는 것을 자초한다.

- **`unicodeRange`에 한글 영역을 포함시켜 놓고 글리프는 없는 상태.** Cereal의 `U+780-FAFF`가 한글(U+AC00–D7AF)을 삼키고 있어, 계산 스타일만 보는 스캐너는 "한글 폰트 있음"으로 읽는다. 렌더링은 정상 폴백되지만 **검사 도구가 거짓 통과한다.** 자기 프로젝트에서 이러면 회귀를 놓친다.

- **라운드 14px·9px.** 토큰 스케일(4·8·12·16·20·24·28·32)에 없는 값이 각각 34회·15회 쓰인다. 배지 높이 26px을 필로 만들려고 나온 리터럴이다. 스케일을 만들었으면 "높이의 절반"이 필요한 컴포넌트에는 `border-radius: 999px`를 쓰는 게 맞다.

- **`--corner-radius-xxlarge`가 24px과 28px 두 개인 것.** 이름 충돌이 토큰 파일에 그대로 남아 있다. 스케일이 자란 흔적이지 설계가 아니다.

- **`opacity 0.001s` 6건.** transition을 끄고 싶은데 속성 목록에서 빼기는 싫어서 남긴 값. 의도는 읽히지만 다음 사람이 "왜 1ms지"에서 멈춘다.

- **가격 어순 불일치.** 보이는 가격 줄 39개 중 38개는 `총액 ₩476,693`인데 1개가 `₩191,203 총액`이다(도쿄 행에서 `₩302,369 총액`도 확인). 둘 다 "임대 호실" 유형. 같은 페이지에서 접두/접미가 섞인다 — 리스팅 타입별 문자열 템플릿이 갈라진 흔적.

- **이미지 `width="100%" height="100%"` 40장.** HTML `width` 속성은 픽셀을 받는 자리다. CLS는 `aspect-ratio` 컨테이너가 막아주고 있어서 실해는 없지만, 속성으로서는 무의미하고 컨테이너를 걷어내는 순간 무방비가 된다.

- **`loading` 속성이 71장 중 63장 미지정.** lazy 4장, eager 4장만 명시. 4,694px 페이지에서 아래쪽 행 이미지가 브라우저 휴리스틱에 맡겨져 있다.

### 스캐너 판정 재검 (기록용)

- **KO1**(한글 본문 행간 중앙값 1.29 < 1.5) — **정탐이되 원인이 다르다.** 한국 로케일의 결함이 아니라 카드 시스템 전역값이고, 영문 페이지도 수치가 같다. 다만 감기는 제목에 대해서는 실제 문제다.
- **KO4**(한글 페이지인데 스택에 한글 폰트 없음) — **정탐.** 위 폭 측정으로 확정. 스택 문자열만으로 낸 판정이 우연히 맞았다.
- **IC3**(텍스트·aria 없는 아이콘 8개) — **오탐.** 내비 탭 아이콘 8장은 탭 4개의 rest/active 이미지 쌍이고, 접근 가능한 이름은 부모 탭이 진다(`aria-selected` 보유).
- **detect.mjs 섹션 0개 / 텍스트 블록 0개 / 폰트 4단** — 로케일·UA 없이 잡힌 축소판 페이지의 결과. 무시할 것.

### 측정 방법 메모

**로케일과 UA를 주지 않으면 다른 사이트를 재게 된다.** 기본 Playwright 컨텍스트로는 높이 1,291px에 카드 0장, 폰트 사이즈 4종(`10 12 14 22`)짜리 SEO 링크 페이지가 나온다. `locale: "ko-KR"` + `timezoneId: "Asia/Seoul"` + 실 Chrome UA를 주면 높이 4,694px, 이미지 71장, 폰트 조합 10종의 진짜 홈이 나온다. 두 결과의 어떤 수치도 서로 호환되지 않는다.

**`networkidle`로는 접속이 안 된다.** 상시 연결이 있어 45초 타임아웃이 그대로 터진다. `waitUntil: "load"` + 고정 대기 3.5초로 바꿔야 한다.

**지연 로딩 행은 스윕 1회로 안 끝난다.** 1회 스윕 후 3,347px, 2회 후 4,694px. 행이 계속 붙는 피드형 페이지는 높이가 수렴할 때까지 반복해야 한다.

**렌더링 폰트는 계산 스타일로 알 수 없다.** `fontFamily`는 선언값만 준다. 같은 문자열을 후보 폰트별로 렌더해 폭을 비교하는 방법(위 표)만 유효하다.

### 계기 수리 후 재실행 (2026-08-17, 수리본 `record.mjs` + `ir.mjs`)
