# sg-landing-forge — 검수·채점 기준 (SSOT)

> 제작물의 하한선과 완성선. 수치 판정은 `scripts/detect.mjs`(룰 ID는 `scripts/rules-lib.mjs`와 1:1)·`scripts/probe.mjs`가 내고, 구성 판정은 캡처를 실제로 본다.
> **이 문서는 검수용이기 전에 착수 전 필독이다** — §1 금지 목록과 §1b 폰트 규칙을 코드 작성 전에 읽으면 검수에서 걸릴 일 자체가 줄어든다.

## 0. 방향 면제 (스타일 채택 조항 — meshy 문제의 해법)

잘 만든 사이트도 티를 갖는다(meshy 실측: 🔴 8개인데 산출물 109개가 전부 정당화). **"기본값으로 소비"가 죄이지 "선택"은 죄가 아니다.** 방향이 특정 티를 스타일로 명시 채택하면:

- 아트디렉터가 `_forge/exemptions.md`에 **룰 ID + 채택 사유 + 정당화 조건**을 선언한다 (예: `CO5 — 다크 시네마 방향의 그라데이션 디스플레이. 조건: 산출물 갤러리 20장+ 위에서만`)
- 검수에서 해당 룰은 실패가 아니라 **"채택된 스타일"로 보고**한다. 선언 없는 티는 여전히 실패다.
- **면제 불가**: QF 전부(품질 바닥), KO 전부(한글 조판), AS2(플레이스홀더), 가짜 증거. 이것들은 스타일이 아니라 결함이다.
- **정당화 조건 미충족 시 면제 무효** — meshy 문법(다크 시네마·글로우·그라데이션)을 채택하려면 그 문법의 연료(산출물 갤러리 밀도)가 먼저 있어야 한다. 갤러리 없는 다크 시네마는 빈 어둠이다.

## 1. 하한선 — detect.mjs가 집행 (면제 선언분 제외, 🔴 0 · QF 0이 통과 조건)

37룰 자동 탐지. 제작 중 특히 밟기 쉬운 것만 요약(전체는 detect 출력이 SSOT):

- **AI 티**: 보라 그라데이션(CO1)·그라데이션 텍스트(CO5)·빈 카드 3장 나열(LA1)·필 뱃지-위-제목(CP1)·번호 뱃지 카드(CP2)·이모지 아이콘(IC2)·화살표 글리프 텍스트(IC5)·사이드 액센트 보더(BD1)·장식 블롭(IC4)
- **자산**: 동일 이미지 3회+ 재사용(AS1 — 이 스킬에선 철칙 위반이기도 하다)·플레이스홀더(AS2)
- **밀도**: 여백 지배 섹션(DE1)·저밀도 카드 행(DE2) — 처방은 압축→병합→"콘텐츠 부족" 보고, 장식으로 채우기 금지
- **품질 바닥(QF)**: 가로 오버플로·정지 시 숨은 텍스트(리빌은 기본 가시로 설계)·행폭 과대(한글 42자)·타이포 하한·모바일 44px 탭 타깃·unsized img
- **한글 조판(KO)**: 행간<1.5·이탤릭·양수 자간·한글 폰트 미지정 + (스크립트 밖) **keep-all 전역**, 2분할 강조가 어순을 깨는지

## 1b. 폰트 규칙 (DESIGN.md 계약의 필수 항목 — 위반은 detect가 잡는다)

- **최소**: 모든 텍스트 ≥ **12px**(법적 고지·캡션 포함, QF4) · 본문 ≥ **15px** · 한글 본문 행간 ≥ 1.5(KO1)
- **최대**: 디스플레이 상한 = **본문 × 4~7** 범위에서 DESIGN.md가 캡을 확정(라이브러리 실측: 4.1~7.2×). 프로젝트에 기존 상한 규정이 있으면 그것이 우선하며 캡 초과 금지
- **단수**: 스케일은 5~8단으로 DESIGN.md에 전체 목록 명시(TS1: 9단+ 🔴), 비율 일관(TS2), **한 화면 동시 위계 ≤ 6단**
- **토큰 강제**: 모든 font-size는 DESIGN.md 스케일 값만 — 임의 px 삽입 금지. 행간은 크기가 아니라 역할에 결합(본문 1.5~1.6 / 리드 1.6 / 디스플레이 1.3~1.4), 한글 자간 0
- 무게 대비는 크기보다 먼저(400/700보다 500/800 같은 극단 대비 권장 — 한글은 무게 표현이 풍부)

## 2. 인터랙션 언어 — probe.mjs가 집행 (라이브러리 교차 실측이 근거)

- 호버: **색 전환·옅은 알파 필·brightness만** — transform·그림자 금지 (toss·linear 실측)
- duration **1~2개 값으로 수렴**(0.1~0.2s), easing 1개, `transition: all` 0개
- 무반응 인터랙티브 요소 0 목표(로고는 관례상 예외), 리빌은 1회성·재은닉 없음
- active 프레스 피드백·focus-visible·disabled 상태 정의 (마감 체크)

## 2a. 자산 3클래스 — 허용 경로와 등급 캡 (공정 §3의 법)

| 클래스 | 정의 | 허용 경로 | 금지 |
|---|---|---|---|
| **E (증거)** | 고객·작업자 얼굴, 후기, 별점, 현장 실적 사진, 사용 수치 | **수집만** — 실물 제공·촬영 | 생성·연출·스톡 대체 **절대 금지** (가짜 증거 = 최악의 사고) |
| **P (제품 화면)** | 앱·UI 스크린샷 | **픽스처 시딩 후 실캡처** — 현실적 데이터(항목 3~4건·현지 명명·날짜·상태)를 먼저 심고 찍는다 | 생성 목업, 빈 껍데기 화면 |
| **I (설명·환경)** | 다이어그램, 색상 시트, 질감, 환경·건물 사진, **예시 산출물 갤러리**(제품이 만들 결과의 예시 — "예시" 정직 라벨 필수, 고객 실적으로 위장 금지) | 직접 제작·생성(imagen)·**정식 라이선스 스톡** | 시장 불일치 소재(한국 시장에 미국 주택) |

**무라벨 금지(생성 소재의 최대 관용구)**: 제품·브랜드가 등장하는 소재에 **라벨·브랜드 마크가 없으면 실패**다. 실무에서 광고할 제품에 이름이 안 붙는 일은 없고, 무라벨 병·무라벨 캔·마크 없는 기기는 생성 이미지의 서명이다. 대응: 가상 브랜드라도 이름·로고를 정하고 **라벨을 붙여 생성하거나 후처리로 합성**한다(가상 브랜드임이 문맥상 명백하면 E클래스 위반이 아니다 — 실고객·실적 위조만 금지). 소재 색이 페이지 브랜드색과 정확히 일치하는 것도 프롬프트 흔적이니 피한다. 판정: 게이트키퍼 실물감 항목.

**동일 시안 반복 금지**: 같은 산출물(같은 헤드라인·설명문·피사체)이 **두 섹션 이상에서 그대로 재등장하면 위반** — "여러 시안을 만드는 제품"이 "한 벌을 돌려쓰는 도구"로 보인다. 단계별 연속성이 필요하면 같은 캠페인의 **다른 변형**(다른 헤드라인·다른 컷)을 쓴다.

**예시 산출물 갤러리 다양성**: 제품 결과물 예시는 **서로 다른 피사체·업종 ≥4**(한 사례를 매체별로 리사이즈해 돌려쓰면 "사진 한 장 리사이즈하는 도구"로 보인다 — AS1의 갤러리 확장, meshy 실측 근거: 고유 산출물 109개가 스펙터클의 연료였다).

**등급 캡**: 자산 스프린트의 이미지 게이트키퍼 등급이 페이지 등급의 상한이다. E 부재 시 페이지 상한 B — 슬롯을 정직하게 생략하고 `homework.md`(샷리스트 브리프)를 발행하며, 보고서에 캡 사유를 명시한다.

**슬롯 우선 규칙 (생성 자산 공통)**: 이미지는 들어갈 자리가 먼저다.
- 모든 생성·크롭·캡처는 섹션 스펙의 **슬롯 명세**(렌더 치수 px 데스크톱·모바일, 종횡비, object-fit, 라운드, 주변 배경색 hex, 투명 여부, 오버레이 안전영역)를 읽고 시작한다. 슬롯 명세가 없으면 생성하지 않고 아트디렉터에게 스펙 보완을 요구한다.
- 생성 해상도 = 슬롯 렌더 크기 ×2(레티나), 종횡비 = 슬롯 종횡비 고정. 프롬프트에 종횡비·구도를 명시하고, 오버레이 슬롯이면 텍스트가 앉을 방향의 구도를 비운다.
- **인슬롯 핏 검증(필수 루프)**: 자산을 실제 슬롯에 넣고 렌더→캡처→확인 — ① 레터박스·여백 땜빵 0 ② object-fit 크롭이 피사체를 훼손하지 않음(머리·간판·제품이 잘리면 실패) ③ 모바일 치수에서도 ①②) ④ 주변 배경색·조명 톤과 정합. 실패 시 실패 원인을 프롬프트에 반영해 재생성, **3회 실패면 자산이 아니라 슬롯이 문제** — 아트디렉터에게 슬롯 재설계(비율·배치 변경) 콜백.
- 게이트키퍼 판정 입력은 원본 파일이 아니라 **인슬롯 렌더 캡처**다(사람은 이미지를 페이지 안에서 본다).

**SVG 정책 (라이브러리 18종 실측 근거)**: 레퍼런스에서 SVG의 용도는 셋뿐이다 — ① 전문 아이콘 세트(단순 기하) ② 로고 ③ **초소형 기능 자산**(마스크 경계·호버 밑줄·괘선 — jobber rip.svg처럼 단일 path·소형 viewBox). **일러스트·다이어그램·시트·건물·사람·제품 그림을 SVG 좌표로 즉석 작도하는 것은 금지** — 18종에서 0건이고(toss는 다색 아이콘조차 SVG를 포기하고 4x PNG, airbnb 일러스트는 PNG 3D 렌더), LLM은 시각 피드백 없이 좌표를 산수로 찍으므로 반드시 어색해진다. 그런 그래픽은 I클래스 경로(imagen 생성→후처리 / 라이선스 스톡 / 실사진·실화면)로. 허용된 마이크로 SVG를 만들 때도 **렌더→눈으로 확인→수정 루프 필수**(blind 사용 금지).

**성능 예산**: 히어로 자산 ≤200KB(webp), LCP 대상 명시, 이미지 width/height 필수(QF6). og:image·파비콘·공유 카드는 자산 스프린트의 산출물이다(근거: jobber는 질감 전체를 169KB로 해냈다 — library 실측).

## 2b. 이미지 콘텐츠 판정 — 게이트키퍼 (공정 §3 종료 조건, 신선한 컨텍스트로)

이미지별로 개별 판정 — **입력은 인슬롯 렌더 캡처**(§슬롯 우선), 필요 부위는 확대 크롭해서 본다:
- **실물감**: AI 생성 티가 나는 부위(창문 비대칭·문·간판 글자·구조 왜곡·질감)를 픽셀 영역으로 지목 — "티 난다" 판정이면 교체
- **핏**: 슬롯 안에서 레터박스·피사체 크롭 훼손·톤 부정합이 보이면 교체(§슬롯 우선 검증을 통과했어도 사람 눈으로 재확인)
- **전후 일관성**: before/after가 같은 건물·같은 촬영·색만 변경으로 읽히는가 — 이 제품군은 여기서 신뢰가 결판난다
- **시장 정합성**: 자산 속 피사체가 대상 시장의 실제 대상과 일치하는가(한국 빌라·상가 시장에 미국 교외 주택 금지)
- **목업 진위감**: 제품 화면이 실제 소프트웨어로 보이는가(뭉개진 글자·비현실 데이터 금지 — 실캡처 원칙)
- **세트 일관성**: 톤·조명·계절이 한 세트로 읽히는가

## 2c. 엔지니어링 하한 — 정적 페이지 금지 (라이브러리 실측이 근거)

레퍼런스의 절반은 코드다: framer는 CSS 모션 2개 뒤에 **JS 스프링 175건(전부 임계감쇠)**, toss는 `opacity = 1 − translateY/50`로 결합된 IO 리빌 시스템, meshy는 `backdrop-filter: blur(20px) saturate(2.2)` 유리 + 고정 앰비언트 글로우 + CTA 그라데이션 스윕, jobber는 `mask-image` 밴드 전환 + 호버 손그림 밑줄. **이 지식을 읽고도 정적 섹션만 쌓는 것은 공정 위반이다.**

**집행: `behavior.mjs`** — 하한 3(히어로 인터랙티브·스크롤 연출·시그니처 마이크로, 역할 커버 필수)은 `_forge/engineering.json`(스키마 §8a)에 AD가 선언하고, 기계가 선언된 트리거를 실행해 선언된 computed-diff가 실제 발생하는지 검증한다. 선언(AD)과 통과 의무(빌더)의 분리가 "억지 인터랙션"을 구조로 차단한다. no-JS·reduced-motion에서 텍스트 비가시 = 실패(리빌의 opacity:0 잔류 사고). 개폐·전환류 0ms 금지(120~150ms 하한), 어휘는 토큰 안에서. 구현은 프로젝트 실제 스택 코드만 — 일회용 정적 HTML 불인정. 질(키치인가, 이해에 복무하는가)은 패널 몫.

## 2d. 시각 앵커·콘텐츠 예산 (판정자: detect IC6·DE1~DE3 + 카피 검수 + AD)

실전 사고 근거: 번호 텍스트 목록 카드("01 건물의 주요 외벽"), 서술형 스탯 밴드("첫 작업 과정 검토 중"), 여백으로 부풀린 얇은 섹션.

- **시각 실체는 이미지로 말한다** — 대상이 물리적 실체(건물·제품·공간·산출물)면 그 실체의 이미지(E/P/I 경로) 위에 주석·오버레이로 설명한다. "01/02/03" 텍스트 목록으로 대체 금지 → **IC6(🔴)이 기계 검출**. (레퍼런스 실측: jobber 업자 얼굴 26장, airbnb 사진 카드, hyundai 풀블리드 — 실체를 텍스트로 설명하는 사례 0)
- **스탯·상태 밴드는 측정값만** — 숫자·날짜·고유명사가 없으면 밴드 자체를 생략한다. "검토 중"·"진행 중" 같은 서술문은 스탯 자리에 금지 → **DE3(🔴 혐의)** + 카피 검수(facts 대조에서 수치 없는 밴드 지적).
- **콘텐츠 예산** — 섹션 수는 facts 재고에 종속된다. 말할 것이 없으면 섹션을 줄여라. 여백+얇은 텍스트로 페이지를 부풀리는 것은 DE1·DE2가 잡고, AD는 계약 단계에서 "facts N개 → 섹션 M개" 예산을 명시한다(E클래스 정직한 생략 원칙의 일반화).
- **깊이 하한(콘텐츠 예산의 반대 방향)** — "정직하게 짧은 페이지"는 facts 조사가 얕았다는 핑계가 될 수 없다. ⓐ facts.md에 **제품 인벤토리 절 의무**: 제품 화면 전수·플로우 단계 전수·산출물 유형과 실규격 전수·프로세스/권한/비용 — 스크롤 깊이는 상상이 아니라 제품 실체에서 나온다. ⓑ **리드 대비 깊이 대조(기계)**: 최종 페이지의 스크롤 길이·섹션 수를 리드 ir.json과 비교, **-40% 초과 축소는 mapping.md에 섹션별 삭제 사유가 전수 기재돼야 통과**(사유 없는 축소 = P6 실패). 스크롤할수록 새 정보가 없으면 페르소나 ⑤가 잡는다.
- **깊이의 단위는 절차가 아니라 장면이다(매뉴얼화 금지)** — 실전 사고: 깊이 하한을 절차 설명(등록 폼·규격·검토·비용·권한)을 큰 섹션으로 늘려 채움 → "가입 전에 읽는 매뉴얼"(매력 44/100). 규칙: **사용 절차·규격·권한은 압축 모듈(한 줄 흐름·콤팩트 표) 1~2개로 제한**하고, 깊이는 **갖고 싶은 산출물·증거·장면의 다양성**으로 채운다. 절차 섹션이 산출물 섹션보다 많으면 매뉴얼이다 — AD가 mapping에서 비율을 명시하고 매력 채점(§7d)이 최종 판정.
- **동어반복 금지(카피×아이콘)** — 같은 섹션의 항목 제목이 **같은 어미·같은 명사로 끝나는 나열**("보여 주는 기능 / 읽는 기능 / 준비하는 기능 / 관리하는 기능")은 위반이고, 그 옆에 이미지·돋보기·복사·톱니 같은 **제네릭 시스템 아이콘 세트**를 붙이면 이중 위반이다(실전 평가에서 "가장 AI스러운 프레임"으로 지목). 항목은 서로 다른 문형·다른 실체를 가리켜야 하고, 아이콘은 세트 고유 스타일이어야 한다(§2d 아이콘 규칙). 같은 아이콘을 다른 섹션에서 재사용하는 것도 금지.
- **반폭 공백 금지** — 카드·밴드에서 콘텐츠가 좌측 절반만 쓰고 우측이 통째로 비면 위반(구분선까지 반폭이면 공백이 강조된다). 여백은 리듬이어야 하고 미완성으로 읽히면 실패 — 실측 사례: 폭 1270 CTA 카드에서 우측 435px 공백.
- **히어로 카피 복제 금지** — 최종 CTA의 헤드라인·CTA 라벨이 히어로를 어미까지 되풀이하면 위반. 페이지 끝은 새 문장으로 닫는다.
- **첫 화면 산출물 하한** — 히어로에 **제품의 완성 산출물이 최소 1점, 산출물 다양성이 제품의 핵심 가치라면 다수(벽 형태)** 실물로 보여야 한다. 큰 글씨+CTA만 있는 히어로, 절차도·스테퍼가 첫 스크롤의 주인공인 히어로는 실패(실측 대조: 경쟁 76점 히어로엔 생성 결과 4장+컨셉 4개가 이미 떠 있고, 44점 히어로엔 흰 배경에 큰 글씨만 있었다). 미도장·미완성 상태의 "입력물" 사진을 히어로에 두는 것도 같은 실패다 — **히어로는 애프터를 판다.**
- **면책·부정 고지 총량 제한** — 면책 문구(정확도·색차·법적 주의)는 **페이지 전체에서 1회**, 그리고 히어로에 두지 않는다(볼 것을 보여주기 전에 불신을 심는 배치 금지). "아직 제공하지 않습니다"류 미제공 고지도 §정직 고지 집약 규칙에 따라 1곳 — 핵심 기능 부재를 랜딩이 자백하는 밴드는 릴리스 노트이지 판매 페이지가 아니다.
- **번호 체계 단일화** — 페이지 내 단계 번호(01·02…)는 하나의 체계만 쓴다. 중간에 리셋되면 "같은 페이지를 두 번 붙인" 인상을 준다(실전 사고: 02가 두 번 등장).
- **소재는 산출물이 아니다** — 스톡·생성 제품 사진을 나열한 스트립은 산출물 전시가 아니며 갤러리 다양성 계수에도 포함되지 않는다. 산출물로 인정되려면 **실제 게재 크롬**(광고 배지·도메인·CTA 버튼·영상 길이·플랫폼 UI)이 붙어야 한다(§산출물 리얼리즘의 계수 규칙).
- **중심 장면 1개 의무** — contract.md에 "이 페이지의 중심 장면"을 한 문장으로 정의한다(예: "제품 링크를 넣자 검색·이미지·영상 광고가 한꺼번에 완성되는 장면"). **히어로는 결과를 판다 — 사용자가 해야 할 입력 작업("~을 등록하세요")을 파는 히어로 금지, CTA도 결과 언어**(형식: "무료로 <제품의 산출물> 만들기/받기" — 광고 서비스면 "광고 시안", 문서 도구면 "보고서" 등 제품마다 치환). 판정: 페르소나 ②·매력 채점.
- **장면 예산(페이지 내 반복 금지)** — 같은 배경·같은 레이아웃 시그니처가 **연속 3섹션 이상 이어지면 위반**(P6에서 bgSequence·섹션 시그니처 run-length 기계 검사). 리드의 리듬(배경 교대·장면 전환)을 계승하는 것이 원칙 — "9,500px 내내 같은 화면" 사고의 방어선.
- **정직 고지는 1곳에 집약** — "베타"·"준비 중" 라벨을 페이지 곳곳에 반복하면 미완성 인상만 커진다. 전용 자리 1곳(예: 가격/상태 모듈)에 모으고 반복 노출 금지. 가짜 증거 금지 원칙은 불변 — 집약은 정직의 포기가 아니라 배치의 규율이다.
- **산출물 리얼리즘** — 제품이 만드는 결과물(광고 시안·문서·디자인 등)을 전시할 때는 **그 결과물이 실제로 게재·사용되는 매체의 실규격·실UI 안에 조립**한다: 검색 광고는 검색 결과 UI로, 배너는 IAB 실규격(300×250 등)으로, 문서는 실제 뷰어 프레임으로. **문구를 이미지에 굽지 않는다** — 텍스트·UI는 HTML/CSS로 조립하고, 이미지 생성은 사진 소재까지만(imagen). 판정자: 게이트키퍼 "목업 진위감" 항목 — 실무자가 보면 규격이 틀린 시안은 즉시 교체.
- **아이콘은 양방향 규칙** — ⓐ 의미 결합 없는 장식 아이콘 금지(IC1~IC4). ⓑ 그러나 라벨·카테고리·리스트에 시각 앵커 0인 텍스트 벽도 금지 — 이때는 **아이콘 세트가 정답**이다(실측: mayoclinic 191개 체계, toss 다색 4x PNG). 제작 규격: imagen 투명 배경 생성(세트 전체 단일 스타일 프롬프트) → 배경 잔여 제거 → `magick -trim +repage` → 캔버스 정규화 → 토큰 색 결합 → **인슬롯 렌더 확인**(실크기로 눈 검수). SVG 즉석 작도는 여전히 금지(§SVG 정책).

## 6b. 자기 diff 게이트 (공정 §5 — 스펙이 원본이다)

v1의 원본은 손 스펙이 아니라 **ir.json + 브리프**다: 골격 수치(그리드·컨테이너·패딩·높이)는 리드 IR에서, 치환 수치(타입·색)는 tokens.json에서 온다. 빌드 직후 `capture.mjs`로 해당 섹션을 측정해 브리프의 수치와 대조한다. 생성 섹션(리드 아날로그 없음)만 손 스펙이 원본이다.

**허용 오차 밴드**: 치수·패딩 ±8px · 폰트 크기 정확 일치(토큰이므로) · 행간 ±2px · 색 정확 일치(hex 토큰) · 모션 duration 정확 일치. 밴드 밖 = 해당 섹션 재작업. 스펙에 없는 값이 측정되면 그 자체가 위반이다.

## 7a. 패리티 채점 (공정 §8 — side-by-side 선호 판정 금지)

- 대상: **히어로 + 대표 섹션 1개**만(나머지는 자기 diff가 담당). 우리 캡처와 리드 레퍼런스의 대응 섹션 크롭을 "익명 출품작 2점"으로 제시.
- **선호를 묻지 않는다**("어느 쪽이 프로냐" 금지 — 장르 편향·수렴 압력·무정보 판정). 같은 루브릭으로 각각 절대 채점:
  ① 마감(폰트·간격 정밀도) ② 위계 명료성 ③ 자산 품질 ④ 밀도 균형 ⑤ 신뢰감 — 각 1~5점.
- **통과**: 전 축에서 레퍼런스 대비 -1점 이내 **그리고** 마감 축 절대 4점 이상. 미달 축이 곧 재작업 지시서다.

## 7b. 페르소나 평가 (공정 §8 — 신선한 눈)

- 평가자 = **대상 사용자 페르소나**(contract.md의 타깃), 새 컨텍스트(제작 과정 모름). 인터랙션 실측 평가자(probe+실조작)도 별도 1인
- 입력: 최종 캡처(데스크톱+모바일) + 히어로 카피. 유도 질문 금지 — 5문항 고정: ① 첫인상 한 줄 ② 무엇을 파는 페이지로 읽히는가 ③ 신뢰가 가는가(이유) ④ 가입/문의하고 싶은가 ⑤ 걸리거나 이해 안 되는 곳
- 판정: ②를 틀리게 답하면 **무조건 🔴**(히어로가 논지 전달 실패). ③④의 부정 응답 중 사실 결핍·구성 문제는 🔴, 취향은 기록만
- 🔴 반영 → 재평가. 2회 재평가에도 ②가 틀리면 서사(plan.md)로 회귀
- 자기 평가로 대체한 경우 보고서에 "자기 평가"임을 명시(신뢰도 구분)

## 8a. 기계 계약 스키마 (v1)

**`_forge/tokens.json`** — conform.mjs의 법전. AD가 쓰고, 승인 시점 sha256을 provenance에 기록(`--expect-hash` 대조 — 빌더가 색을 추가해 합법화하는 최후 수단 차단):
```json
{ "colors": { "base": [{"hex":"#…","role":"neutral|brand|semantic"}],
    "derived": [{"name":"glass","formula":"#FFFFFF @ .7 blur(20px)","resolved":"rgba(255,255,255,0.7)"}],
```

## 8b. 재현 시험 체크리스트 (Tier-R 번들 완전성 — P1 통과 조건)

번들이 리드 자격을 얻으려면: ① tree 1440/390 양쪽 존재, scrollHeight 실제 페이지와 일치 ② 섹션 분할이 눈으로 본 섹션 수와 ±1 ③ @keyframes 수확(0개면 CSS 수확 실패 의심) ④ 자산 매니페스트에 표시 rect 결합률 ≥50% ⑤ record에 호버 또는 리빌 타임라인 ≥1 ⑥ 재현 불가 목록 명시(WebGL·로그인 뒤 화면·서버 데이터). **완전성의 최종 기준은 재현 시험이다: IR만으로 원본을 오차 밴드 내 재건축→capture 대조 통과 시 `ir.json.reproduction.stamp`에 기록.** 스탬프 실패는 계기 결함 신호 — 문서가 아니라 계기를 고쳐라.

## 8c. 잔존·divergence 게이트 (신종 사고 "덜 치환된 클론"의 방어선 — 격하 금지)

- **기계부(P6)**: ⓐ 리드 팔레트 잔존 — 리드 색은 tokens.json에 없으므로 conform 위반으로 자동 검출 ⓑ verbatim 잔존 — 출하 코드에서 리드 CSS 리터럴(고유 클래스명·시그니처 값 조합) grep = 0 ⓒ 자산 해시 — 번들 자산과 출하 자산의 해시 교집합 = 0
- **사람부(P7)**: 신선한 패널에게 최종 캡처만 주고 "이 페이지가 참고한 원본 레퍼런스를 특정할 수 있는가" — 특정되면 실패. 구조 차용은 업계 보편이나 **정체는 남으면 안 된다.**
- provenance.md는 transform ledger로: 유지한 구조 요소·제거한 시그니처를 전수 기록(감사 가능성).

## 7c. AI-티 시각 채점 — 섹션별 철거 판정 (P7 필수, 마지막 눈)

기계 게이트를 전부 통과해도 눈에는 AI스러울 수 있다("티 0인데 허접" 사고). 그래서 마지막 판정은 사람의 눈 프로토콜이다:

- **판정자**: 신선한 컨텍스트 에이전트 1인. **스펙·브리프·제작 과정을 보지 않는다(블라인드)** — 입력은 섹션별 스크린샷(데스크톱+모바일, detect 스캔의 섹션 클립 재사용)뿐.
- **채점**: 섹션마다 AI-스러움 역척도 1~5점. 5=사람이 기획한 실서비스로 보임 / 3=템플릿 냄새 / 1=명백한 AI 생성물. 근거는 픽셀로 지목(어느 부위가 왜). 참고 축: 시각 앵커 실재(실이미지·아이콘·수치 vs 텍스트 벽), 클리셰 패턴, 콘텐츠 실질(측정값·고유명사 vs 서술문), 제네릭함("이 섹션만 보고 무슨 서비스인지 알겠는가").
- **철거선: ≤3점 = 해당 섹션 완전 삭제 후 재단조.** 수리·미세 조정 금지 — 철거다.
- **재단조 규칙**: 같은 방식의 재제출 금지. 치환 전략을 최소 1축 교체해야 한다 — ⓐ 시각 앵커 교체(텍스트→주석 이미지/실캡처/아이콘 세트) ⓑ graft(mapping.md의 세컨더리 레퍼런스 골격으로 교체) ⓒ 카피 각도 교체(facts의 다른 사실로). 재단조 후 재채점.
- **2연속 철거 = AD 콜백**: 섹션 자체가 문제다 — 콘텐츠 예산(§2d)에 따라 정직한 생략 또는 섹션 재설계. 세 번째 같은 시도는 없다.
- 통과선: **전 섹션 ≥4점**. 점수표는 `_forge/qa/ai-score.md`에 섹션별 점수+픽셀 근거로 기록.

## 7d. 매력 채점 — "출하 가능"과 "사고 싶다"는 다른 시험이다 (P7 필수)

실전 사고: 전 게이트 통과("출하 가능") 페이지가 블라인드 디자이너 평가에서 44/100, 경쟁사는 82·92. 완성도 게이트는 깨짐·정렬·가독성을 재고, 욕망은 아무도 재지 않았다.

- **판정자**: 블라인드 디자이너 에이전트 2인(제작 과정·스펙 모름) — ① 아트디렉션 관점 절대 채점 /100 ② 경쟁 2종(인터뷰·AD가 지정, 라이브러리 문서 활용) 대비 상대 채점 /100.
- **통과선: 절대 ≥70 그리고 경쟁 최고점 대비 −20 이내.** 미달 시 섹션 수리(P8)로 처리 금지 — **중심 장면·방향 자체의 재설계**로 AD 콜백(P2로 회귀).
- 채점 근거는 반드시 "무엇을 버려야 하는가" 목록을 포함(추가 목록만 내는 평가는 반려).
- 기록: `_forge/qa/desire-score.md`.
