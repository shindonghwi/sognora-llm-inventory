## 1.0.0 — 2026-08-17 (아키텍처 전환: 생성 → 변환. 하브루타 3라운드 합의)

실전 5회 전패 + "그대로 카피할 만큼의 정보가 없다"는 지적으로 전면 재설계. 진단 두 겹: 산문 규칙은 실행 에이전트를 구속하지 못하고(토큰 13개 선언한 런이 hex 32개 사용, keyframes 0), 손 스펙은 페이지의 수천 미시 결정을 못 담는다 — 생성에서 스펙의 침묵은 LLM 사전분포(=AI 티)로, 변환에서는 레퍼런스 실측값으로 채워진다.

- **변환 아키텍처(P0~P9)**: 리드를 재현급 실측(번들→IR)해 골격을 세우고 토큰·카피·자산·시그니처를 치환. 빌더의 일은 창조가 아니라 전사+치환
- **계기 5종 신설·검증**: `bundle.mjs`(DOM+computed 트리·CSS·@keyframes 99개 수확 확인·자산 매니페스트 — 로컬 캐시 전용·커밋 금지), `record.mjs`(rAF 타임라인·오버슈트 감지·CDP 리스너 인벤토리), `ir.mjs`(커밋 가능한 측정 사실 증류 — meshy 9섹션 분할 검증), `conform.mjs`(토큰 준수: 소스 린트+렌더 전수, alpha 정책·어휘 예산·해시 변조 방지 — nolpop 탄생 테스트에서 위반 10종 검출), `behavior.mjs`(engineering.json 선언→실측 검증 + no-JS/reduced-motion 가시성)
- **강제 지도(enforcement map)**: 모든 의무에 판정자 명시 — 판정자 없는 규칙은 추가 불가
- **잔존·divergence 게이트**: 신종 사고 "덜 치환된 클론" 방어 — 리드 팔레트·verbatim·자산 해시 잔존 0(기계) + "원본을 특정할 수 있는가" 판정(패널)
- **2단 라이브러리**: Tier-S 요약 18종 유지, Tier-R 번들은 리드 지목 시 온디맨드 수집·로컬 캐시(공개 저장소 커밋은 재배포 — 절대 금지)
- **정직 고지**: 변환은 바닥을 사주지 천장을 사주지 않는다(치환 취향은 AD·패널 몫), 번들 확보 불가 시 생성 폴백은 등급 캡 B, 리드 회전(3회 내 재사용 금지)

## 0.18.1 — 2026-08-17 (슬롯 우선 — "이미지가 지맘대로" 사고 대응)

실전 사고: 이미지 생성이 들어갈 자리의 크기·종횡비를 모른 채 돌아 슬롯과 안 맞는 이상한 자산이 반복 생산됨. 수정:

- **섹션 스펙의 자산 슬롯을 완전 명세로**: 렌더 치수(데스크톱·모바일)·종횡비·object-fit·라운드·주변 배경색·투명 여부·오버레이 안전영역
- **슬롯 우선 철칙**: 슬롯 명세 없으면 생성 없다. 생성 해상도 = 슬롯 ×2, 종횡비 고정, 프롬프트에 구도 명시
- **인슬롯 핏 검증 루프**: 실제 슬롯에 렌더→캡처→확인(레터박스 0·피사체 크롭 훼손 0·톤 정합), 3회 실패 시 슬롯 재설계 콜백
- **게이트키퍼 입력을 인슬롯 렌더 캡처로 변경** — 사람은 이미지를 페이지 안에서 본다

## 0.18.0 — 2026-08-17 ("정적 HTML 끄적임" 사고 대응 — 엔지니어링 계약 신설)

실전 사고: 라이브러리의 인터랙션·JS 실측(framer 스프링 175건, toss IO 리빌, meshy 유리+글로우, jobber mask 전환)이 "읽을거리"로만 존재하고 빌드 계약에 없어, 정적 섹션만 쌓아도 전 게이트 통과. 수정:

- **engineering.md 필수 산출물(§2⑦)** — 엔지니어드 컴포넌트 인벤토리, **하한 3개**(히어로 인터랙티브 + 스크롤 연출 + 시그니처 마이크로 인터랙션), 각각 라이브러리 출처·상태 전이표·수용 기준
- **동작 증거 게이트(§7)** — 항목별 probe 수치 또는 조작 전후 캡처 쌍 없이 완료 선언 불가. A등급 조건에 포함
- 빌드 산출물 정의 강화 — 프로젝트 실제 스택의 컴포넌트 코드만 인정, 일회용 정적 HTML 불인정. 개폐류 0ms 금지(120~150ms 하한)
- 세계관에 명문화: "랜딩은 소프트웨어다 — 레퍼런스의 절반은 엔지니어링이다"

## 0.1.2 — 2026-08-17 ("왜 meshy가 안 나오나" 대응)

- **방향 면제 조항 신설(forge-rules §0)** — meshy 실측(🔴 8개인데 산출물 109개가 정당화)이 근거. 방향이 명시 채택한 티는 exemptions.md 선언으로 "채택된 스타일" 처리. 단 QF·KO·AS2·가짜 증거는 면제 불가, 정당화 조건(예: 갤러리 밀도) 미충족 시 무효

- I클래스에 "예시 산출물 갤러리" 명시 허용(생성 가능 — "예시" 정직 라벨 필수, 고객 실적 위장 금지)

## 0.1.0 — 2026-08-16

- 신설. sg-landing-craft를 폐기하고 하브루타 재설계 — 사용자 판정 "스킬이 레퍼런스 퀄리티를 못 따라간다"의 원인 규명에서 출발:
  - 레퍼런스 퀄리티의 실체 = 성숙한 시스템 + **증거 재고**(디자인 불가·수집만 가능) + 측정된 실행
  - 기존 스킬은 검수 80%/제작 20%였고, 측정과 판정 사이에 빌드를 스펙에 묶는 기계 장치가 없었다
- 10페이즈 공정(파일 계약으로 런타임 중립): 인터뷰(+증거 인벤토리·리드 레퍼런스) → facts+숙제 브리프 → 아트디렉터(단일 결정권·리듬은 리드 1개 소유·섹션 스펙 수치화·provenance) → 자산 스프린트(E/P/I 클래스·픽스처 시딩·이미지 게이트키퍼 전진 배치·성능 예산·og) → 카피(소리 내어 읽기) → 섹션 빌드+**자기 diff 게이트**(스펙이 원본) → AD 일관성 검수 → 계기 검수(모바일 별도 구도) → **패리티 채점**(선호 판정 금지 — 5축 절대 채점, 레퍼런스 -1 이내) → 라운드 2(실패 섹션 정밀 수리) → 배포 체크리스트
- 핵심 금지: 가짜 증거(E클래스 생성) 절대 금지 · 시그니처 복제 금지(숫자만 차용, provenance 감사) · 문서 없으면 코드 없다
- 하브루타에서 기각된 내 초안: side-by-side 블라인드 선호 판정(장르 편향·수렴 압력), 레퍼런스 블렌드 규칙(프랑켄슈타인), 모션 엔지니어 역할, 자산 절대주의(데드락)
- 승계: 라이브러리 18종(측정 캐시로 승격)·detect/probe/rules-lib·directions(history 차별)·benchmarks·페르소나/인터랙션 평가
