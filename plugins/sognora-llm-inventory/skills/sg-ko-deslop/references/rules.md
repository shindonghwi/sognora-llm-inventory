# sg-ko-deslop — 룰북 (SSOT)

> 사용자가 직접 「AI 슬롭」이라고 짚은 표현(P·B·C)과 장르, 오탐, 눈으로 볼 것을 적는다. 일반 한국어 AI 흔적(G)은 `patterns.md`. 검사기 `scripts/scan.py`의 규칙 번호와 같다. 규칙을 고치면 여기, `scan.py`의 `RULES`, `tests/fixtures/cases.json`을 함께 고친다.

## 장르

장르마다 켜는 규칙과 고치는 방향이 다르다. 검사기에 `--genre`로 넘긴다. 안 넘기면 경로로 짐작하고, 출력에 「(경로로 짐작)」이 붙는다.

| 장르 | 대상 | 켜는 규칙 | 고치는 방향 |
|---|---|---|---|
| `제안서` | 공공·기업 제안서, 사업계획서, 보고서 원고 | P1~P6·P8~P10, G 전부 | 쪽 제목과 제목 밑 한 줄, 목록·표 칸·카드는 개조식 명사형으로 끝낸다. 「~합니다」는 마침표로 끝나는 본문 문단에만. 기능은 「무엇을 산출하는가 + 숫자 근거」로 쓴다. 조작법은 뺀다 |
| `발표` | 발표자료 장 제목과 글 | 제안서와 같다 | 장마다 큰 제목 한 줄(개조식 명사구) + 그림 하나 또는 큰 숫자 하나 |

| `영상` | 유튜브·쇼츠 내레이션, 자막(.srt·.vtt), 영상 제목·영상 설명 | P1·P2(⚪·🟡), B3(⚪), G | 구어체는 허용한다. 약속·카피 규칙은 끈다. 영상 전용 규칙은 아직 없다(사용자가 짚으면 더한다). 댓글·채널 설명은 `댓글` |

| `댓글` | 유튜브 채널 댓글, 답글, 채널 설명 | C1~C6, P2, G(대구·쉼표 ⚪), P1·B3(⚪) | 시청자가 단 것 같은 한 줄 반응. 설명·소개·날짜 나열·구독 부탁 없이 꽂힌 말 하나에 대한 감상만 쓴다. 어미는 보지 않는다. 약속·개조식 규칙은 끈다 |

## P1 조작 안내 말투 · 🔴(제안서·발표·대본) · 🟡(화면)

읽는 사람에게 버튼 쓰는 법을 알려 주는 말투다. 앱 첫 화면 안내문처럼 들린다. 평가위원과 사용자가 보려는 것은 무엇을 산출하고 근거가 무엇인지다.

- 걸리는 말: 「버튼을 누르고」 「누르면」 「고르면」 「선택하면」 「들어가기」 「들어가서」 「둘러보기」 「해 보기」 「눌러 볼 수 있는」 「살펴보세요」
- 사용자 지적(2026-11-02, 제안서 쪽 제목 「역할 버튼을 누르고 3분 안에 화면 네 개를 봅니다」 「역할 버튼으로 들어가기」를 보고): 「이런말안하게하면안되나. 이거 ai슬롭인데」

| 전 | 후 |
|---|---|
| 지역·노선·기간을 고르면 지표 7개를 다시 계산합니다 | 기간·지역·노선·운영사별 지표 7개 산출 |
| 노선 순위를 누르면 그 노선만 봅니다 | 노선별 호출 순위 |
| 역할 버튼으로 들어가기 | 시연 사이트 접속 |
| 3분 둘러보기 | 시연 순서 |

예외: 사용 설명서·런북처럼 조작 순서 자체가 내용인 문서. 그때도 「확인해 보세요」 같은 빈 권유는 뺀다.

## P2 숫자 포장·쉬움 과장 · 🔴(제안서·발표·대본) · 🟡(영상·화면)

내용 없이 가볍고 빠르다는 인상만 주는 숫자와 말이다.

- 걸리는 말: 「3분 안에 화면 네 개」 「단 3초 만에」 「클릭 한 번으로」 「한눈에」 「손쉽게」 「누구나 쉽게」
- 숫자는 측정값이나 약속일 때만 쓴다(「1년 치 365만 건에서 0.065초」 「1급 장애 4시간 안에 복구」). 「4시간 안에 복구」는 약속(SLA)이라 P2가 아니다.

## P3 서술문 제목 · 🔴(제안서·발표) · 🟡(화면)

쪽 제목·장 제목·표 제목을 「~하고, ~합니다」 문장으로 쓰는 것. 사용자가 짚은 제안서는 38쪽 제목이 전부 이 틀이었다.

- 공공 제안서 제목은 명사형이다: 「시연 사이트 접속」 「시스템 구성」 「품질 검사 기준」 「이관 절차」. 제목 밑에 주장 한 줄(헤드 메시지)을 둘 때도 명사형으로 끝낸다(P9).
- 「쉼표 + 짧은 서술문」 카피 제목은 더 나쁘다(「세부 요구 39개 중 25개, 이미 동작합니다」). 사용자 지적(2026-10-30): 발표 장 제목은 개조식 명사구.
- 화면: 빈 상태는 한 줄 명사형(「받은 배치 없음」). 「~이 없습니다」 문장은 쓰지 않는다. 알림(「저장했습니다」)과 오류 제목(「불러오지 못했습니다」)은 문장이어도 된다.
- 예외: 마지막 장 「감사합니다」.

## P4 구어체 카피 동사 · 🔴(제안서·발표·대본·화면)

사용자가 2026-10-30에 콕 집어 금지한 말: 「이미 동작합니다」 「지금 돌아갑니다」 「762건 잡았습니다」 「1년 치를 넣고 재 봤습니다」 「숫자로 약속합니다」. 같은 결로 「만들어 왔습니다」 「해냈습니다」, 2026-11-02 표지의 「운행 기록을 넣어 두었습니다」(「~해 두었습니다」). 대본은 평이한 발표체로 쓴다: 「구현되어 있습니다」 「검출되었습니다」 「시험했습니다」.

## P5 모호한 약속 · 🔴(제안서·발표·대본)

공공 제안서는 대개 입찰 공고나 제안요청서에 「기술제안서는 계약서와 같은 효력」 조항이 있고, 작성 지침에 「~가 가능하다 같은 모호한 표현은 불가능으로 평가」라고 적는다. 해당 사업 문서에서 조항을 찾아 보고에 적는다.

- 걸리는 말: 「가능합니다」 「검토하겠습니다」 「노력하겠습니다」 「최대한」 「최선을 다하겠습니다」
- P5b(🟡): 「할 수 있습니다」 「예정입니다」 「도모」. 약속이면 단정으로(「4시간 안에 복구합니다」), 약속할 수 없으면 문장을 뺀다.
- **「할 수 있다」를 단정으로 바꾸면 새 약속이 생긴다.** 이 스킬은 바꾸지 않고 보고의 「사람 검토」 칸에 남긴다.

## P6 「1인·혼자」 · 🔴(제안서·발표·대본)

제안서·발표에서 수행 인력을 「1인」 「혼자」로 쓰지 않는다. 역할과 투입 인력·참여율로 쓴다(「책임 PM 참여율 100%」). 「1인당」은 해당 없다.

## P7 화면이 자기를 해설 · 🟡(화면)

화면 문구가 「~입니다. ~하면 ~이 바뀝니다」처럼 화면을 설명한다. 제목·표 머리·범례·축 이름이 이미 설명이다. 사용자 지적(2026-10-30): 「문구도 전부 너무 많음, ai슬롭디자인, 슬롭문구, 한국인처럼」.

검사기는 메시지 키 이름(confirm·error·done·saved …)으로 알림·오류·확인 문구를 거른다.

## P8 화살표 대응 제목 · 🟡(제안서·발표·화면)

「바라는 것 → 이 제안의 답」 「기술 과제 → 해법」. 같은 틀(번호 원 4줄 → 화살표 → 답 카드)을 쪽마다 반복하면 템플릿처럼 보인다. 표 하나(「요구 / 대응 / 쪽」)로 쓴다.

## P9 개조식 자리의 「~합니다」 · 🔴(제안서·발표)

표지, 기능 카드, 목록 항목, 표 칸, 제목 밑 한 줄, 캡션을 「~합니다」 문장으로 쓰는 것. 기능 넷을 「~검사합니다」 「~기록합니다」 「되돌립니다」로 늘어놓으면 서비스 홍보 페이지의 기능 소개가 된다. 공공 제안서의 개조식 자리는 명사형으로 끝낸다.

- 사용자 지적(2026-11-02, 제안서 표지를 보고): 「1페이지 모든 글;; ~~검사합니다. ~~합니다. ~까지 기록합니다. 되돌립니다. … 전부다 aislop이네」
- 검사기: 목록 항목·표 칸이 「~니다」로 끝나거나, 마침표 없는 줄이 「~니다」로 끝나면 잡는다. 마침표로 끝나는 본문 문단은 잡지 않는다.

| 전 | 후 |
|---|---|
| 운영사 3곳의 서로 다른 형식을 표준 18항목으로 바꾸고 12개 규칙으로 검사합니다 | 운영사 3곳 형식의 표준 18항목 변환, 12개 규칙 검사 |
| 측정값으로 자동 판정하고, 보완 요청부터 적합 결정까지 기록합니다 | 측정값 자동 판정, 보완 요청~적합 결정 이력 |
| 대기시간 산식을 미리 보고 적용하고, 이력에서 되돌립니다 | 대기시간 산식 미리보기·적용·이전 판 복원 |
| 모든 행을 12개 규칙으로 검사하고 기준을 넘으면 경보합니다(제목 밑 한 줄) | 전 행 12개 규칙 검사, 기준 초과 시 경보 |

예외: 대본·영상·보고·댓글은 말이나 대화라 「~합니다」가 맞다. 화면 알림·오류 문구는 P3·P7의 예외 그대로.

## P10 풀지 않은 업무 용어 · 🔴(대본) · 🟡(제안서·발표·영상·보고·글)

처음 읽는 한국 사람이 바로 못 알아듣는 업무 용어와 한자어 묶음. 평가위원은 알아도, 그 글을 말로 옮겨야 하는 사람(대표·발표자)과 처음 읽는 사람은 못 알아듣는다. 쉬운 말로 풀거나, 처음 나올 때 한 번 풀어 쓴다. 대본은 소리 내어 말하는 글이라 🔴다.

- 사용자 지적(2026-11-03, 제출한 제안서와 발표 대본을 보고): 「한국어인데 뭐라는지 하나도 모르겠네」, 「증감과 산식버전은또뭐냐 왜케 말을어렵게」, 「글도 한국인이 하나도 못 알아보는 거임」
- 검사기: 이때 걸린 말(증감, 산식, 원시 DB, 배치 오류율, 인수 기준, 런북, 적재, 「경계 N개」, 「산출합니다」)만 잡는다. 목록에 없는 어려운 말은 「눈으로 볼 것」에서 본다. 화면 메뉴 이름(「산식 관리」)은 ⚪로 둔다.

| 전 | 후 |
|---|---|
| 지표마다 앞 기간 대비 증감과 적용 산식 버전을 함께 표시합니다 | 지표마다 지난 기간보다 얼마나 늘고 줄었는지, 어떤 계산식으로 낸 숫자인지 함께 나옵니다 |
| 오류 행은 분석에서 제외하되 원시 DB에는 남깁니다. 배치 오류율이 2%를 넘으면 경보합니다 | 틀린 줄은 통계에서 빼지만 원본은 지우지 않습니다. 한 번에 받은 묶음에서 틀린 줄이 2%를 넘으면 경보가 울립니다 |
| 운영사 3곳의 가상 운행 기록 98일 치를 적재했습니다 | 가상 운영사 3곳의 운행 기록 98일 치를 넣었습니다 |
| 인수 기준은 1급 결함 0건입니다 | 납품을 받는 기준은 1급 결함 0건입니다 |
| PM이 응답하지 않으면 담당자가 런북 5종으로 재기동합니다 | PM과 연락이 닿지 않으면 담당자가 복구 설명서 5종을 보고 서버를 다시 켭니다 |

## 보고(B) — 작업 보고·채팅 답변

사용자가 2026-11-02 영상 작업 세션의 보고를 붙여 보이며 이런 글에도 이 스킬을 쓸 수 있는지 물었다. 그 글에서 뽑은 표지다. 원문 일부:

> 미리보기는 일부러 낮은 품질로 뽑긴 했지만, 그것만으로 넘기지 않고 어디가 문제인지 직접 확인할게요. …
> 화질이 나빴던 건 미리보기의 낮은 샘플 수만이 아니라 제 설계 탓도 컸습니다. 원인을 찾아 고쳤어요. (아래에 같은 원인을 표로 다시)
> … 쓰기 전에 빈틈부터 실험으로 메울게요. … 이게 맞으면 이야기의 결말이 나옵니다.

| ID | 표지 | 심각도 | 고치는 법 |
|---|---|---|---|
| B1 | 성실함 예고: 「그것만으로 넘기지 않고」 「직접 확인할게요」 「빈틈부터 메울게요」 「꼼꼼히」 | 🟡 | 할 일을 예고하지 않는다. 한 일과 결과를 쓴다(「같은 장면을 원본 크기로 잘라 비교해 보니 초점 범위와 샘플 수가 원인이었습니다.」) |
| B2 | 자책 고백: 「제 설계 실수」 「제 설계 탓도 컸습니다」 「제가 놓쳤습니다」 | 🟡 | 원인을 사실로 한 번 쓴다(「초점 범위를 좁게 잡아 화면 대부분이 흐렸습니다」). 「A만이 아니라 제 탓도」 반전(G-C8)과 같이 지운다 |
| B3 | 예고편 훅: 「이게 맞으면 ~가 나옵니다」 | 🟡 | 실험할 것과 그 결과로 정할 것을 그대로 쓴다 |
| B4 | 개수 예고: 「두 가지 생겼습니다」 「세 가지가 문제입니다」 「쓰는 사람은 셋입니다」 | 🟡 | 개수를 먼저 말하지 않는다. 바로 내용을 쓴다(「운영사마다 데이터 모양이 다르고 인증도 사람이 합니다」) |
| B5 | 문서식 답변: 채팅 답에 `##` 제목, 항목마다 「**굵은 머리말:**」 | 🟡 | 말로 하듯 문단으로 쓴다. 표는 비교할 값이 있을 때만 |
| 눈 | 같은 설명 반복: 문단으로 한 번, 다시 요약으로 한 번, 표로 또 한 번 | 🟡 | 하나만 남긴다. 표가 있으면 문단을 지운다 |
| 눈 | 남은 질문 되풀이: 앞에서 물은 것을 끝에서 다시 묻고 요약에서 또 묻는다 | 🟡 | 맨 끝에 한 번 |
| 눈 | 끊어 치기: 모든 문장을 짧은 「~입니다.」로 끊어 번역한 목록처럼 읽힌다 | 🟡 | 이어지는 말은 「~고」 「~는데」로 잇는다. 말하듯 쓴다 |
| 눈 | 번역투 지시어: 앞 문장을 「이 ~ 시스템을」처럼 「이」로 받는다 | 🟡 | 한 문장으로 합치거나 「그걸」로 받는다 |

B4·B5와 눈 두 줄은 사용자가 2026-11-03 사업 설명 답변(제목 8개, 굵은 머리말 8개, 「셋입니다」식 예고 3번)을 받고 짚었다: 「응답할떄도 한국어처럼말해라」. 업무 글(제안서·발표)의 개조식과 다르게, 채팅 답변은 한국 사람이 옆에서 말해 주듯 쓴다.

## 댓글(C) — 유튜브 댓글·채널 설명

사용자가 2026-11-02~03 쇼츠 채널의 댓글과 채널 설명 후보를 보고 짚었다. 2026-11-03에 형식이 바뀌었다. 여러 줄 해설 댓글을 버리고 시청자가 단 것 같은 한 줄 반응을 쓴다. 사용자 원문(여러 줄 해설 댓글을 보고): 「왜케 ai같지」 「간결하잖아」.

| ID | 표지 | 심각도 | 사용자 원문 | 고치는 법 |
|---|---|---|---|---|
| C1 | 소개 문장: 「~물은 장면이에요」 「~다룬 영상입니다」 | 🔴 | 「너무 설명충같은데. 좀 한국인스럽게못하나」 | 소개를 지우고 꽂힌 말 하나에 대한 감상만 쓴다 |
| C2 | 머리말: 「배경은」 「용어는」 「배경을 말씀드리면」 | 🔴 | 같은 지적 | 앞뒤 사정과 용어 풀이를 쓰지 않는다 |
| C3 | 날짜·회의 나열: 「10월 27일 외교부 국감에서」 | 🟡 | 같은 지적 | 날짜와 회의 이름을 덜어낸다 |
| C4 | 안내문 톤: 「~장면을 올립니다」 「~채널입니다」 「담았습니다」 「끝까지 보세요」 | 🔴 | 「따지는장면을올린다는건 별로인데?」 | 채널이 무엇을 올리는지 안내하지 않는다 |
| C5 | 한 줄이 김: 공백 포함 60자 초과(링크·해시태그 제외) | 🟡 | 「간결하잖아」 | 한 문장, 30자 안팎으로 줄인다 |
| C6 | 구독·좋아요·알림 부탁: 「좋아요 구독 알림까지 해 주시면 감사하겠습니다」 | 🔴 | 「좋아요, 구걸하지말자」 | 그 줄을 통째로 지운다 |
| 눈 | 여러 줄 배경 설명 | 🟡 | 「왜케 ai같지」 | 한 문장으로 줄인다. 검사기는 줄마다 보고 댓글의 경계를 모르므로 줄 수는 사람이나 호출하는 쪽이 센다 |
| 눈 | 편들기 해설·조롱, 최근 댓글과 같은 틀·끝맺음, 의견 묻는 말, 느낌표 연발 | 🟡 | 채널 규칙 | 뺀다 |

- 좋은 예(사용자가 참고로 고른 다른 채널의 실제 댓글): 「한마디 한마디가 아주 속이 시원하네요」 「늦게나마 정신차리셔서 다행입니다 ^^」 「우리들 세금을 월급으로 받아갈거면 ...신분 정확하게 밝혀야죠?」
- 나쁜 예: 짧은 줄로 나눈 배경 설명 여러 줄 뒤에 붙은 「좋아요 구독 알림까지 해 주시면 감사하겠습니다🙏」

- **말투는 보지 않는다.** 어미를 고르거나 통일하지 않는다. 「~네요」 「~입니다 ^^」 「~밝혀야죠?」 모두 정상이고, 존댓말 끝과 반말 끝이 섞여도 잡지 않는다.
- **C5 기준값**: 사용자 기준 「30자 안팎, 길어도 두 줄」의 두 줄 값으로 60자를 잡았다. 30자 안팎은 형식 목표이지 판정선이 아니다. 게시한 한 줄 댓글 46편(최장 55자)과 참고 예(최장 35자)는 넘기고, 예전 나쁜 예(62자)는 잡는다.
- **이모지**: 예외가 없다. 모두 G-C5(🟡)다. 「^^」는 이모지가 아니다.
- **게이트**: C3 처방은 날짜를 덜어내는 것이라, 이 장르의 게이트는 빠지기만 한 숫자를 ⚠️로 알리고 넘어간다. 바뀌거나 새로 생긴 숫자는 그대로 실패다.
- **영상 제목·영상 설명은 `영상`으로 본다.** 영상 설명은 장면을 소개하는 글이라 소개 문장을 금지하는 이 장르가 맞지 않는다. 사용자 좋은 예 「10월 27일 외통위 국감, ~ 붙은 장면 전체입니다.」도 영상 설명이다.

## 오탐 — 이건 슬롭이 아니다

- **가운뎃점 병렬**: 「기간·지역·노선·운영사」는 공문의 정상 표기다. 넷 넘게 늘어놓거나 제목에 쌓일 때만 줄인다.
- **개조식·표·번호 목록**: 제안서·보고서의 정상 형식이다.
- **합니다체 종결 반복**: 대본과 제안서 본문 문단(마침표로 끝나는 산문)은 「~합니다」로 끝나는 게 정상이다(일반 humanizer의 「종결어미 다양화」는 적용하지 않는다). 제안서의 개조식 자리는 P9다.
- **약속 시간**: 「1시간 안에 첫 보고, 4시간 안에 복구」는 SLA다(P2 아님).
- **한자어 공문 어휘**: 「착수·검수·하자보수」 같은 낱말 하나는 업계 용어다. 업무 용어를 묶어 쌓은 말(「인수 기준」 「적용 산식 버전」)은 P10이라 푼다.
- **「」 안의 말**: 금지어를 가리키는 문장(「『가능합니다』는 쓰지 않는다」)은 검사기가 건너뛴다.
- **대본·영상의 「~하고,」**: 말할 때 숨 쉬는 자리라 ⚪로 낮췄다.
- **판정 표지 🔴🟡**: 판정 결과를 적는 동그라미·네모는 이모지로 세지 않는다(✅ 같은 장식 이모지는 센다).
- **보고의 사실 고백 한 번**: 「제 설계 실수였습니다」가 원인 보고로 한 번 나오면 둔다. 같은 고백이 두 번이거나 「A만이 아니라」 반전과 붙으면 고친다.
- **댓글의 감상 「좋아요」**: 「이 말 좋아요」 「구독자」 「구독하고 갑니다」는 부탁이 아니라 C6에 걸리지 않는다.
- **댓글의 따옴표 말**: `"…"`, `'…'` 안은 영상 속 사람 말이라 문체 규칙에서 건너뛴다. 줄 길이(C5)에는 센다.
- **댓글의 「~ 만에」**: 「3분 만에 끝난 거임」이 장면의 사실이면 P2가 아니다. 남기고 이유를 적는다.

남긴 것은 보고에 이유를 한 줄 적는다.

## 눈으로 볼 것 (판정자: 에이전트)

검사기는 글만 본다. 제안서·발표자료는 PDF를 쪽 그림으로 떠서 넘겨 본다(`pdftoppm -r 60 -png <파일.pdf> <접두>`).

- **AI 생성 사진**: 노을·고속도로·도시 야경 같은 스톡풍 표지·배경. 표지는 실제 화면 캡처나 글자만으로.
- **홍보 페이지 같은 표지**: 공공 제안서 표지에는 사업명, 공고번호, 제출처, 날짜, 제안사만 둔다. 한 줄 카피, 번호 붙은 기능 목록, QR과 접속 안내, 사진을 얹으면 서비스 홍보 페이지 첫 화면이 된다(2026-11-02 사용자 지적).
- **같은 틀 반복**: 번호 원 + 화살표 카드, 큰 숫자 4칸 줄, 동그라미 타임라인, 화면 위 번호 원 + 아래 번호 설명이 거의 모든 쪽에 있으면 템플릿이다. 한 쪽에 하나, 내용에 맞는 형식(표·간트·구성도)을 고른다. 문장 제목 + 화면 캡처 + 번호 표지 + 번호 설명 + 큰 숫자 묶음 + 화살표 표가 38쪽 내내 이어진 제안서를 보고 사용자가 「포맷도 맘에 안 들고」라고 했다(2026-11-03). 포맷은 본문을 쓰기 전에 시안 한 쪽으로 확인받는다.
- **출처 없는 숫자·기준**: 발주처가 정하지 않은 개수·기준·역할(「표준 18항목」 「12개 규칙」 「지표 7개」)을 요구사항처럼 단정하면, 읽는 사람이 요구인지 제안인지 가리지 못한다. 처음 나올 때 「제안 안」이라고 밝히고 기대는 요구사항 번호를 붙인다(2026-11-03 사용자 「그게 필요하다는 건가 제안한 건가?」 「규칙도 지 맘대로 쓰고」).
- **말로 옮길 사람 시험**: 제안서·발표자료·대본은 그 글을 말로 옮길 사람(대표·발표자)이 문장마다 설명할 수 있는지 본다. 검사기가 통과해도 이 시험을 못 넘으면 고친다.
- **배지 반복**: 「실제 시연 화면」 「확대」 같은 같은 배지를 그림마다 다는 것(사용자가 짚은 제안서에서 31번, 27번). 캡션 한 번이면 된다.
- **장마다 바뀌는 강조색**: 초록·파랑·보라·주황이 장별로 바뀌는 것. 무채색 + 강조 한 색.
- **캡처 속 옛 디자인**: 화면을 고친 뒤 캡처를 다시 찍지 않으면 문서와 실제 화면이 어긋난다.
