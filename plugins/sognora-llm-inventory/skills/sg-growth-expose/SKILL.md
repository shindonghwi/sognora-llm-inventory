# sg-growth-expose — 노출 최적화 (웹 SEO+GEO · 앱 ASO)

> 이 파일 하나가 Claude Code와 Codex 양쪽에서 동작한다.
> 감사 체크리스트·리스팅 규격·금지 전술·판정 한계는 `references/rules.md`(SSOT).

## 철칙

1. **실행 = 적용 완료가 기본.** git 관리 프로젝트면 바로 수정한다(git이 안전망). git이 아니면 `.bak` 백업 후 수정. 지시에 "점검만/감사만"이 있을 때만 보고서로 끝낸다.
2. **대상은 스킬이 판별한다.** 웹/앱/둘 다를 사용자에게 묻지 않는다 — 프로젝트 신호로 판정하고(§1), 판정 근거를 보고에 한 줄 남긴다.
3. **프로젝트 로컬 스킬 우선.** 대상 레포에 자체 SEO 스킬(`.claude/skills/seo-audit` 등)이 있으면 웹 감사는 그쪽에 위임하고, 이 스킬은 로컬 스킬이 다루지 않는 층(GEO·ASO)만 보강한다. 같은 일을 두 벌로 하지 않는다.
4. **역효과 전술은 거부한다.** rules.md의 금지 목록에 해당하는 요청은 수행하지 않고 이유를 설명한다.
5. **성과를 단정하지 않는다.** 이 스킬이 보장하는 것은 "노출될 자격"(인덱스 가능·크롤러 가시·리스팅 완비)이지 순위·설치가 아니다. 보고서에 순위 상승을 약속하는 문장을 쓰지 않는다.
6. **무인 완주.** 되묻지 않는다. 예외는 측정 배선의 인증(Search/Play Console 자격증명 — 사용자만 줄 수 있음)뿐이며, 그마저도 없으면 그 항목만 "보류"로 표시하고 나머지를 완주한다.

## 절차

### 1. 대상 판별 (되묻기 금지)

cwd에서 신호를 읽어 판정한다. 근거는 rules.md §대상 판별.

| 판정 | 신호 예 | 작업 |
|---|---|---|
| **웹** | package.json(next 등) + 앱 신호 없음 | §2 |
| **앱** | `brand.yaml`의 `bundle_id`, android/·ios/·fastlane | §3 |
| **둘 다** | brand.yaml에 `web_domain` + `bundle_id` 모두 | §2 + §3 |
| **플릿** | 인자로 상위 폴더·레포 목록을 받음 | 레포별 §1부터 반복, 결과는 통합 표 1개 |
| **판별 불가** | 웹도 앱도 아님 | 무엇이 없어서 판별 불가인지 보고 후 종료 |

### 2. 웹 — SEO+GEO 감사 후 적용

1. **로컬 SEO 스킬 확인**: 있으면 웹 SEO 감사·수정은 그 스킬 절차로 위임 실행. 없으면 rules.md §웹 체크리스트로 자체 감사.
2. **GEO 층은 항상 이 스킬이 본다** (로컬 스킬이 안 다루는 영역): robots.txt의 AI 크롤러(GPTBot·ClaudeBot·PerplexityBot 등) 허용, 핵심 페이지 SSR 가시성(JS 없이도 본문이 있는가), 추출 적합 구조(Q&A 헤딩·표·구조화 데이터).
3. **적용**: 발견 항목을 심각도순으로 수정. 수정 후 `build`(가능하면 `type-check`·`lint`)가 통과해야 완료다 — 깨진 채로 끝내지 않는다.
4. 다국어 프로젝트면 로케일별 메타·hreflang 정합까지. 문구는 메시지 파일 관례를 따른다(하드코딩 금지).

### 3. 앱 — 스토어 리스팅 생성

1. `brand.yaml`(앱명·번들ID·도메인)과 앱의 실제 기능(라우트·features·메시지 파일)을 읽어 **근거 있는 키워드 후보**를 만든다 — 앱에 없는 기능을 리스팅에 쓰지 않는다.
2. rules.md §리스팅 규격대로 **지원 로케일별** 타이틀·짧은 설명·전체 설명·키워드를 생성한다.
3. 산출은 레포의 리스팅 관례 위치(fastlane metadata 등)가 있으면 거기에, 없으면 `store-listing/{locale}/`에 파일로 쓴다.
4. **스토어 제출은 하지 않는다** — 업로드는 사람의 일이다. 생성물 끝에 "검수 포인트"(과장 표현·금지어·로케일 어색함 후보)를 표로 붙여 검수를 빠르게 한다.

### 4. 측정 배선 (가능한 경우만)

Search Console·Play Console 연동이 이미 있으면 노출·클릭 데이터를 회수해 다음 실행의 우선순위에 쓴다. 자격증명이 필요한데 없으면 설정 방법 한 줄만 남기고 보류 — 완주를 막지 않는다.

### 5. 보고 1회

한 줄 상태(판정 대상 / 발견 N건 / 적용 N건 / 보류 N건) + 변경 파일 목록 + 검수 포인트(앱) + 보류 항목과 이유. **"순위가 오를 것"이라는 약속 없이**, 무엇이 노출 자격을 얻었는지만 말한다.

## 옵션

- `점검만` / `감사만` — 수정 없이 보고서만
- `웹만` / `앱만` — 판별을 무시하고 한쪽만
- `로케일: en,ko` — 리스팅·메타 생성 로케일 한정 (기본: 프로젝트 지원 로케일 전부)
