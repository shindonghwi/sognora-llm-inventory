# sg-growth-expose — 노출 최적화 (웹 SEO+GEO · 앱 ASO)

> 이 파일 하나가 Claude Code와 Codex 양쪽에서 동작한다.
> 감사 체크리스트·리스팅 규격·금지 전술·판정 한계는 `references/rules.md`(SSOT).


> **계기 위치** — 이 스킬은 사용자 프로젝트에서 도는데 계기는 플러그인 안에 있다. 상대경로 `scripts/…`는 거기 존재하지 않는다. 첫 실행에 한 번 잡고, 이후 모든 명령의 `$S`는 이 경로다:
> ```bash
> S=$(sg path sg-growth-expose 2>/dev/null) || S=$(ls -td ~/.claude/plugins/cache/*/*/*/skills/sg-growth-expose/scripts ~/.codex/plugins/cache/*/*/*/skills/sg-growth-expose/scripts 2>/dev/null | head -1)
> ```

## 철칙

1. **실행 = 적용 완료가 기본.** 단 **복원 지점을 먼저 만든다** — "git이 안전망"은 클린 트리일 때만 참이다. 더티 트리에서 수정하면 사용자의 미커밋 변경과 스킬 수정이 뒤섞여 되돌릴 수 없다.
   - 수정 전: `git status --porcelain`으로 확인 → **더티면 그 상태로 1회 커밋하거나(`chore: growth-expose 실행 전 스냅샷`) 작업 브랜치를 만든 뒤** 진행한다. 둘 다 불가하면 `.bak` 전수 백업.
   - 수정 후: 변경분을 **한 커밋으로 묶어** 되돌릴 지점을 남기고, 보고서에 그 커밋 해시를 적는다.
   - git이 아니면 `.bak` 백업 후 수정. 지시에 "점검만/감사만"이 있을 때만 보고서로 끝낸다.
2. **대상은 스킬이 판별한다.** 웹/앱/둘 다를 사용자에게 묻지 않는다 — 프로젝트 신호로 판정하고(§1), 판정 근거를 보고에 한 줄 남긴다.
3. **프로젝트 로컬 스킬 우선.** 대상 레포에 자체 SEO 스킬(`.claude/skills/<이름>` 또는 `.agents/skills/<이름>` — Claude·Codex 어느 쪽 폴더든)이 있으면 웹 감사는 그쪽에 위임하고, 이 스킬은 로컬 스킬이 다루지 않는 층(GEO·ASO)만 보강한다. 같은 일을 두 벌로 하지 않는다.
4. **역효과 전술은 거부한다.** rules.md의 금지 목록에 해당하는 요청은 수행하지 않고 이유를 설명한다.
5. **성과를 단정하지 않는다.** 이 스킬이 보장하는 것은 "노출될 자격"(인덱스 가능·크롤러 가시·리스팅 완비)이지 순위·설치가 아니다. 보고서에 순위 상승을 약속하는 문장을 쓰지 않는다.
6. **무인 완주.** 되묻지 않는다. 예외는 측정 배선의 인증(Search/Play Console 자격증명 — 사용자만 줄 수 있음)뿐이며, 그마저도 없으면 그 항목만 "보류"로 표시하고 나머지를 완주한다.

## 절차

### 1. 대상 판별 (되묻기 금지)

계기가 판정한다 — `node "$S/audit.mjs" --detect` (cwd 기준, 파일 존재 검사라 결정적. 판별 불가면 exit 1). 근거는 rules.md §대상 판별. 출력의 근거 줄을 보고에 그대로 옮긴다.

| 판정 | 신호 예 | 작업 |
|---|---|---|
| **웹** | package.json(next 등) + 앱 신호 없음 | §2 |
| **앱** | `brand.yaml`의 `bundle_id`, android/·ios/·fastlane | §3 |
| **둘 다** | brand.yaml에 `web_domain` + `bundle_id` 모두 | §2 + §3 |
| **플릿** | 인자로 상위 폴더·레포 목록을 받음 | 레포별 §1부터 반복, 결과는 통합 표 1개 |
| **판별 불가** | 웹도 앱도 아님 | 무엇이 없어서 판별 불가인지 보고 후 종료 |

### 2. 웹 — SEO+GEO 감사 후 적용

**계기가 판정한다** — `$S/audit.mjs`(의존성 0 — Node 내장 fetch·fs). 인자는 최소다: 필수는 URL 하나, 로케일은 sitemap에서 자동 감지, 산출물은 `.sognora/growth/qa/audit.json`.

```
node "$S/audit.mjs" --preflight          # 철칙 1 — 더티면 exit 2, 스냅샷 먼저
node "$S/audit.mjs" --origin <URL>       # 감사 → .sognora/growth/qa/audit.json (🔴 있으면 exit 1)
# … 수정 …
node "$S/audit.mjs" --origin <URL>       # 재감사: 🔴 0(특히 H1)인지 확인하고 보고
```

- 판정 `red|yellow|intent|note` × **처분 `fix`가 코드로 강제된다**: `auto`(수정) · `report-only`(보고만 — 렌더링 아키텍처 등) · `forbidden`(**훈련 봇 불가침**) · `intent`(코드에 명시된 제외 — 의도 확인 전 수정 금지).
- UA 원장은 `scripts/crawlers.json`. 행마다 **1차 출처·확인일·처분(fix)**이 붙어 있고 코드는 그 처분을 그대로 옮긴다. 확인일이 180일을 넘으면 감사가 `R0` 🟡로 스스로 알린다 — 낡음은 데이터가 드러낸다. CCBot은 "1차 미확인"으로 정직하게 표시돼 있다.
- **H1(hreflang 상호참조)이 최우선 검사다.** A→B면 B→A인지, 자기참조·x-default가 있는지 — `build` 통과로는 절대 안 잡히는 런타임 결함이고, 수정 후 재감사로 사후 검증까지 이 체크가 담당한다. sitemap 인덱스의 자식은 **전부** 읽는다(예전엔 5개로 잘라 로케일 6개 이상 사이트에서 H1이 거짓 🔴를 냈다).
- 임계가 휴리스틱인 항목(SSR 가시 텍스트 150/500자, title 60·description 160자)은 출력에 그렇게 명시된다. **길이는 표시 절단 관행이지 공식 제한이 아니다.**

1. **로컬 SEO 스킬 확인**: 있으면 웹 SEO 감사·수정은 그 스킬 절차로 위임 실행. 없으면 rules.md §웹 체크리스트로 자체 감사.
2. **GEO 층은 항상 이 스킬이 본다** (로컬 스킬이 안 다루는 영역): robots.txt의 AI 크롤러 처리(**계열별 처분은 rules.md §체크 9의 표를 따른다 — 훈련 봇은 불가침, 비구속 UA는 보고만**), 핵심 페이지 SSR 가시성(JS 없이도 본문이 있는가), 추출 적합 구조(Q&A 헤딩·표·구조화 데이터).
3. **적용**: 발견 항목을 심각도순으로 수정. 수정 후 프로젝트의 빌드 명령(`package.json` scripts의 build, 있으면 type-check·lint)을 실행해 exit 0이어야 완료다 — 깨진 채로 끝내지 않는다. 그 다음 `--origin` 재감사가 🔴 0이어야 한다(`build` 통과만으로 완료 선언 금지).
4. 다국어 프로젝트면 로케일별 메타·hreflang 정합까지. 문구는 메시지 파일 관례를 따른다(하드코딩 금지).

### 3. 앱 — 스토어 리스팅 생성

1. `brand.yaml`(앱명·번들ID·도메인)과 앱의 실제 기능(라우트·features·메시지 파일)을 읽어 **근거 있는 키워드 후보**를 만든다 — 앱에 없는 기능을 리스팅에 쓰지 않는다.
2. rules.md §리스팅 규격대로 **지원 로케일별** 타이틀·짧은 설명·전체 설명·키워드를 생성한다.
3. 산출은 레포의 리스팅 관례 위치(`fastlane/metadata/…`)가 있으면 거기에, 없으면 `.sognora/growth/store-listing/{locale}/`에 rules.md §리스팅 규격의 파일명으로 쓴다. 쓴 뒤 `node "$S/audit.mjs" --listing`으로 자수·필수 필드를 판정한다(스토어는 파일명으로 자동 판별, 필수 필드 누락은 🔴).
4. **스토어 제출은 하지 않는다** — 업로드는 사람의 일이다. 생성물 끝에 "검수 포인트"(과장 표현·금지어·로케일 어색함 후보)를 표로 붙여 검수를 빠르게 한다.

### 4. 측정 배선 (가능한 경우만)

Search Console·Play Console 연동이 이미 있으면 노출·클릭 데이터를 회수해 다음 실행의 우선순위에 쓴다. 자격증명이 필요한데 없으면 설정 방법 한 줄만 남기고 보류 — 완주를 막지 않는다.

### 5. 보고 1회

한 줄 상태(판정 대상 / 발견 N건 / 적용 N건 / 보류 N건) + 변경 파일 목록 + 커밋 해시 + 검수 포인트(앱) + 보류 항목과 이유. 보고서는 `.sognora/growth/report.md`에 쓴다. **"순위가 오를 것"이라는 약속 없이**, 무엇이 노출 자격을 얻었는지만 말한다. 금지 문구는 rules.md §판정의 한계.
