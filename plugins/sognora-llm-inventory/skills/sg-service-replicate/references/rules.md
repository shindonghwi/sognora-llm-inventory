# sg-service-replicate — 룰북 (SSOT)

> 관찰과 재현의 계약. Claude Code·Codex가 같은 파일을 읽는다. 내용 수정은 이 파일에서만 한다.

## 산출물 위치

대상 프로젝트에 기존 저장 형식이 있으면 따른다. 없으면 `.sognora/service/` 아래에 필요한 만큼 만든다.

- `scope.json`: `intent`(`observe`|`faithful`|`localize`|`new-plan`), 대상 URL, 여정, 로그인 범위, 허용된 외부 동작, 금지 사항, 결과물 위치
- `observations.json`: 관찰 항목
- `journeys.json`: 여정 항목
- `content.md`: 콘텐츠 명세
- `coverage.json`: 검증 셀
- `evidence/reference/`, `evidence/local/`: 원본·로컬 증거 파일

계정 개인정보·세션 토큰·쿠키는 저장하지 않는다. 화면 층을 sg-web-replicate로 진행하면 그 원장(`.sognora/replica/`)의 id를 참조하고 같은 측정을 복사하지 않는다.

## 관찰 항목

각 항목에 id, URL, 관찰 시각, 로그인 구분, viewport와 DPR, 사전 상태, 실행 조작, 관찰 결과, 증거 파일, 확실성을 연결한다. 확실성은 `observed`, `inferred`, `unverified`다. 파일을 채운 것만으로 검증 완료가 되지 않는다.

다른 시점의 간접 증거는 원래 조작을 입증하지 못한다. 스크린샷과 DOM 스냅샷의 viewport·시점이 다르면 하나의 측정으로 합치지 않는다. 이미지 내부 카피는 DOM 텍스트에 없더라도 실제로 확인한 출처를 연결한다. 스크롤바 폭이 포함된 측정값을 breakpoint 수치로 일반화하지 않는다.

## 여정 항목

시작 상태, 순서 있는 조작, 각 예상 결과, 분기 입력, 복귀·취소·새로고침, 외부 부작용 경계를 기록한다. 예:

| 상태 | 행동 | 다음 상태 | 복원/불확실성 | 확인 |
|---|---|---|---|---|
| 이름 | 가상 별명 입력 후 다음 | 날짜 질문 | 뒤로가기 미시험 | observed |
| 날짜 | 유효한 날짜 완성 | 시간 질문 | 자동 포맷과 자동 이동 | observed |
| 시간 | 시간 모름 | 성별 질문 | 재선택 미시험 | observed |
| 이메일 | 미제출 | 미확인 | 후속 전환 원인 미확정 | unverified |

가상 입력은 `testData`로 명시하며 사용자 사실로 저장하지 않는다. 서로 다른 분기·템플릿을 추정으로 채우지 않는다. 원인을 확정하지 못한 전환(예: 제출하지 않았는데 다음 단계로 넘어감)을 규칙으로 삼지 않는다.

## 콘텐츠 명세

각 블록에 역할, 순서, 길이/행 수, 화자·톤, 개인화 위치, 이미지/영상 slot과 비율, CTA 목적, 근거를 남긴다. 대체한 고유 문구는 의도적 차이로 기록한다. `localize`에서는 블록마다 `keep`(구조·순서·역할·경계)과 `swap`(캐릭터·그림·대사·브랜드)을 표시하고, `keep`으로 표시한 것을 구현에서 바꾸지 않는다. 리뷰·성과·인증은 실제 근거와 데모를 구별한다.

사업 기획 분석을 함께 할 때는 문장마다 출처 층을 적는다: `observed`(직접 본 것), `operator`(운영사가 글·인터뷰에서 밝힌 것 — 인과나 성과의 독립 근거가 아니다), `hypothesis`(우리 사업에서 검증할 것).

## 검증

각 `journey × viewport × state`에 원본 근거, 로컬 근거, 결과, 차이, 미확인 사유를 연결한다. 결과는 `pass`, `fail`, `unverified`, `excluded`를 쓴다. 원본을 보지 못한 상태를 로컬 fixture만으로 pass 처리하지 않는다.

- 콘텐츠: 정보 순서, 분기별 질문과 응답, 텍스트 밀도, 개인화 위치, 무료/유료 경계.
- 화면: 같은 조건의 캡처와 주요 영역 측정, 폰트, 이미지 비율·crop, 고정 영역, 가로 overflow, 모바일 포커스.
- 동작: 동일 입력의 전후 상태, 자동 이동·건너뛰기, 오류·빈 상태, 뒤로가기, 새로고침, 이어보기. 관찰하지 않은 시간값을 수치로 단정하지 않는다.
- 데이터: 계산·생성·fixture 모드 구분, 입력 변경에 대한 결과 일관성, 원본 API·결제 연결 부재.
- 실행: 대상 프로젝트의 build·lint·typecheck와 필요한 기능 검증. 통과한 검사는 새 변경이나 미해결 우려 없이 반복하지 않는다.

사용자가 수치 목표를 주면 그 기준으로 판정한다. 없으면 차이를 실제 측정값으로 보고하며 임의의 유사도 백분율을 만들지 않는다.

이 스킬의 판정자는 브라우저 증거 원장을 맡은 에이전트다. 결정적 스크립트 판정은 없다 — 여정과 콘텐츠는 서비스마다 구조가 달라 고정 규칙으로 잴 수 없기 때문이다. 그래서 증거 파일이 연결되지 않은 `pass`는 `unverified`로 되돌린다.

## Do-NOT

- 금지된 외부 동작(결제·구매 확정·유료 크레딧 사용·체험 구독 시작 등)을 "확인만" 하려고 실행하지 않는다.
- 사용자가 허용하지 않은 원본 계정의 데이터·프로필·설정 저장·삭제·초기화를 조사 편의로 실행하지 않는다. 허용된 변경은 `scope.json`의 허용 범위와 여정 항목에 기록한다.
- 접근하지 못한 유료 결과·비공개 프롬프트·계산 로직을 복구했다고 쓰지 않는다. 원본 결과 몇 개로 동일 알고리즘을 입증할 수 없다.
- `scope.json`의 `intent`를 스스로 올리지 않는다. 재현 요청을 새 기획으로 교체하지 않는다. 사용자가 사업성 판단을 요청하지 않았는데 재현 작업을 철회·보류·다른 사업 탐색으로 전환하지 않는다. 요청받은 판단에서도 차별화 부족·경쟁 과다·공개 수치 부재만으로 결론내리지 않고, 미확인 수치는 미확인으로 적는다.
- 특정 서비스의 조사 자료 원문(스크린샷·전문 카피·리뷰)을 이 스킬 폴더에 넣지 않는다. 조사 자료는 대상 프로젝트의 `.sognora/service/`에 둔다.

## 보고

조사한 경로·여정·로그인 범위, 구현한 부분, fixture 사용, 실제 재생한 시나리오, 남은 차이와 미접근 영역, 실행 방법을 짧게 제시한다. 지켜진 금지 사항(예: 결제 미실행)을 한 줄로 명시한다. 스킬 문법 검증은 실행·행동·시각 품질 검증과 별개다.
