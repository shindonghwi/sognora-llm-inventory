# sg-service-replicate — CHANGELOG

## 0.1.1 — 2026-11-11 (재현 요청이 새 기획·사업 보류 권고로 바뀌는 이탈 차단)

사고: 팔리는 서비스를 가깝게 따라 만들고 캐릭터·그림·대사만 달리해 작은 점유율을 노리는 과제에서, 세션이 신규 분기형 웹툰을 제안하고 독점적 차별화·검증된 CAC 부재를 이유로 사업 보류와 다른 사업 탐색을 권했다. 세션의 해석 오류지만 스킬도 막지 못했다 — 4절이 "차별화"와 "새 기획"을 기본 어휘로 썼고, 사례 문서가 "사업성이 자동으로 나오지 않는다"로 끝났으며, 요청 수준을 기록하는 자리가 없었다.

- `scope.json`에 `intent`(`observe`·`faithful`·`localize`·`new-plan`) 신설. "재현·따라 만들기·~처럼"은 `faithful`/`localize`이고 스스로 `new-plan`으로 올리지 않는다.
- 철칙 5 신설: 사용자가 정한 전략을 바꾸지 않는다. 검증된 형식을 따르는 작은 점유율 전략은 정당한 선택이다. 철회·보류 권고 금지는 "요청받지 않은 전환"과 "수치 부재만으로 내린 결론"에 한정한다 — 요청받은 근거 있는 사업성 의견은 막지 않는다.
- 4절의 기본 목적을 "재현할 때 무엇을 유지해야 하는가"로 바꾸고 유지할 것/교체할 것 정리를 산출물로 정했다. 경쟁 과다나 공개 CPC·CAC 부재만으로 철회·보류를 결론내리지 않고 미확인은 미확인으로 적는다. 새 기획의 품질 기준(고객 상황·광고 표현·장면 흐름·결과물 예시)은 `new-plan`에서 그대로 유지한다.
- 사례 문서의 해석 절을 "재현할 때 유지할 구조"로 고치고 마지막 문장을 새 분야로 옮기는 요청에만 걸리게 했다. rules.md에 `keep`/`swap` 표시와 Do-NOT 한 줄 추가. 트리거 "웹툰형 사주처럼 기획해줘" → "…만들어줘".

## 0.1.0 — 2026-11-11

- 최초 생성. Codex 개인 스킬(`service-experience-replica`)로 잘못 만들어졌던 것을 무기고 정식 소스로 편입했다.
- 이름을 `sg-<도메인>-<동작>` 규칙에 맞추고 description에 트리거·비대상을 명시했다. 산출물 위치를 `.service-replica/`에서 `.sognora/service/`로 옮겼다.
- sg-web-replicate와의 분담 표를 넣었다 — 이 스킬은 여정·콘텐츠·개인화·재방문·사업 기획, 그 스킬은 화면 일치·브랜드 가상화·자산 생성. 원장은 서로 참조하고 중복 기록하지 않는다.
- 런타임 중립: 브라우저를 제품 이름이 아니라 능력(사용자 세션 연결형 / 격리형)으로 고르게 했다. "기존 탭을 먼저 쓴다"는 한쪽 런타임의 탭 규칙이라 "도구의 탭 규칙을 따른다"로 바꿨다. Codex 전용 `agents/openai.yaml`은 싣지 않았다(스킬 본체 한 벌 원칙 — 표시 정보는 SKILL.md frontmatter가 양쪽에 제공한다).
- 참고 문서 정리: `evidence-contract.md` → `references/rules.md`(출처 층·Do-NOT·판정자 명시 추가). 타이트사주·웹툰형 사주 두 사례 문서는 화면 수치·단계별 조사 로그를 빼고 `references/case-webtoon-fortune.md` 한 장(관찰한 여정·운영사 설명·기획 해석·절차상 교훈)으로 줄였다. 조사 원자료는 스킬에 넣지 않는다.
- 결제 금지 등 사용자 제약 보존을 철칙 1로 올렸다.
- 철칙 4는 절대 금지가 아니라 "조사 편의를 위한 임의 변경 금지"다 — 사용자가 허용한 입력·상태 변경은 기록하고 실행한다.
