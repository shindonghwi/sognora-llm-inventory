# sg-ko-humanize — 룰북 (SSOT)

> Claude Code·Codex 양쪽이 공유하는 본체. 내용 수정은 이 파일에서만 한다.

심각도 표기 — 🔴 **즉시 제거**(하나만 있어도 AI 티가 남) / 🟡 **반복 시 제거**(한두 번은 자연스러움) / ⚪ **적극 모드에서만**.

## 건드리지 않는 것 (Do-NOT)

고유명사·제품명·기관명, 숫자·날짜·단위, 큰따옴표 안의 인용, 법조문, 수식·통계 표기, 업계 표준 용어와 영어 약어(API·LLM·GPU·prompt·token 등 — 억지 한국어 직역 금지).

## 과윤문 가드

변경률 30% 넘으면 경고, 50% 넘으면 채택 금지·롤백. 수치 판정은 `scripts/change_rate.py`가 한다 — 모델의 자가 추정은 참고용일 뿐이다.

## 1. 번역투 어법

영어 문장 구조가 한국어에 그대로 비쳐 보이는 경우. AI 한글의 티는 대부분 여기서 난다.

- 🔴 "~에 대해/대한"이 목적어 노릇 → 조사로 바로 연결. "일정에 대해 이야기했다" → "일정을 이야기했다"
- 🔴 "~에 있어(서)" → "~에서"로 바꾸거나 삭제
- 🔴 "가지고 있다"형 소유 직역 → 상태 서술로. "높은 안정성을 가지고 있다" → "안정성이 높다"
- 🔴 겹피동 "~되어지다/~지게 되다" → "~되다" 또는 능동
- 🟡 "~를 통해"가 한 문단에 거듭 → "~로", "~해서"로 바꿔 분산 (한두 번은 놔둔다)
- 🟡 "~와 관련해/관련된" → "~에", "~의"
- 🟡 "~을 바탕으로/기반으로" 잦으면 → "~로"
- 🟡 "~에 의해" 피동 → 행위자를 주어로. "위원회에 의해 결정된" → "위원회가 정한"
- 🟡 "~할 수 있다"가 습관처럼 붙음 → 근거가 있으면 단정형으로
- 🟡 "~라는 점에서", "~을 위해" 목적절이 겹침 → "~라서", "~하려고"로 간결하게
- 🟡 "그/그녀/그것/그들"이 문단 내내 등장 → 한국어는 주어 생략이 자연스럽다. 절반 이상 지우거나 이름·직함으로
- 🟡 명사 앞에 수식어가 3어절 넘게 쌓임 → 문장을 끊거나 수식을 뒤로 뺀다
- 🟡 겹조사 "~에서의/~으로의/~에의" → 절로 풀어쓴다 (단순 "~의"는 놔둔다)
- 🟡 부정관사 직역 "하나의/한 명의/일종의" 반복 → 빼거나 "한"으로. "하나의 방식으로 묶은" → "한 방식으로 묶은" (강조 의도가 분명한 단건은 보존)
- 🟡 한글 뒤 괄호 영어 병기가 매번 반복 → 첫 등장에서만
- 🟡 광고풍 외래어(seamless·robust·leverage류) → 우리말로 풀기. 표준 기술 용어는 예외

## 2. 피동·얼버무림

단정을 피하려는 기계적 습관.

- 🟡 "~로 보인다/판단된다/여겨진다" 남발 → 말할 수 있는 건 말한다
- 🟡 완곡 겹치기 "~일 가능성이 있을 것으로 보인다" → 완곡은 하나만
- 🟡 "양쪽 모두 일리가 있다/신중한 접근이 필요하다" 류 기계적 양시론 → 입장을 정하거나 조건을 단다

## 3. 상투구·과장

AI가 즐겨 쓰는 서명 같은 문구들. 이 카테고리는 발견 즉시 처리한다.

- 🔴 마무리 공식 "결론적으로/요약하자면/이를 통해 알 수 있듯" → 거의 삭제, 살려도 한 번
- 🔴 "시사하는 바가 크다/주목할 만하다/중요한 의미를 갖는다" → 삭제하거나 구체적 결론으로
- 🔴 예고 공식 "크게 세 가지로 나눌 수 있다/다음과 같다" → 예고 없이 바로 말한다
- 🔴 과장 어휘 "혁신적/획기적/전례 없는/압도적/파격적" → 사실과 숫자로
- 🔴 무생물 의인화 "기술이 말해준다/시대가 요구한다" → 사람·기관을 주어로
- 🔴 촉구형 마무리 "~할 때다/~해야 할 시점이다" → 문서에 많아야 한 번
- 🔴 전환 공식 "X를 넘어 Y로/X에서 Y의 시대로" → 많아야 한 번

## 4. 전개·구조 공식

문서 골격에서 나는 티.

- 🔴 이모지 장식(제목·목록 머리) → 격식 글이면 전부 삭제
- 🔴 콜론 제목 "X: Y" 반복 → 명사구 하나로 압축 (논문·보고서의 정식 절 제목은 예외)
- 🔴 연결어미 뒤 쉼표 "-고,", "-며,", "-지만," → 쉼표를 뺀다 (AI 한국어의 대표 지문)
- 🔴 문두 접속사 "또한/따라서/즉/나아가" 도배 → 대부분 삭제, 내용이 흐름을 잇게
- 🟡 산문 자리를 차지한 불릿 목록 → 칼럼·리포트 장르면 문단으로 되돌린다
- 🟡 "먼저 - 또한 - 마지막으로" 기계 전개 → 접속사를 줄이고 내용으로 잇는다
- 🟡 "A가 아니라 B다" 대구 반복 → 한 번은 살린다 (전부 깨면 글의 목소리가 죽는다), 나머지는 평서문
- 🟡 "1) 2) 3)" 괄호 나열 → 산문에 녹인다
- 🟡 메타 화법 "이는 ~를 의미한다/이 점에서 보면" → 본문에 녹이거나 삭제
- 🟡 "즉" 반복 → 문서에 두 번 이하

## 5. 형식명사·명사화

"것·점·바·수"와 한자 명사화가 문장을 흐리는 경우.

- 🔴 "~한 것이다/~할 것이다" 연발 → 일부는 "~다"로 끊는다
- 🟡 "주목할 점은 ~라는 점이다" → "~다" 직설로
- 🟡 "~다는 뜻이다/~다는 것이다" 맺음 → 직접 맺는다
- 🟡 권고 도배 "~해야 한다/~할 필요가 있다" → 주체를 밝혀 단언하거나 조건문으로 변주
- 🟡 "-성/-적/-화" 명사화 누적 → 동사·형용사로 푼다. "확장성 있는 구조의 구현" → "구조를 넓히기 쉽게 만든다"
- 🟡 "~적 N" 연쇄("구조적 한계, 전략적 접근…") → 명사 붙임("전략 접근")이나 풀어쓰기

## 6. 리듬

한 문장씩은 멀쩡한데 나란히 두면 기계 같은 경우.

- 🟡 문장 길이가 전부 비슷 → 짧은 문장과 긴 문장을 섞는다. 긴 문장은 인접 문장을 이어 만들 것 (내용 추가 금지)
- 🟡 같은 종결어미 4문장 이상 연속 → 다양화. 습관성 진행형 "~하고 있다"는 단순형으로("검토하고 있다" → "검토한다")
- 🟡 경어 단계 뒤섞임(해요체·합쇼체 혼용 — 대화·구어 한정) → 하나로 통일

## 7. 장식

- 🔴 따옴표 강조 도배 → 실제 인용만 남기고 평어로
- 🟡 본문 볼드 남발 → 격식 글이면 거의 제거
- ⚪ 대시(—) 부가설명이 문장마다 → 쉼표·괄호·별도 문장으로 (원문에 원래 있던 대시는 유지)

## 윤문 순서

**상투구·과장(3) → 번역투(1) → 형식명사(5) → 피동·얼버무림(2) → 전개·구조(4) → 장식(7) → 리듬(6)**
삭제할 것부터 지우고, 문장을 고치고, 리듬은 마지막에 본다. 리듬을 먼저 만지면 앞 단계 수정으로 도로 깨진다.

## 자체검증 (윤문 직후 — 위반 항목의 edit는 롤백)

1. [ ] 고유명사·숫자·날짜·인용이 원문과 한 글자도 다르지 않다
2. [ ] 변경률 30% 이하다 (확정 수치는 change_rate.py)
3. [ ] 장르가 그대로다 — 칼럼이 수필로, 보고서가 블로그로 변하지 않았다
4. [ ] 격식이 그대로다 — 격식체↔구어체 어느 쪽으로도 안 움직였다 ('-했-'을 '-하였-'로 올리는 것도 위반)
5. [ ] 🔴 등급 패턴이 하나도 안 남았다
6. [ ] 원문에 없던 표현을 심지 않았다 — 빼기만 했다. 살아있는 구어(감탄·반문·부가설명)는 살려뒀다
