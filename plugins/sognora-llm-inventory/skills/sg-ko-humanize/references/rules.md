# sg-ko-humanize — 룰북 (SSOT)

> Claude Code·Codex 양쪽이 공유하는 본체. 내용 수정은 이 파일에서만 한다.

심각도 표기 — 🔴 **즉시 제거**(하나만 있어도 AI 티가 남) / 🟡 **반복 시 제거**(한두 번은 자연스러움) / ⚪ **적극 모드에서만**.

## 건드리지 않는 것 (Do-NOT)

고유명사·제품명·기관명, 숫자·날짜·단위, 큰따옴표 안의 인용, 법조문, 수식·통계 표기, 업계 표준 용어와 영어 약어(API·LLM·GPU·prompt·token 등 — 억지 한국어 직역 금지).

## 과윤문 가드

변경률 30% 넘으면 경고, 50% 넘으면 채택 금지·롤백. 수치 판정은 `scripts/change_rate.py`가 한다 — 모델의 자가 추정은 참고용일 뿐이다.

## 1. 번역투 어법

영어 문장 구조가 한국어에 그대로 비쳐 보이는 경우. AI 한글의 티는 대부분 여기서 난다.

- 🔴 "~에 대해/대한"이 목적어 노릇 → 조사로 바로 연결. "일정에 대해 이야기했다" → "일정을 이야기했다"
- 🔴 "~에 있어(서)" → "~에서"로 바꾸거나 삭제
- 🔴 "가지고 있다"형 소유 직역 → 상태 서술로. "높은 안정성을 가지고 있다" → "안정성이 높다"
- 🔴 겹피동 "~되어지다/~지게 되다" → "~되다" 또는 능동
- 🟡 "~를 통해"가 한 문단에 거듭 → "~로", "~해서"로 바꿔 분산 (한두 번은 놔둔다)
- 🟡 "~와 관련해/관련된" → "~에", "~의"
- 🟡 "~을 바탕으로/기반으로" 잦으면 → "~로"
- 🟡 "~에 의해" 피동 → 행위자를 주어로. "위원회에 의해 결정된" → "위원회가 정한"
- 🟡 "~할 수 있다"가 습관처럼 붙음 → 근거가 있으면 단정형으로
- 🟡 "~라는 점에서", "~을 위해" 목적절이 겹침 → "~라서", "~하려고"로 간결하게
- 🟡 "그/그녀/그것/그들"이 문단 내내 등장 → 한국어는 주어 생략이 자연스럽다. 절반 이상 지우거나 이름·직함으로
- 🟡 명사 앞에 수식어가 3어절 넘게 쌓임 → 문장을 끊거나 수식을 뒤로 뺀다
- 🟡 겹조사 "~에서의/~으로의/~에의" → 절로 풀어쓴다 (단순 "~의"는 놔둔다)
- 🟡 부정관사 직역 "하나의/한 명의/일종의" 반복 → 빼거나 "한"으로. "하나의 방식으로 묶은" → "한 방식으로 묶은" (강조 의도가 분명한 단건은 보존)
- 🟡 한글 뒤 괄호 영어 병기가 매번 반복 → 첫 등장에서만
- 🟡 광고풍 외래어(seamless·robust·leverage류) → 우리말로 풀기. 표준 기술 용어는 예외

## 2. 피동·얼버무림

단정을 피하려는 기계적 습관.

- 🟡 "~로 보인다/판단된다/여겨진다" 남발 → 말할 수 있는 건 말한다
- 🟡 완곡 겹치기 "~일 가능성이 있을 것으로 보인다" → 완곡은 하나만
- 🟡 "양쪽 모두 일리가 있다/신중한 접근이 필요하다" 류 기계적 양시론 → 입장을 정하거나 조건을 단다

## 3. 상투구·과장

AI가 즐겨 쓰는 서명 같은 문구들. 이 카테고리는 발견 즉시 처리한다.

- 🔴 마무리 공식 "결론적으로/요약하자면/이를 통해 알 수 있듯" → 거의 삭제, 살려도 한 번
- 🔴 "시사하는 바가 크다/주목할 만하다/중요한 의미를 갖는다" → 삭제하거나 구체적 결론으로
- 🔴 예고 공식 "크게 세 가지로 나눌 수 있다/다음과 같다" → 예고 없이 바로 말한다
- 🔴 과장 어휘 "혁신적/획기적/전례 없는/압도적/파격적" → 사실과 숫자로
- 🔴 무생물 의인화 "기술이 말해준다/시대가 요구한다" → 사람·기관을 주어로
- 🔴 촉구형 마무리 "~할 때다/~해야 할 시점이다" → 문서에 많아야 한 번
- 🔴 전환 공식 "X를 넘어 Y로/X에서 Y의 시대로" → 많아야 한 번

## 4. 전개·구조 공식

문서 골격에서 나는 티.

- 🔴 이모지 장식(제목·목록 머리) → 격식 글이면 전부 삭제
- 🔴 콜론 제목 "X: Y" 반복 → 명사구 하나로 압축 (논문·보고서의 정식 절 제목은 예외)
- 🟡 연결어미 뒤 쉼표 "-고,", "-며,", "-지만," → **밀도가 높을 때만**(문장당 0.5회 초과) 덜어낸다. **법률·계약·약관은 전면 면제.**
  > 🔴이었으나 강등했다. 1987년 대한민국 헌법 원문(AI 이전, 사람이 쓴 최고 격식 문서)에서 `-고,` 15회·`-며,` 49회, **합 64회** 실측 — "AI 한국어의 대표 지문"으로 규정하면 헌법이 64곳 위반이 된다. 긴 병렬문의 쉼표는 표준 문장부호 용법이다.
- 🔴 문두 접속사 "또한/따라서/즉/나아가" 도배 → 대부분 삭제, 내용이 흐름을 잇게
- 🟡 산문 자리를 차지한 불릿 목록 → 칼럼·리포트 장르면 문단으로 되돌린다
- 🟡 "먼저 - 또한 - 마지막으로" 기계 전개 → 접속사를 줄이고 내용으로 잇는다
- 🟡 "A가 아니라 B다" 대구 반복 → 한 번은 살린다 (전부 깨면 글의 목소리가 죽는다), 나머지는 평서문
- 🟡 "1) 2) 3)" 괄호 나열 → 산문에 녹인다
- 🟡 메타 화법 "이는 ~를 의미한다/이 점에서 보면" → 본문에 녹이거나 삭제
- 🟡 "즉" 반복 → 문서에 두 번 이하

## 5. 형식명사·명사화

"것·점·바·수"와 한자 명사화가 문장을 흐리는 경우.

- 🔴 "~한 것이다/~할 것이다" 연발 → 일부는 "~다"로 끊는다
- 🟡 "주목할 점은 ~라는 점이다" → "~다" 직설로
- 🟡 "~다는 뜻이다/~다는 것이다" 맺음 → 직접 맺는다
- 🟡 권고 도배 "~해야 한다/~할 필요가 있다" → 주체를 밝혀 단언하거나 조건문으로 변주
- 🟡 "-성/-적/-화" 명사화 누적 → 동사·형용사로 푼다. "확장성 있는 구조의 구현" → "구조를 넓히기 쉽게 만든다"
- 🟡 "~적 N" 연쇄("구조적 한계, 전략적 접근…") → 명사 붙임("전략 접근")이나 풀어쓰기

## 6. 리듬

한 문장씩은 멀쩡한데 나란히 두면 기계 같은 경우.

- 🟡 문장 길이가 전부 비슷 → 짧은 문장과 긴 문장을 섞는다. 긴 문장은 인접 문장을 이어 만들 것 (내용 추가 금지)
- 🟡 같은 종결어미 4문장 이상 연속 → 다양화. 습관성 진행형 "~하고 있다"는 단순형으로("검토하고 있다" → "검토한다")
- 🟡 경어 단계 뒤섞임(해요체·합쇼체 혼용 — 대화·구어 한정) → 하나로 통일

## 7. 장식

- 🔴 따옴표 강조 도배 → 실제 인용만 남기고 평어로
- 🟡 본문 볼드 남발 → 격식 글이면 거의 제거
- ⚪ 대시(—) 부가설명이 문장마다 → 쉼표·괄호·별도 문장으로 (원문에 원래 있던 대시는 유지)

## 8. 내부 용어 노출 (제품 카피 전용)

**문체는 멀쩡한데 어휘가 기능 명세서에서 그대로 온** 경우. 앞의 1~7번이 전부 통과시키는 사각지대이고, 실무에서 "AI가 쓴 티"로 가장 먼저 지적당하는 자리다. 판정 기준은 하나 — **읽는 사람이 쓰는 말인가, 만든 사람이 쓰는 말인가.**

적용 장르: `랜딩`(마케팅 카피)·`UI`(앱 기능 화면)·`블로그`·`구어`. **`스펙`·`법률`·`공적`·`리포트`는 전면 면제** — 거기서는 "읽기 전용"이 정확한 용어다.

**`랜딩`과 `UI`를 가르는 이유** — 위험한 건 어휘가 아니라 **쓰인 자리**다. 파일 권한 드롭다운의 "읽기 전용"은 옳고, 랜딩 히어로의 "읽기 전용 화면으로 공유합니다"는 틀렸다. 같은 단어를 한 등급으로 묶으면 둘 중 하나는 반드시 오판한다.

- 🔴 **어디서도 변호가 안 되는 것** — "결정할 화면 / 제공량 / 인입 / 상태값 / 유효성 검사 / 예외 처리 / 어드민 / 프로비저닝 / 디폴트 / 파라미터 / 엔드포인트". 고객이 이 말을 쓰는 자리는 없다. "플랜별 제공량" → "요금제별 크레딧"
- 🔴 **랜딩에서만** / 🟡 UI에서 — "읽기 전용 / 쓰기 전용 / 편집 화면 / 작업 화면 / 관리 화면 / 지원 범위 / 적용 대상 / 적용 위치 / 워크스페이스 / 온보딩 / 플로우 / 트리거 / 케이스". 기능 화면에서는 조작 대상의 이름이라 성립하지만, **설득하는 문장에 들어가면 명세서 낭독**이 된다. "편집 화면을 거치지 않고" → "고칠 일 없이"
- 🟡 운영 지표어 "진입/이탈/유입/전환율"이 고객용 문장에 → 고객 행동으로. "진입한 고객" → "들어온 고객"
- 🟡 명세 동사·공문 수식 "수행한다/처리했습니다/반영한다/제공한다", "정상적으로", "해당 OO" → 구체 동사·지시어로. "결과를 정리합니다" → "시안을 만듭니다" · "해당 시안" → "이 시안"
- 🟡 같은 것을 두 이름으로("요금제"와 "플랜") → 하나로 통일. **셀 수 있는 부분은 기계가 센다** — 파일 안은 KOH21, **파일 간은 KOH22**(파일을 여러 개 넘겼을 때, 각 파일의 '지배 용어'가 서로 다르면 잡는다). 실제로 랜딩은 "요금제"로 통일돼 있고 요금제 페이지는 "플랜" 6회였는데 **각 파일은 내부적으로 일관돼서 KOH21이 침묵했다** — 사람이 눈으로 찾았고, 그래서 KOH22를 세웠다. "고객/사용자"는 넣지 않았다: 실측에서 고객=시공사의 의뢰인, 사용자=좌석 수로 서로 다른 것을 가리켰다. **클러스터 표 밖의 표류와 프로젝트 전역 표류는 여전히 사람 몫이다.**

> 이 목록은 gpt-5.6-sol 교차검증을 거쳤다. 초안은 위 두 줄을 한 덩어리 🔴로 묶었는데, "읽기 전용·편집 화면·지원 범위는 일반 사용자도 자연스럽게 쓴다"는 반론이 옳았다. 어휘 목록을 늘리는 대신 **장르 축을 하나 더 세워** 해결했다.

> **왜 늦게 추가됐나** — 이 룰북은 산문 교정에서 출발해 문장 수술 규칙만 갖췄다. 그런데 실제 요청은 대부분 제품 카피였고, 거기서 나는 AI 티의 절반은 문장이 아니라 **단어 출처**였다. "문체 검사에서 🔴 0건"이 "고객이 읽을 만하다"를 뜻하지 않는다는 걸, 랜딩 카피가 만점을 받고 사람에게 반려당하고 나서야 반영한다.

**내부 용어(8) → 상투구·과장(3) → 번역투(1) → 형식명사(5) → 피동·얼버무림(2) → 전개·구조(4) → 장식(7) → 리듬(6)**

## 장르 예외 — 헌법 코퍼스 실측이 근거

번역투로 분류한 표현 중 일부는 **법률·계약·약관·기술 스펙에서 정상 어법**이다. 1987년 헌법 원문 실측: "에 있어" 9회 · "에 대하여/에 대한" 19회 · "할 수 있" 53회. 이 장르에서는 밀도 기준으로만 보고, 단독 출현을 위반으로 세지 않는다.

- **법률·계약·약관**: 연결어미 쉼표 전면 면제 · "에 있어/에 대하여" 면제 · 겹조사 면제(고문체 어법)
- **기술 스펙**: "다음과 같다" 면제(뒤에 표·코드블록·목록이 오면 정당한 예고다 — 삭제하면 뒤따르는 블록이 고아가 된다) · **§8 내부 용어 전면 면제**(개발자가 독자다)
- **UI 계열 = `랜딩`(마케팅 카피) + `UI`(앱 기능 화면·i18n)**: 산문 규칙을 끄고 어휘 규칙을 켠다. 문자열 하나가 곧 한 문장이므로 **문서 단위 밀도가 아니라 문자열 단위**로 센다. 둘의 차이는 §8 문맥 의존 어휘의 등급뿐이다(랜딩 🔴 / UI 🟡).
  - 면제: 연결어미 쉼표 · 문두 접속사 · "것이다" 연발 · 콜론 제목 · 예고 공식 — 버튼 라벨과 eyebrow에 산문 리듬 규칙을 들이대면 UI가 깨진다
  - 강화: **§8 내부 용어 전면 적용** · "~할 수 있다" 밀도 (능력 서술 도배는 기능 명세서를 그대로 옮긴 카피의 지문이다)
  - 종결어미 4연속·문장 길이 다양화(§6)는 **적용하지 않는다** — 필드마다 독립 문자열이라 리듬을 논할 단위가 아니다
- 판정: `scripts/detect_ko.py --genre 법률|스펙|랜딩|UI|칼럼|리포트|블로그|공적|구어`
- **코드·메시지 파일(.ts/.tsx/.js/.json/…)에 장르를 안 넘기면 exit 2로 거절한다.** 기본 장르는 큰따옴표 안을 인용으로 지우므로 그 호출은 언제나 🔴0 exit 0을 낸다 — "깨끗함"과 "아무것도 안 봄"이 구분되지 않는 거짓 통과였고, 이 카테고리를 만든 사고의 원인이 정확히 그것이다. 침묵 대신 거절하는 것이 `change_rate.py`의 "미지원 구문 — 수정 금지"와 같은 규약이다.

## 게이트가 막지 못하는 것 (정직한 한계)

`change_rate.py`의 불변식은 숫자·조항·부정·극성·조건·URL·영문 고유명사를 **문장 쌍 단위로** 대조한다. 그래도 못 잡는 것이 있고, 여기 적어둔다 — **막지 못하는 걸 막는 척하는 것이 이 무기고에서 반복된 최악의 패턴**이었다.

- **맨몸 반의어 반전**: "많다→적다", "크다→작다"처럼 부정 표지 없이 뜻이 뒤집히는 교체. `"-지 않"` 프레임(적지 않↔많지 않)과 **UI 동작 어휘**(저장↔삭제·구독↔해지·공개↔비공개 등 11쌍)는 잡는다 — 버튼 라벨의 동작어는 닫힌 집합이라 열거할 수 있고, 초단문 카피에서는 이게 **유일한 방어선**이다. 그 밖의 일반 산문 반의어는 사전 없이는 여전히 불가.
- **한글 고유명사**: `--protect 놀팝,서울` 로 명단을 줄 때만 검사한다. 명단 없이 조사 앞 명사를 추출하면 오탐이 터진다.
- **이중부정 해소**: "없지 않다→있다"는 의미 보존인데 부정 개수가 2→0이라 ABORT가 난다(알려진 오탐).
- 이 셋은 **사람이 봐야 한다.** 게이트가 통과시켰다고 내용이 보존됐다는 뜻이 아니다.

### 로케일 쌍은 `locale_parity.py`가 본다 (축이 다르다)

`change_rate.py`는 **같은 파일의 before/after**만 본다. 한 로케일만 고치면 그 안에서는 아무 불변식도 안 깨진다 — en은 "No. …"인데 ko에서 "아니요"가 사라지는 사고가 여기서 난다. 별도 계기로 판정한다: 키 누락·숫자·보간 토큰·URL·기술 약어(JPG/PNG/MB…)·응답 극성.

- **통화가 걸린 값은 비교하지 않는다** — `$19 ↔ 19,000원`은 정당한 로케일 차이다. 실코퍼스에서 이걸 안 빼면 요금제 파일이 통째로 오탐이었다.
- **약어는 기술 용어 화이트리스트로만 본다** — 첫 구현이 연속 대문자를 전부 약어로 셌다가 터졌다. 영문 eyebrow의 "SHARE WITH CLIENTS"는 대문자가 **장식**이고 한글에 대응물이 없는 게 정상이다.
- **번역이 맞는지는 판정하지 않는다.** 문장 수·어순·길이 비율도 안 본다(언어마다 정상적으로 다르다). 이 계기가 잡는 건 "한쪽만 고쳐서 사실이 어긋난 것"뿐이다.
- 템플릿 리터럴·전개 구문이 나오면 **exit 2로 판정을 포기한다** — 반쯤 파싱한 결과로 "정합함"을 선언하지 않는다.
