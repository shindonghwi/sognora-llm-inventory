# sg-demand-mine — 수요 채굴

> 이 파일 하나가 Claude Code와 Codex 양쪽에서 동작한다. 규칙·스키마·킬 기준은 `references/mine-rules.md`(SSOT).
> **이 스킬은 아이디어를 내지 않는다. 이미 일어나고 있는 지불과 불만을 찾아 그 자리를 보여줄 뿐이다.**

## 세계관 — 왜 채굴인가

LLM에게 "사업 아이디어를 내라"고 하면 학습 분포의 평균이 나온다(= 매번 비슷하고 시대에 뒤진 제안). 근본 원인은 셋이고, 각각에 장치가 있다:

1. **근거 없는 생성** → 증거에서 역산한다. 모든 카드는 URL·날짜·원문 인용을 달고, **인용은 수집 코퍼스와 기계 대조**된다(지어낸 인용은 즉사).
2. **주제를 사람이 고름** → 시드를 데이터가 고른다. 사용자가 주는 것은 주제어가 아니라 **문형**뿐이고, 실제 검색 질의와 시장 실측이 순위를 매긴다. *"엑셀 자동화"를 시드로 넣으면 엑셀 자동화 아이디어가 나온다 — 그건 발굴이 아니라 생성이다.*
3. **누적을 현재로 오독** → **유량으로만 잰다.** 누적 평점 55만은 5년치 합계일 뿐 오늘의 수요가 아니다. 최근 리뷰가 며칠에 걸쳐 쌓였는지(일 유입), 최근 창의 불만율, 1위 앱 방치일, 신규 진입 수, 90일 대 이전 90일 언급 추세 — 전부 흐름이다.

그리고 **판정 기준은 매출 규모가 아니라 first-dollar**다. 작은 시장은 탈락 사유가 아니라 기록 항목이다.

## 공정 — P0~P5

- **P0 운영자 프로파일**(이 스킬은 되묻는다 — 사용자만 아는 것이므로). 한 배치로: ① 가용 시간·기간 ② 보유 역량 ③ 자본 ④ **기피 도메인·규제 회피 범위**(의료·금융·개인정보는 1인에게 치명적일 수 있다) ⑤ **유통 접근권** — 이미 닿을 수 있는 사람·채널이 구체적으로 무엇인가 ⑥ 시장(글로벌/특정 국가) ⑦ 수익 형태 선호. → `_idea/<run>/00_operator.md`
- **P1 시드 발견(데이터가 주제를 고른다)** — `node scripts/seeds.mjs --out _idea/<run>/seeds --market <us|kr|…> [--top 20] [--fresh-days 120] [--stems "..."]`. 산출: 실제 질의·문제 구절·기회 순위표(유입/불만/방치/신규진입/추세). **사람은 문형만 준다.** 운영자 기피 도메인에 걸리는 시드는 여기서 제외.
- **P2 신호 수집** — 상위 시드에 대해 `node scripts/signals.mjs --q "<시드들>" --en "<영문>" --out _idea/<run>/signals --market <시장>`. 산출: `corpus.jsonl`(URL·날짜·원문 인용·클래스) + `collection-log.md`(채널별 시도/성공/차단 — **차단은 숨기지 않는다**). **A급 0건이면 여기서 정지하고 정직 보고**(근거 없는 생성보다 URL 붙은 생성이 더 위험하다).
- **P3 카드 합성 + 린트** — 코퍼스에서만 카드를 쓴다(스키마 mine-rules §카드). `node scripts/cards.mjs --cards _idea/<run>/cards --corpus <corpus.jsonl> [--ledger _idea/ledger.json] --out _idea/<run>` → 통과분만 존치. **카드 0개는 정상 결과다.**
- **P4 킬 패널(블라인드) — 기록이 파일 계약이다.** `node scripts/panel.mjs --cards <dir> --init --out <dir>`로 판정 서식을 만들고, 신선한 컨텍스트 판정자 둘을 돌린다: ① **킬 판정자** — 죽이라고 시킨다(§킬 기준 6종 전부 심문 + **살아있는 대안을 실물로 확인해 이름·가격 기재 의무**) ② **역구성 판정자** — 인용문만 주고(아이디어는 숨김) 문제를 복원시켜 카드의 문제 진술과 어긋나면 세탁. 결과를 `verdicts.json`에 채우고 `panel.mjs --panel`로 검증 — **미기재·모순(역구성 불일치인데 survive)이 있으면 P5로 갈 수 없다.** 산출: 생존자 + **사망자 명부와 치명 사유**.
- **P5 숏리스트·핸드오프** — 3축 표(증거 강도 / 운영자 적합[빌드·유통 분리] / first-dollar 근접)를 그대로 보이고 합성 점수는 만들지 않는다. 상위 후보를 **sg-biz-validate 입력 브리프**로 넘기되 **운영자 목표 기준**(절대 매출이 아니라 first-dollar 도달·유지 가능성)을 명시 필드로 싣는다. `ledger.json` append.

## 절단선 — sg-biz-validate와의 분업

> **sg-demand-mine**: 입력은 **운영자 프로파일**(아이디어 없음). 산출은 증거 기반 후보 목록과 사망자 명부. **금지 — 경쟁사 심층 해부·단위 경제·TAM 추정·PRD.** 경쟁 확인은 "같은 문제를 푸는 살아있는 유료 제품이 있는가, 가격은 얼마인가"까지.
> **sg-biz-validate**: 입력은 **아이디어 1개**. 산출은 진입/조건부/철회 판정과 PRD.
> 핸드오프 브리프에 운영자 목표 기준을 싣지 않으면, biz-validate의 시장 규모 기준이 mine이 옳게 건져 올린 소규모 기회를 자동 철회시킨다.
