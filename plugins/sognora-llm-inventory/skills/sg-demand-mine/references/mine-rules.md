# sg-demand-mine — 규칙·스키마·킬 기준 (SSOT)

## 0. 첫 번째 안전장치 — 수집 실패 시 카드를 만들지 않는다

근거 없는 생성은 사용자가 "이상하다"고 알아채지만, **URL이 붙은 생성은 알아챌 수 없다.** 그래서 수집이 실패하면 이 스킬은 무해한 게 아니라 유해하다. A급 채널이 전부 비면 `signals.mjs`가 종료 코드 1로 멈추고, 그 실행은 카드를 만들지 않는다.

## 1. 증거 3클래스

| 클래스 | 정의 | 예 |
|---|---|---|
| **A (지불)** | **돈이 오간 흔적만** | 유료 앱 사용자의 결제·해지·가격 불만, 공개 가격표, 유료 플랜 이탈 언급 |
| **B (시간·노력)** | 사람들이 시간을 쓰는 흔적 | 커뮤니티 고통 스레드, 미해결 이슈, 반복 질문 |
| **C (정황)** | 배경 | 출시·규제·해외 사례 — **단독으로 카드 성립 불가** |

- 커뮤니티 불만은 B급이다. **불만 ≠ 지불 의사.**
- 모든 증거는 URL + 날짜 + **원문 인용**(요약 금지 — 요약하면 대조가 불가능해진다).
- **증거 TTL 12개월** — 초과 인용은 재확인 의무. 수요 신호는 부패한다(2년 전 불만은 이미 해결됐을 수 있다).

## 2. 지표는 유량이다 (누적 금지)

누적 평점·누적 후기·누적 다운로드는 **몇 년치 합계**일 뿐 오늘의 수요가 아니다. 판정에 쓰는 것은:

- **수요 유량** — 최근 리뷰 N건이 실제로 며칠에 걸쳐 쌓였나(일 유입). 50건이 12일이면 활발, 186일이면 식어가는 시장.
- **불만 유량** — 최신성 창(기본 120~180일) 안의 ★≤3 비율.
- **방치도** — 1위 앱의 마지막 업데이트 경과일. 길수록 기회.
- **진입 유량** — 최근 1년 신규 출시 앱 수. 많으면 수요가 살아 있다는 뜻(동시에 경쟁 신호).
- **추세** — 최근 90일 대 이전 90일 언급량. 하강이면 늦었다.

누적은 보고서에 "참고값"으로만 표기한다.

## 3. 카드 스키마 (`cards.mjs`가 기계 검증)

```json
{ "id": "kebab-slug",
  "problem": "한 문장",
  "payer": "이름·역할로 특정 — '중소기업·소상공인·사용자'는 무효",
  "currentSpend": { "amountKRW": 130000, "unit": "연", "source": "인용 근거" },
  "evidence": [{ "class": "A|B|C", "url": "…", "date": "YYYY-MM-DD", "quote": "코퍼스 원문 그대로" }],
  "whyNow": { "type": "기술|규제|가격|행동|플랫폼", "source": "URL", "date": "12개월 내", "claim": "…" },
  "whyNotYet": "최근에야 가능해짐 | 시장이 작아 보여서 | 유통이 어려워서 | 이미 있음(→탈락)",
  "buildScope": "4주 내 첫 버전 범위",
  "firstDollar": [{ "actor": "…", "premiseTrueToday": "오늘 이미 참인 전제", "effort": "…", "failSignal": "실패를 무엇으로 관측하나" }],
  "distribution": { "mode": "operator-reach|resident-demand", "evidence": "운영자 접근권 서술 또는 URL" },
  "pricing": "과금 형태",
  "marketSize": "기록 항목 — 탈락 기준이 아니다",
  "clicheType": "two-sided|ai-wrapper|community|logistics|none",
  "clicheProof": "클리셰 유형이면 추가 입증(미제출 = 탈락)" }
```

**first-dollar 하드룰**: 첫 단계는 **오늘 실행 가능**해야 한다("먼저 1,000명 모은다"류 무효). 각 단계에 실패 관측 신호가 있어야 한다.
**why-now 하드룰**: 유형을 하나 고르고 **12개월 내 날짜 출처**를 단다. "LLM 때문" 단독 서술은 무효 — 그걸 허용하면 모든 카드가 AI 래퍼가 된다.
**역-why-now가 진짜 판정자다**: "그럼 왜 아직 아무도 안 했나"에 답하지 못하면 탈락. 이 질문 하나가 시대착오와 "이미 있는데 모름"을 동시에 잡는다.

## 4. 킬 기준 (P4 — 하나라도 확정 사망이면 탈락)

1. **이미 있음** — 같은 문제를 푸는 살아있는 유료 제품이 있는데 그 약점이 증거로 특정되지 않음
2. **커머디티** — 플랫폼·모델 제공자가 기본 기능으로 흡수하면 남는 것이 없음
3. **유통 부재** — ①운영자가 이미 닿는 사람 ②상주 수요(키워드·스레드 **URL 증거** 필수) 둘 다 없음. **1인 운영자의 병목은 빌드가 아니라 유통이다**
4. **증거 세탁** — 역구성 판정자가 인용문만 보고 복원한 문제가 카드의 문제 진술과 어긋남
5. **시대** — why-now 무효 또는 역-why-now 무응답
6. **규제 지뢰** — 운영자가 밝힌 회피 범위를 넘는 규제(의료·금융·개인정보)

**B급만 있는 카드**는 탈락이 아니라 **관찰 목록으로 격리**한다(정보를 버리지 않되 숏리스트를 오염시키지 않는다).

## 5. 클리셰 — 블랙리스트가 아니라 입증 책임 전환

유형으로 죽이면 좋은 아이디어까지 죽는다(한쪽 면을 이미 가진 매칭 서비스는 훌륭하다). 대신 해당 유형이면 **추가 증거를 의무화**하고 미충족 시 탈락시킨다:

| 유형 | 요구 증거 |
|---|---|
| 양면 시장 | 한쪽 면을 이미 확보했다는 증거 |
| AI 래퍼 | 기반 모델이 그대로는 못 하는 워크플로·데이터 증거 |
| 커뮤니티·콘텐츠 | 초기 100명이 어디서 오는지 증거 |
| 물류·이행 | 1인 운영 가능한 이행 경로 |

## 6. 정렬 — 합성 점수 금지

합성 점수는 게임된다. **3축 표를 그대로 보인다**: 증거 강도(A급 수·최신성) / 운영자 적합(**빌드와 유통을 분리 채점**) / first-dollar 근접(단계 수·지불자 특정도). 정렬은 증거 강도 우선, 동률이면 first-dollar 근접.

## 7. 반복 실행 — ledger만 축적

수요 신호는 부패하므로 코퍼스 전면 축적은 과설계다. 축적하는 것은 `_idea/ledger.json` 하나: `{problem 요지, verdict, 사망 사유, date}`. **이전에 죽은 문제를 다시 제안하려면 새 증거나 상황 변화를 제시해야 한다.**

## 8. 할당량 금지

"카드 최소 N개"는 쓰레기를 채우는 유인을 만든다. 하한은 **신호 수집량**에만 걸고, **카드 0개도 정직한 결과**다. 참고 상한은 8개.

## 9. 채널 정책

- **차단 확인 시 우회 금지** — 사실을 로그에 기록하고 대체 채널로 간다. 차단을 숨기고 "리뷰를 분석했다"고 쓰면 그게 가짜 증거다.
- **정책 제외**: 외주·구인 마켓(크몽·숨고·잡코리아 등)은 증거로 쓰지 않는다.
- 수집 로그에 **언어·지역 분포**를 남긴다(영어권 과대·국내 과소 편향을 드러내기 위해).

## 10. 스킬이 판정할 수 없는 것

**지속력** — 최고점 카드가 운영자가 6개월 못 버틸 도메인이면 실패한다. 숏리스트에 "이 문제를 6개월 붙들 수 있는가"를 자문 항목으로 붙이되, 판정은 사용자에게 남긴다.
