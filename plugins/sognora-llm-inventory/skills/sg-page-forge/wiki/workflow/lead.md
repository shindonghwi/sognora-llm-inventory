# P1 — 리드와 근거: 골격은 실측에서 온다

> 판정자: `ir.mjs`의 completeness 스탬프(미달 IR은 audit에서 "미제공"급) · `references/corpus-baseline.json`(규칙의 자) · history 대조(동일 리드 3회 내 재사용 금지).

## 왜 리드인가

생성에서 스펙의 침묵은 LLM 사전분포로 채워지고(=AI 티), 변환에서 침묵은 레퍼런스 실측값으로 채워진다(=품질 바닥이 상속된다). 그래서 골격(그리드·리듬·모션·인터랙션 구조)은 리드 사이트의 IR에서 오고, 표현(팔레트·타이포·카피·자산·시그니처)은 의무 치환이다. **숫자는 차용 가능, 표현·자산·시그니처는 불가.**

## 리드 고르기

- 사용자가 URL을 지목했으면 그것이 리드다.
- 아니면 `references/library/INDEX.md`(요약 실측 23종)에서 **화면 문제**로 고른다 — 업종이 닮았다는 이유로 고르지 않는다. 같은 동사(고른다/쓴다/…)를 같은 밀도로 푼 사례가 리드다.
- 동일 리드는 최근 3회 내 재사용 금지(`$SG_PAGE_FORGE_HOME/history.json`). 변환 아키텍처에서 리드 선택이 다양성의 제1축이다.
- 리드를 **겉모습까지 옮기면 "가져다 쓴 것"으로 거절된다**(담화 v4 실측). 리드에서 오는 것은 좌표계·리듬·모션 계기·인터랙션 구조뿐이고, 겉모습은 P2에서 사용자가 고른 시안이 정한다.

## IR 확보

```bash
# 스킬에 배포된 IR(references/ir/ — 읽기 전용)에 리드가 있으면 계약 lead에 그 이름만 적는다
ls "$S/references/ir/"
# 없으면 리드 사이트를 수집해 IR로 증류 — 원본 번들은 스킬 밖($SG_PAGE_FORGE_HOME), IR은 프로젝트 .sognora/page/ir/
node "$S/ir.mjs" all --url <리드 URL> --name <이름>     # → .sognora/page/ir/<이름>.json (measured facts + completeness)
```

계약의 `lead`는 **이름**이다. audit은 `.sognora/page/ir/<이름>.json` → 스킬 배포 `references/ir/<이름>.json` 순으로 찾고, URL이 적혀 있으면 "미제공 — 먼저 ir.mjs로 수집"으로 보고한다. 스킬 폴더에 런타임이 쓰지 않는다(설치본 업데이트 시 소실·지문 불일치). 새 리드 IR을 스킬에 넣는 것은 저장소 편집이다.

- IR은 섹션 기하·리듬·타입 롤·자산 슬롯·모션 어휘와 `completeness` 블록(1440/390 트리·scrollHeight 정합·keyframes>0·자산 rect 결합률≥50%·record 타임라인≥1)을 갖는다. 미달 IR은 리드 자격이 없고 audit에서 "미제공"으로 표기된다.
- 번들(원본 CSS·자산 사본)은 재배포 금지라 저장소에 올리지 않는다. 다른 사용자는 IR만으로 빌드·검증이 되고, 원본 대조가 필요할 때만 자기 컴퓨터에 수집한다. **캐시 없이 돌지 않는 축은 설계 결함이다** — 그런 축은 "미제공=판정되지 않음"으로 보고하지 통과로 쓰지 않는다.
- 로그인 벽 등으로 수집 불가면 생성 폴백을 선언하고 등급 캡 B를 고지한다.

## cases.md — 리드·비교·대조
