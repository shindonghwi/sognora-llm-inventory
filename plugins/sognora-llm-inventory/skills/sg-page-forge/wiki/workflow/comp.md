# P2 — 시안: 코드 전에 사람이 고른 그림

> 판정자: `comp.mjs --check`(시안 없는 페이지 🔴) · 사용자 선택(이 스킬에서 인터뷰 다음으로 허용되는 유일한 질문) · [judge/comp-judge](../judge/comp-judge.md)(P6에서 시안 대비).

## 왜 시안이 먼저인가

시각 목표물 없이 CSS부터 짜면 제일 싼 것(문단·카드 3장·가운데 히어로)으로 수렴한다. 리드를 줄 단위로 옮겨도 사용자는 "그냥 가져다 쓴 것"이라 거절한다(담화 v4). 판정 기준이 취향인 사용자에게는 **코드 전에 그림**이 필요하고, 그림은 이미지 모델이 LLM보다 잘 그린다. 담화 v5에서 통한 유일한 순서가 이것이다: 시안 3안 → 사용자 선택 → 전사.

## 절차

1. **브리프 컴파일** — 계약(유형·decision·facts·must/mustNot)과 방향([directions](../directions.md) 7축)과 토큰(있으면)을 프롬프트로 컴파일한다. facts가 빈 페이지는 시안을 만들지 않는다(빈 틀을 베끼게 된다). `do` 화면 브리프에는 "소개문 도입 금지"가 붙는다.
2. **방향이 다른 2~3안** — 같은 브리프로 축이 다른 시안을 뽑는다(예: 잉걸 근접 / 연기 커튼 / 정면). 한 안만 뽑으면 고를 것이 없다.
   ```bash
   node "$S/comp.mjs"      # 계약의 모든 페이지에 3안씩 → .sognora/page/comps/<slug>-1..3.png + <slug>.prompt.md
   ```
   Codex 내장 `imagegen` 스킬을 `codex exec`에 프롬프트를 파이프해 호출한다(스킬 이름은 imagen이 아니라 **imagegen**). 프롬프트 전문은 `<slug>.prompt.md`에 남긴다 — 같은 계약이면 같은 브리프가 나와야 한다. **codex CLI가 없는 환경**(Claude Code 단독)에서는 죽지 않고 프롬프트 파일만 쓴 뒤 "시안 축 미제공"으로 보고한다(exit 0). 사용자가 그 프롬프트를 다른 이미지 생성기에 넣어 `comps/<slug>-1.png`로 두면 `--check`가 통과하고 진행된다 — 되묻는 것이 아니라 경로를 안내한다.
3. **공통 규칙(프롬프트에 박는다)** — 실제 운영 중인 프리미엄 사이트 스크린샷처럼, 1536×1024(데스크톱) · 요소 6~10개 · 굵은 고딕·유리 블러 상자·알약 남발·보라 그라데이션·가운데 히어로+카드 3 금지 · 한글은 깨지면 자리만 잡아도 됨 · 토큰이 없으면 색을 지어내지 말고 무채색 뼈대.
4. **사용자에게 보여 고르게 한다.** 시안 파일을 보여주고 선택을 받는다(Claude=파일 전송+선택형 질문, Codex·기타=파일 경로 출력+번호 목록). "섞기/다시 뽑기"도 선택지다. 고른 시안이 `comp`이고 계약의 `comp` 필드가 그것을 가리킨다.
5. 시안이 좋은지는 기계가 판정하지 않는다. 시안이 존재하는가, 무슨 프롬프트였는가만 `comp.mjs`가 관할한다.

## 시안이 곧 상한이다

- 이미지 모델이 못 그리는 것(복잡한 인터랙션, 데이터 화면의 실제 상태)은 시안이 아니라 [types](../types/index.md)의 필수 구조와 [systems/components](../systems/components.md)가 정한다.
- 시안의 한글 오타·깨짐은 카피가 아니다. 카피는 facts에서 온다.
- 사용자가 "그냥 만들어"라고 했을 때만 시안 없이 P3로 간다. 그 경우 보고서에 "시안 없음"을 적는다.
