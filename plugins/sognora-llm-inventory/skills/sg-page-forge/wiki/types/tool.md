# 유형 — 도구 화면 `tool` (쓴다 → 직접 해본다)

- 근거 수준: 실전 사고(도구 화면 12/24가 첫 화면의 10~20%만 일로 덮음) + Carbon 행 높이 실측 + NN/G 상태 화면 지침.
- 판정자: 기계(scan 규칙 `tool.no-input`(입력 0 → 🔴, **보이는 텍스트 입력·file·canvas만 센다** — hidden csrf로 통과하던 구멍 폐쇄)·`work.below-fold`·`work.starved`·`work.unmeasured`·`type.landing-drift`).

## 동사와 필수 구조

| 항목 | 값 |
|---|---|
| 사용자 동사 | 쓴다(직접 해본다) |
| 필수 구조 | 입력(업로드·텍스트·캔버스) + 실행 버튼 |
| 소개문으로 열어도 되나 | ❌ |
| 블록 간 세로 간격 | **16~32px** — 입력→실행→결과가 한 화면. Carbon 행 높이 xs 24 / sm 32 / md 40 |
| 일 점유율 실측 | 도구 32(구조 밀도), 계정 폼 62~65% |

## 규칙

- **입력이 화면 상단에** — 파일 업로드·텍스트 프롬프트·캔버스 중 하나가 첫 화면에 있어야 한다. 설명이 입력보다 위에 오면 안 된다.
- **실행 → 결과 → 다음 행동**이 한 화면에서 끝난다(결과 보려고 스크롤·페이지 이동 금지).
- **비로그인 체험 경계를 명시** — 어디까지 무료인지, 언제 로그인·결제가 필요한지를 실행 전에 알린다([pricing](pricing.md)의 자동갱신 고지와 같은 원칙).
- **상태 커버리지**가 여기서 가장 중요하다 — 처리 중·실패·용량 초과·지원하지 않는 형식([components](../systems/components.md) §상태).
- **설득 금지** — 후기·가격표·기능 자랑은 랜딩과 요금제의 일이다.
- 카탈로그에서 항목을 고르면 도착하는 곳. **여기서 실제로 결과가 나와야 한다.**

## 관측 한계 (초록·빨강 둘 다에 새긴다)

주 행위 요소는 **표준 마크업**으로만 분류한다: `table`·`canvas`·`video`·`form`·균일한 반복 단위. **커스텀 컨트롤은 못 본다** — 숨은 `input[type=file]` + 커스텀 드롭존, 가상 스크롤, div 캔버스 대체물. 실측 사고: 업로드가 `input[type=file] 1x1 숨김` + 드롭존이라 분류에 실패했는데 계기가 "조작할 덩어리가 없다 · 0%"라고 단정했다. 화면에는 380px 설정 패널과 1200px 작업 영역이 있었다. **못 잰 것을 없다고 쓰는 것은 거짓 진술이다.**

- 분류 실패는 🔴이 아니라 **`work.unmeasured`(🟡)**, 문구에 "일이 없다는 뜻이 아니다".
- 분류에 성공했으나 그게 그 화면의 일이 아닌 경우는 기계가 모른다 — 🔴 문구에 "오분류면 되돌릴 것".
- 고치는 방향은 분류기 확장이 아니라 **마크업을 표준으로 되돌리는 것** — 숨은 file input을 `<form>`·`<label>`로 감싸면 계기도 보고 스크린리더도 본다.
