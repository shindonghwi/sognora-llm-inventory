# 페이지 유형 — 동사가 유형을 정한다

가장 흔한 사고: `/product`를 만들라 했더니 또 설득형 랜딩이 나왔다(히어로+CTA+후기). **유형 목록에 그 페이지가 없으면 에이전트는 가장 익숙한 형태(랜딩)로 회귀한다.** 스펙의 침묵을 사전분포가 채우는 패턴이다. 그래서 브리프에서 **"이 페이지에서 사용자가 하는 동사"**를 먼저 정하고, 동사가 유형을 결정한다.

| 사용자가 하는 것 | 유형 | 문서 | 필수 구조 | 소개문으로 열어도 되나 |
|---|---|---|---|---|
| 읽는다(설득당한다) | `landing` | [landing](landing.md) | 히어로·증거·CTA | ✅ |
| 읽는다(회사를 안다) | `about` | [about](about.md) | 짧은 헤더 + 사실 + 연락 경로 | ✅ |
| 읽는다(조건을 확인한다) | `document` | [document](document.md) | 시행일·문의처 + 목차 + 번호 절 | ✅ |
| 고른다 | `catalog` | [catalog](catalog.md) | 반복 항목 그리드 + 진입 액션 | ❌ |
| 쓴다(직접 해본다) | `tool` | [tool](tool.md) | 입력 + 실행 버튼 | ❌ |
| 정한다(비교 후 결제) | `pricing` | [pricing](pricing.md) | 열=플랜·행=속성 | ❌ |
| 적는다 | `form` | [form](form.md) | 필드 3~5개 | ❌ |
| 본다·관리한다 | `dashboard` | [dashboard](dashboard.md) | 반복 데이터 + 상태 화면 | ❌ |

**목록에 없는 화면은 동사를 직접 선언한다** — `read:<라벨>`·`do:<라벨>`(예: `do:갤러리`). 없다고 랜딩으로 회귀하는 것이 위의 사고다. 여러 프로젝트에서 반복되면 그때 등재한다. 맨 유형명은 화이트리스트로 막는다 — **알 수 없는 유형은 exit 2**(예전엔 오타 `catlog`까지 ✅ 도장을 찍었다. 검사 부재보다 나쁘다).

> 소개·문서 유형은 v1.6.7에 신설됐다. 그 전까지 목록에 없어서 소개·문의·개인정보·약관·이용정책·환불 6종이 한 번에 같은 화면으로 나왔다. 유형 목록의 공백은 곧 사고다.

## 유형이 정하는 것과 정하지 않는 것

- **정체성 토큰**(팔레트·타입 스케일·radius·모션 duration)은 유형과 무관하게 상속 — 페이지가 새로 만들면 위반(기계, scan 규칙 `token.*`). 폰트 패밀리·easing은 기계가 렌더에서 수집하지 않으므로 관행(판정자 없음) — AD 검수.
- **밀도 토큰**(섹션 패딩·블록 간격·행 높이·컨트롤 크기·그리드 갭)은 **유형이 결정** — 랜딩 값 상속 금지. [spacing](../systems/spacing.md)
- 페이지끼리의 닮음은 [sameness-judge](../judge/sameness-judge.md): 같은 유형끼리 닮은 것은 정상, **다른 유형이 같은 틀**만 결함.
