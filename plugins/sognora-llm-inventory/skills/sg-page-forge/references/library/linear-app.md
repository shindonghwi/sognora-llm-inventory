# linear.app 분석

장르/단위: 개발자 도구(이슈 트래커·제품 개발 시스템) / 랜딩 · 분석일 2026-08-15 · 상태: **완전**

한 줄 요약: **"모션 절제의 기준"으로 불리지만, 실측하면 절제가 아니라 부재다.** 호버 14개 표본 중 transform이 움직인 것 0개, 스크롤 리빌 26개 표본 중 발화한 것 0개. 이 사이트가 정교해 보이는 이유는 잘 만든 애니메이션이 아니라 **애니메이션이 있어야 할 자리에 제품 화면의 밀도를 넣었기 때문**이다.

## 자산 운용

**비디오 0, canvas 0, iframe 0.** 제품 화면이 전부 실제 DOM이거나 정지 이미지다. 코드 diff 섹션은 이미지가 아니라 진짜 HTML — 그래서 `.line.diff-old` / `.diff-new` 클래스와 실제 신택스 컬러(`#F79CE0` 키워드, `#8FA6FF` 컴포넌트, `#83DCDC` 식별자)를 그대로 읽을 수 있다.

**프레이밍 규칙 — 프레임을 안 씌운다.** 브라우저 크롬 없음, 기기 목업 없음, 원근 틸트·3D 회전 없음. 정면 평면으로 놓고 **뷰포트 좌우로 그냥 잘라낸다.** 화면이 "화면 밖에도 계속 있다"는 인상이 생기고, 스크린샷이 랜딩용 소품이 아니라 실제 앱 창처럼 읽힌다.

**grain 레이어 11개** — 256×256 타일, `mix-blend-mode: overlay`, opacity 0.6(subtle)/0.9, inset 1px. 스크린샷 위에 필름 그레인을 덮어 페이지 배경과 접합한다. **다크 배경에 PNG를 붙였을 때 나는 "떠 있는 느낌"을 없애는 장치**이고, 저밀도 30%에서도 화면이 싸구려로 안 보이는 실질적 이유다.

**초점 제어는 애니메이션이 아니라 명도로 한다.** 겹친 UI 조각 중 주목시킬 하나만 정상 밝기, 나머지는 배경 명도 근처까지 눌러버린다(op 0.8 패널 다수). 모션 없이 시선을 옮긴다.

**후기 카드** — 유일한 명도 반전. 카드1은 `linear-gradient(rgb(178,213,255) → …)` + 흰색 40% 오버레이에 **거대한 OpenAI 로고 워터마크**, 카드2는 Ramp 브랜드 `rgb(228,242,34)`. 잉크는 페이지 배경색 `rgb(8,9,10)`을 그대로 쓴다. 하단에 로고 + 1px 세로 룰 + 이름/직함.

**FIG 일러스트** — 채움 없는 선 아이소메트릭. 다크에서 일러스트가 무거워지지 않게 하는 유일한 방법에 가깝다.

**측정한 14개 호버 표본 전부에서 `transform` 변화 0, `box-shadow` 변화 0.** scale도, translateY도, lift도, 그림자 확장도 없다. 프라이머리 버튼은 `transform`을 transition 목록에 넣어두고도 실제로는 안 쓴다.

호버 언어는 두 갈래뿐이다.
- **텍스트/링크** → `filter: brightness(1.25~1.4)` 로 통째로 밝히기
- **컨트롤** → 흰색 알파 표면 얹기(.02 / .05 / .08 — 요소 중요도 순)

무반응 5개: skip link, 로고 링크, Search workspace, New issue, Workspace — 전부 a11y 요소이거나 목업 내부 장식이라 정상이다.

### 스크롤 리빌 — 없다

h2 6개 · section 6개 · 베네핏 카드 · Changelog 카드 · 고객 카드 · 프리푸터를 **스크롤 전/후로 비교: 26개 중 opacity·transform이 변한 것 0개.** 전부 처음부터 `opacity: 1, transform: none, animation: none`.

정지 상태에서 안 보이는 요소는 5개뿐이고 하나도 콘텐츠가 아니다.

| 요소 | opacity | 정체 |
|---|---|---|
| `Skip to content →` | 0 | 포커스 시 노출 (a11y 정상) |
| 히어로 배경 IMG 1416×768 | 0.08 | 배경 텍스처 레이어 |
| Slack 목업 내 메시지 | 0 | 시뮬레이션 재생용 |
| `MwJdiW_glow` | 0.04 | 글로우 레이어 |

`@keyframes fadeIn`은 **`0% { opacity: 0 } 100% { opacity: 1 }`이 전부**다. translateY가 없다. 업계 표준이 된 "fade + translateY(20px) + IntersectionObserver"를 이 사이트는 **한 번도 쓰지 않는다.**

### 모션 언어

- transition 선언 **243개**, `transition: all` **0개** — 전부 프로퍼티 명시
- 실제 요소에서 측정된 duration은 **2종뿐**: `0.1s`(51개) · `0.16s`(33개)
- CSS 전체 인터랙션 duration: 0.2s(22) · 0.4s(7) · 0.5s(5) · 0.12s(5) · 0.15s(5) · 0.18s(4) · 0.3s(3) · 0.1s(3) — **전부 ≤0.5s**
- easing 분포: **`steps(1)` 175회(최다)** · `ease` 24 · `var(--ease-out-cubic)` 8 · `var(--ease-out-quad)` 6 · `cubic-bezier(.32,.72,0,1)` 3 · `cubic-bezier(.16,1,.3,1)` 1 · `var(--ease-in-out-quad)` 1
  → 토큰화된 감속 커브 체계(`--ease-out-*`). **가속(ease-in) 단독 커브는 진입에 한 번도 안 쓴다.**
- transition 프로퍼티 빈도: **color 60** · filter 23 · transform 20 · border 10 · background-color 10 · box-shadow 10 · opacity 10 · background 9 → 압도적 1위가 color

### infinite 26곳의 정체

MO1 티로 잡힌 26곳은 전부 **제품 목업 내부이거나 마퀴**다. 페이지 크롬 자체의 무한 애니메이션은 0개다.

| 애니메이션 | 개수 | 사양 | 위치 |
|---|---|---|---|
| `grid-dot-*-*-agent` | 175 | 2.8~3.2s **steps(1)**, opacity 0.3 | 에이전트 그리드 점멸 |
| `xt7VyG_scroll` / `scroll-abs` | 2트랙 | 30s linear | 로고월 마퀴(중복 트랙, `noFade` 변형) |
| `cursorBlink` | — | 1.25s ease | 목업 내 타이핑 커서 |
| `PPSGPG_blink` | — | 1.2s **steps(1)** | 목업 내 상태 점멸 |
| `w9ZFkq_shine` | — | 2.2s linear | 목업 내 텍스트 그라데이션 스윕 |

**`steps(1)`이 최다 easing인 게 핵심이다.** 시스템이 일하는 척하는 표시(점, 커서, 상태)는 부드럽게 보간하지 않고 **똑딱 넘긴다.** 기계는 미끄러지지 않는다는 판단이 easing 선택에 들어가 있다.

### 접근성 · reduced-motion

- 포커스 링 **`outline: rgb(94,105,209) solid 1px` + `outline-offset: 2px`** — 브랜드 인디고, box-shadow 링이 아닌 진짜 outline
- `prefers-reduced-motion` @media **7블록**. 결정적인 건 방향이다: **`(prefers-reduced-motion: no-preference)`로 모션을 "추가"한다.** 기본이 무모션이고 허용될 때만 얹는 구조 — 흔한 `reduce일 때 끄기`의 반대
- `@media not (prefers-reduced-motion: no-preference) { .video { display: none } }` — 영상은 감추는 게 아니라 아예 제거
- 다만 `reducedMotion: reduce` 컨텍스트에서도 animation 178 / transition 150이 남는다. 선언은 옳지만 커버리지는 부분적이다
- 무라벨 아이콘 71개(IC3)는 실제 결함이다. 대부분 목업 내부지만 aria가 없다

## 배울 것

1. **호버에서 요소를 움직이지 마라.** 14표본 transform 변화 0. 표면 톤(흰색 알파 .02/.05/.08)과 `filter: brightness()` 두 가지로 전부 처리한다. lift·scale·그림자 확장은 없어도 되는 게 아니라 **없어야 정밀해 보인다.**
2. **스크롤 리빌 없이도 최고 평가를 받는다.** 26표본 0/26. "리빌 = 고급"은 이 사이트가 반증한다. 콘텐츠가 처음부터 거기 있으면 스크롤이 빠른 사용자를 벌주지 않는다.
3. **duration을 2개로 수렴시켜라.** 실측 0.1s / 0.16s. `transition: all` 0개, 프로퍼티는 항상 명시. 토큰 이름(`--ease-out-quad`)까지 정리돼 있다.
4. **reduced-motion은 "끄기"가 아니라 "켜기"로 짜라.** `no-preference`일 때 얹는 구조라 기본 경로가 항상 안전하다.
5. **다크 위계는 색이 아니라 명도 4단 + 알파 서피스 4단으로 만든다.** 텍스트 `#F7F8F8 → #D0D6E0 → #8A8F98 → #62666D`, 표면 `.02/.03/.05/.07`. 불투명 서피스는 6곳뿐 — 알파로 쌓으면 배경이 하나로 유지된다.
6. **포화색은 남의 브랜드에만 허용한다.** 페이지 크롬 포화색 0. 유일한 원색 면적이 고객사(Ramp) 브랜드 컬러라 후기 섹션이 광고가 아니라 인용으로 읽힌다.
7. **디스플레이 타이포는 비율로 고정한다.** 72/64/48px 전부 line-height 1.0 + letter-spacing -0.022em + weight 510. 크기만 바뀌고 인상은 동일하다.
8. **시뮬레이션 모션은 `steps(1)`로.** 최다 easing이 steps(1)인 이유 — 시스템 활동 표시는 보간하면 유기체처럼 보인다.
9. **스크린샷은 프레임 대신 grain + 컷오프로 접합한다.** 브라우저 목업·3D 틸트 대신 정면 평면 + overlay 그레인 + 뷰포트 절단. 화면이 "계속 이어진다"는 인상이 생긴다.
10. **초점은 모션이 아니라 명도로 옮긴다.** 겹친 UI 중 하나만 정상 밝기, 나머지는 배경 근처까지 눌러 시선을 고정한다.
11. **템플릿을 숨기지 말고 드러낸 뒤 자산으로만 변주하라.** 피처 섹션 5개가 `672+672` / padding 128 고정인데 지루하지 않은 건 매 섹션 제품 화면이 완전히 다르기 때문이다.
12. **번호 체계가 프로그레스 바를 대체한다.** `FIG 0.2 → 1.0 → 1.1 → 2.0 …` 만으로 스크롤 위치감이 생기고, 도면 은유가 "정밀한 도구"라는 주장을 문서 형식 자체로 증명한다.
13. **메가메뉴에 아이콘을 넣지 마라.** 3열 텍스트 전용. 라벨 + 2줄 설명이면 충분하고, 아이콘 6개가 빠지면서 패널이 조용해진다.
14. **중앙 정렬은 페이지당 한 번만.** 전 페이지 좌측 정렬, 프리푸터 CTA 한 곳만 중앙 — 그래서 그 한 곳이 결론으로 읽힌다.

## 버릴 것

**"Linear glow" 복제 — 이 사이트가 클리셰의 원조가 된 지점.** 실측한 원본은 이렇다.

```
radial-gradient(circle, rgba(255,255,255,0.02~0.04) 0%, rgba(0,0,0,0) 50%)
400×400px · mix-blend-mode: lighten (히어로 1개만 normal) · 9개
```

**흰색 2~4%다. 색이 없다.** 그런데 2021~2023년 시드 스테이지 랜딩이 이걸 베끼면서 보라/파랑 60% + `blur(100px)` + 800px 블롭으로 번역됐고, 지금 그 형태가 우리 CO1/M3 티로 잡힌다. 원본을 베낀 게 아니라 **원본의 인상을 오해해서 증폭**한 결과다. 다크 배경에 컬러 글로우를 얹고 싶어질 때마다 이 수치를 다시 볼 것.

**나머지:**

- **다크 + 고정폭 + 거대 좌측 헤드라인 "개발자 툴 룩"** 자체가 이제 템플릿이다. 2026년에 이 조합은 차별화가 아니라 카테고리 표시다.
- **밀도 30% 흉내.** Linear의 여백을 지탱하는 건 여백 감각이 아니라 **제품 스크린샷의 정보 밀도**다. 그 자리에 넣을 화면이 약하면 결과는 세련된 절제가 아니라 그냥 빈 페이지다(DE1이 잡는 지점).
- **Berkeley Mono는 유료 라이선스.** 무료 대체(JetBrains Mono·IBM Plex Mono)로 바꾸면 FIG 라벨과 코드 패널의 인상이 눈에 띄게 달라진다. 폰트를 못 맞출 거면 모노 라벨 체계 자체를 안 쓰는 편이 낫다.
- **번호 체계는 제품이 5단계 워크플로(Intake→Plan→Build→Diffs→Monitor)라서 성립한다.** 순서가 없는 제품에 `1.0 / 2.0`을 붙이면 가짜 정밀함이 된다.
- **Linear도 완벽하지 않다 — 따라 하면 안 되는 결함:** 무라벨 아이콘 71개(IC3), 카드 속 카드(LA4), reduced-motion 컨텍스트에서도 남는 animation 178 / transition 150. 선언은 모범이지만 커버리지는 부분적이다.
