## 수치

### 타이포 — 16px 하나가 페이지의 절반이다

폰트 사이즈 고유값 16개: `12 13.5 14 15 16 17 18 20 21 22 24 26 30 37 44 72`.
스캐너는 이걸 🔴TS1로 잡지만 실제 분포를 세면 얘기가 다르다.

| 층 | 사이즈 | 노드 수 / 303 | 정체 |
|---|---|---|---|
| 본문 단일층 | **16** | **150 (49.5%)** | 페이지의 절반. 카드 설명·스펙·링크·푸터가 전부 여기 |

읽는 사람이 마주하는 위계는 **16 → 24/30 → 44 → 72, 네 단**이다. 그 사이 12단은 전부 컴포넌트 하나가 쓰고 마는 값이라 화면에 공존하지 않는다.

### 폰트 4패밀리 — 웨이트 축을 패밀리로 쪼갰다

@font-face 5건 중 아이콘 폰트를 빼면 **한글 본문 폰트가 4개**고, 넷 다 `font-weight: 400`으로 선언돼 있다.

| 패밀리 | 파일 | 실측 용도 | 노드 수 |
|---|---|---|---|
| `HyundaiSansHeadKR` | HyundaiSansHeadKRMedium.woff2 (611KB) | 섹션 표제 44px · 히어로 차명 72px · 카드 제목 · 랭킹 | 115 |
| `HyundaiSansTextKR` | HyundaiSansTextKRMedium.woff2 (636KB) | 본문 16px 기본 · 버튼 라벨 · 퀵태스크 | 109 |

즉 **Head/Text 축(디스플레이 vs 본문) × Medium/Regular 축(강/약)의 2×2**를 `font-weight` 대신 `font-family` 네 개로 구현했다. 한글 웹폰트에서 웨이트당 파일이 어차피 따로 나오니 CSS 웨이트 축을 쓸 이유가 없다는 판단이고, 결과적으로 `font-weight` 값은 페이지 전체에서 의미를 잃었다(대부분 400·500이 섞여 있지만 렌더에는 영향이 없다).

대가는 명확하다. **네 파일 합계 2,405KB, 전체 5.1MB의 47%.** `font-display` 미지정(=block), `unicode-range` 서브셋 없음, 넷 다 t=128ms에 병렬 요청.

## 자산 운용 — 대형 제품 비주얼을 33KB로 만드는 법

### 1. 히어로는 사진이 아니라 무대 + 오려낸 차다

7슬라이드 전부 같은 구조다.

```
.fluid-container  1425×950
  background-image: url(car-bg-w.jpg)      /* 1920×950 */
  background-size: auto 100%               /* 세로 고정, 가로는 흘림 */
  background-position: 50% 0%              /* 상단 중앙 기준 */
  └ img  1360×380 투명 PNG, 좌표 x=33 y=326 (7슬라이드 전부 동일)
  └ .txt-wrap  position:absolute; left:7vw; top:152px; width:1260px
      └ p.car-name  86px/82px  (.long → 72px)  (.white → #fff)
      └ p.sub-txt   26px/38px  margin-top:14px
```

배경은 **딱 두 장**(`car-bg-w.jpg`, `main_kv_bg_w.jpg`)을 7슬라이드가 돌려 쓴다. 스튜디오 그라디언트라 거의 단색이고, **1920×950이 2,727 바이트**다. 그 위에 모델별 투명 컷아웃이 18~31KB.

| | 파일 수 | 합계 |
|---|---|---|
| 배경(공유) | 2 | **5.5KB** |
| 차량 컷아웃 | 7 | 180KB |
| **7슬라이드 풀블리드 히어로 전체** | 9 | **185KB** |

슬라이드 하나당 33KB다. 같은 화면을 1920×950 사진 7장으로 만들면 최소 1.5MB다.

부수 효과가 더 크다. **컷아웃 좌표가 7슬라이드 전부 x=33 y=326으로 고정**이라 차가 바뀌어도 바퀴가 닿는 바닥선이 1px도 안 움직인다. 캐러셀이 넘어갈 때 차만 갈리고 무대는 그대로다. 사진 7장으로는 절대 못 맞추는 정합이고, 이게 "잘 만든 기업 사이트" 인상의 절반을 만든다.

`background-size: auto 100%`도 의도적이다. 세로를 950px에 고정하고 가로를 흘려보내기 때문에 **뷰포트 폭이 아무리 바뀌어도 바닥선 y좌표가 변하지 않는다.** `cover`였다면 세로가 스케일돼서 차와 바닥이 어긋난다.

### 2. 전송 포맷과 URL을 분리했다

저장한 143개 중 **132개가 실제로는 AVIF**인데 URL은 전부 `.jpg` / `.png`다. 응답 헤더에 `cf-resized`가 붙는다 — Cloudflare Image Resizing이 엣지에서 `Accept` 헤더를 보고 트랜스코딩한다.

```
https://www.hyundai.com/contents/mainbanner/main_kv_the_new_grandeur.png
  → Content-Type: image/avif   (28,906 B)
```

원본 마크업·CMS·기획자는 계속 png/jpg를 다루고, 포맷 최적화는 인프라가 가져간다. `<picture>` 분기도 없고 빌드 파이프라인도 안 건드린다. AVIF가 아닌 11개는 전부 유튜브 썸네일(`i.ytimg.com`)과 SVG/GIF, 즉 **CDN 밖에 있는 것들뿐**이다.

### 3. 한 장을 세 크기로 굴린다

이벤트 배너는 **739×489 마스터 한 장**만 존재하고, 세 군데에서 다른 크기로 나온다.

| 위치 | 표시 크기 | 비 | object-fit |
|---|---|---|---|
| Events 카드 | 433×286 | 1.514 | fill |
| 메가패널 프로모 | 216×144 | 1.500 | fill |
| 마스터 | 739×489 | 1.511 | — |

세 비율이 소수점 셋째 자리에서만 갈리기 때문에 `fill`인데도 왜곡이 안 보인다. **비율을 먼저 정하고 마스터를 그 비율로 발주하면 `object-fit: cover`도 `srcset`도 필요 없다.** Model 섹션도 똑같다. 560×420 마스터 하나가 576×432(1위)와 224×168(2·3위)로 나가고, 셋 다 정확히 4:3이다.

Brand 카드만 예외적으로 **256×400 소스를 256×400에 그대로** 쓴다. 리사이즈 자체가 없다.

### 4. 아이콘은 2026년에도 스프라이트다

`/static/images/ico_btn.png` 한 장을 `background-position`으로 잘라 쓴다(`0 -18px`, `-18px -19px` …). 인라인 SVG는 페이지 전체에서 2개뿐이다.

### 5. 대가

- 이미지 143개 합계 **1,177KB**. 페이지 전체 5.1MB의 23%밖에 안 된다. **차를 보여주는 게 일인 사이트에서 이미지가 가장 가벼운 항목**이 됐다.
- 그 예산을 폰트가 다 먹었다. 서브셋 없는 한글 woff2 4개 = 2,405KB.
- `<img>` 127개 중 **`width`/`height` 속성이 붙은 게 0개, `loading="lazy"`가 0개.** 전부 즉시 로드되고 아무도 자리를 예약하지 않는다(🟡QF6). 히어로가 컷아웃이라 LCP 자체는 가볍지만 하단 100장이 초기에 같이 뜬다.
- 인증마크 7개·차량 컷아웃 전부 **1× 자산**이다. 레티나 대응 없음.

## 인터랙션

### 모션 언어가 사실상 하나다

duration 0.3s(99) / 0.4s(30) / 0.2s(11). easing `ease`(110) / `ease-in-out`(30). property는 **`all`이 110개**.
캐러셀 이동만 `transform .4s ease-in-out`이고 나머지 전부 `all .3s ease`다. 게으른 구현이지만 **결과적으로 페이지 전체가 한 박자로 움직인다.**

### 스크롤 리빌이 0건이다

probe 스윕 결과 `hiddenAtRest: 8, revealedAfterScroll: 0`. 페이드업도, AOS도, 순차 등장도 없다. 스크롤하면 이미 거기 있던 것이 그냥 보인다. 기업 사이트에서 이건 결함이 아니라 **선택**이고, 정보 밀도가 높은 홈에서 리빌을 깔면 스캔을 방해한다는 판단으로 읽힌다.

### 호버는 "이미지가 자란다" 하나로 통일

probe가 14표본 전부 "무반응"으로 잡았는데 오탐이다. 상태 변화가 **hover된 요소가 아니라 그 안의 `img`에 걸려 있다.**

```css
.list-item-model > img:hover        { transform: scale(1.1); transition: .3s }
.el-carousel__unit:hover .el-image  { transform: scale(1.2); transition: transform .3s ease-in }
.model-list > li:hover              { background: #F6F3F2 }
.el-carousel__arrow:hover           { opacity: 1 }      /* 평상시 반투명 */
```

프레임은 `overflow: hidden`으로 고정된 채 안쪽 이미지만 1.1~1.2배로 커진다. 레이아웃이 1px도 안 밀린다. 리스트 행 호버는 `#F6F3F2` — 메가패널·칩 바닥과 **같은 색 하나**가 세 가지 일을 한다.

### 텍스트를 호버에만 얹는 두 섹션

Brand와 SNS 카드는 **평상시 순수 사진이고, 텍스트가 아예 없다.**

```css
/* Brand */
.link .txt-wrap        { position:absolute; inset:0; opacity:0; display:flex; justify-content:center }
.link:hover .txt-wrap,
.link:focus .txt-wrap  { opacity:1; background: rgba(0,0,0,.6) }

/* SNS */
.box-desc              { 279×279; background: rgba(0,44,95,.9) }   /* 네이비 90% */
```

스크림이 **호버 상태에만 존재**한다. 평상시 사진 위에 검은 그라디언트를 깔아두는 흔한 처리와 정반대인데, 캠페인 이미지가 주인공인 섹션에서는 이쪽이 맞다. `:focus`를 같이 잡아둬서 키보드 사용자도 동일하게 본다.

이 때문에 스캐너 🟡CO3(본문 대비 3.66:1)는 **오탐**이다. 대비를 잰 대상이 `opacity:0`인 rest 상태의 흰 글자다.

### 헤더 전환

| 상태 | position | background | border | height |
|---|---|---|---|---|
| scrollY = 0 | `absolute` | `transparent` | none | 80px |
| scrollY > 0 | `fixed` | `rgba(255,255,255,.9)` + `blur(5px)` | 1px `#E5E5E5` | 81px |

그림자 없이 헤어라인 하나로 끝낸다. 히어로가 950px(뷰포트 900보다 50px 큼)이라 **첫 화면에서 퀵태스크 스트립이 반쯤 잘려 보이고**, 그게 스크롤 어피던스가 된다.

한 번 `isFixed`가 붙으면 다시 0으로 올라와도 안 떼진다. 되돌아온 첫 화면에서는 히어로 위에 흰 바가 남는다.

### 캐러셀 컨트롤

- 히어로 화살표는 **인접 슬라이드의 모델명을 라벨로 단다**(`← NEXO` / `KONA Electric →`). 어디로 가는지 클릭 전에 알려주는 처리.
- 도트 12×12, 피치 24px, `radius: 60%`, 활성 `#007FA8`.
- 재생/정지 토글 18×18, `#575757`, CSS `border` 삼각형/막대. **페이지 전체에 이 토글이 딱 1개**다.
- Events 캐러셀 화살표는 44×44 `rgba(31,45,61,.4)` 사각형이고 카드 이미지 위에 반쯤 걸친다.

## 배울 것

1. **대형 제품 비주얼 = 공유 무대 + 투명 컷아웃.** 배경 2장(5.5KB)에 컷아웃 7장(180KB)으로 풀블리드 히어로 7슬라이드가 끝난다. 슬라이드당 33KB. 제품이 주인공인 랜딩에서 배경 사진 여러 장을 발주하는 대신, **무대 한 장을 만들고 제품만 갈아 끼우는 구조**를 먼저 검토할 것.

2. **컷아웃 좌표를 슬라이드 전부에서 동일하게 못 박아라.** x=33 y=326 고정 덕에 캐러셀이 넘어가도 바닥선이 안 흔들린다. 이 정합이 "돈 들인 사이트" 인상을 만든다. `background-size: auto 100%` + `position: 50% 0%`로 뷰포트가 변해도 세로 기준선이 고정되는 것도 같은 논리다.

3. **비율을 먼저 정하고 마스터를 발주하면 반응형 이미지 파이프라인이 필요 없다.** 739×489 한 장이 433×286과 216×144로, 560×420 한 장이 576×432와 224×168로 나간다. 셋 다 오차 0.01 이내라 `object-fit: fill`인데도 왜곡이 없다. `srcset` 없이 이게 된다.

4. **전송 포맷은 엣지에 위임하라.** URL은 `.png`인데 실제로는 AVIF가 온다(132/143). CMS·마크업·에디터는 아무것도 안 바뀌고 CDN 설정 한 줄로 이미지 예산이 절반이 된다.

5. **세로 리듬은 값 하나로 잠가라.** 섹션 간 gap 0, 전부 `padding-top: 140px`. 표제 +140, 서브카피 +88(58+30). 일곱 섹션 예외 없음. 컬럼 폭은 섹션마다 다르게 놔뒀는데도 페이지가 정돈돼 보이는 이유가 여기 있다. **가로는 풀어도 되고 세로는 잠가야 한다.**

6. **호버 스크림은 rest가 아니라 hover에만 존재시켜라.** 캠페인 이미지 섹션에서 상시 그라디언트는 사진을 죽인다. `opacity:0` → `hover/focus`에 `rgba(0,0,0,.6)`. `:focus`를 같이 잡는 것까지가 한 세트다.

7. **호버는 프레임이 아니라 안쪽 이미지에 걸어라.** `overflow:hidden` 프레임 고정 + 내부 `img { scale(1.1) }`. 레이아웃 시프트 0으로 반응성을 만든다. 사이트 전체 호버 언어를 이거 하나로 통일해도 충분하다.

8. **메가 패널은 좌측 카테고리와 우측 첫 행의 y를 맞춰라.** 레일 라벨 y=497 ↔ 해당 그룹 리프 첫 행 y=497. 링크 30개 이상을 5열 그리드에 깔면서도 소속이 안 흐트러진다. 폭 250 레일 + 210.5 피치 5열이 실측값.

9. **한글 웹폰트는 웨이트가 아니라 패밀리로 쪼개라.** Head/Text × Medium/Regular 4패밀리, 전부 `font-weight: 400`. 한글은 어차피 웨이트당 파일이 따로 나오니 CSS 웨이트 축이 무의미하다. 다만 **서브셋과 `font-display`는 반드시 같이 가야 한다**(아래 참조).

10. **브랜드 컬러를 다섯 개로 묶고 회색은 순중립으로.** 네이비=액션, 틸=상태, 웜그레이=바닥, 근검정=푸터, 시안=FAB. 역할이 하나씩만 배정돼 있어서 색을 보면 뭘 하는 건지 알 수 있다. 회색 램프에 틴트를 안 섞었기 때문에 웜그레이 면이 유일하게 따뜻해서 눈에 띈다.

11. **캐러셀 화살표에 목적지를 써라.** `← NEXO` / `KONA Electric →`. 다음이 뭔지 알면 클릭률이 달라진다. 모델·상품처럼 항목에 이름이 있는 캐러셀에서 즉시 이식 가능.

12. **랭킹은 크로뮴 없이 크기로.** 1위는 이미지 576×432 + 타이틀 37px, 2·3위는 224×168 + 17px. 배지도 리본도 없이 2.57배 크기 차이만으로 순위가 읽힌다.

13. **스크롤 리빌은 안 넣어도 된다.** 정보 밀도가 높은 기업 홈에서 리빌은 스캔 방해다. 이 페이지는 0건이고 아무도 아쉬워하지 않는다.

14. **첫 화면을 뷰포트보다 50px 크게.** 히어로 950px / 뷰포트 900px. 퀵태스크 스트립이 반쯤 잘려 보이는 게 스크롤 어피던스가 된다.

## 버릴 것

1. **서브셋 없는 한글 웹폰트 2,405KB.** 전체 5.1MB의 47%. `font-display` 미지정(=block), `unicode-range` 없음, 네 파일 t=128ms 동시 요청. 이미지를 33KB까지 깎아놓고 폰트에서 그 70배를 흘린다. 최소한 `font-display: swap` + KS X 1001 상용 2,350자 서브셋(파일당 100~150KB)은 갔어야 한다.

2. **`<img>` 127개 전부 `width`/`height` 없음, `loading="lazy"` 0개.** 자리 예약도 지연 로드도 없어서 하단 100장이 초기에 같이 뜬다. 속성 두 개 추가로 끝나는 문제다.

3. **자동재생 캐러셀은 19개인데 정지 버튼은 1개.** 히어로만 멈출 수 있고 EV 스펙·Events·Model은 못 멈춘다. WCAG 2.2.2 위반이고, 스펙을 읽는 도중 카드가 넘어가면 사용자는 그냥 포기한다.

4. **SNS 릴스 썸네일이 잘려서 글자가 사라진다.** 16:9 유튜브 `hqdefault`(480×360)를 279×279 정사각에 center-crop해서 넣는다. 결과가 `**F**OR ME, AVANTE / Pl**eos Connect**` — 양쪽이 다 날아간다. 게다가 세 번째 카드는 포토샵 UI가 그대로 찍힌 썸네일이다. **크롭 비율을 바꿀 수 없다면 소스 비율에 프레임을 맞춰야 한다.**

5. **`word-break: keep-all`이 5%(15/303)에만 걸려 있다.** 한글이 어절 중간에서 잘린다. toss.im은 350노드 전부에 걸어놨다. 카피가 짧아서 지금은 티가 덜 날 뿐, 카피가 길어지는 순간 무너진다. 전역 한 줄이면 끝난다.

6. **`transition: all` 110개.** 리페인트 비용이 예측 불가능해진다. 결과적으로 박자가 맞는 건 다행이지 설계가 아니다. `transition: transform .3s ease, opacity .3s ease`로 명시할 것.

7. **쓰지도 않는 Element UI CSS를 통째로 싣는다.** `.el-table-filter`, `.el-upload`, `.el-tabs--card`, `.el-pager` 규칙이 스타일시트에 다 있는데 이 페이지엔 해당 컴포넌트가 없다. 게다가 `design2020` / `design2023` / `design2026` 세 세대의 CSS가 한 파일에 공존한다. 스타일시트 1,033KB의 상당 부분이 이거다.

8. **CSS 커스텀 프로퍼티 0개.** `#002C5F`가 22군데에 리터럴로 박혀 있다. SCSS 컴파일 결과라 다크 모드도 테마 전환도 리브랜딩도 전부 전수 치환이다.

9. **헤더 `isFixed`가 안 풀린다.** scrollY 0으로 돌아와도 흰 바가 히어로 위에 남는다. 그리고 전환 시 80px→81px(border 1px)로 **1px 레이아웃 시프트**가 난다. border를 `box-shadow: inset 0 -1px`로 바꾸면 둘 다 해결된다.

10. **로고와 스킵링크가 `<a>`가 아니라 `<button>`이다.** 기업 사이트에서 가장 많이 눌리는 로고를 새 탭으로 못 연다. 휠클릭·⌘클릭·URL 미리보기가 전부 죽는다. Brand 카드도 `href="javascript:void(0)"`다.

11. **히어로 차명 72px이 `<p>`다.** 페이지에서 가장 큰 활자가 의미상 문단이다. `<h1>`은 로고("HYUNDAI")가 가져갔다. 나머지 heading 순서(h2 섹션 / h3 카드)는 깔끔한데 여기만 어긋난다.

근거: ①②③④가 통과했고 특히 **②가 정확히 일치**한다(IR 9 = 실측 9 = 이틀 전 수동 계측 9). 섹션 y·h·컨테이너(1180/1120)·열 수(1·1·2·2·4·1·2·4·3)·타입 스케일(44/30/24/16)·duration(300ms 지배)이 전부 잡혔으므로 **"섹션마다 그리드를 바꾸는 대기업 브랜드 홈"의 골격 표본으로 즉시 사용 가능**하다. 이번 D조에서 IR이 온전한 유일한 사이트다.

제약: ⑤ 실패로 **모션 어휘는 이름만 있고 궤적이 없다.** 이 번들에서 호버·리빌을 베끼면 안 된다. 모션까지 재현급으로 올리려면 모달이 안 뜨는 조건(재방문 쿠키 상태)에서 record를 다시 돌려야 한다.

### 계기 수리 후 재실행 (2026-08-17, 수리본 `record.mjs` + `ir.mjs`)

수리 내용: `ir.mjs` 오버레이·커튼을 섹션으로 잡고 히어로를 삼키던 버그 수정 + `layers` 필드 신설, 섹션 문턱 `0.85 → 0.8`·`depth 9 → 10`. `record.mjs` 셀렉터가 내비·배너에 갇히던 문제 수정.

**가장 중요한 소득: `layers`가 모달을 잡아냈다.** 신설 필드가 단 하나를 물었는데, 그게 정확히 위 ⑤ 실패의 원인이다.

```json
layers: [{ "y": 0, "h": 900, "position": "fixed", "cls": "v-modal", "bg": "rgb(0, 0, 0)" }]
```

**그리고 이것이 구 증류본의 히어로 배경값을 오염시키고 있었다.** 구본은 히어로 `bg: rgb(0,0,0)`으로 적었는데, 그 검정은 페이지가 아니라 **`v-modal` 마스크**였다. 수리본이 오버레이를 섹션에서 제외하자 히어로의 진짜 배경이 드러난다 — **`rgb(246, 243, 242)`(따뜻한 오프화이트)**. 위 "시각 확인"에 적은 *"히어로만 검정이고 나머지는 흰색/연회색"*은 **이 오염 때문에 잘못 읽은 것**이다. 정정한다: 히어로가 어두워 보이는 건 ① 차량 사진 자체와 ② 모달 마스크 때문이고, **섹션 배경은 오프화이트다.**

**섹션 9개 → 10개**(모바일 12개). 눈으로 센 9~10개와 ±1 안이다. 아래 표는 **2026-08-17 최종 계기**(문턱 0.75 / 깊이 14) 기준이며, 데스크톱 10개는 중간 계기(12:05판)와 동일하다 — 이 사이트는 문턱을 더 내려도 결과가 안 바뀐다(실제 `<section>` 태그를 쓰고 컨테이너가 1180으로 뷰포트의 0.82라 애초에 여유가 있다).

달라진 점 넷:
- **`bgSequence`가 실제 색을 문다.** 구본 `rgb(0,0,0) → null×8`(모달 오염) → 신본 **`rgb(246,243,242) → null×7 → rgb(246,243,242) → rgb(28,27,27)`**. 오프화이트로 열고 오프화이트로 닫은 뒤 최하단만 다크(`#1C1B1B`)다.
- **푸터가 둘로 쪼개진다**(`y=6588 h=266` 링크 3열 + `y=6854 h=475` 다크 바). 배경색이 실제로 갈리므로 분리가 맞다.
- **컨테이너가 1180 하나 → 1380 / 1180 / 1120 세 종.** 본문 5개 섹션이 **1180**, Events만 **1380**으로 200px 넓고, 푸터 두 블록이 **1120**으로 60px 좁다. 히어로와 Model은 컨테이너 없이 풀블리드다.
- **높이 리듬**: 950 / 745 / 877 / 767 / 856 / 722 / 835 / 616 / 266 / 475.
- **남은 결손 하나 — 히어로 headline.** #1의 headline이 `이전 슬라이드 이동`(캐러셀 화살표의 스크린리더 라벨)으로 잡힌다. 히어로 카피가 모달에 가려 트리에 온전히 안 들어온 탓이다. 나머지 7개 섹션 표제(44px)는 전부 정상이다.

> 중간 계기(02:18판)에서는 Events도 `y=5239 h=513` + a11y 라벨로 놓쳤는데, **12:05판에서 `y=4917 h=835 "Events"`로 복구됐다.**

**record 재실행 — 여전히 hover 0건 · reveal 0건 · 실행중 애니메이션 0건.** 셀렉터 수리(header/nav/banner/cookie/consent/curtain 제외 + y축 분산)로는 안 풀린다. 당연한 결과다 — 위 ⑤에서 규명했듯 문제는 **셀렉터 선택이 아니라 포인터 가로채기**이고, `layers`가 방금 그 가로채는 물체(`v-modal`, fixed, 1440×900 전면)를 별도로 확인해 줬다. **⑤ 실패 판정 유지**, 사유는 이제 추정이 아니라 두 계기가 독립적으로 가리키는 사실이다.

**최종 판정: 리드 자격 있음(조건부) 유지.** 골격 근거는 더 강해졌다 — 배경 오염 제거(`#000` → `rgb(246,243,242)`), 컨테이너 3종(1380/1180/1120) 분리, 푸터 2분할, Events 표제 복구. 모션은 여전히 사용 불가하고, 모달이 안 뜨는 조건에서 record를 다시 돌려야 한다는 제약도 그대로다. **담당 5종 중 계기 변경에 결과가 흔들리지 않은 유일한 사이트다** — 실제 `<section>` 태그를 쓰고 컨테이너가 뷰포트의 0.82라 문턱 어디에서도 안정적으로 잡힌다.
