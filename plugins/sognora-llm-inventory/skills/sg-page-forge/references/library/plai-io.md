# plai.io 분석

장르/단위: 마케팅 SaaS(멀티플랫폼 광고 운영 도구) / 랜딩 1페이지 · 분석일 2026-08-15 · 상태: **완전** (detect + probe + 풀페이지 캡처 5조각 육안 확인 + 호버 실측)

측정 조건: 1440×900, light, 문서 전체 높이 13,293px, 콘텐츠 컨테이너 1224px(좌우 여백 108px). Webflow 제작.

## 수치

**폰트 8단** — 16 / 18 / 22 / 24 / 27 / 48 / 60 / **115.2**px
빈도 실측(텍스트 노드 보유 요소 기준): `16/400` 120회 → `18/700` 84회 → `18/400` 27회 → `22/400` 20회 → `48/700` 13회 → `24/700` 12회 → `115.2/700` 3회 → `60/700` 3회 → `27` 1회.
본문은 명확히 **16px/400**, 그래서 **디스플레이 배율 7.2×**(115.2 ÷ 16). 문단 주력인 18px 기준으로 잡아도 6.4×. 8단 목록의 중앙값(25.5) 기준으로는 4.5×지만, 이 사이트가 실제로 체감시키는 건 7.2× 쪽이다 — 카드·내비·푸터가 전부 16px이라 16이 진짜 바닥이다.

**웨이트는 400 / 500 / 700 셋뿐.** 500은 폼 라벨과 내비 일부에만 쓰인다. 사실상 400과 700의 2단 대비.

**트래킹**: 115.2px에 `-1.6px`(-0.014em), 48px에 `-0.8px`(-0.017em), 본문은 `normal`. 디스플레이만 음수 트래킹, 본문은 손대지 않음.
**행간**: h1 120.96px(1.05), h2 51.84px(1.08), 본문 27.9px(1.55). **디스플레이는 1.05까지 조이고 본문은 1.55로 푼다** — 배율보다 이 대비가 크다.

**밀도**(contentArea ÷ 섹션면적) 중앙값 **39.1%**
섹션별: s0 153% · s1 80% · s2 39% · s3 22% · s4 27% · s5 114% · s6 28%.
100%를 넘는 두 곳(히어로+통계밴드, 최종 CTA 밴드)은 스크립트가 절대배치·풀블리드 배경을 겹쳐 세기 때문이고, 의미 있는 실제 폭은 **22~80%**. 제품 스크린샷을 끼고 있는 구간이 80%, 카드 그리드·FAQ가 22~27%. **자산이 있는 구간은 꽉 차고, 텍스트만 있는 구간은 과감히 비운다.**

**고유 정보성 자산 24개** (`imagesInformative` 고유 URL 수 = 24, 재사용 0).
장식 자산에서만 재사용 발생: `stars.svg` ×19(후기 별점), `Icon.svg` ×6, `Cross icon.svg` ×4.

## 자산 운용

**핵심 문법: "제품 스크린샷 1장 = 섹션 1개".** 스텝 4연작 + 에이전시 2섹션, 총 6개 섹션이 각각 1224px 폭 자산 1장만 갖는다. 장식 일러스트는 히어로의 작은 산봉우리와 푸터 로켓뿐 — 본문 구간엔 0개.

**스크린샷 프레이밍 — 플레이트는 CSS가 아니라 이미지에 구워져 있다.** 측정해 보면 이미지 래퍼(`.wrapper.features`)는 배경 `transparent`, radius 0, 그림자 none이다. 즉 눈에 보이는 파스텔 플레이트는 **디자인 툴에서 앱 캡처를 색 캔버스 위에 올려 한 장으로 익스포트한 것**. 이미지 자체는 1224×689(스텝0만 724), `border-radius: 8px`.
- 플레이트 색이 섹션마다 다르다: 페리윙클 `#BDBAEC` → 크림 `#FFF5D2` → 민트 `#B9E1E9` → 인디고 `#1209BD` → 민트-페리윙클 그라데이션. **같은 레이아웃의 반복을 색으로만 구분한다.**
- 크롭: 앱 UI가 플레이트 안쪽에서 **우측·하단으로 잘려 나간다**(테이블 컬럼이 잘린 채 끝남). 브라우저 크롬·디바이스 목업 **일절 없음**. "전체를 보여주지 않는다"가 규칙.
- 화면은 실제 제품이고 실제 데이터다: $13,267.84 / CPC $1.03 / CTR 2.96%, 광고 크리에이티브 그리드에 실제 나이키 신발 소재가 들어 있다.

**로고 문법 두 벌을 의도적으로 병용**
1. 통계 밴드 고객사 6개 → **흰 단색, 폭 비균등**(원본 비율 유지)
2. As featured in 언론 8개 → **풀컬러, 원본 사각 락업 그대로**
3. 통합 카드 6개 → **풀컬러 브랜드 마크**(Meta 파랑, Google 사색, Stripe 보라 워드마크)
히어로의 플랫폼 아이콘 13개만 반대로 **전부 무채색**. 같은 성격의 자산도 위치에 따라 채도 정책을 뒤집는다.

**고유 24 / 재사용 0** — 정보성 이미지는 단 한 장도 돌려쓰지 않는다. 재사용은 장식(별 ×19, 아이콘 ×6, 크로스 ×4)에서만.

**요약: 호버가 살아 있는 건 버튼·링크·캐러셀 화살표뿐. 카드·후기·FAQ·푸터 링크는 전부 죽어 있다.** 대신 살아 있는 것들은 색 반전이나 회전 같은 "확실히 보이는" 변화를 준다 — 미묘한 그림자 승격 같은 건 하나도 없다.

### 스크롤 리빌

- 정지 상태 숨김 요소 **29~30개**, 전부 `opacity: 0` → 1. **`transform` 변화 없음(translateY 0).** 페이드 인 단 하나의 패턴.
- 대상은 예외 없이 **섹션 제목 + 그 서브카피 한 쌍**. 이미지·카드·폼은 리빌 대상이 아니다 — 즉 "말이 나타나고 그림은 처음부터 거기 있다".
- 실제 사람 속도로 스크롤하면 **29/29 전부 발화**(재현 확인). probe의 빠른 스크롤 패스에서는 30 중 26만 발화 — **빠른 스크롤에 취약**하고, 이게 detect의 QF2 🔴(정지 상태 미표시 텍스트 2건)의 정체다.

### 모션 언어

- duration 상위: **`0.2s` 39회, `0.1s` 38회** — 두 값이 전부. 0.3s 이상 없음.
- easing: **`ease` 77회 단일**. 커스텀 cubic-bezier 0건.
- 애니메이트 속성: `background-color` 26 · `color` 22 · `opacity` 16 · **`all` 10** · `transform` 3.
- `transition: all` **10건 존재** — 정리되지 않은 채 남아 있다(카드가 그 예: all인데 호버 규칙이 없음).
- 캐러셀만 별도 타이밍: `data-duration=800`, `data-delay=3000`, `data-easing=ease`, `data-infinite=false`. 슬라이드 650px + 간격 208px = **스텝 858px**, 19장. 좌우로 넘쳐 이웃 카드가 잘려 보이는 peek 캐러셀.
- 미디어: `<video>` 0, `<canvas>` 0, `<iframe>` 2. **동영상 없이 GIF 1장으로 움직임을 처리한다.**

### 고정 내비 거동

- `.sticky-nav-div`, `position: fixed`, `top: 0`, 높이 108px, 배경 흰색 불투명(**backdrop-filter 없음**), 그림자 `0 10px 50px rgba(15,31,61,.06)`.
- 정지 상태에서는 `top: -120px`에 **화면 밖으로 파킹**돼 있다(히어로 위에는 별도의 투명 내비가 얹혀 있음).
- 히어로를 지나면 `translateY(120px)`로 내려와 자리를 잡는다. **한 번 내려오면 다시 숨지 않는다** — 아래로 더 스크롤해도(2500 / 5000px 지점) 위로 되돌려도(-800px) 계속 top:0 유지. 흔한 "위로 스크롤 시에만 표시" 패턴이 아니라 **"히어로 통과 후 상주"** 패턴.

## 배울 것

1. **디스플레이 배율 7.2× (115.2px ÷ 본문 16px)** — 웨이트는 700 하나로 두고 크기 대비만으로 임팩트를 만든다. 400/500/700 3단이면 충분.
2. **행간 대비를 배율과 함께 움직여라**: 디스플레이 1.05(115.2/120.96), 본문 1.55(18/27.9). 큰 글씨를 조이고 작은 글씨를 풀어야 배율이 "크다"가 아니라 "정리됐다"로 읽힌다.
3. **디스플레이에만 음수 트래킹**(115.2px에 -1.6px = -0.014em, 48px에 -0.8px = -0.017em), 본문은 `normal` 유지.
4. **통계 배너(LA2 🔴)를 살리는 유일한 조합**: 수치 3개를 세로 헤어라인으로 구획하고, **같은 밴드 안에 실고객 로고 6개를 붙인다.** 수치만 있으면 공허하고, 로고가 붙는 순간 검증된 수치가 된다.
5. **번호를 뱃지가 아니라 제목 문자열에 넣는다** — `0. Set Up Your Brand`. 별도 스텝 인디케이터 UI가 사라지고 목차가 헤드라인 자체가 된다. 0부터 시작하는 것도 의도적.
6. **동일 레이아웃 4연작을 색으로만 구분한다.** 스텝 0~3이 구조적으로 완전히 동일한데(중앙 제목 → 서브 → 1224px 자산 1장 → 상하 패딩 80px), 스크린샷 플레이트 색을 페리윙클 → 크림 → 민트 → 인디고로 갈아 지루함을 막는다. 레이아웃을 바꾸는 것보다 싸고 안전하다.
7. **반복 블록 중 딱 하나에만 CTA를 준다.** 4연작 중 2번에만 화살표 링크가 있다. 넷 다 주면 리듬이 죽고, 넷 다 안 주면 출구가 없다.
8. **CTA를 버튼이 아니라 서브카피 안의 인라인 파란 볼드 링크로 처리** — "Generate ... from one AI-powered **Creative Hub**." 문장을 읽는 흐름에서 링크가 튀어나온다. 버튼 개수를 늘리지 않고 진입점을 늘리는 법.
9. **스크린샷은 잘라서 쓴다.** 브라우저 크롬·디바이스 목업 없이, 앱 UI를 색 캔버스 위에 얹어 **한 장의 이미지로 구워** 우측·하단을 잘라낸다(1224×689, radius 8px). 전체를 보여주지 않는 게 오히려 "더 있다"를 만든다.
10. **로고 채도 정책을 위치별로 뒤집는다**: 고객사=흰 단색, 언론=풀컬러 원본 락업, 통합 카드=풀컬러 브랜드 마크, 히어로 플랫폼 아이콘=무채색. "로고는 전부 회색조로" 같은 단일 규칙보다 맥락별 규칙이 낫다. 로고 폭을 억지로 균등화하지 않는 것도 포함.
11. **화살표 링크 호버 = 화살표 `rotate(-45deg)`** (→ 가 ↗로). 색·밑줄을 건드리지 않고 방향 하나로 "여기서 나간다"를 말한다. 캐러셀 화살표는 `translateX(5px)` + 배경 `#145AFF` 점등.
12. **최종 CTA 밴드를 228px로 얇게.** 풀스크린 CTA 섹션 대신 좌 헤드라인 / 우 버튼 한 줄 띠. 페이지를 늘리지 않고 마지막 출구를 만든다.
13. **폼 플레이스홀더에 농담을 심는다** — `Steve Wozniak` / `thewoz@apple.com` / `Apple`. 입력 필드는 보더 0, 배경 `#F1F3F6`, radius 12, 높이 60. 필드 배치도 2열 → 반폭 1열 → 전폭 텍스트영역으로 일부러 비대칭.
14. **비대칭 좌우 분할을 페이지당 두 번만 쓴다**(통합 카탈로그, FAQ). 중앙 정렬이 14블록 지배하는 페이지에서 두 번의 좌우 분할이 챕터 전환처럼 읽힌다. 좌: 파란 대문자 아이브로(16/700, 자간 2px) + 48px 2줄 제목, 우: 본문 + 화살표 링크 + 헤어라인.
15. **모션 예산 = duration 2값(0.1s / 0.2s) × easing 1값(`ease`).** 스크롤 리빌은 `opacity` 단독, translateY 없음. 커스텀 베지어 0건으로도 성립한다.
16. **고정 내비는 "히어로 통과 후 상주"**: `top:-120px`에 파킹 → `translateY(120px)`로 진입 → 이후 숨지 않음. 스크롤 방향마다 나타났다 사라지는 내비보다 예측 가능하다. 불투명 흰 배경 + `0 10px 50px rgba(15,31,61,.06)`, backdrop-filter 없음.
17. **후기는 아웃라인 별 + 실제 아바타 + 길이 제각각**으로. 별을 채우지 않고(파란 아웃라인 5개), 카드 높이를 인용문 길이대로 두고, 650px 카드가 좌우로 잘려 나가게 둔다(peek 캐러셀, 스텝 858px, 19장, autoplay 3s / 800ms).
18. **카드 그림자를 오프셋 + 초대형 블러로**: `17px 17px 200px rgba(64,69,79,.06)`. 대칭 그림자가 아니라 우하향 오프셋에 200px 블러, 알파 6%. 흰 배경 위 흰 카드를 보더 없이 띄우는 방법.

## 버릴 것

- **`radius: 12px` 100% 지배(34/34)** — 버튼·카드·입력·칩이 전부 같은 곡률이라 위계가 0이다. 이 페이지에서 유일하게 다른 값은 스크린샷 이미지의 8px인데, 그건 이미지 속성이라 눈에 안 잡힌다. 최소 2단(예: 컨트롤 8 / 컨테이너 16~20)으로 갈라야 한다.
- **카드·후기·FAQ·푸터 링크 호버 전멸.** `transition: all`만 선언해 두고 호버 규칙이 없는 `.integration-card`가 상징적이다. 클릭 가능한 587×280 카드가 마우스에 아무 반응이 없다.
- **내비 CTA의 그린 `#1EBD53` 호버.** 정지색 `#6E7687`(무채색 슬레이트)에서 그린으로 튀는데, 그린은 페이지 어디에도 없는 색이다(브랜드 블루·네이비뿐). 게다가 같은 문구 `Start Free` 버튼이 히어로에서는 파랑→네이비로 다르게 반응한다 — **동일 라벨·동일 목적지 버튼의 호버 언어가 두 개.**
- **Space Grotesk 단독 스택** — 2차 기본값. 배울 건 폰트 선택이 아니라 배율·행간·트래킹 정책이다. 폰트를 따라 쓰면 그냥 2023년 SaaS 랜딩이 된다.
- **스크롤 리빌이 빠른 스크롤에 취약** — 30 중 4가 미발화 상태로 남는 경우가 재현된다. `opacity:0` 초기값에 IntersectionObserver를 걸 때는 fallback(빠른 스크롤·prefers-reduced-motion·JS 실패)이 필요하다. 제목과 서브카피가 통째로 안 보이는 실패 모드다.
- **width/height 미지정 이미지 83개** — 1224×689짜리 대형 자산이 6장이나 되는 페이지에서 CLS를 방치했다.
- **텍스트·aria 없는 아이콘 11개**(히어로 플랫폼 아이콘 일부, 통합 카드 로고, 푸터 소셜). 히어로 아이콘 13개는 alt를 잘 채웠는데(`Plai AI Spotify Ads` 등) 나머지가 비었다 — 절반만 한 접근성.

- **⚡ 이모지를 헤드라인 문자열에 직접 박기**(`⚡Trusted by 200K+ campaigns`) — 48px 디스플레이에 OS 기본 이모지가 붙어 폰트 톤이 깨진다. 아이콘이 필요하면 SVG로.
