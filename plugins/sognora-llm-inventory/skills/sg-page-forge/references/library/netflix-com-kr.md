### 한글 조판 — 브랜드 서체에 한글이 없다

이 페이지에서 가장 중요한 한국어 로케일 발견이다. `@font-face` 17건을 전수로 뜯고, 캔버스가 아니라 **실제 DOM 노드 폭 측정**으로 판정했다.

```
'영화무제한' 200px 700 렌더 폭 (px)
  "Netflix Sans"                            865.00
  "Netflix Sans","Helvetica Neue"           865.00
  "Helvetica Neue"                          865.00
  "ZZZNope"  (존재하지 않는 폰트)             865.00   ← 전부 동일
  serif                                     999.03   ← 다른 폰트일 때만 값이 바뀐다
```

**Netflix Sans 계열에 한글 글리프가 없다.** 한글이 들어간 순간 선언 스택 `"Netflix Sans","Helvetica Neue","Segoe UI",Roboto,Ubuntu,sans-serif`를 전부 통과해 **OS 기본 산세리프**가 그린다. 웹폰트로 로드되는 건 `Netflix Sans 400/500/700` 3벌이고, 이들이 실제로 담당하는 글자는 **`7,000` `TV` `PlayStation` `Xbox` `Chromecast` `Apple TV` `iOS` `Android` `netflix.com` 그리고 쉼표·괄호**뿐이다.

로케일별 대응 서체는 있는데 한국어만 없다 — `NKufi`(아랍어), `GraphikTH`(태국어), `Netflix Sans JA`(일본어). **한국어는 시스템 폰트에 맡기기로 한 결정이다.**

그래서 이 페이지의 한글 조판 3원칙이 전부 "시스템 폰트를 견디는" 방향으로 정렬돼 있다:

1. **`letter-spacing: normal` 전역** — 어떤 서체가 올지 모르니 자간을 건드리지 않는다. (`ohou.se`가 Pretendard 전제로 `-0.3px`을 전역에 거는 것과 정확히 반대 결정이고, 둘 다 옳다. **자간은 서체를 아느냐 모르느냐의 함수다.**)
2. **`word-break: keep-all` 전역** — 어절 중간에서 안 끊는다. 페이지의 모든 문자열이 1st-party 편집 카피라 가능한 선택이다.
3. **행간을 넉넉히 고정** — 1.25/1.5. 시스템 폰트는 OS마다 실제 자체 높이가 달라서, 행간을 조이면 특정 OS에서만 붙는다.

`keep-all`이 실제로 만든 줄바꿈(390 실측):

```
영화, 시리즈 등을
무제한으로                     ← 어절 경계
7,000원으로 시작하세요. 멤버십은 언제든지 해지
가능합니다.                    ← "해지 / 가능합니다" 어절 경계
```

## 실측 토큰 — `:root` 변수가 0개다

`:root`/`html`/`body`에 선언된 CSS 커스텀 프로퍼티: **0개.** 전수 조사 결과다.

대신 **Hawkins 디자인 시스템이 레이아웃 값을 인라인 `--hcw--*` 변수로 컴파일해서 요소마다 박는다.** 그런 요소가 페이지에 **71개**.

```html
<div data-layout="container"
  style="--hcw--layout-container--columnSpacing:0px;
         --hcw--layout-container--flexDirection:row;
         --hcw--layout-container--justifyContent:center;
         --hcw--layout-container--padding:0px;
         --hcw--layout-container--rowSpacing:0px;
         --hcw--layout-container--width:100%">
```

브레이크포인트가 **7단(`xs s m l xl xxl xxxl`)**이고, 반응형 prop이 변수 접미사로 펼쳐진다:

```
--hcw--layout-item--flex-xs   : 0 0 calc(100% - 0.75rem)      ← 1열
--hcw--layout-item--flex-s    : 0 0 calc(50%  - 0.75rem)      ← 2열
--hcw--layout-item--flex-m    : 0 0 calc(33.33% - 0.75rem)    ← 3열

--hcw--layout-container--padding-xs  : 2rem 1rem
--hcw--layout-container--padding-l   : 1rem 2rem
--hcw--layout-container--columnSpacing-xs : 0.75rem
--hcw--layout-container--columnSpacing-l  : 1rem
```

**전역 토큰 계층 없이 컴포넌트 인스턴스 계약만으로 굴러간다.** `ohou.se`의 `--ds-*` 876개 3계층과 정반대 전략이다. 색·타이포는 emotion 해시 클래스(`default-ltr-iqcdef-cache-*`)에 하드코딩되고, **런타임에 바꿀 수 있는 건 레이아웃뿐**이다. 다크모드 토글이 없는(다크 고정) 페이지라서 성립한다.

H1 블록은 588px 폭에 `text-align: center`. 히어로 안에서 y=257~567 — **첫 화면(900px) 안에 폼까지 전부 들어온다.**

### 폼 — 부품이 3개다

```
[ 안내문 16/24 400 ]              588 × 24    y=471
[ 이메일 입력 413×56 ][ 8 ][ CTA 167×56 ]     y=511
```

- 입력창 실제 크롬: `background: rgba(22,22,22,.7)` + `border: 1px solid rgba(128,128,128,.7)` + `radius: 4px`. **반투명이라 뒤 포스터가 비친다.**
- `placeholder`가 **없다.** `이메일 주소`는 `<label>`이고 `position: absolute`로 필드 안에 떠 있다.

- 인풋과 버튼 사이 **8px**. 버튼 `margin-left: 8px`로만 만든다.
- 모바일(390)에서는 인풋 폭 100%(326), CTA는 **아래로 떨어져 가운데 정렬 126×48**.

### Top 10 캐러셀 — 순위 숫자를 카드 밖으로 내보낸다

```
컨테이너 x=148 ────────────────────────────────── 1144 ──
        │
        │  [1]카드 x=170 ──180──┤  44  ├── x=394 ──180──┤ …
        └──22──┘
         ↑ 순위 숫자가 여기 61.2×127로 들어앉는다 (x=148, 카드 하단 정렬)
```

- 카드 **180×252** = 정확히 **5:7 포스터비**. 피치 **224**(카드 180 + 간격 44).
- 카드 10장 → `scrollWidth 2240` / `clientWidth 1144`. 10 × 224 = 2240, **딱 떨어진다.**
- `overflow-x: scroll` + **`scroll-snap-type: x mandatory`**.
- 순위 숫자 박스 **61.2 × 127**, x=**148** — 카드보다 **22px 왼쪽**, 즉 컨테이너 왼쪽 끝에 정확히 붙는다. 하단은 카드 바닥(y=1306)과 **정렬**.
- 첫 카드가 x=170에서 시작하는 이유가 이것이다. **컨테이너가 숫자 오버행 22px를 미리 예약한다.**

카드 내부 4층:

```html
<button data-uia="top-10-element-1">
  <div>                                          ← 180×252, radius 8, bg #232323
    <div style="animation-delay:0ms">…</div>     ← 스켈레톤, absolute inset-0, z:1
    <span style="background-image:url(…webp)">   ← 포스터, absolute inset-0, z:2

  </div>
  <span>                                          ← 순위 숫자, z:2

    <span aria-hidden="true" data-content="1">1</span>  ← 외곽선 레이어
  </span>

```

**포스터가 `<img>`가 아니라 `<span>`의 `background-image`다.** 그래서 페이지 전체 `<img>`가 2개(로고 + 히어로)뿐이다. 순위 숫자는 **같은 숫자를 두 번 겹쳐** 채움+외곽선을 만든다 — 위 레이어는 `aria-hidden`이라 스크린리더에 "11"로 안 읽힌다.

## 자산 운용

### ① 히어로 아트월은 라이브 그리드가 아니라 **구운 JPG 1장**

```
KR-ko-20260810-TRIFECTA-perspective_e8797612-….jpg
└─┬┘ └──┬──┘ └──┬───┘ └────┬────┘
 국가  로케일  빌드일자   레이아웃 코드
```

파일명에 **국가·로케일·빌드일자·레이아웃 이름**이 박혀 있다. 원본 **2000×1125(16:9)**, 394KB.

`srcset`으로 3단 배급:

| descriptor | 파일 | 적용 뷰포트 |
|---|---|---|
| `2000w` | `_large.jpg` | 1280 · 1440 · 1920 |
| `1279w` | `_medium.jpg` | 1024 |
| (small) | `_small.jpg` | 390 · 768 |

히어로 박스 높이도 같이 움직인다: **664 → 664 → 760 → 888 → 888 → 996.**

1440에서 2000×1125를 1440×888 박스에 `object-fit: cover` → 실제 렌더 1578×888, **좌우 138px(9.6%) 잘림.** 인물 얼굴이 중앙에 안 오게 설계된 "perspective" 레이아웃이라 잘려도 안 깨진다.

**이게 왜 중요한가:** 실시간 콘텐츠 그리드를 렌더하면 LCP가 카탈로그 API에 묶인다. 한 장으로 구우면 **LCP = 정적 CDN JPG 1개**가 된다. 콘텐츠 신선도는 파일명의 날짜(`20260810`)로 관리 — **주 단위로 다시 구워 배포한다.**

### ② 스크림이 2스톱이 아니라 13스톱이다

### ③ 섹션 경계를 선이 아니라 **곡면**으로 만든다

히어로 바닥 y=788에 놓인 요소 하나가 전부다:

```css

                    rgba(64,97,231,.4) 80%, rgba(0,0,0,.1) 100%);
border-radius: 50% 50% 0 0 / 100% 100% 0 0;        /* 타원 상단 */
border-top: 4px solid transparent;
```

검은 타원 커튼이 히어로 아래에서 100px 올라오고, 그 안쪽에 **푸른보라 블룸**(`rgba(64,97,231,.4)`)이 번진다. 타원 테두리를 따라 히어로의 붉은 글로우가 새어 나와 **자홍색 헤어라인**으로 보인다. 폭을 1872px로 키운 덕에 곡률이 완만하다 — 1440px로 잡으면 반원처럼 튄다.

검정 위 검정 섹션을 나누는 문제를 **선 대신 곡률과 색 번짐**으로 푼 사례다.

### ④ 스켈레톤이 디자인의 일부다

```css
.skeleton {
  position: absolute; inset: 0; z-index: 1;
  border-radius: .5rem; background-color: rgb(35,35,35);
  animation: loading 4000ms infinite linear;
}
@keyframes loading {
  0%   { background-color: rgb(35,35,35); }
  40%  { background-color: rgb(35,35,35); }   /* 40%까지 정지 */
  70%  { background-color: rgb(65,65,65); }   /* 밝아졌다 */
  90%  { background-color: rgb(35,35,35); }   /* 돌아온다 */
}
@media (prefers-reduced-motion) { .skeleton { animation: none; } }
```

- 주기가 **4초**로 길다. 흔한 1.5초 시머보다 훨씬 느긋해서 **초조해 보이지 않는다.**
- **0~40%가 완전 정지 구간**이다. 빠르게 로드되면 사용자는 애니메이션을 아예 못 본다.
- 카드마다 인라인 `animation-delay`로 **스태거**를 준다.
- `prefers-reduced-motion`에서 **끈다.**
- 카드 배경도 같은 `#232323`이라, 이미지가 실패해도 **빈 구멍이 아니라 회색 포스터 자리**로 남는다.

### ⑤ 폰트: `font-display: optional`

`@font-face` **17건 전부** `font-display: optional`(가변폰트 4건만 `swap`).

`optional`은 ~100ms 블록 후 준비 안 됐으면 **그 페이지뷰 동안 웹폰트를 아예 안 쓴다.** 스왑이 없으니 **폰트로 인한 CLS가 0**이다. 브랜드 서체 노출을 포기하고 레이아웃 안정성을 산 것이다.

한국 로케일에선 이 트레이드오프가 거의 공짜다 — **어차피 한글은 시스템 폰트가 그린다.** 실제로 로드되는 3벌(400/500/700)이 담당하는 건 라틴·숫자뿐이라, 못 받아도 잃는 게 `7,000` 숫자 모양 정도다.

### ⑥ 아이콘

인라인 SVG **13개**. Hawkins가 아이콘을 `--hcw--icon--mask-{small|medium|large|extra-large}` 변수의 `mask-image`로 배급 — 크기 4단이 변수로 스위칭된다.

## 배울 것

### 1. 링크 예산을 먼저 정하고 페이지를 짠다

3,276px 페이지의 `<a>`가 19개, **헤더에는 1개**(로그인)뿐이다. 요금제·콘텐츠·회사소개 어느 것도 헤더에 없다. 전환형 랜딩에서 헤더 내비게이션은 **이탈 경로 목록**이다. 이 페이지는 그걸 통째로 지웠고, 대신 사용자가 궁금해할 것을 **FAQ 6개로 페이지 안에서 처리**한다.

적용: 랜딩을 짤 때 "섹션 몇 개"보다 **"이 페이지를 떠나는 방법이 몇 개인가"**를 먼저 세라. 목표 동작 외 링크가 헤더에 2개 이상이면 전환형이 아니다.

### 2. 반복 CTA는 변형하지 말고 **같은 컴포넌트를 그대로** 두 번 쓴다

y=511과 y=2506의 두 CTA는 **167×56px, 24px/500, `#E50914`, `radius: 4px`, `padding: 12px 24px`, 좌측 마진 8px까지 전부 동일**하다. 안내문("시청할 준비가 되셨나요?…")도 **글자 하나 안 바뀐다.**

흔한 실수가 두 번째 CTA를 "지금 바로 시작하세요!" 식으로 변주하는 것이다. 그러면 사용자는 **다른 동작인 줄 안다.** 같은 폼을 같은 문구로 다시 내미는 건 반복이 아니라 **재확인**이다.

적용: 반복 CTA는 복사가 아니라 **같은 컴포넌트 인스턴스**로 만들어라. 카피 변주를 하고 싶으면 그건 CTA가 두 종류라는 뜻이고, 단일 목표가 아니라는 뜻이다.

### 3. 섹션 간격을 **하나의 값**으로 고정하고 구분선을 없앤다

섹션 5경계가 전부 **64px**. 폭 900px 넘는 1px 라인이 페이지에 **0개**. 검정 단일 배경 위에서 **간격만으로** 섹션이 갈린다.

구분선은 "여기가 경계다"를 말해주는 대신 **읽는 흐름을 끊는다.** 간격이 일정하면 선이 없어도 경계가 읽히고, 페이지가 하나의 문서처럼 흐른다.

적용: 섹션 간격을 1값으로 잠근 뒤 구분선을 전부 빼 보라. 그래도 경계가 읽히면 선은 처음부터 불필요했던 것이다.

### 4. 아트워크는 **날짜가 박힌 정적 이미지 1장**으로 굽는다

`KR-ko-20260810-TRIFECTA-perspective_….jpg` — 국가·로케일·빌드일자·레이아웃이 파일명에 있다. 수십 개 포스터가 원근으로 깔린 화면이 **API 호출 0회, 이미지 요청 1회**로 나온다.

"신선해 보이는 콘텐츠 벽"과 "빠른 LCP"는 보통 상충하는데, **신선도를 렌더링이 아니라 배포 주기로 옮기면** 둘 다 얻는다.

적용: 히어로에 콘텐츠 그리드가 필요하면 실시간 렌더 대신 **주기적으로 굽는 합성 이미지**를 검토하라. 파일명에 날짜를 넣어 캐시 무효화와 갱신 이력을 동시에 해결한다.

### 5. 이미지 위 스크림은 **2스톱이 아니라 12등분 이징**으로 만든다

`rgba(0,0,0,.8) → transparent` 대신 8.333% 간격 13스톱. 어두운 아트 위에서 2스톱 그라디언트는 **밴딩이 눈에 보인다.**

그리고 히어로 스크림이 `0.85 → 0.6`으로만 떨어진다 — **아트가 완전히 노출되는 구간이 0이다.** 어떤 포스터가 들어와도 흰 글자 대비가 보장된다.

적용:
```css
/* 이렇게 말고 */
background: linear-gradient(rgba(0,0,0,.85), transparent);
/* 이렇게 */
background: linear-gradient(rgba(0,0,0,.85) 10%, rgba(0,0,0,.82) 32%,
            rgba(0,0,0,.765) 46%, rgba(0,0,0,.686) 61%,
            rgba(0,0,0,.63) 75%, rgba(0,0,0,.6) 97%);
```
**그리고 최저 알파를 0으로 내리지 마라.** 텍스트가 얹히는 영역이면 하한을 0.6 근처에 둔다.

### 6. 폼은 **라벨 1개 + 버튼 1개**로 줄이고, 플로팅 라벨로 자리를 미리 비운다

`placeholder`가 없다. `<label>`이 필드 안에 떠 있다가 포커스 시 `top: 8px / 12px`로 축소 이동하고, 인풋 `padding: 24px 16px 8px`이 그 자리를 **처음부터 비워둔다.** 라벨이 움직여도 **레이아웃이 1px도 안 밀린다.**

placeholder-only 폼은 값을 입력하는 순간 무슨 필드였는지 사라진다. 플로팅 라벨은 그걸 해결하면서 필드 개수도 1개로 유지한다.

적용: 필드가 1개인 폼에서 placeholder 대신 플로팅 라벨을 쓰고, **인풋 패딩으로 라벨의 최종 위치를 선점**하라. 진입 이징은 감속(`cubic-bezier(.32,.94,.6,1)`), 복귀는 가속(`cubic-bezier(.4,0,.68,.06)`)으로 나눈다.

### 7. 장식 요소를 **컨테이너 여백 안으로** 밀어넣어 폭을 벌지 않는다

Top 10 순위 숫자(61.2×127)가 카드보다 **22px 왼쪽**, 정확히 컨테이너 좌측 끝(x=148)에 붙는다. 첫 카드는 x=170에서 시작한다. 숫자가 카드 안에 들어갔다면 포스터를 가리거나 카드를 키워야 했다.

**여백은 비워두는 곳이 아니라 오버행을 받는 곳으로도 쓸 수 있다.**

적용: 카드 밖으로 나가는 장식(순위·뱃지·번호)은 컨테이너 패딩을 그만큼 예약해서 받아라. 오버행 폭을 첫 아이템 오프셋으로 정확히 상쇄하면 정렬이 안 깨진다.

### 8. 스켈레톤을 **느리게, 늦게 시작하게, 끌 수 있게** 만든다

4000ms 주기 · **0~40% 정지** · 카드별 `animation-delay` 스태거 · `prefers-reduced-motion`에서 `none` · 스켈레톤 색과 카드 배경이 같은 `#232323`.

1.5초 시머를 전 카드가 동시에 돌리면 페이지가 **깜빡이는 것처럼** 보인다. 4초에 앞 40%를 정지시키면 빠른 로드에서는 **애니메이션이 아예 안 보이고**, 느린 로드에서만 부드럽게 등장한다.

적용: 스켈레톤 주기를 2배 이상 늘리고 keyframe 앞부분을 정지 구간으로 둬라. 카드 그리드에는 반드시 스태거를 준다.

### 9. 브랜드 색이 **대비 하한선**이면 호버는 어두워지는 방향으로 간다

`#E50914` 위 흰 글자 = **4.79:1**. AA 일반 기준 4.5를 0.29 넘긴다. 밝히는 순간 깨진다. 그래서 호버가 `#C11119`(**6.25:1**)로 **어두워진다** — 시각적 피드백과 접근성이 같은 방향이다.

적용: 버튼 호버를 정하기 전에 **평상시 대비를 먼저 재라.** 4.5~5.5 구간이면 호버는 어둡게 갈 수밖에 없다. "호버는 밝게"는 대비 여유가 있을 때만 성립하는 관습이다.

### 10. 한국어 페이지에서 **웹폰트에 한글이 없다면** 조판 규칙 3개를 그에 맞춘다

Netflix Sans에 한글이 없어서 시스템 폰트가 그린다. 그 전제 위에서 세 결정이 일관된다 — `letter-spacing: normal` 전역(어떤 서체가 올지 모른다), `word-break: keep-all` 전역(1st-party 카피뿐이다), 행간 1.25/1.5로 넉넉히(OS별 자체 높이 차이를 흡수).

**자간은 서체를 아느냐 모르느냐의 함수다.** Pretendard를 확정한 페이지가 `-0.3px`을 전역에 거는 것과, 서체가 미정인 페이지가 `normal`로 두는 것은 같은 원칙의 두 결과다.

적용: 한글 웹폰트를 안 싣기로 했다면 자간을 **건드리지 마라.** 그리고 행간을 조이지 마라. 반대로 서체를 확정했다면 그 서체 기준 자간을 전역에 걸어도 된다.

### 11. 스크롤 연출과 스티키 UI를 **0으로 두는 것도 선택지**다

리빌 0건, 스티키 0건, 스무스 스크롤 0건. 헤더는 위로 그냥 사라진다.

전환 페이지에서 스크롤 연출은 **"여기서 멈춰 구경하라"는 신호**다. 목표가 폼 제출 하나라면 그 신호는 목표와 경쟁한다. 대신 이 페이지는 하단에 폼을 한 번 더 놓아서 "다 봤으면 여기"로 받는다.

적용: 스크롤 리빌을 넣기 전에 **그 애니메이션이 목표 동작을 돕는지 늦추는지** 판단하라. 전환형이면 기본값을 0으로 두고, 정말 필요한 곳만 추가하는 방향이 맞다.

### 12. 검정 위 검정 경계는 **선이 아니라 곡률로** 나눈다

1872×100 요소 하나 — 뷰포트보다 432px 넓게, `border-radius: 50% 50% 0 0 / 100% 100% 0 0`으로 타원 상단을 만들고, 안쪽에 푸른보라 블룸을 깐다. 히어로의 붉은 글로우가 타원 테두리로 새어 나와 자홍 헤어라인이 된다.

**폭을 뷰포트보다 크게 잡는 게 핵심이다.** 1440px로 잡으면 반원처럼 튀고, 1872px면 완만한 호가 된다.

적용: 같은 배경색 위에서 섹션을 나눠야 하면 `border-radius`의 **타원 문법**(`/`)과 **오버사이즈 폭**을 조합하라. 곡률 = f(폭 / 높이)이므로 폭으로 조절한다.

### 13. 전역 토큰 없이 **컴포넌트 인라인 계약**만으로 가는 길도 있다

`:root` 커스텀 프로퍼티 0개. 대신 71개 요소가 인라인 `--hcw--layout-*` 변수를 들고 있고, 반응형 prop이 브레이크포인트 접미사(`-xs`~`-xxxl`)로 펼쳐진다.

**다크모드 토글이 없고 테마가 하나라면 전역 토큰 계층의 값이 줄어든다.** 런타임에 바꿀 필요가 있는 건 레이아웃뿐이므로, 색·타이포는 빌드타임 클래스로 굳히고 레이아웃만 변수로 노출한 것이다.

적용: 토큰 시스템을 설계할 때 **"런타임에 바뀌어야 하는 값"과 "빌드타임에 굳어도 되는 값"을 먼저 나눠라.** 전자만 변수로 만든다.

## 버릴 것

### 1. FAQ 답변이 24px × 1,096px 측정 — 한 줄에 45자 이상

답변 패널 `1144px`에 `padding: 24px` → 실제 측정 폭 **1,096px**, 폰트 **24px**. 한글 24px 기준 한 줄에 **45~48자**가 들어간다. 편안한 측정은 한글 기준 **한 줄 25~35자**다.

실측 첫 답변이 그대로 3줄로 흐르는데, 눈이 다음 줄 시작점을 잃는다. `max-width: 60ch` 정도만 걸면 해결된다. **답변에 `max-width`가 아예 선언돼 있지 않다.**

### 2. FAQ 질문 행에 호버 피드백이 **없다**

probe 결과 `changed: {}`, `dead: true`. 1,144×84px = **96,096px²의 클릭 가능 영역**인데 커서를 올려도 아무 반응이 없다. 커서 모양 외에 "이게 눌린다"는 신호가 0이다.

같은 페이지의 포스터 카드는 `scale(1.05)`를 주고 버튼은 색이 바뀐다. **아코디언만 빠졌다.** 배경을 `#2D2D2D` → `#333` 정도로만 올려도 된다.

### 3. FAQ 질문과 답변이 **같은 24px/400**이라 위계가 없다

질문 `24px / 400`, 답변 `24px / 400`. 색도 둘 다 `#FFFFFF`. 열었을 때 어디까지가 질문이고 어디부터 답인지 **1px 구분선 하나로만** 구별된다.

질문을 500으로 올리거나 답변을 18px로 내리면 즉시 풀린다. 24px 본문은 데스크탑 랜딩에서 과하게 크기도 하다.

### 4. 입력 필드 테두리 대비가 **3.00:1 — 딱 걸침**

`rgba(128,128,128,.7)` on `#000` = **3.00:1**. WCAG의 비텍스트 대비 기준이 정확히 3:1이라 **소수점 아래로 내려가면 실패**다. 반투명이라 뒤 포스터 밝기에 따라 실효 대비가 더 떨어지는 구간도 생긴다.

이 페이지에서 **가장 중요한 단 하나의 인터랙티브 요소**의 경계선이 하한에 붙어 있다. `rgba(255,255,255,.5)` 정도면 여유가 생긴다.

### 5. `placeholder`가 없어 **입력 형식 힌트가 0**이다

라벨 `이메일 주소`만 있고 예시(`name@example.com`)가 없다. 플로팅 라벨 자체는 좋은 선택이지만, 라벨이 축소되어 올라간 뒤에는 **필드 안이 완전히 빈 상태**가 된다. 형식 오류를 입력 전에 막을 장치가 없다.

### 6. 히어로 아트가 좌우 **9.6% 잘린다**

2000×1125(16:9)를 1440×888(16:9.87) 박스에 `cover` → 렌더 1578×888, **좌우 138px 손실.** 1920에서는 세로가 잘린다. 아트를 16:9로 굽는데 히어로 박스는 브레이크포인트마다 다른 비율(664/760/888/996)이라 **어느 뷰포트에서도 원본 그대로 안 보인다.**

"perspective" 레이아웃이 잘림에 강하게 설계된 덕에 사고는 안 나지만, **아트 비율과 박스 비율이 어디서도 안 맞는 건 설계 미스**다. 박스 높이를 `aspect-ratio: 16/9`로 잡거나, 아트를 박스 비율에 맞춰 굽는 쪽이 맞다.

### 7. 광고형 배너의 −32px 겹침이 **모바일에서 의미를 잃는다**

데스크탑에서는 배너가 히어로 곡면 아래에 걸쳐 "히어로의 연장"처럼 읽힌다. 390에서는 팝콘 일러스트가 위로, 텍스트·버튼이 세로로 쌓이면서 **겹침의 의도가 사라지고** 그냥 카드 하나가 된다. 겹침을 유지하는 비용(z-index·음수 마진)만 남는다.

### 8. 12px 법인 고지가 한글 시스템 폰트로 5줄

`사업자등록번호` `통신판매업신고번호` 등 전자상거래법 고지가 **12px**. 한글을 시스템 폰트로 그리는 페이지에서 12px은 OS에 따라 렌더가 크게 흔들린다. 대비는 10:1로 충분하지만 **자체 크기가 문제**다. 법적 필수 고지를 14px로 올려도 디자인은 안 무너진다.

### 9. 히어로 이미지에 `fetchpriority="high"`가 없다

LCP 요소가 확실한 1440×888 히어로 JPG인데 `loading="auto"`, `fetchpriority` 미지정, `<link rel="preload">`도 없다. `srcset` 3단 배급까지 해놓고 **우선순위 힌트만 빠졌다.** 한 줄로 얻을 수 있는 LCP 개선을 안 가져가고 있다.

## 측정 방법 메모

- 표준 도구 4종(`detect`/`probe`/`capture`/`fetch-assets`) 전부 헤드리스에서 정상 통과. Akamai 차단 없음.

| 회색 버튼 | `rgba(128,128,128,0.4)` → `rgba(128,128,128,0.3)` | 19 |
| **FAQ 아코디언 행** | `transform: none` → **`matrix(1.05, 0, 0, 1.05, 0, 0)` = `scale(1.05)`**, 배경 `rgb(35,35,35)` 불변 | 27 |

셋 다 새 사실이다:
- **브랜드 레드 `#E50914`(229,9,20)가 호버에서 `#C11119`(193,17,25)로 어두워진다.** 밝기만 내리는 게 아니라 R을 −36, G를 **+8**, B를 +5 움직인다 — 순수 `brightness()` 필터가 아니라 별도로 고른 색이다.

- 회색 버튼은 **알파만** 0.4 → 0.3으로 낮춘다(색상 불변).

reveal은 여전히 **0건** — `scroll` 리스너가 없는 페이지라는 위 관찰과 정합한다. 실행중 애니메이션 10건 전부 `loading` 4000ms도 그대로.

**ir 재증류 — 데스크톱 섹션은 여전히 1개.** 문턱이 `0.85 → 0.8`로 내려왔는데도 안 잡힌다: 이 사이트의 컨테이너가 **1144 / 1440 = 0.794**라 **0.6%p 차이로 미달**한다. 위 ②의 진단이 그대로 유효하고, 필요한 문턱은 **0.79 이하**다.

> **"섹션 1개 = 로그인 게이트에 막혀 히어로만 수집됐다"는 해석은 오답이다.** 트리에 히어로 아래 콘텐츠가 전부 들어 있다 — 텍스트 노드로 `지금 뜨는 콘텐츠` · `가입해야 하는 또 다른 이유` · `자주 묻는 질문` · `시청할 준비가 되셨나요?…` · `넷플릭스서비시스코리아 유한회사 통신판매업신고번호…` · `이 페이지는 Google reCAPTCHA의 보호를 받아…`까지 확인된다(총 텍스트 노드 67개, 노드 368개, `scrollHeight=3276`). 섹션 골격도 깊이 10, 폭 1144에 정확히 존재한다(위 ② 참조). **수집은 완전하고, 증류만 실패한 경우다.**

모바일은 1개 → **5개**로 개선됐다(`y=0 h=664` / `y=867 h=201` / `y=1124 h=826` / `y=2006 h=541` / `y=2855 h=1063`). 390 뷰포트에서는 콘텐츠가 화면 폭을 거의 다 쓰기 때문이다. **모바일 IR은 이제 골격 입력으로 쓸 만하고, 데스크톱 IR은 아직 아니다.**

**주의 — 컨테이너 값이 퇴행했다.** 히어로 컨테이너가 `1144` → **`588`**로 바뀌었다. 오버레이 제외 규칙이 히어로 내부 하강을 막으면서, 가장 넓은 중앙 정렬 자손으로 안쪽 텍스트 블록(588)을 고른 결과다. **페이지 전역 컨테이너는 트리 실측대로 1144가 맞다**(본문 섹션 3개가 전부 폭 1144). 재현 입력으로 588을 쓰면 안 된다.

`layers`는 **빈 배열**이다. 히어로와 본문 사이의 핑크→붉은 아크는 앰비언트 레이어로 안 잡혔다 — `position: fixed/absolute` + `h ≥ 300` 조건에 안 맞는 얇은 요소이거나 배경 그라디언트로 그려진 것으로 보인다. 시각 확인에서 본 그 경계는 **여전히 IR에 없다.**

**이 단계(02:18판)의 판정: 보류.** 단 성격이 바뀌어 있었다 — 모션은 이미 재현 가능한 수치를 갖췄고(위 호버 표), 남은 결손은 **데스크톱 섹션 추출 하나**였다.

> **이후 최종 계기에서 문턱이 0.75로 내려가 섹션 5개로 해소됐고, 판정도 "리드 자격 있음"으로 바뀌었다. 문서 끝의 "## 최종 계기 재판정"이 정본이다.**

## 최종 계기 재판정 (Tier-R, 2026-08-17 · `ir.mjs` 문턱 0.75 / 깊이 14)

계기의 후보 폭 문턱이 `0.8 → 0.75`로 내려가면서 **컨테이너 1144(= 뷰포트의 0.794)가 통과**했다. 위 ②에서 지목한 "0.6%p 미달"이 그대로 해소됐다.

### 섹션 1개 → 5개, 눈과 정확히 일치

| # | y / h | tag | 컨테이너 | 열 | bg | headline |
|---|---|---|---|---|---|---|
| 1 | 68 / **720** | div | 588 | 1 | `#000` | **56px `영화, 시리즈 등을 무제한으로`** |
| 2 | 999 / **315** | div | **1144** | **6** | `#000` | 24px `지금 뜨는 콘텐츠` |
| 3 | 1362 / **377** | div | **1160** | **4** | `#000` | 24px `가입해야 하는 또 다른 이유` |
| 4 | 1787 / **615** | div | **1144** | 1 | `#000` | 24px `자주 묻는 질문` |

**눈으로 센 8블록 중 3개는 `h >= 200` 문턱 미달이라 정당하게 빠진다** — 상단 바(~70px), 광고형 멤버십 프로모 배너, 하단 CTA 반복(`y=2466 h=**116**`, 트리에서 직접 확인). 자격 블록만 세면 **5 = 5. 정확히 일치한다.** 모바일도 5개(`y=68 h=496` / `867 h=201` / `1112 h=838` / `1990 h=557` / `2819 h=1003`).

새로 드러난 것 셋:

- **컨테이너가 세 종이다: 1144 / 1148 / 1160.** 본문 두 섹션과 푸터가 1144~1148로 사실상 같고, **`가입해야 하는 또 다른 이유` 카드 4장 섹션만 1160으로 16px 넓다.** 카드 사이 간격을 컨테이너를 넓혀 흡수한 자리다.
- **열 수가 섹션마다 다르다: 1 → 6 → 4 → 1 → 1.** Top10이 6열(포스터 5장 + 화살표 자리), 가입 이유가 4열, 나머지는 단일 열.
- **`bgSequence`가 `#000` ×5.** 3,276px 전체에서 배경 전환이 **한 번도 없다**는 사실이 이제 5개 섹션 전수로 확인됐다. 위 본문의 "덜어낸 랜딩" 판단을 계기가 뒷받침한다.
- 높이 리듬: **720 → 315 → 377 → 615 → 570.** 히어로가 압도적으로 크고(2.3배), 나머지는 315~615에서 논다.

**히어로 컨테이너 588은 여전히 퇴행값이다.** 오버레이 제외 규칙이 히어로 내부 하강을 막아 안쪽 텍스트 블록을 고른다. **페이지 전역 컨테이너는 1144**이고, 이제 섹션 2·4·5가 독립적으로 그 값을 물어 준다. 재현 입력에 588을 쓰면 안 된다.
