## 수치

### 한글 타이포 — toss와 정확히 반대인 두 결정

같은 한국어 사이트인데 toss와 두 지점에서 정반대다. 둘 다 옳다. **장르가 다르기 때문이다.**

| | toss.im (랜딩) | ohou.se (커머스 피드) |
|---|---|---|
| `letter-spacing` | 172개 노드 전부 `normal`(0) | **253개 노드 전부 `-0.3px`. 예외 0건** |
| `word-break` | 350개 전부 `keep-all`. 예외 0건 | `normal` 219 / `keep-all` **18** / `break-all` **16** |
| 최대 폰트 | 80px | **32px** (페이지 전체에서 1회) |
| 폰트 단 | 18단 | 10단 (`10 11 12 13 14 16 17 18 20 32`) |
| 웨이트 | 400/500/600/700 4단 | **400(126) + 700(118) = 96%의 이분법** |
| 서체 | Toss Product Sans(자체) | **Pretendard Variable** |

`body`가 `font-size:15px / line-height:15px(=1.0) / letter-spacing:-0.3px`. toss와 똑같이 **행간 상속을 1.0으로 죽여놓고** 컴포넌트마다 명시하는데, 자간은 반대로 **전역에 -0.3px을 걸어 전부 상속시킨다.**

**자간 -0.3px은 Pretendard를 쓴다는 사실의 결과다.** Pretendard는 기본 자간이 라틴 기준으로 느슨해서 한글 본문에서 -0.3 ~ -0.5px을 빼는 게 관례가 됐다. toss는 자체 서체라 뺄 필요가 없었다. **"한글에 자간 주지 마라"는 규칙이 아니라 서체 의존 변수**라는 게 두 표본을 겹쳐야 보이는 결론이다.

### word-break — 이 사이트의 가장 이식성 높은 발견

18개 `keep-all`과 16개 `break-all`이 뭐에 걸렸는지 전수로 봤다. 규칙이 하나로 떨어진다.

**글을 누가 썼느냐로 갈린다.**

| 값 | 걸린 대상 | 실제 문자열 |
|---|---|---|
| `keep-all` | **오늘의집이 쓴 편집 카피** | `집돌이가 될 수밖에 없는 집, 아날로그 취향 가득한 18평 투룸` · `가구 배송도 가볍게, 원하는날도착` · `휴식과 취미를 모두 즐길 수 있게, 실용적으로 꾸민 6평` |
| `break-all` | **판매자가 올린 상품명** | `[특가]퀵슬립 / 베스트슬립 인기매트리스 모음 (적당탄탄출시!)` · `필터 추가 증정! 스톤 음식물처리기 건조분쇄 2L (SC-S0201)` · `높이/길이 모두 조절되는 풀스텐 식기건조대 外 99종` |
| `normal` | 그 외 219개 — 줄바꿈이 일어날 일 없는 짧은 라벨·크롬 | |

판매자 문자열엔 `[]`, `/`, `(SC-S0201)` 같은 **끊을 수 없는 긴 토큰**이 박혀 있다. `keep-all`을 걸면 269px 카드를 뚫고 나간다. 그래서 **내가 통제하는 문장에는 `keep-all`, 남이 업로드한 문자열에는 `break-all`**을 건다. toss가 전역 `keep-all`을 박을 수 있었던 건 페이지의 모든 글자가 1st-party였기 때문이다.

`line-clamp` 전수 조사가 이 규칙을 그대로 복창한다:

| clamp | size / line-height | word-break | 박스 높이 | 정체 |
|---|---|---|---|---|
| 2 | 32px / 42px (1.31) | `keep-all` | 42px | 히어로 제목 |
| 3 | 16px / 24px (1.5) | `keep-all` | 72px | 편집 콘텐츠 제목 |
| 2 | 16px / 24px (1.5) | `keep-all` | 48px | 편집 콘텐츠 제목 |
| 2 | 13px / 17px (1.31) | `break-all` | 34px | **판매자 상품명** |

**클램프된 텍스트 박스는 예외 없이 (keep-all + 16~32px + 편집) 아니면 (break-all + 13px + 판매자) 둘 중 하나다.** 그리고 전부 clamp가 걸려 있어 카드 높이가 문자열 길이와 무관하게 고정된다. 그리드가 절대 안 흔들리는 1차 이유가 이거다.

### 행간 — 비율이 아니라 정수 px

toss는 1.3/1.4/1.5/1.6 배율로 관리한다. ohou는 **px 정수값**으로 관리한다.

`10/14` `11/11` `12/16` `12/20` `13/17` `13/18` `14/18` `14/20` `16/20` `16/24` `17/23` `18/24` `20/28` `32/42`

배율로 환산하면 `1.0 · 1.154 · 1.25 · 1.286 · 1.308 · 1.333 · 1.353 · 1.4 · 1.429 · 1.5 · 1.667`로 열한 종이 흩어져 지저분한데, **행간 값 자체는 `11 14 16 17 18 20 23 24 28 42`의 정수 px 10종**으로 깔끔하다. 같은 12px 본문이 어디서는 16px, 어디서는 20px 행간을 받는 것도 배율이 아니라 **"이 슬롯의 높이가 몇 px이어야 하는가"**로 정해지기 때문이다. **고정 높이 카드를 픽셀로 조립하는 커머스에서는 행간을 비율로 두면 반올림이 슬롯마다 다르게 떨어져 카드가 1px씩 어긋난다.**

주의: `11px / line-height 11px`(=1.0) 10개가 있다. 한글에 행간 1.0은 위아래가 붙는다. 전부 카드 위 초소형 라벨이라 1줄로 끝나서 티가 안 날 뿐, 2줄이 되는 순간 깨진다.

### 표면

- `border-radius` 100개 중 **`4px`가 53개**. 그다음 16px(18) · 100%(11, 원형 아바타/버튼) · 24px(7).
- **`box-shadow`는 페이지 전체에서 값 1개 × 7회**: `rgba(63,71,77,.15) 0 2px 5px`. 전부 캐러셀 좌우 화살표 원형 버튼이다.
- 보더 1px `#EAEDEF`(4회) — 헤더 하단 구분선.
- 배경값 실측 용도: `#FFFFFF`(본문 전역) / `#F7F9FA`(**푸터 전용**) / `#03101D`(최상단 프로모 바) / `#EAEDEF`(히어로 img 플레이스홀더) / `#F5F5F5`(**상품 썸네일 플레이스홀더** — `production-item-image` 269×269 10개).

**본문 영역 전체가 순백이다.** 전수 확인: 고정 헤더를 뺀 비-흰색 풀블리드 밴드는 **푸터(y3846, 1425×334, `#F7F9FA`) 하나뿐**이고, 프로모 바(y0, h50, `#03101D`)는 폭 1156px 중앙 블록이라 풀블리드도 아니다. 즉 **내비 아래 183px부터 푸터 전 3846px까지 3,663px 구간에 배경 전환이 0회다.**

toss가 흰색/`#F9FAFB` 두 값을 A/B로 번갈아 깔아 챕터를 나눈 것과 정반대다. **ohou는 배경으로 아무것도 나누지 않고, 섹션 구분을 전적으로 「20px 표제 + 여백」에 맡긴다.**

플레이스홀더 회색이 `#EAEDEF`(신)와 `#F5F5F5`(레거시 `production-item-*`) 두 벌인 것도 아래 「카드 2세대」와 같은 원인이다.

## 실측 토큰 — `--ds-*` 876개, 3계층

`:root`에는 커스텀 프로퍼티가 **0개**다. 런타임에서 안 잡힌다. 전부 462KB짜리 `root-Xkxf4pmX.css` 안에 있고, 별도 셀렉터에 물려 있다. 직접 수확한 결과 **876개 토큰이 3계층**으로 나뉜다.

| **3846–4180** | **334** | 푸터 `#F7F9FA` | 고객센터 카드 3개(1px 보더) + 링크 3컬럼 + 법인정보 + 인증 뱃지 3개 + 소셜 4개. **페이지의 유일한 비-흰색 풀블리드 밴드** |

(세션마다 모듈이 바뀌므로 y값은 이 측정 회차 기준이다. 고정된 것은 순서가 아니라 아래의 헤더 문법이다.)

### 섹션 헤더가 단 하나의 문법이다

표제 있는 블록 8개가 **전부 똑같다.**

```
20px / 28px(1.4) / 700 / #2F3438   x=145  (좌단)
16px / 20px(1.25) / 700 / #00A1FF  x=1240 (우단, "더보기")
```
1240 + 41 = 1281 = 콘텐츠 우측 끝. **표제 크기·색·위치·더보기 링크가 8회 반복되며 단 1px도 안 바뀐다.** 20px 표제와 32px 히어로 사이에 아무것도 없다 — 페이지의 위계는 사실상 **32 / 20 / 16 / 14 / 13 / 12의 6단**이고, 그중 32px은 1회뿐이라 **실사용 5단**이다.

### 배너 카드는 설명이 제목 위에 온다

```
14px / 20px / 400 / #2F3438   전상품 무료배송          ← 아이브로(설명)
16px / 24px / 700 / #2F3438   매일 새로운 장보기 핫딜 오마트  ← 제목
```
간격 22px. 보통의 제목→부제 순서를 **뒤집어서** 서술문을 위, 서비스명을 아래에 둔다. 스캔할 때 "뭘 해주는 서비스인지"가 먼저 읽히고 이름은 나중에 붙는다.

### 상품 카드가 두 세대 공존한다

같은 페이지에 **구현이 다른 상품 카드 2종**이 있다. 실측 차이:

| | 레거시 (`production-item-*`, BEM) y≈2170 | 신 DS (`css-*`, emotion) y≈3720 |
|---|---|---|
| 가격 | **17px / 23px / 700 / `#000000`** | **18px / 24px / 700 / `#141414`** |
| 할인율 | 17px / 700 / **`#0AA5FF`** | 18px / 700 / **`#00A1FF`** |
| 리뷰수 | 12px / 16px / **700** / `#9E9E9E` | 12px / 16px / **400** / `#8C8C8C` |
| 상품명 | 13px / 17px / 400 / `#424242` | 13px / 18px / 400 / `#141414` |

**한 화면 안에서 6개 값이 어긋난다.** 사이즈 1px, 웨이트 300, 색 4종. 이게 `--ds-legacy-*` 231개가 아직 살아 있는 이유이자 결과다.

### 상품 카드 정보 밀도 — 7층인데 안 지저분한 이유

한 카드에 **판매자명 / 상품명 2줄 / 할인율 / 가격 / 별점 / 리뷰수 / 배송뱃지 / 특가칩**이 다 들어간다. 그런데 정돈돼 보인다. 조건 4개:

1. **좌측 1개 축에 전부 정렬.** 269px 카드 안에서 모든 행이 같은 x에서 시작한다. 중앙정렬·우측정렬 0건.
2. **사이즈 단이 3개뿐.** 12(메타) / 13(상품명) / 17~18(가격). 카드 안에서 위계는 색이 진다.
3. **가격 행만 유일하게 굵고 크다.** 시선 앵커가 카드당 정확히 1개.
4. **높이가 고정.** 상품명은 `line-clamp:2`로 34px 고정, 이미지는 269×269 고정. 문자열이 길든 짧든 카드 높이가 안 변한다.

## 자산 운용 — UGC를 상업 페이지로 만드는 문법

이미지 76개 · png 36 / jpg 27 / webp 2 / avif 1 / svg 1 / data-URI 8.

### ① 핵심: 크롭을 CSS가 아니라 **URL 계약**으로 처리한다

사용자 사진은 비율·해상도가 제각각으로 들어온다. ohou는 그걸 **레이아웃에 닿기 전에 CDN에서 정규화**한다.

```
https://prs.ohousecdn.com/v1-504677840543872.jpg?w=850&h=510&c=c
                                                  └─────┘ └──┘ └─┘
                                                  목표 박스  center crop
```

실측된 파라미터 조합 전부:

| 쿼리 | 사용처 | 표시 크기 |
|---|---|---|
| `w=850&h=510&c=c` | 히어로 | 847×508 (5:3) |
| `w=360&h=360&c=c&q=0.8` | 상품 썸네일 | 269×269 (1:1) |
| `w=360&h=240&c=c` | 집들이 4-up | 269×179 (3:2) |
| `w=256&h=342&c=c` | 세로 UGC 캐러셀 | 173×230 (3:4) |
| `w=480&h=321&c=c` | 시공 리뷰 3-up | 365×244 (3:2) |
| `w=480&h=480&c=c&q=50` | 정사각 3-up | 365×365 (1:1) |
| `w=36&h=36&c=c` | 아바타 | 24×24 (1:1, 1.5x) |
| `w=72` / `w=256` / `w=144` | 아이콘류(비율 보존) | |

**비율은 딱 4개다: 1:1, 3:2, 3:4, 5:3.** 그리고 `c=c`(center crop)가 붙는 순간 원본이 뭐든 이 4개 중 하나로 강제된다.

그래서 생기는 결과 3가지:
- CSS에 **`aspect-ratio` 정의가 실질 0건**이고 `padding-top:%` 비율 박스도 0건이다. 박스는 그냥 고정 px, 이미지는 이미 맞는 비율로 도착한다.
- `object-fit`이 `fill` 34개 / `cover` 25개 / `contain` 17개. **`fill`을 써도 안 찌그러진다** — CDN이 비율을 보장했기 때문이다.
- 폭은 `72 · 144 · 256 · 360 · 480 · 850`의 **고정 사다리**에서 고른다. 269px 슬롯에 360을 주고(1.34x), 88px 슬롯에 256을 준다(2.9x). 슬롯별 정확한 DPR 계산이 아니라 **"다음 단계 위"를 집는 방식**이라 캐시 히트율이 올라간다.

### ② 사진 위 텍스트를 4중으로 방어한다

히어로 실측 구조:

```
a 847×508
├ img 847×508   ?w=850&h=510&c=c   object-fit:cover
│                background-color: #EAEDEF        ← ② 로딩 전 구멍 방지
└ div 847×160   position:absolute bottom  padding: 0 30px 30px
   background: linear-gradient(rgba(0,0,0,0), rgba(0,0,0,0.4))   ← ③ 스크림
   ├ p    32px/42px 700 #FFF  keep-all  clamp:2  ls:-0.3px
   │      text-shadow: rgba(63,71,77,0.25) 0 2px 10px            ← ④ 헤이즈
   └ span (flex)
      ├ img 24×24 border-radius:100%   ?w=36&h=36&c=c
      └ span 16px/20px 400 #FFF        guk.home
```

1. **CDN 크롭**으로 기하 보장
2. **`#EAEDEF` 배경색**을 img에 직접 — 로딩 중에도 회색 사각형이지 흰 구멍이 아니다
3. **160px 하단 스크림**(사진 높이의 31.5%), `투명 → rgba(0,0,0,0.4)`
4. **`text-shadow: rgba(63,71,77,.25) 0 2px 10px`** — 검정이 아니라 **UI 회색과 같은 계열(`#3F474D`)의 25%**, 블러 10px에 스프레드 0. 그림자가 아니라 **헤이즈**다

**toss는 스크림이 0개다.** 자기가 발주한 사진이라 저대비 영역을 골라 앉히면 그만이었다. ohou는 고를 수가 없다 — 남의 집 사진이고, 창문이 어디 있을지 모른다. **통제 못 하는 사진 위에 글자를 올리려면 방어를 겹쳐야 한다**는 게 이 대비의 결론이다.

그리고 이 스크림 그라디언트는 **페이지 전체에서 유일한 그라디언트**다. 장식으로는 한 번도 안 쓴다.

### ③ 사진마다 저작자가 붙어 다닌다

모든 UGC 사진에 **24×24 원형 아바타 + 16px 흰색 핸들**이 좌하단에 박혀 있다(`밍지의방` `slowyu` `잇츠솜` `옐로우동동` `dailyen_home` `배무드` `미니로니홈` `리유에르` `muulizip`). 캐러셀 아이템 9개 전수 확인. **예외 없다.**

아바타도 `?w=36&h=36&c=c`로 같은 파이프라인을 탄다. 프로필 사진 역시 사용자가 올린 것이라 크롭 계약이 필요하다.

### ④ 스크랩 버튼이 카드의 기본 부품이다

UGC 사진이든 상품이든 **우하단에 북마크(스크랩) 아이콘**이 상시 노출된다. 호버로 나타나지 않는다. 커머스에서 UGC의 목적은 감상이 아니라 **수집 → 재방문**이고, 그 동작을 첫 화면부터 노출한다. `--ds-productCardScrap-*` / `--ds-scrapButton-*` 두 벌의 토큰이 따로 있을 만큼 1급 부품이다.

### ⑤ 사진을 예쁘게 만들지 않는 구역이 있다

「유저들의 인테리어 시공 리뷰」 3장은 **보정도 스타일링도 안 된 실제 현장 사진**이다 — 보양지 깔린 욕실, 살림살이 널린 주방, 빈 방. 바로 위 「추천 집들이」의 잘 꾸민 컷들과 같은 365px 폭·같은 카드로 나란히 놓인다.

**증거로 쓰는 사진과 영감으로 쓰는 사진을 시각적으로 구분하지 않는다.** 시공 리뷰를 카탈로그 품질로 보정하면 리뷰의 기능(진짜라는 증거)이 죽는다.

### ⑥ 오버레이 뱃지 실측

챌린지 카드 우하단 카운터: **60×26, `rgba(33,38,41,0.5)`, `border-radius:13px`(=높이의 절반), 흰색 14px/700, bottom:12px right:12px**. 순검정이 아니라 `#212629` 50%다 — 스크림 색과 같은 계열을 유지한다.

## 인터랙션 — 거의 없다

### 트랜지션 전수

정지 상태에서 **duration이 0이 아닌 요소는 페이지 전체에 6개**뿐이다.

| property | 개수 | duration | easing |
|---|---|---|---|
| `transform` | 4 | 0.2s | `ease` |
| `opacity` | 2 | 0.2s | `ease-in-out` |

`transition: all`이 **1,176개 요소**에 걸려 있지만 전부 **duration 0s**다. 값만 있고 시간이 없다 — 실제로는 아무것도 안 움직인다. (스캐너가 `transition: all`만 세면 "1176건 남용"으로 잡히는데, **duration을 같이 안 재면 나오는 오탐**이다.)

### 호버 (실측)

| 대상 | 변하는 것 | from → to |
|---|---|---|
| 내비 링크 | color만 | `#2F3438` → `#00A1FF` |
| UGC 카드 제목 | color만 (a·div·p 3계층 동시) | `#424242`/`#2F3438` → `#00A1FF` |
| 로고 | **무반응** | — |
| 버튼 | **무반응** | — |

**호버는 색 하나만 바꾸고, 트랜지션이 없으니 즉시 바뀐다.** transform·box-shadow·opacity 호버 0건. 카드가 뜨지도, 커지지도, 그림자가 지지도 않는다. toss(0.1~0.2s 색 전환)보다 한 단계 더 금욕적이다.

### 스크롤

- **리빌 애니메이션 0건.** 스크롤로 나타나는 요소가 없다. 대신 **뷰포트 밖 컴포넌트를 언마운트**한다 — 성능 최적화지 연출이 아니다.
- `loading="lazy"` 속성은 **76개 이미지 전부에 없다.** 네이티브 지연로딩 대신 JS 마운트로 처리한다. 로딩 중엔 1×1 base64 png 8개가 자리를 잡는다.

### 헤더 — 스크롤하면 붙는다

| scrollY | fixed 바 |
|---|---|
| 0 | **0개** (정적) |
| 120 이상 | 2개 |

- 주 내비: `position:fixed; top:0; height:81px; z-index:1102; background:#FFFFFF`
- 부 내비: `position:fixed; top:29px; height:52px; z-index:1101; background:#FFFFFF`

부 내비가 주 내비(z 1102) **뒤로 밀려 들어가** 스크롤 시엔 81px 한 줄만 보인다. 정지 시 183px → 스크롤 시 81px로 접힌다.

**`backdrop-filter: none`, `box-shadow: none`.** 불투명 흰색 + `1px #EAEDEF` 하단 보더로 끝낸다. toss가 그라디언트 하드스톱으로 푼 문제를 여기선 **그냥 불투명하게** 푼다. 블러도 그림자도 없다.

## 배울 것

1. **`word-break`를 "누가 쓴 글이냐"로 나눠라.** 내가 쓴 편집 카피 18개는 `keep-all`, 판매자가 올린 상품명 16개는 `break-all`. 실측 문자열이 이유를 다 설명한다 — `(SC-S0201)`, `[특가]퀵슬립 / 베스트슬립`처럼 **끊을 수 없는 토큰이 박힌 3rd-party 문자열에 `keep-all`을 걸면 카드를 뚫는다.** toss의 "전역 keep-all"은 모든 글자가 1st-party일 때만 성립하는 규칙이다. UGC·판매자 데이터가 섞이는 순간 규칙을 둘로 쪼개야 한다.

2. **한글 자간은 "0" 고정 규칙이 아니라 서체 종속 변수다.** ohou는 Pretendard Variable에 `body` 레벨 `letter-spacing:-0.3px`을 걸고 253개 노드 전부 상속시킨다(예외 0). toss는 자체 서체에 172개 전부 `normal`. **두 표본을 겹치면 "자간 건드리지 마라"가 아니라 "쓰는 서체의 기본 자간을 실측하고 한 번 정해서 전역에 못 박아라"가 규칙이다.** 컴포넌트마다 다른 자간이 나오는 게 진짜 문제다.

3. **고정 높이 카드를 만들 거면 행간을 배율이 아니라 px로 잡아라.** 실측 사다리 `12/16` `13/17` `14/18` `16/24` `17/23` `18/24` `20/28` `32/42` — 배율로는 1.0~1.67로 지저분하지만 px로는 4의 배수로 떨어진다. 배율로 두면 폰트 크기 바꿀 때 카드가 1px씩 어긋나고, 그리드 정렬이 깨진다. 랜딩은 배율(toss), 커머스는 px(ohou).

4. **UGC의 비율은 CSS가 아니라 CDN URL로 통제하라.** `?w=360&h=360&c=c` — 목표 박스와 center crop을 URL에 박아 **레이아웃에 닿기 전에** 정규화한다. 결과: `aspect-ratio` 정의 0건, 비율 박스 해킹 0건, `object-fit:fill`을 써도 안 찌그러짐. 비율은 `1:1 · 3:2 · 3:4 · 5:3` 4종으로 끝. 폭은 `72·144·256·360·480·850` 고정 사다리에서 "다음 단계 위"를 집는다(슬롯별 정확한 DPR 계산 안 함 → 캐시 히트율↑).

5. **통제 못 하는 사진 위의 글자는 방어를 4겹으로 쌓아라.** ① CDN 크롭으로 기하 보장 ② `img`에 `background:#EAEDEF` 직접(로딩 중 흰 구멍 방지) ③ 하단 **160px**(사진 높이의 31.5%) 스크림 `투명→rgba(0,0,0,.4)` ④ `text-shadow: rgba(63,71,77,.25) 0 2px 10px`. **그림자 색이 순검정이 아니라 UI 회색 계열(`#3F474D`)의 25%, 블러 10px·스프레드 0** — 그림자가 아니라 헤이즈라 사진을 더럽히지 않는다. 사진을 직접 발주하는 사이트(toss)는 이 4겹이 다 필요 없다. **"스크림을 깔아라"가 아니라 "사진의 통제권이 없으면 깔아라"**가 규칙이다.

6. **UGC엔 저작자를 예외 없이 붙여라.** 24×24 원형 아바타 + 16px 핸들이 모든 사용자 사진 좌하단에 있다. 캐러셀 9개 전수 확인, 예외 0. 아바타도 `?w=36&h=36&c=c`로 같은 크롭 파이프라인을 탄다(1.5x). 출처 표기는 법적 알리바이가 아니라 **"이건 연출컷이 아니라 실제 집"이라는 신뢰 장치**다. 뗄 거면 UGC를 쓸 이유도 없다.

7. **증거용 사진은 예쁘게 만들지 마라.** 「시공 리뷰」 3장은 보양지 깔린 욕실·살림 널린 주방 같은 무보정 현장 사진이고, 바로 위 「추천 집들이」의 연출컷과 **같은 365px 카드로 나란히** 놓인다. 리뷰 사진을 카탈로그 품질로 보정하는 순간 리뷰의 기능(진짜라는 증거)이 죽는다.

8. **배경으로 섹션을 나누지 않아도 된다 — 표제의 절대적 일관성이 대신한다.** 헤더 아래 183px부터 푸터 전 3846px까지 **3,663px 구간에 배경 전환이 0회**(전수 확인, 비-흰색 풀블리드 밴드는 푸터 하나뿐). 그런데도 섹션이 안 뭉개지는 건 헤더 문법이 8회 반복되며 **1px도 안 바뀌기** 때문이다 — `20px/28px/700/#2F3438` 좌단 x=145 + `16px/20px/700/#00A1FF` "더보기" 우단 x=1240(+41=1281=콘텐츠 우단). toss는 흰색/`#F9FAFB`를 A/B로 번갈아 깔아 8개 섹션을 나눴다. **두 방법 다 되지만, 섞으면 안 된다.** 배경도 바꾸고 표제도 흔들면 리듬이 사라진다.

9. **커머스 카드 7층을 정돈하는 조건 4개.** ① 좌측 1개 축 정렬(중앙·우측정렬 0건) ② 카드 내 사이즈 단 3개(12 메타 / 13 상품명 / 17~18 가격) ③ **가격 행만 유일하게 굵고 큼** — 시선 앵커 카드당 1개 ④ `line-clamp:2`로 상품명 34px 고정 + 이미지 269×269 고정 → **문자열 길이와 무관하게 카드 높이 불변.** 밀도의 적은 정보량이 아니라 **높이의 가변성**이다.

10. **배너 카드는 설명을 제목 위에 둬라.** `14px/400 전상품 무료배송` → 22px → `16px/700 매일 새로운 장보기 핫딜 오마트`. 서술문이 먼저 읽히고 서비스명이 뒤에 붙는다. 처음 보는 자사 서비스 이름은 그 자체로 아무 정보가 없다.

11. **호버는 색 하나, 트랜지션도 없이.** 내비·카드 제목 모두 `#2F3438 → #00A1FF` 색상만, duration 0. 페이지 전체에서 실제 duration을 가진 요소는 **6개**(transform 4 + opacity 2, 전부 0.2s). transform·shadow 호버 0건. **"잘 만든 사이트"의 표식은 카드가 뜨는 것이 아니다** — 두 번째 한국어 표본에서도 같은 결론이 나왔다.

12. **그림자는 "떠 있어야 하는 것"에만 1개.** `box-shadow` 값 1종 × 7회(`rgba(63,71,77,.15) 0 2px 5px`), 전부 캐러셀 화살표 버튼. 콘텐츠 위에 실제로 겹쳐 뜨는 컨트롤에만 쓰고 카드엔 안 쓴다. `border-radius`도 100개 중 **4px가 53개** — 사진을 사진으로 읽히게 하는 각진 값이지, 앱 위젯처럼 둥근 12~16px이 아니다.

13. **고정 헤더는 불투명하게 끝내도 된다.** `backdrop-filter: none`, `box-shadow: none`, 불투명 흰색 + `1px #EAEDEF` 하단 보더. 스크롤 120px에서 붙고, 부 내비(52px)가 주 내비(81px) 뒤로 밀려 들어가 **183px → 81px로 접힌다.** 블러 없이도 가독성 문제가 안 생긴다.

14. **디자인 토큰은 컴포넌트 계층까지 내려라.** 876개가 프리미티브(513) → 시맨틱(라이트/다크 2벌) → 컴포넌트(28개)로 3계층. **상품 카드 하나가 토큰 그룹 8개**(가격·제목·리뷰·혜택·배송정보·배송옵션·스크랩·품절배너)로 쪼개져 있다. 알파 스케일이 `blackAlpha-50`~`950` **19단**인 것도 사진 위 오버레이를 다루는 서비스의 필연이다 — 색보다 알파를 자주 쓴다.
