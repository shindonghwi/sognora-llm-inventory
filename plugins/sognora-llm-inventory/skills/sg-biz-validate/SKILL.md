# sg-biz-validate — 아이디어 → 진입 판정 → PRD

> 이 파일 하나가 Claude Code와 Codex 양쪽에서 동작한다.
> 인터뷰 질문 풀·경쟁사 분석 축·판정 기준·PRD 양식은 `references/rules.md`(SSOT).

**이 스킬만 되묻는다.** 다른 스킬은 무인 완주가 원칙이지만, 여기서는 대화가 기능이다. 사용자만 아는 것(자본·기간·보유 역량·리스크 감수 범위)을 모르면 판정이 공허해진다. 다만 **조사로 알 수 있는 것은 절대 묻지 않는다** — 경쟁사·시장 규모·가격대는 직접 찾는다.

## 철칙

1. **조사로 알 수 있는 건 묻지 않는다** — 사용자에게 묻는 것은 사용자만 아는 것뿐이다.
2. **한 번에 하나씩** — 질문은 한 번에 하나. 여러 개를 한꺼번에 던지지 않는다.
3. **근거 없는 숫자 금지** — 시장 규모·경쟁사 매출·사용자 수는 출처와 함께 적고, 못 찾으면 "미확인"이라 쓴다. 추정치는 **추정임을 명시하고 계산 과정을 보인다.**
4. **불리한 결론을 숨기지 않는다** — 판정이 "철회"면 그대로 말한다. 사용자가 듣고 싶어 하는 답을 만들지 않는다. 스킬의 가치는 안 될 걸 미리 알려주는 데 있다.
5. **경쟁사는 실물로 확인한다** — 이름만 나열하지 않는다. 실제 사이트·앱을 열어 기능과 가격을 직접 본다.

## 절차

### Phase 0. 인터뷰 설계 (질문 수를 먼저 정한다)

1. 사용자의 첫 입력을 읽고 **구체성 등급**을 매긴다: 한 줄 아이디어(막연) / 타깃·문제까지 있음(보통) / 이미 기획 문서가 있음(구체).
2. rules.md의 질문 풀에서 **아직 답이 없는 것만** 고른다. 이미 말한 내용은 다시 묻지 않는다.
3. 사용자에게 **먼저 예고한다**: `질문 {N}개만 하겠습니다. 그다음은 제가 조사합니다.`
   - 막연: 5~7개 / 보통: 3~5개 / 구체: 1~3개. **최대 8개를 넘지 않는다.**
4. 질문은 선택지 형태가 가능하면 선택지로 낸다(런타임에 선택지 도구가 있으면 사용). 사용자가 "모르겠다"고 하면 **가정을 세워 진행하고 가정임을 기록한다.**

### Phase 1. 인터뷰 (한 번에 한 문항)

예고한 개수만큼 묻는다. 답을 받을 때마다 필요 없어진 질문은 버린다(줄어드는 건 괜찮다, 늘리려면 이유를 말한다).
답변을 `_biz/{run_id}/00_brief.md`에 정리한다. **이때부터 사용자는 기다리면 된다.**

### Phase 2. 경쟁사 발굴·분석 (조사 — 되묻지 않는다)

1. **발굴**: 검색으로 후보를 모으고, rules.md의 "인지도" 기준을 통과한 곳을 **최소 3곳** 확정한다. 국내·해외를 섞고, 직접 경쟁 외에 대체재(사용자가 지금 이 문제를 해결하는 다른 방법)도 1곳 이상 넣는다.
2. **실물 확인**: 각 경쟁사의 사이트·앱을 실제로 열어 기능·온보딩·가격을 본다. 화면 확인이 필요하면 `sg-web-replicate`의 캡처 스크립트를 재사용할 수 있다.
3. **분석**: rules.md의 8축(핵심기능·차별점·가격·타깃·수익모델·유통채널·규모 신호·약점)으로 표를 만든다. 약점 축이 곧 우리의 진입 틈이므로 **사용자 리뷰·평점의 불만**을 근거로 채운다.
4. 산출: `_biz/{run_id}/01_competitors.md`

### Phase 3. 진입 판정 (돈을 벌 수 있는가)

rules.md의 판정 기준으로 **진입 / 조건부 진입 / 철회** 중 하나를 고르고 근거를 단다. 최소한 다음을 계산한다:
- **시장 규모** — 추정이면 계산식을 보인다(예: 대상 사업자 수 × 침투율 × 객단가)
- **단위 경제** — 고객 1명당 예상 매출과 비용, 손익분기까지 필요한 고객 수
- **진입 틈** — 경쟁사가 못 하거나 안 하는 것이 무엇이고, 왜 지금까지 아무도 안 했는지
- **리스크** — 무너뜨릴 수 있는 요인 3개와 각각의 조기 감지 신호
- 사용자가 밝힌 자본·기간·역량으로 **실제 도달 가능한지**

산출: `_biz/{run_id}/02_verdict.md`. **판정이 "철회"여도 PRD를 억지로 쓰지 않는다** — 대신 "이 조건이 바뀌면 재검토" 항목을 남긴다.

### Phase 4. PRD (판정이 진입·조건부 진입일 때만)

rules.md의 PRD 양식으로 `_biz/{run_id}/03_prd.md`를 쓴다. 핵심은 **MVP 범위 확정**이다 — 넣을 것보다 **뺄 것(Non-goal)** 을 명확히 적고, 각 기능이 Phase 3의 진입 틈과 어떻게 연결되는지 한 줄씩 단다. 연결되지 않는 기능은 MVP에서 뺀다.

### Phase 5. 보고 1회

한 줄 판정 + 경쟁사 3곳 요약 + 진입 틈 + MVP 범위 + 다음 검증 액션(가장 싸게 가설을 깰 방법)을 제시하고, 산출물 3개 경로를 안내한다.

`run_id`는 `YYYY-MM-DD-NNN`, cwd 기준으로 만든다.

## 후속 명령

- "경쟁사 더 찾아줘" — Phase 2만 재실행해 추가
- "판정 다시" — 새 정보(사용자 추가 답변·시장 변화)를 반영해 Phase 3 재실행
- "MVP 더 줄여" / "이 기능 빼고" — Phase 4만 재실행
- "다른 각도로" — 타깃·수익모델을 바꿔 Phase 3부터 재실행
