# sg-biz-validate — 룰북 (SSOT)

> Claude Code·Codex 양쪽이 공유하는 본체. 내용 수정은 이 파일에서만 한다.

## 질문 풀 (사용자만 아는 것)

조사로 알 수 있는 것은 여기 없다. 아래에서 **아직 답이 없는 것만** 골라 묻는다.

**A. 동기·맥락** (막연한 아이디어일 때 우선)
- A1 이 아이디어는 어디서 나왔나 — 직접 겪은 불편인가, 남이 겪는 걸 봤나, 시장이 커 보여서인가
- A2 이 문제로 실제로 곤란해하는 사람을 몇 명이나 아는가

**B. 자원·제약** → **묻지 않는다. `~/.sognora/biz-profile.md`에서 읽는다** (§운영자 프로필)
아이디어마다 바뀌지 않는 상시 사실이라 매 런 다시 물으면 낭비다. 프로필이 없을 때만 1회 만들고, 이후 런은 건너뛴다.

**비용은 절대 묻지 않는다** — 서버비·AI 생성 단가·외부 API 요금은 **공개 가격표로 조사되는 값**이고, 철칙 1(조사로 알 수 있는 건 묻지 않는다)의 대상이다. 사용자에게 "월 예산이 얼마냐"고 되묻는 것은 에이전트가 할 계산을 사용자에게 떠넘기는 것이다 → §계산 규칙의 "월 고정비 산출"로 처리한다.

**C. 시장·고객**
- C1 첫 고객이 될 구체적인 한 명을 묘사한다면
- C2 그 사람이 지금 이 문제를 어떻게 해결하고 있나 (대체재)
- C3 돈을 내는 사람과 쓰는 사람이 같은가

**D. 수익·검증**
- D1 생각해둔 과금 방식이 있나 (구독·건별·수수료·광고·없음)
- D2 이미 확보한 채널이 있나 (기존 고객·커뮤니티·팔로워·제휴)
- D3 "이 조건이면 접겠다"는 선 → **프로필에 있으면 묻지 않는다**

**E. 확정 사항** (구체적인 기획이 이미 있을 때)
- E1 이미 정해서 바꿀 수 없는 것 (플랫폼·기술·파트너·브랜드)
- E2 반드시 넣어야 하는 기능과 그 이유

## 운영자 프로필 (`~/.sognora/biz-profile.md` — 한 번만 만들고 계속 재사용)

아이디어가 바뀌어도 안 바뀌는 사실들이다. **런 시작 시 이 파일을 먼저 읽고, 있으면 해당 질문을 전부 건너뛴다.**

**사용자 스코프에 둔다** — 운영자 사실은 프로젝트와 무관하므로 `.sognora/biz/`(프로젝트별)에 두면 레포를 옮길 때마다 다시 묻게 되고, 그건 철칙 2 위반이다. 프로젝트 고유 사정이 있으면 `.sognora/biz/profile-override.md`로 덮는다.

| 항목 | 내용 |
|---|---|
| 형태 | 혼자 / 팀(인원) |
| 보유 강점 | 기술·유통·업계 인맥·기존 고객 중 실제로 가진 것 |
| 목표 수준 | 부업 현금흐름 / 본업 대체 / 투자 규모 |
| 병렬 한도 | 동시에 유지 가능한 제품 수 (솔로 운영자의 진짜 제약은 현금이 아니라 **본인 시간**인 경우가 많다) |
| 접는 선 | "이 조건이면 접겠다"는 기준 |
| 작성일 | `YYYY-MM-DD`. **6개월 지났으면 런 시작 시 요약을 보여주고 "그대로인가" 1회만 확인**한다(그 외에는 묻지 않는다) |

- 파일이 없으면 **첫 런에서만** 위 항목을 묻고 만든다. 그 뒤 런에서는 묻지 않는다(내용이 바뀌었으면 사용자가 먼저 말한다).
- 프로필 항목이 비어 있어도 **되물어 붙잡지 않는다** — 업계 통례로 가정하고 가정임을 기록한다.
- **프로필 항목마다 소비처를 명시한다** — 수집만 하고 판정에 안 쓰면 B1과 똑같은 결함을 층위만 바꿔 재발시킨 것이다:

  | 항목 | 어디서 소비되나 |
  |---|---|
  | 목표 수준 | 손익분기 고객 수의 합격선 **이자 인건비 수식** — 부업 목표면 인건비 $0, **본업 대체 목표면 목표 월수입을 고정비 인건비로 넣는다**(금액은 묻지 말고 해당 국가·직군 중위소득 등 조사값으로 놓고 "가정" 표시). **부업 목표에 "유니콘 가능성"을 논하면 미소비**(001 런의 실제 사고) |
  | 병렬 한도 | 이미 유지 중인 제품 수 대비 여력 — 없으면 판정에 "지금은 착수 불가"를 명시 |
  | 접는 선 | **철회 판정의 직접 입력.** 산출된 수치가 접는 선을 넘으면 철회다 |
  | 보유 강점 | "진입 틈을 메울 역량" 조건의 근거 |
  | 형태 | 고정비의 인건비 항목·운영 부하 |

- **금액·기간을 프로필에 적지 않는다.** 런웨이는 시점마다 달라져 금방 낡고, 판정에는 산출된 월 고정비와 손익분기 고객 수가 쓰인다.

### 질문 방식
- **한 번에 하나.** 선택지로 낼 수 있으면 선택지로(모르면 "모르겠음"도 유효한 답).
- 사용자가 "모르겠다"고 하면 **업계 통례로 가정을 세우고 가정임을 기록**한다. 되묻어 붙잡지 않는다.
- 답에서 이미 드러난 항목은 건너뛴다. 예고한 개수보다 줄어드는 것은 괜찮다.

## 경쟁사 — "인지도" 기준

이름만 아는 회사를 나열하지 않는다. 아래 중 **2개 이상** 충족해야 인지도 있는 경쟁사로 센다.

- 앱스토어·플레이스토어 리뷰 500개 이상 또는 상위 랭킹 이력
- 언론 보도·투자 유치 기록이 있음
- 검색 시 자연 노출 상위 (브랜드 검색량이 있음)
- 커뮤니티에서 실제 사용 후기가 반복적으로 언급됨
- 유료 고객 사례·로고가 공개돼 있음

**표에 "충족 기준" 열을 만들어 경쟁사마다 어느 2개를 통과했는지 적는다.** 자작 기준으로 대체 금지(001 런이 "상장사·대형 브랜드"라는 임의 기준을 썼다). 기준 미달인데 비교가 필요한 곳은 **별도 섹션 "기준 미달 참고"**로 분리하고 본 표에 섞지 않는다.

**구성 요건**: 최소 3곳. 국내·해외 혼합. 그중 1곳 이상은 **대체재**(같은 문제를 다른 방식으로 해결하는 것 — 엑셀·카톡·수기 등 비-제품 포함).

## 경쟁사 분석 8축

| 축 | 무엇을 적나 |
|---|---|
| 핵심 기능 | 실제로 무엇을 해주는가 (마케팅 문구가 아니라 사용 흐름) |
| 차별점 | 그들이 내세우는 강점 |
| 가격 | 요금제·무료 범위·숨은 비용. 가격 페이지 실물 확인 |
| 타깃 | 누구에게 파는가 (개인/소상공인/기업, 산업) |
| 수익모델 | 구독·건별·수수료·광고·라이선스 |
| 유통 채널 | 어떻게 고객을 데려오는가 (검색·앱스토어·영업·제휴·커뮤니티) |
| 규모 신호 | 리뷰 수·다운로드·채용 공고·투자·고객 로고 (추정이면 근거 명시) |
| **약점** | **리뷰·커뮤니티의 반복되는 불만.** 이게 진입 틈의 근거다 |

- **8축 열 이름은 위 표 그대로 고정이다.** 열을 바꾸거나 빼는 것 금지 — 확인 못 한 칸을 "미확인"으로 남기는 것과 **열 자체를 조용히 없애는 것은 다르다**(실전 사고: 두 런 모두 자작 열로 갈아치웠고, 그 결과 **유통 채널 축이 경쟁사 14곳 전부에서 사라졌다** — 정작 판정 기준은 "확보 채널로 도달 가능한가"를 묻는다).
- 약점은 반드시 **인용 근거**를 단다(리뷰 문구 요지 + **URL**). 근거가 없으면 칸을 비우지 말고 **"미확인(제품 분석 기반 추정)"**이라고 명시한다 — 추정을 실측처럼 보이게 두는 것이 진짜 위반이다.
- 확인 못 한 칸은 비워두고 "미확인"이라 쓴다. 채워 넣지 않는다.

## 진입 판정 기준

**진입** — 아래를 모두 만족
- 진입 틈이 경쟁사 약점에서 나왔고, 그 틈을 메울 역량을 사용자가 갖고 있다
- **월 고정비와 손익분기 고객 수를 숫자로 산출**했고, 그 고객 수가 확보 채널·시장 규모로 도달 가능하다
- 돈 내는 주체가 명확하고, 대체재보다 나은 이유가 한 문장으로 설명된다

**조건부 진입** — 위 중 하나가 불확실하지만 **싸게 검증 가능**할 때. 무엇을 어떻게 검증하면 판정이 뒤집히는지 명시한다.

> **숫자 산출은 판정 종류와 무관한 의무다.** "조건부"는 *불확실성의 표시*이지 *계산 면제*가 아니다 — 월 고정비·변동비·손익분기 고객 수는 세 판정 모두에서 산출한다. (실전 사고: 002 런이 단위 경제를 통째로 생략하고 조건부를 냈다. 이 구멍을 열어두면 "싸게 검증 가능"이 소프트웨어에서 거의 항상 참이라 **모든 아이디어가 조건부로 수렴**하고, 경제성 근거의 철회가 구조적으로 못 나온다.)

**철회** — 하나라도 해당
- 경쟁사가 이미 그 틈을 메우고 있거나, 메우지 않는 합리적 이유가 있다(수요 없음·규제·구조적 불가)
- 산출된 손익분기 고객 수가 시장 규모·확보 채널로 도달 불가능하다(예: 손익분기가 국내 전체 대상 수의 상당 비율을 요구한다)
- 차별점이 "더 싸게" 하나뿐이다 (자본력 싸움이 되어 대개 진다)
- **산출된 수치가 프로필의 접는 선을 넘는다**(접는 선은 철회의 직접 입력이다 — 매핑 표에만 두면 판정 기준만 읽는 에이전트가 놓친다)
- 돈 내는 주체가 불명확하다

**금지**: 판정을 흐리게 쓰지 않는다("가능성은 있어 보입니다" 같은 문장 금지). 셋 중 하나를 고르고 근거를 댄다.

## 계산 규칙

- **시장 규모**: **하향식 = 큰 시장 총액에서 우리 몫을 비율로 잘라 내려온다**(업계 보고서 $X × 배분율). **상향식 = 대상 수 × 침투율 × 객단가로 쌓아 올린다.** 둘 다 시도하고 차이가 크면 이유를 적는다. (실전 사고: 001 런이 두 라벨을 정확히 반대로 붙였다 — $89.8B 배분을 "상향식", 사업체 38,280곳×객단가를 "하향식"이라 씀)
- **비용은 고정/변동을 먼저 가르고 시작한다.** 섞으면 손익분기가 실제보다 좋게 나온다. 판단 기준 한 줄: **고객이 한 명 늘 때 같이 늘어나면 변동비.**
  - **월 고정비**(고객 수와 무관): 호스팅·DB·스토리지·대역폭 기본요금 / 고정 좌석제 SaaS / 도메인·메일 / 사람 인건비.
  - **변동비**(고객·사용량에 비례): **AI 추론(모델 단가 × 1건당 토큰·이미지 수 × 1인 월 사용 건수)** · 종량 API 호출 · **결제 수수료**(매출 비례) · 초과 트래픽.
  - 각 항목은 **공개 가격표를 조사해** 쌓고 출처 URL 또는 "가정" 표시를 단다. 스택이 아직 없으면(Phase 4 이전) **낙관·보수 2안을 만들고 보수안으로 판정한다** — 가정 하나로 결론이 뒤집히는 걸 막는 유일한 장치다.
- **단위 경제**: 고객 1명당 월 매출 − 변동비 = 기여이익. 고정비 ÷ 기여이익 = 손익분기 고객 수. 낙관·기준·보수 3개 시나리오로 낸다.
- 모든 가정에는 **출처 또는 "가정"** 표시를 단다. 출처 없는 숫자를 사실처럼 쓰지 않는다.

## PRD 양식

1. **한 줄 정의** — 누구의 어떤 문제를, 어떻게 해결하는 제품인가
2. **진입 틈과의 연결** — Phase 3에서 찾은 틈을 어떻게 공략하는가
3. **핵심 사용자 시나리오** 3개 — 사용자가 처음부터 목적 달성까지 밟는 흐름
4. **MVP 기능 목록** — 기능마다 "왜 MVP인가"를 진입 틈과 연결해 한 줄
5. **Non-goal** — 이번에 안 하는 것과 그 이유. **MVP 목록보다 길어도 좋다**
6. **화면 목록** — 화면명 · 목적 · 진입 경로 · 주요 상태(빈/로딩/오류)
7. **성공 지표** — 측정 가능한 숫자와 기준선. "많이 쓰이면 성공" 같은 문장 금지
8. **첫 검증 액션** — 개발 전에 가장 싸게 가설을 깰 방법
9. **미해결 질문** — 아직 모르는 것과 언제까지 답이 필요한지
