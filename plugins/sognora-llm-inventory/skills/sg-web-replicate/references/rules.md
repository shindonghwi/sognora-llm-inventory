# sg-web-replicate — 룰북 (SSOT)

> Claude Code·Codex 양쪽이 공유하는 본체. 내용 수정은 이 파일에서만 한다.

## 기본값 (사용자 지정이 없을 때 — 되묻지 말고 이걸 쓴다)

- **뷰포트**: `1440x900`(데스크톱) · `768x1024`(태블릿) · `390x844`(모바일)
- **DPR**: 1 (레티나 비교가 필요하면 2를 명시)
- **라우트**: **탐색된 전부**. 사이트를 복제하라는 요청은 사이트 전체를 뜻한다 — 홈 1개만 만들고 끝내지 않는다. 사용자가 범위를 좁혀 말했을 때만 축소한다.
  - 상한(`--max`)은 폭주 방지용 안전장치이지 작업 범위가 아니다. 상한에 걸리면 **올려서 다시 탐색**한다. 상한에 걸린 채로 진행하고 "미탐색이 남았다"고 보고하는 것은 요청 불이행이다.
  - **범위를 임의로 줄이지 않는다.** 탐색 결과가 예상보다 크면(고유 페이지 20개 초과, 또는 성격이 다른 하위 사이트가 섞여 있음) 자르거나 혼자 판단하지 말고 **사용자에게 그룹별 페이지 수와 함께 선택지를 제시해 범위를 확인한다**(§무인 완주 예외). 확인 전까지는 명백한 본체(홈 + 같은 템플릿 계열)부터 진행해 시간을 낭비하지 않는다.
  - 범위 제안 전에 **별칭을 정리한다**: 같은 내용이 여러 경로로 열리면(`/post/001`과 `/post/001.html`) 하나로 센다. 중복을 세어 페이지 수를 부풀리면 사용자가 범위를 잘못 판단한다.
- **테마·로케일**: 원본의 기본 상태 하나. 다크모드·다국어는 지정 시에만
- **인증**: guest 상태만. 로그인 구간은 사용자가 자격증명을 준 경우에만
- **스크롤 지점**: 0% · 50% · 100%
- **강도**: 기본 게이트(아래). `--strict`면 엄격 게이트

## 측정 항목 (이 값들이 판정 근거다)

**레이아웃** — 요소별 x, y, width, height (`getBoundingClientRect`) · 부모-자식 gap · padding · margin · 컨테이너 max-width
**타이포그래피** — font-family, size, weight, line-height, letter-spacing
**장식** — 색(배경·전경·보더), border-width, border-radius, box-shadow
**동작** — sticky/fixed offset, 스크롤 지점별 위치 변화, hover 전후의 크기·색 변화, transition duration·easing
**반응형** — 브레이크포인트 경계값, 각 뷰포트에서의 컬럼 수·정렬

측정 대상은 **의미 있는 블록**(헤더·내비·히어로·섹션 컨테이너·카드·버튼·푸터)이다. 모든 DOM 노드를 재는 것은 낭비다.

## 통과 게이트

| 항목 | 기본 | 엄격(`--strict`) |
|---|---|---|
| 주요 블록 위치·크기 오차 | ≤ 2px | ≤ 1px |
| 폰트 크기·line-height 오차 | ≤ 1px | 0 |
| pixel diff 불일치율 (뷰포트당) | ≤ 2% | ≤ 0.5% |
| 의도치 않은 가로 스크롤 | 0건 | 0건 |
| 콘솔 오류 | 0건 | 0건 |
| 누락 자산(404) | 0건 | 0건 |
| 선언한 상호작용 시나리오 통과 | 100% | 100% |
| 선언한 라우트·상태 캡처율 | 100% | 100% |
| **폰트 family 일치** | 100% | 100% |
| 대체(미달성) 자산 | 보고 필수 | 0건 |

- **폰트는 타협 대상이 아니다.** 렌더된 `font-family`가 원본과 다르면 그 자체로 미달이다 — 치수 오차가 우연히 게이트를 통과해도 실패로 본다.

- 안티앨리어싱 때문에 pixel-perfect 0%는 불가능하다. 위 허용치가 현실적 기준이다.
- `override.json`에 선언된 의도적 차이는 diff 대상에서 제외한다. **선언되지 않은 차이는 전부 결함이다.**
- 게이트 미통과 상태에서 "완료"를 선언하지 않는다. 남은 오차를 표로 보고한다.

## 캡처 신뢰 규칙

- 파일명·요청값이 아니라 **실측 뷰포트**가 기준이다. `meta.json`의 `viewportRequested`와 `viewportMeasured`가 다르면 그 캡처는 기준 자료로 쓰지 않고 재캡처한다.
- 원본과 로컬은 **같은 조건**에서만 비교한다(뷰포트·DPR·스크롤 지점·상태). 조건이 다르면 diff 결과는 무효다.
- 애니메이션은 캡처 전 정지시킨다(`prefers-reduced-motion` + transition 무력화). 그러지 않으면 같은 페이지도 매번 다르게 찍힌다.

## 배치 규칙 (대상 프로젝트에 코드를 넣을 때)

**우선순위**: ① 프로젝트 규칙 문서(`CLAUDE.md`·`AGENTS.md`·`docs/*`) → ② 기존 코드 관례 → ③ **[`layout-presets.md`](layout-presets.md) 프리셋** → ④ 스택이 프리셋과 전혀 다를 때만 사용자 확인. 자기 취향으로 정하지 않고, 프리셋이 있으므로 새 프로젝트에서 배치를 묻지 않는다.

문서를 읽을 때 확인할 것: 라우팅 계층과 페이지 구현 계층이 분리돼 있는가 · 공용 컴포넌트와 화면 전용 컴포넌트의 경계 · 자동 생성 폴더(수정 금지 구역) · 정적 자산 위치 · 스타일·디자인 토큰 정의 위치.

**분리형 구조 주의** — 라우트 파일은 라우팅만 하고 화면 구현은 별도 계층에 두는 프로젝트가 있다(예: `src/app/**`는 라우팅, `src/features/{page}/`에 구현). 이런 곳에서 라우트 파일에 화면을 통째로 넣으면 규칙 위반이다. 섹션이 여러 개면 그 계층의 하위 관례(`sections/` 등)를 따른다.

**자동 생성 구역은 건드리지 않는다** — API 클라이언트·타입처럼 도구가 생성하는 폴더는 수정 금지다. 문서에 "수정 금지"로 표시된 경로를 확인한다.

**다국어(i18n) 프로젝트**
- 화면 문구를 **하드코딩하지 않는다.** 메시지 파일에 키로 넣고 컴포넌트는 번역 훅으로 읽는다.
- 원본 텍스트는 **기본 로케일 값**으로 넣는다. 지원 로케일이 여럿이면 나머지는 비워두고 "번역 필요"로 보고한다 — 임의로 기계번역해 채우지 않는다.
- 키 이름은 기존 메시지 파일의 계층 관례를 따른다(`common.*`, `{page}.*` 등).
- **게이트와의 관계**: 문구가 키로 빠져도 렌더 결과는 원본과 같아야 한다. 기본 로케일에서 diff가 통과하지 않으면 키 연결이 잘못된 것이다.

## 시각적 동작 재현

**이 스킬은 화면만 복제한다.** 기능(로그인·결제·검색 등 서버 로직)은 대상이 아니다. 원본 JS를 복원하지 않고 관찰한 것만 상태표로 적는다:

| 트리거 | 대상 | 변화 | 지속시간 |
|---|---|---|---|
| hover | .cta-button | 배경 #111 → #333, y -2px | 150ms ease-out |

- 서버 응답으로 채워지는 영역(목록·검색 결과)은 **같은 모양의 로컬 fixture**로 채운다. 원본 API를 호출하지 않고, 그 기능을 구현하지도 않는다.
- 로딩·빈 상태·오류 상태는 원본에서 관찰됐을 때만 화면으로 재현한다.
- **레이아웃에 영향 주는 서드파티 임베드**(iframe 위젯·리사이즈 스크립트)는 빠뜨리면 그 아래 전 구간이 밀린다. 실측에서 가장 흔한 오차 원인이므로 인벤토리에 남기고 그대로 넣는다.

## 안전 경계

- 원본에서 **상태를 바꾸는 조작 금지**: 결제, 가입·탈퇴, 글 작성·삭제, 메일 전송, 장바구니 담기 등. 클릭 전에 그 버튼이 조회성인지 확인한다.
- 캡처에 개인정보(이름·이메일·주문번호)가 찍히면 저장 전에 마스킹한다.
- robots.txt를 존중하고, 요청 간격을 둔다(연속 캡처 사이 최소 300ms).
- **자산은 원본 그대로가 기본이다.** 목표는 "완전히 똑같이"이므로 폰트·이미지·아이콘은 `fetch-assets.mjs`로 받은 실제 파일을 쓴다. 유사 폰트로 바꾸거나 아이콘을 직접 그리지 않는다(폰트가 다르면 글자 폭이 달라져 모든 치수가 어긋난다).
- 대체가 허용되는 경우는 둘뿐이다: ① 자산을 받을 수 없을 때(403·인증·CORS, 재시도 후에도 실패) ② 사용자가 교체를 명시적으로 지시했을 때(로고 등). 이때만 **CSS/SVG 재현 → 이미지 생성 위임(Codex는 `imagegen`) → 크기만 맞춘 플레이스홀더** 순으로 내려가고, 원본 측정 크기·종횡비를 그대로 쓴다.
- 대체한 항목은 전부 `override.json`에 기록하고 **"원본 미달성 항목"으로 보고한다** — diff에서 빠졌다고 해결된 것이 아니다.
- 복제물을 공개 배포할 때 타사 브랜드 자산(로고·상표·유료 폰트)을 그대로 쓰는 것은 사용자 책임이다. 최종 보고에 이 한 줄을 남긴다.
- 이 스킬은 학습·프로토타입·자사 리뉴얼용이다. 타인의 서비스를 그대로 배포하는 용도가 아님을 보고에 명시한다.
