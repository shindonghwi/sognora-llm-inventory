# sg-web-replicate — 측정 기반 웹 복제

> 이 파일 하나가 Claude Code와 Codex 양쪽에서 동작한다.
> 측정 항목·게이트 기준·안전 경계는 `references/rules.md`(SSOT). 명세 양식은 `references/spec-template.md`.

## 철칙

1. **눈대중 금지** — "비슷해 보인다"는 판정 근거가 아니다. 판정은 `scripts/`가 뽑은 수치와 diff만 인정한다.
2. **측정 없는 수치 금지** — 원본에서 측정하지 않은 `max-width`·`padding`·`clamp()`를 임의로 넣지 않는다.
3. **동작은 관찰로 재현** — 난독화된 원본 JS를 복원하려 들지 않는다. 관찰 가능한 상태 전이(hover 전후, 열림/닫힘)를 상태표로 적고 그대로 구현한다.
4. **의도적 차이는 선언** — 원본과 다르게 갈 항목(로고·브랜드명·삭제할 섹션)은 시작 시 `_replica/override.json`에 기록한다. 선언 안 된 차이는 전부 결함으로 취급한다.
5. **안전 경계** — 원본에서 상태를 바꾸는 조작(결제·가입·삭제·전송)은 실행 금지. 로그인 필요 구간은 사용자가 자격증명을 준 경우에만. 캡처에 개인정보가 찍히면 마스킹한다. 복제 결과물의 브랜드 자산 사용 책임은 사용자에게 고지한다.
6. **무인 완주 (예외 하나)** — 중간에 되묻지 않는다. 판단이 필요하면 안전한 기본값(rules.md)을 택하고 최종 보고에 근거를 남긴다. **유일한 예외는 인증**이다 — 자격증명은 사용자만 줄 수 있으므로, 로그인 벽이 실제로 탐지됐을 때 한 번 요청한다(§2 참조).

## 절차

### 1. 계약 확정 (LLM 콜 0)
대상 URL·복제 범위·뷰포트 세트·의도적 변경을 확정해 `_replica/contract.json`으로 저장한다. 기본값은 rules.md를 따른다.

### 2. 라우트 탐색 (브라우저 1회 기동)
```
node scripts/discover.mjs --url <URL> --out _replica/routes.json [--depth 2] [--max 100]
```
- sitemap.xml·robots.txt(가장 싸고 정확) + 실제 브라우저 링크 크롤을 합쳐 라우트 원장을 만든다.
- 각 라우트에 `status`·`title`·`auth`(guest|required)를 기록한다. `--max` 상한에 걸리면 미탐색이 남았음을 보고한다.
- **사용자가 라우트를 명시했으면 이 단계를 건너뛴다**(불필요한 크롤 금지).
- **로그인 벽이 탐지되면**: 그 라우트들을 목록으로 제시하고 **사용자에게 한 번 요청한다** — ① 로그인 세션 파일(`--storage state.json`) ② 테스트 계정 ③ "guest 범위만 복제"로 진행. 응답 전까지 guest 라우트 작업을 계속 진행하고, 인증 구간은 "보류"로 표시해 완주를 막지 않는다. 자격증명은 저장소·보고서에 기록하지 않는다.

### 3. 캡처 + 측정 (라우트당 브라우저 1회 기동)
```
node scripts/capture.mjs --url <URL> --out _replica/ref/<라우트> [--headed] [--viewports 1440x900,768x1024,390x844] [--storage state.json]
```
- 실제 Chromium을 띄워 **한 번의 기동으로 한 페이지의 전 상태**를 훑는다: 뷰포트별 × (초기·스크롤 지점·hover·메뉴 열림).
- 산출: 스크린샷 + `measure.json`(요소별 x/y/w/h·폰트·여백·색), `meta.json`(요청 뷰포트 vs 실측 뷰포트·DPR — **불일치 시 그 캡처는 기준으로 쓰지 않는다**).
- 실패 시 `--headed`로 1회 재시도(봇 차단 대응).

### 4. 명세 작성 (LLM 콜 1)
`measure.json`을 근거로 `spec-template.md` 양식에 맞춰 `_replica/spec.md`를 쓴다. 토큰(색·폰트·간격 스케일) → 공통 셸(헤더·푸터) → 섹션별 치수 → 상호작용 상태표 순. **모든 수치에 근거 필드**(어느 캡처의 어느 요소)를 단다.

### 5. 구현
spec.md 순서대로: 디자인 토큰 → 공통 셸 → 대표 섹션 → 나머지 → 반응형. 프레임워크는 대상 프로젝트 관례를 따른다.

**자산 처리 — 원본 그대로가 기본이다.** 목표는 "완전히 똑같이"다. 비슷하게 그리는 것이 아니다.

```
node scripts/fetch-assets.mjs --url <URL> --out _replica/assets [--storage state.json]
```
- 페이지가 실제로 로드한 **폰트 파일(woff2/woff/ttf)·이미지·아이콘·SVG**를 네트워크 응답에서 그대로 내려받고, `@font-face` 규칙(family·weight·style·unicode-range)과 CSS 변수를 추출해 `assets.json`에 기록한다.
- 구현에는 **받은 파일을 그대로 쓴다.** 폰트는 시스템 폰트나 유사 폰트로 바꾸지 않는다 — 폰트가 다르면 글자 폭이 달라져 모든 치수가 어긋난다.
- 웹폰트가 CDN(Google Fonts 등)에서 오면 같은 CDN 링크를 그대로 쓰거나 받은 파일을 셀프호스팅한다. **대체 폰트로 근사하지 않는다.**
- 이미지·아이콘도 받은 원본을 쓴다. 임의로 SVG를 그리거나 비슷한 도형으로 대체하지 않는다.

**생성·대체는 최후 수단이다.** 다음 경우에만 쓰고, 전부 `override.json`에 기록한 뒤 보고에 명시한다:
1. 자산을 받을 수 없을 때(403·인증 필요·CORS 차단) — 재시도 후에도 실패한 것만
2. 사용자가 브랜드 자산 교체를 **명시적으로 지시**했을 때(로고 교체 등)

이때만 원본에서 측정한 **정확한 크기·종횡비**로 대체물을 만든다: 비트맵이 필요하면 Codex의 `imagegen`(또는 런타임의 이미지 생성 도구), 그마저 없으면 크기만 맞춘 플레이스홀더. 대체한 항목은 diff 대상에서 제외되지만, 그 개수는 "원본 미달성 항목"으로 보고한다.

### 6. 비교 게이트 (반복)
```
node scripts/diff.mjs --ref _replica/ref/<라우트> --local <로컬URL> --out _replica/diff/<라우트> [--strict] [--override _replica/override.json]
```
- 원본과 로컬을 **동일 조건**(같은 뷰포트·DPR·스크롤 지점)에서 캡처해 pixel diff + 요소별 수치 비교.
- exit 0 통과 / 1 오차 초과 / 2 실행 불가. 통과할 때까지 4~6을 반복하되, **오차 상위 항목부터** 고친다.
- override.json의 `ignore` 항목은 diff에서 제외된다.

### 7. 완료 보고 1회
라우트 원장(탐색·처리·보류), 게이트 수치, 미달 항목, 선언된 의도적 차이, 미처리·미탐색 항목을 표로 보고한다. 게이트 미통과인데 완료로 선언하지 않는다.

## 사전 준비 (첫 실행 시 1회)

스크립트는 playwright가 필요하다. 없으면 exit 2와 함께 안내가 뜬다:
```
npm i -D playwright pixelmatch pngjs && npx playwright install chromium
```
pixelmatch·pngjs가 없으면 pixel diff는 건너뛰고 수치 비교만 수행한다(게이트는 계속 작동).

## 최적화 규칙

- **브라우저 기동은 최소화** — 페이지당 1회 기동으로 전 상태를 훑는다. 상태마다 새로 띄우지 않는다.
- **headless 기본** — 창 장식 때문에 뷰포트가 어긋나는 것을 막고 재현성을 확보한다. `--headed`는 사람 검수·봇 차단 폴백일 때만.
- **캡처는 증분** — 이미 있는 캡처는 `--force` 없이는 다시 찍지 않는다.
- **LLM 콜 최소** — 캡처·측정·diff는 전부 스크립트(콜 0). LLM은 명세 작성과 구현에만 쓴다. 스크린샷을 LLM에 통째로 넣어 "비교해줘" 하지 않는다(비싸고 부정확하다 — 판정은 diff.mjs가 한다).
- **라우트 여러 개면 병렬** — 3개 이상이고 런타임이 서브에이전트를 지원하면 라우트당 1개(동시 최대 3, 브라우저 동시 기동 부담 고려)로 캡처·구현을 분배하고, 메인은 게이트만 확정한다.

## 옵션

- `뷰포트: 1440x900,390x844` — 기본 3종 대신 지정
- `라우트: /, /about` — 복제 범위 지정 (기본: 주어진 URL 1개)
- `--headed` — 크롬 창을 실제로 띄워 눈으로 확인
- `--strict` — 오차 허용치를 rules.md의 엄격 기준으로
